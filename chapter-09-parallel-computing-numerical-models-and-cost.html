Why parallel computing: numerical models and their cost

A plate on a \(1000\times1000\) grid has \(10^{6}\) unknown temperatures. Jacobi iteration reduces the iteration error to \(10^{-6}\) after \(2.6\times10^{6}\) sweeps and \(1.3\times10^{13}\) floating-point operations. One core of the machine used in this book performs a sweep of this grid in 1.6 to 2.6 ms, so the run takes about 1.5 hours. A grid ten times finer in each direction multiplies the work by \(10^{4}\): 1.7 years. A program that stops when two successive sweeps differ by less than \(10^{-6}\) ends the \(1000\times1000\) run after about \(2\times10^{5}\) sweeps, 5 to 9 minutes at the rates measured here, with an error of about 0.15 to 0.17 in a field whose centre value is 0.25 (Chapter 4 measured 191,001 sweeps and a maximum error of 0.167). A faster single core is not available. In Rupp's continuation of the trend data shown in the lecture, the clock frequency doubled every 27.8 months from 1990 to 2003 and has had a slope of \(-0.011\) doublings per year since 2004; the earlier trend would give 354 GHz in 2021, and the highest clock among the entries since 2010 is 4.0 GHz. This chapter derives the five-point model of the plate, the convergence of Jacobi iteration and the iteration count that produce these numbers, shows which statements of the lectures the numbers confirm and which they correct, and states how much speedup a parallel machine must deliver.

Grounded in two recordings of the NPTEL course High Performance Scientific Computing (Prof. Shivasubramanian Gopalakrishnan, IIT Bombay): W3L1, Need for Parallel Computing, and W3L2, Role of Numerical Models in Solving Complex Problems on Computers. Lecture material: Moore's law, the MOSFET and Dennard scaling; the plateau of clock frequency and the growth of the core count; the sum of 10,000 integers by 10 and by 100 people; Amdahl's law; numerical modelling and its three errors; the central difference; the steady heat conduction problem on a plate as a linear system; the claim that iterative solvers are more efficient; the layers between a program and the hardware, the instruction set architecture (ISA) and the application binary interface (ABI). The objects of the chapter and the running case

The chapter studies one numerical problem and the cost of solving it. The plate problem is the steady temperature \(u(x,y)\) of a thin square plate of uniform material, \(0\le x,y\le1\). Steady heat conduction without sources in a material of constant conductivity \(\kappa\) obeys Laplace's equation \(\partial^2u/\partial x^2+\partial^2u/\partial y^2=0\) in the interior (Fourier's law \(\mathbf q=-\kappa\nabla u\) and the balance \(\nabla\cdot\mathbf q=0\)). The boundary values are given. This book fixes one boundary condition for all its solvers, the canonical problem: \(u=1\) on the top edge \(y=1\), and \(u=0\) on the other three edges. The lecture poses a different Dirichlet problem (the section on the stencil gives the difference); nothing in the matrix, the spectrum or the iteration count of this chapter depends on the boundary values, and only the code that fills the boundary changes.

The grid. A grid with \(N\) interior points per side has spacing \(h=1/(N+1)\). The array u holds \((N+2)\times(N+2)\) doubles in row-major order. The element u[IDX(i,j)], with #define IDX(i,j) ((i)*(N+2)+(j)), approximates the temperature at \(x_j=jh\), \(y_i=1-ih\). Row \(i=0\) is the top edge and row \(i=N+1\) the bottom edge. The indices \(1\le i,j\le N\) are the interior; the \(N^2\) interior values are the unknowns. The four edges hold the boundary values and are never changed. The lecture writes the grid with \(i\) along the horizontal axis and \(j\) downward and counts "\(i\) and \(j\) from 0 to \(n\)"; that grid has \((n+1)^2\) nodes, and the unknowns are the \(N^2\) interior nodes when the edges are given.

The scheme and the solver. The five-point scheme replaces the equation at each interior node by the statement that the value there equals the average of its four neighbours. A Jacobi sweep computes, for every interior node, the average of the four neighbours in the current array and stores it in a second array, unew. The change of a sweep is the largest absolute difference between unew and u over the interior. The program swaps the two arrays and repeats until the change is below the tolerance tol or max_iter sweeps are done. The iteration error after \(k\) sweeps is the largest difference between the \(k\)-th iterate and the exact solution of the five-point equations.

The cost. A point update is the computation of one new interior value together with the change at that node. It takes three additions and one multiplication for the average and one subtraction for the change, so one sweep performs \(F=5N^2\) floating-point operations (\(F\), the operation count, in the notation of this book; comparisons and absolute values are not counted). The work \(W\) of a solve is the number of operations of all sweeps, \(W=5N^2k\) for \(k\) sweeps. The time \(T_1\) is the wall-clock time of the solve on one thread, and \(t_{\mathrm{pt}}\) the time of one point update. With \(p\) processing elements, \(T_p\) is the wall-clock time, \(S_p=T_1/T_p\) the speedup and \(E_p=S_p/p\) the efficiency; \(f\) is the serial fraction of \(T_1\) in Amdahl's law (\(P=1-f\) is the parallel proportion in the lecture's notation). The symbols \(\rho\) (spectral radius of the iteration), \(\varepsilon\) (target iteration error) and \(\tau_{ij}\) (truncation error) are defined where they first appear.

The machine. Every time in the chapter comes from one laptop, an Intel Core i5-12450H under Windows 11, with programs built by gcc 13.3 in a WSL 2 Ubuntu 24.04 guest (-O2, no -march flag, one thread). The processor is hybrid: 4 performance cores with 2 hardware threads each and 4 efficient cores with 1 thread each, 12 logical processors, with a maximum turbo frequency of 4.40 GHz for a performance core and 3.30 GHz for an efficient core (Intel ARK, which returned HTTP 403 to a scripted request on 2026-10-26; the figures are those recorded in chapter 11 and agree with TechPowerUp). The guest does not let a program choose its core, so a single-thread time is a time on an unknown core of the two kinds. The machine was shared with other jobs during the captures. A timing listing is checked only by its return code and prints one sample; every other listing is deterministic and checked byte for byte.

The programs of this chapter are the first versions of programs that later chapters extend: the same names (jacobi_step, u, unew, N, max_iter, tol), the same layout and the same boundary conditions appear in the OpenMP, MPI, CUDA and OpenACC versions of Jacobi iteration (chapters 12, 16, 20 and 24) and in the profiling of a slow solver (chapter 27).

Moore's law, Dennard scaling and the end of faster single cores W3L1 0:39

What the lecture states. The lecture attributes two observations to engineers of the 1970s. Gordon Moore predicted that the number of transistors per unit area of an integrated circuit doubles roughly every 18 months; the lecture's chart (Our World in Data, 1971 to 2018) is captioned "approximately every two years". Robert Dennard's rule, shown as a table, says that if the linear dimension of a MOSFET (metal-oxide-silicon field-effect transistor, the switch of a logic gate) shrinks by a factor \(K\) (the slide writes \(k\)), then voltage, current, capacitance and switching delay fall by \(K\) and the power per circuit by \(K^2\). The lecture states that Dennard scaling "is already broken", because a voltage large enough to tell a 0 from a 1 is needed; that clock frequency and single-thread performance have stopped growing while the transistor count still grows (the chart "35 years of microprocessor trend data", credited to Horowitz, Labonte, Shacham, Olukotun, Hammond and Batten, with extrapolations by C. Moore); and that the only way to more computing power is more cores, from one core two decades ago to more than 128 today, which a single computation uses only if it is written as a parallel program.

What the sources say. Moore's 1965 article, written as director of research at Fairchild Semiconductor, states that the "complexity for minimum component costs has increased at a rate of roughly a factor of two per year", expects this to continue for at least 10 years, and gives 65,000 components per circuit for 1975 (reprint, p. 2 of 4). His 1975 paper reports that the complexity "has approximately doubled every year" since the introduction of integrated circuits and expects a slope that "might approximate a doubling every two years, rather than every year, by the end of the decade" (IEDM Technical Digest 1975, pp. 11–13). The figure of 18 months has another source. Bohr (IEEE SSCS Newsletter, Winter 2007, p. 11) writes that in the 1970s and 1980s a process generation, with 0.7 times the feature size and so twice the density, came every 3 years, and that growing chips made the transistor counts of the industry's microprocessors (he plots Intel's) rise close to 4 times every 3 years, "or 2x every 18 months"; since the mid-1990s generations came every 2 years and the count doubled about every 2 years. The lecture's 18 months describes one period of one company's products, and its own slide gives the longer-run figure.

The listing below tests the doubling time against a data set. Rupp's repository of microprocessor trend data (karlrupp/microprocessor-trend-data, files 50yrs/transistors.dat and 50yrs/frequency.dat, CC BY 4.0, retrieved 2026-10-26) continues the lecture's chart with 99 transistor counts and 101 clock frequencies from 1971 to 2021. It also tabulates Dennard scaling for \(K=\sqrt2\), the linear shrink of one process generation. A circuit dissipates \(P_{\mathrm{sw}}=CV^2\nu\) in switching: a node of capacitance \(C\) is charged through the voltage \(V\) at the clock frequency \(\nu\). Ideal scaling takes \(C\to C/K\), \(V\to V/K\), \(\nu\to K\nu\), so \(P_{\mathrm{sw}}\to P_{\mathrm{sw}}/K^2\), while the area of a circuit falls by \(K^2\). The "V fixed" column keeps \(V\) constant and \(\nu\) rising by \(K\) per generation. The program is deterministic, so the check is exact.

def parse(text):
    return [tuple(map(float, item.split(":"))) for item in text.split()]


def fit(points, lo, hi):
    """Least-squares line log2(value) = a + s * year over lo <= year < hi; returns (s, n, intercept)."""
    pts = [(y, log2(v)) for y, v in points if lo <= y < hi]
    n = len(pts)
    my = sum(y for y, _ in pts) / n
    mv = sum(v for _, v in pts) / n
    s = sum((y - my) * (v - mv) for y, v in pts) / sum((y - my) ** 2 for y, _ in pts)
    return s, n, mv - s * my

The table at the end of the output explains the plateau. Under ideal Dennard scaling the power per circuit falls by \(1/K^2\) while circuits become \(K^2\) times denser, so power per unit area stays at 1.00 while the clock rises by \(K\) per generation: ten generations (about 20 years) give circuits 1024 times as dense, running 32 times faster, at the same power per chip area. Dennard et al. state this under their Table I: the delay of each circuit falls by a factor \(K\), its power dissipation by \(K^2\), and "the power density remains constant" (IEEE J. Solid-State Circuits SC-9(5), 1974, p. 265); the lecture's table reproduces this. If the voltage stops falling while clock and density still rise, the power per circuit stays constant and the power per unit area doubles at each generation, 32 times after five. A chip cannot dissipate that, so the clock stops rising.

The lecture explains the stop of voltage scaling by the need of "a certain finite voltage" to identify the binary states. Bohr (p. 12) names a mechanism: Dennard's rule assumed that the threshold voltage \(V_T\) would scale with the supply voltage, and after 30 years of scaling the leakage current of a switched-off transistor (sub-threshold leakage) had grown from below \(10^{-10}\) to above \(10^{-7}\) amperes per micrometre of gate width; "due to leakage constraints, it will be difficult to further scale \(V_T\) and thus it will also be difficult to scale operating voltage." The two accounts are compatible. The lecture also says that today's computers use "3 nanometer technology"; the chart on the same slide plots gate lengths from 50 to 15 nm, and this chapter did not check which dimension a manufacturing node name denotes.

Consequences. The transistor count still doubles and the clock does not, so the added transistors become cores, caches and vector units, which a program uses only if it is written for them. The lecture's slide on parallel computing states the consequence: high performance computing involves parallel programming; "you cannot run away from parallel programming in the future"; "automatic parallelization has been a disaster so far"; messages must be communicated; Amdahl's law. The next section treats the last two, and the section on source code and instructions tests the claim about automatic parallelization on the Jacobi sweep.

Boundary of the evidence. The fits describe a public data set of products of several vendors, not a controlled measurement; "frequency" is the listed clock of an entry. The break at 2004 is read off the plot, and the fit from 2007 shows that the sign of the slope does not depend on it. The fits say nothing about causes; those come from Dennard et al. and Bohr.

Dividing a sum among people, and Amdahl's law W3L1 11:09

The lecture's example. A person who adds one integer per second needs 10,000 s to add a bag of 10,000 integers. With 10 people of equal skill the naive expectation is 1000 s. The lecture counts two additional steps and neglects the cost of handing out the numbers and of returning the results: each person adds 1000 numbers, taking 1000 s, and then one person adds the 10 partial sums, taking 10 s, so the time is 1010 s. With 100 people each adds 100 numbers in 100 s and one person adds 100 partial sums in another 100 s, so the time is 200 s and the speedup is 50: "if I put 100 times more resources I actually go only 50 times faster". The lecture presents this as the motivation of Amdahl's law.

The model. Let \(M\) be the number of integers (the lecture's 10,000; \(N\) is kept for the grid size of the plate problem) and \(p\) the number of people. The slowest person adds \(\lceil M/p\rceil\) integers, and one person then adds the \(p\) partial sums, so

\[ T(p)=\Big\lceil \frac{M}{p}\Big\rceil+p,\qquad p\ge2,\qquad T(1)=M. \tag{9.1} \]

The two terms have opposite trends. Ignoring the ceiling, \(dT/dp=1-M/p^2\) is zero at \(p^*=\sqrt M\), the second derivative \(2M/p^3\) is positive, and \(T(p^*)=2\sqrt M\), a speedup of \(S_{p^*}=\sqrt M/2\). For \(M=10^4\): \(p^*=100\), \(T=200\) s and \(S=50\). The lecture's 100 people are the best team size of this model, not an arbitrary choice. The model is symmetric under \(p\leftrightarrow M/p\), so \(p=10\) and \(p=1000\) take the same time, 1010 s: a team of 1000 people is as slow as a team of 10, and a team of 10,000 takes 10,001 s, as long as one person. The listing evaluates (9.1) and prints the best team found by search.

A serial part that grows with the team. Amdahl's law (below) assumes a serial fraction that does not depend on the number of workers. In (9.1) the serial step, adding \(p\) partial sums, takes \(p\) seconds. To express the times as \(T_p=fT_1+(1-f)T_1/p\) the fraction would have to be \(f=p^2/(M(p-1))\approx p/M\). The column f_eff of the listing shows it: 0.0011 at \(p=10\), 0.0101 at \(p=100\), 0.1001 at \(p=1000\). A fraction that grows tenfold when the team grows tenfold is not a constant of the problem. The serial step is a property of the algorithm that combines the results: one person adds all the partial sums. If the partial sums are added in pairs, in rounds, each round halves the number of sums, and the time is \(\lceil M/p\rceil+\lceil\log_2p\rceil\) (the same neglect of communication cost). The listing shows that this changes the result: 107 s at \(p=100\) (speedup 93.5) and 20 s at \(p=1000\) (speedup 500). The serial part of a parallel program depends on how the results are combined, so it is not a property of the problem alone. Chapter 15 treats tree-shaped combination of results (reductions) in message passing, including the cost of the messages that this model neglects.

"""The lecture's bag of 10,000 integers, added by p people at one addition per second."""
from math import ceil, log2, sqrt

M = 10_000                      # integers in the bag; one addition takes one second


def t_flat(p):
    """Each person adds ceil(M/p) numbers; one person then adds the p partial sums."""
    return M if p == 1 else ceil(M / p) + p


def t_tree(p):
    """The p partial sums are added pairwise: ceil(log2 p) rounds of one addition each."""
    return ceil(M / p) + ceil(log2(p))


def f_eff(s, p):
    """Serial fraction that Amdahl's law (fixed f) would need to give speedup s on p workers."""
    return (1 / s - 1 / p) / (1 - 1 / p)


print(f"{'p':>6} {'T flat':>8} {'S flat':>7} {'f_eff':>7} | {'T tree':>7} {'S tree':>7}")
for p in (1, 10, 100, 200, 1000, 10000):
    s = M / t_flat(p)
    f = f"{f_eff(s, p):7.4f}" if p > 1 else "      -"
    print(f"{p:6d} {t_flat(p):8d} {s:7.1f} {f} | {t_tree(p):7d} {M / t_tree(p):7.1f}")

best = min(range(1, M + 1), key=t_flat)
print(f"best flat team: p = {best}, T = {t_flat(best)} s, S = {M / t_flat(best):.1f}; "

From phenomenon to computation: three errors W3L2 0:40

The lecture's pipeline. The lecture starts from the statement that closed-form solutions of the partial differential equations (PDEs) that describe heat transfer, fluid flow and electromagnetism are rarely available, so a computation replaces them. The pipeline has four stages, drawn as four boxes: a phenomenon (flows, heat transfer, electromagnetics); the governing equations (Navier–Stokes, the heat equation, Maxwell's equations); a numerical method (finite differences, finite volumes, Galerkin methods, the lattice Boltzmann method); and the computation. Each arrow introduces an error, drawn as a red box. The error of the first arrow is the modelling error: assumptions such as the continuum hypothesis (treating a fluid as continuous although it consists of molecules), uniform viscosity or uniform conductivity. The error of the second arrow is the discretization error: the derivatives are replaced by differences, and the lecture's example is the central difference \(f'(x)\approx(f(x+h)-f(x-h))/(2h)\), obtained from Taylor series by neglecting terms of higher order. The error of the third arrow is the arithmetic error: finite precision, with round-off. The lecture's thesis is that "the entire game of numerical modelling is to sort of balance all these errors": a computer accurate to \(10^{-100}\) is of no use if the method has an error of \(10^{-2}\); a 16th-order method is of no use on a computer that works to \(10^{-8}\); and neither helps if the model assumed constant viscosity. How many digits are needed depends on the use: 35 versus 35.231579 degrees Celsius for human comfort, but more digits for a controlled chemical experiment, and the number of digits "has direct impact on the effort in the computations".

The model of this chapter makes the thesis a statement that can be checked. Let \(u_{\mathrm{phys}}\) be the temperature of the physical plate, \(u\) the exact solution of the governing equation, \(u_h\) the exact solution of the difference equations on a grid of spacing \(h\), and \(U\) the numbers the program holds at the end. By the triangle inequality, in any norm,

\[ \|u_{\mathrm{phys}}-U\|\le\underbrace{\|u_{\mathrm{phys}}-u\|}_{\text{modelling}}+\underbrace{\|u-u_h\|}_{\text{discretization}}+\underbrace{\|u_h-U\|}_{\text{solver and arithmetic}}. \tag{9.3} \]

The lecture assigns the third term to arithmetic. For an iterative solver the third term has two parts: the iteration error, which exists in exact arithmetic because the iteration stops, and the rounding error. The section on the iteration shows that the iteration error is the one that dominates when the stopping rule is careless. The modelling error cannot be computed from the model; this chapter does not estimate it. A scale shows why the lecture rejects the alternative of tracking molecules. At atmospheric pressure \(p_0=101325\) Pa and temperature 293.15 K, the ideal-gas law gives \(n=p_0/(k_BT)=2.5\times10^{25}\) molecules per cubic metre, with the exact value \(k_B=1.380649\times10^{-23}\) J/K (NIST CODATA). A cubic kilometre of air holds \(2.5\times10^{34}\) molecules. Storing three position and three velocity components of each as doubles takes \(1.2\times10^{36}\) bytes, which is \(8\times10^{25}\) times the 15 GB of memory of this chapter's machine.

The central difference, with its Taylor series. The slide shows only the final formula. For a function with three continuous derivatives, Taylor's theorem gives

\[ g(x\pm h)=g(x)\pm hg'(x)+\frac{h^2}{2}g''(x)\pm\frac{h^3}{6}g'''(\xi_\pm),\qquad \xi_\pm\in(x-h,x+h), \]

so the difference of the two values is \(2hg'(x)+\tfrac{h^3}{6}\bigl(g'''(\xi_+)+g'''(\xi_-)\bigr)\), and

\[ \frac{g(x+h)-g(x-h)}{2h}=g'(x)+\frac{h^2}{6}g'''(\xi),\qquad \xi\in(x-h,x+h). \tag{9.4} \]

The method is second-order accurate: the error falls by 4 when \(h\) is halved. The lecture states this; (9.4) gives the constant, \(|g'''|/6\). Rounding enters through the values of \(g\). Let \(u_r\) be the unit roundoff, the largest relative error of one rounded floating-point result under round-to-nearest. For a binary format with an \(\ell\)-digit significand it is \(2^{-\ell}\): \(2^{-53}=1.1\times10^{-16}\) for IEEE double precision (53 digits) and \(2^{-24}=6.0\times10^{-8}\) for single precision (24 digits) (Goldberg 1991, section "Relative Error and Ulps", where \(\varepsilon=(\beta/2)\beta^{-p}\)). If \(x\pm h\) are exact and each value of \(g\) has a relative error of at most \(u_r\), the numerator of (9.4) has an absolute error of at most \(2u_r|g|\), and the quotient has an error of at most \(u_r|g|/h\). With \(M_0=\max|g|\) and \(M_3=\max|g'''|\) near \(x\), the total error is bounded by

\[ B(h)\le\frac{M_3}{6}h^2+\frac{M_0\,u_r}{h},\qquad h^*=\Bigl(\frac{3M_0u_r}{M_3}\Bigr)^{1/3},\qquad B(h^*)=\frac{M_3}{2}\,h^{*2}. \tag{9.5} \]

The first term falls with \(h\), the second rises, and the bound has a minimum at \(h^*\), where the truncation term is one third of the bound and the rounding term two thirds. The minimum is therefore \(M_3h^{*2}/2\); for \(M_0=M_3\) it is \(\tfrac12(3u_r)^{2/3}\): \(2.4\times10^{-11}\) in double and \(1.6\times10^{-5}\) in single precision. The fourth-order formula \([g(x-2h)-8g(x-h)+8g(x+h)-g(x+2h)]/(12h)\) has truncation error \(h^4g^{(5)}(\xi)/30\) and a rounding term at most \(1.5\,u_rM_0/h\) (the coefficients \(1,8,8,1\) sum to 18, and \(18/12=1.5\)); its bound is minimal at \(h^*=(11.25\,u_r)^{1/5}\) with value \(h^{*4}/6\) for \(M_0=M_5\).

The listing tests (9.5). It differentiates \(g(x)=e^x\), whose derivatives are all \(e^x\), so the relative error does not depend on \(x\) and can be averaged over 256 points \(x=j/128\). #define NPOINT 256

static double rel_rms(int dbl, int order, int k)
{
    double h = ldexp(1.0, -k), sum = 0.0;
    for (int j = 0; j < NPOINT; j++) {
        double x = j / 128.0, e = exp(x), v;
        if (dbl && order == 2)
            v = (exp(x + h) - exp(x - h)) / (2 * h);
        else if (dbl)
            v = (exp(x - 2*h) - 8*exp(x - h) + 8*exp(x + h) - exp(x + 2*h)) / (12 * h);
        else if (order == 2)
            v = (expf((float)(x + h)) - expf((float)(x - h))) / (2 * (float)h);

                 - expf((float)(x + 2*h))) / (12 * (float)h);
        sum += (v / e - 1) * (v / e - 1);
    }
    return sqrt(sum / NPOINT);
}

The plate problem and the five-point stencil W3L2 13:28

The lecture's plate. The lecture's example is a square plate whose edges are held at given temperatures. The slide labels three corners \(T_0\) and the bottom-right corner \(T_\infty\); the top and left edges are held at \(T_0\), and the temperature along the right and bottom edges varies from \(T_0\) to \(T_\infty\). The lecture assumes a uniform material (constant conductivity) and a thin plate (no variation across the thickness), models the temperature by Laplace's equation, discretizes the plate at points of uniform spacing chosen by the accuracy wanted (temperature differences 10 m, 100 m or 1 km apart for a flat city heated by a fire at its edge), addresses a point by indices \((i,j)\), writes the discretized equation at a point, and assembles the equations into \(A\mathbf x=\mathbf b\) with the statement, on its slide, "You can choose any Linear Algebra Solver (iterative or Direct). Iterative is more efficient." This chapter keeps the plate and the assumptions and replaces the boundary values by the canonical ones (\(u=1\) on the top edge, 0 on the others), because \(T_0\) and \(T_\infty\) are symbols without values, and one fixed boundary condition lets all the solvers of the book be compared. The replacement changes only the right-hand side \(\mathbf b\) of the system and the boundary fill of the code; the stencil, the matrix \(A\), its spectrum and the iteration count do not depend on the boundary values.

Deriving the stencil. The lecture's slide gives the discretized equation as \((T_{i-1,j}-T_{i,j}+T_{i+1,j})/(\Delta x)^2+(T_{i,j-1}-T_{i,j}+T_{i,j+1})/(\Delta y)^2=0\). The coefficient of the centre value in each term should be \(-2\), not \(-1\). A test shows this: a constant temperature \(T\equiv c\) satisfies Laplace's equation, and the slide's expression evaluates to \(c/(\Delta x)^2+c/(\Delta y)^2\ne0\) for it. The derivation gives the correct coefficient. For a function \(u\) with six continuous derivatives, Taylor's theorem gives \(u(x\pm h,y)=u\pm hu_x+\tfrac{h^2}{2}u_{xx}\pm\tfrac{h^3}{6}u_{xxx}+\tfrac{h^4}{24}u_{xxxx}\pm\dots\) with all derivatives at \((x,y)\). The sum of the two values minus \(2u\) leaves the even terms,

\[ u(x+h,y)+u(x-h,y)-2u(x,y)=h^2u_{xx}+\frac{h^4}{12}u_{xxxx}+O(h^6), \]

and the same in \(y\). Adding the two and dividing by \(h^2\) defines the five-point operator \(\Delta_h\) and gives its truncation error \(\tau\):

\[ \Delta_hu(x,y)=\frac{u(x\!+\!h,y)+u(x\!-\!h,y)+u(x,y\!+\!h)+u(x,y\!-\!h)-4u(x,y)}{h^2} =\Delta u+\tau,\quad \tau=\frac{h^2}{12}\bigl(u_{xxxx}+u_{yyyy}\bigr)+O(h^4). \tag{9.6} \]

The five-point scheme sets \(\Delta_hU=0\) at every interior node. Solved for the centre value it says \(U_{ij}\) is the average of its four neighbours, which is the Jacobi update of the model section. With the slide's coefficient the same manipulation would give a centre value equal to half the sum of the neighbours, an operation that doubles a constant field at every step instead of keeping it.

The linear system. Number the \(n=N^2\) unknowns row by row, \(m=(i-1)N+(j-1)\). The scheme becomes \(A\mathbf U=\mathbf b\), where \(A\) has 4 on the diagonal and \(-1\) in the columns of the (up to) four neighbouring unknowns, and \(b_m\) is the sum of the boundary values among the neighbours of node \(m\). For the canonical problem \(b_m=1\) for the \(N\) unknowns of row 1, next to the top edge, and 0 otherwise. The matrix is symmetric, has at most 5 nonzeros per row, and has half-bandwidth \(N\): the nonzero entries lie within \(N\) places of the diagonal. Its eigenvalues are \(4\bigl[\sin^2\frac{j\pi h}{2}+\sin^2\frac{l\pi h}{2}\bigr]\), \(1\le j,l\le N\), all positive (Saad, Iterative Methods for Sparse Linear Systems, 2nd ed., §13.2, eq. 13.14, p. 427), so \(A\) is positive definite and the system has exactly one solution. The lecture's count of \(n^2\) equations in \(n^2\) unknowns is right for the interior unknowns.

How the error behaves. The question is how the difference \(e=u-U\) between the exact solution of the plate equation and the exact solution of the five-point equations depends on \(h\). Take a solution \(u\) with bounded fourth derivatives on the closed square, and let \(e_{ij}=u(x_j,y_i)-U_{ij}\) at the nodes. Both \(u\) and \(U\) have the same values on the boundary, so \(e=0\) there. Since \(\Delta_hU=0\) and \(\Delta_hu=\tau\) by (9.6), the error satisfies \(\Delta_he=\tau\) in the interior. A discrete minimum principle turns this into a bound. If \(\Delta_hw\le0\) at every interior node, then each \(w_{ij}\) is at least the average of its neighbours, so a minimum of \(w\) at an interior node would force all four neighbours to equal it; repeating the argument along the grid reaches the boundary, so \(\min w\) is attained on the boundary. Now take \(\varphi(x)=x(1-x)/2\), a quadratic, so that \(\Delta_h\varphi=\varphi''=-1\) exactly at every node, and \(0\le\varphi\le\frac18\). Let \(\tau_{\max}=\max|\tau|\). Then \(\Delta_h(\pm e+\tau_{\max}\varphi)=\pm\tau-\tau_{\max}\le0\), the function \(\pm e+\tau_{\max}\varphi\) is non-negative on the boundary, hence non-negative everywhere, and so \(|e|\le\tau_{\max}\varphi\le\tau_{\max}/8\). With (9.6):

\[ \max_{ij}|e_{ij}|\le\frac{1}{8}\max|\tau|\le\frac{h^2}{96}\max\bigl|u_{xxxx}+u_{yyyy}\bigr|+O(h^4). \tag{9.7} \]

The error is of second order in \(h\), with a constant fixed by the fourth derivatives of the solution. The bound is a proof of order, not a prediction of size, because it takes the worst \(\tau\) over the whole square at every node.

A solution with a known discrete counterpart. To test (9.7) without a solver, take \(u(x,y)=\sin(\pi x)\sinh(\pi y)/\sinh\pi\). It satisfies Laplace's equation, equals \(\sin\pi x\) on the top edge \(y=1\), and vanishes on the other edges: the structure of the canonical problem with a continuous boundary value. It has \(u_{xxxx}=u_{yyyy}=\pi^4u\), so \(\tau=h^2\pi^4u/6+O(h^4)\), and (9.7) gives \(\max|e|\le h^2\pi^4/48\approx2.03\,h^2\). The five-point equations have the closed-form solution \(U(x_j,y_i)=\sin(\pi x_j)\sinh(\gamma y_i)/\sinh\gamma\) with \(\cosh(\gamma h)=2-\cos(\pi h)\): the factor \(\sin\pi x\) is an eigenfunction of the second difference in \(x\), and the second difference in \(y\) then requires \(\cosh(\gamma h)=2-\cos\pi h\). The listing prints three things: the truncation error of the stencil applied to \(u\) at the centre, divided by \(h^2\pi^4u/6\); the largest error \(|u-U|\) over the interior for \(N=7\) to 127 with the ratio between successive errors (4 if the error is \(O(h^2)\)); and the largest residual of the five-point equations for the closed-form \(U\), which checks the formula. The program is deterministic, so the check is exact.

def exact(x, y, kmax=1200):
    s = 0.0
    for k in range(1, kmax, 2):
        a = k * pi
        s += 4 / a * sin(a * x) * (exp(a * (y - 1)) - exp(-a * (y + 1))) / (1 - exp(-2 * a))

def solve(N):
    """Unknown (i,j) has number (i-1)N + (j-1); b = 1 for the unknowns next to the top edge."""
    A, b = np.zeros((N * N, N * N)), np.zeros(N * N)

    return np.linalg.solve(A, b).reshape(N, N)

Jacobi iteration: convergence, iteration count and the serial code W3L2 18:00

What the lecture says and does not say. After assembling \(A\mathbf x=\mathbf b\) with \(n^2\) unknowns, the lecture recalls that iterative solvers are more efficient than direct ones for this problem, says that one writes a code that assembles and solves the equations, and shows the plot that the program produces. It names no iterative method and shows no code. This chapter chooses Jacobi iteration, the simplest method, whose sweep treats every node independently of the others, which is what the later parallel versions need, and writes the code that the lecture leaves out. The section on the cost tests the claim of efficiency.

The iteration and its error. The Jacobi sweep computes \(U^{k+1}_{ij}=\tfrac14\bigl(U^k_{i-1,j}+U^k_{i+1,j}+U^k_{i,j-1}+U^k_{i,j+1}\bigr)\) at every interior node, where boundary neighbours hold the boundary values. In vector form \(\mathbf U^{k+1}=G\mathbf U^k+\mathbf c\) with \(G=\mathrm{Id}-A/4\) and \(\mathbf c=\mathbf b/4\). The exact solution \(\mathbf U\) of \(A\mathbf U=\mathbf b\) is a fixed point, \(\mathbf U=G\mathbf U+\mathbf c\), so the error \(\mathbf e^k=\mathbf U^k-\mathbf U\) obeys \(\mathbf e^{k+1}=G\mathbf e^k\) and \(\mathbf e^k=G^k\mathbf e^0\). The iteration converges for every starting vector if and only if the spectral radius \(\rho(G)\), the largest modulus of an eigenvalue of \(G\), is below 1 (Saad, §4.2.1, Theorem 4.1, p. 115). The matrix \(G\) is symmetric, so its eigenvectors can be chosen orthogonal and \(\|G^k\|_2=\rho^k\) in the Euclidean norm.

The spectrum. Take the vectors \(\varphi_{jl}\) with entries \(\varphi_{jl}(r,s)=\sin(j\pi rh)\sin(l\pi sh)\), \(1\le r,s\le N\), for \(1\le j,l\le N\), and zero outside the interior. The identity \(\sin((r+1)\theta)+\sin((r-1)\theta)=2\sin(r\theta)\cos\theta\) (Saad eq. 13.5, p. 424) shows that the sum of the two neighbours of \(r\) in the first index is \(2\cos(j\pi h)\varphi_{jl}\), and the same in the second index; the sines vanish at \(r=0\) and \(r=N+1\), so the boundary terms are absent. Dividing the sum of four neighbours by 4:

\[ G\varphi_{jl}=\mu_{jl}\varphi_{jl},\qquad \mu_{jl}=\frac{\cos(j\pi h)+\cos(l\pi h)}{2},\qquad \rho(G)=\cos(\pi h)=\cos\frac{\pi}{N+1}. \tag{9.8} \]

The largest modulus is \(\cos\pi h\), attained for \((j,l)=(1,1)\), with eigenvalue \(+\rho\), and also for \((N,N)\), where \(\cos(N\pi h)=-\cos(\pi h)\) gives \(-\rho\). Demmel's 1995 lecture notes state the same result in the 2-norm of the error, \(\rho_{\mathrm{Jacobi}}(n)=\cos(\pi/(n+1))\) (CS 267, Lecture 24, 1995). For large \(N\), \(\rho\approx1-\pi^2/(2(N+1)^2)\): the spectral radius approaches 1 as \(h^2\) goes to zero.

The iteration count. The component of the error along \(\varphi_{11}\) shrinks by \(\rho\) per sweep, and every other component shrinks at least as fast. After \(k\) sweeps the slowest component dominates. Write the error as \(\mathbf e^k\approx-a_1\rho^k\varphi_{11}\), where \(-a_1\) is the coefficient of the initial error \(\mathbf e^0=-\mathbf U\) along \(\varphi_{11}\), so that \(a_1\gt0\) is the coefficient of \(\mathbf U\). The iteration error \(\|\mathbf e^k\|_\infty\) reaches a target \(\varepsilon\) when \(a_1\rho^k=\varepsilon\), since \(\varphi_{11}\) has the value 1 at the centre. Hence

\[ k(\varepsilon)=\frac{\ln(a_1/\varepsilon)}{-\ln\rho}\approx\frac{2(N+1)^2}{\pi^2}\ln\frac{a_1}{\varepsilon},\qquad -\ln\cos\theta=\frac{\theta^2}{2}+\frac{\theta^4}{12}+\dots \tag{9.9} \]

For the canonical problem \(a_1\) can be computed. For large \(N\) the coefficient of \(\mathbf U\) along \(\varphi_{11}\) is \(4\iint u\sin\pi x\sin\pi y\,dx\,dy\), and by orthogonality of \(\sin k\pi x\) only the \(k=1\) term of the series for \(u\) contributes: \(4\cdot\frac{4}{\pi\sinh\pi}\cdot\int_0^1\sin^2\pi x\,dx\cdot\int_0^1\sinh\pi y\sin\pi y\,dy=4\cdot\frac{4}{\pi\sinh\pi}\cdot\frac12\cdot\frac{\sinh\pi}{2\pi}\), so \(a_1=4/\pi^2=0.405\). The factor \(N^2\) in (9.9) is the central fact about the method: doubling the number of points per side multiplies the number of sweeps by 4, whatever the tolerance. Demmel's notes give the same count for a reduction of the error by a factor of 2, \(m\approx((n+1)/\pi)^2\) sweeps. The intuition is that one sweep moves information by one node, so \(N\) sweeps are needed to cross the plate, but Jacobi needs a number of order \(N^2\) to damp the smoothest error.

The stopping rule is not an error bound. The code cannot see the iteration error; it sees the change \(d^k=\mathbf U^{k+1}-\mathbf U^k\) and stops when its largest entry is below tol. Two relations connect the two. First, \(d^k=(G-\mathrm{Id})\mathbf e^k\), so \(\mathbf e^{k+1}=G(G-\mathrm{Id})^{-1}d^k\). The eigenvalue of \(G(G-\mathrm{Id})^{-1}\) belonging to \(\mu\) is \(\mu/(\mu-1)\), whose modulus is largest at \(\mu=\rho\), so in the Euclidean norm

\[ \|\mathbf e^{k+1}\|_2\le\frac{\rho}{1-\rho}\,\|d^k\|_2,\qquad \frac{\rho}{1-\rho}\approx\frac{2(N+1)^2}{\pi^2}, \tag{9.10} \]

with equality when \(d^k\) lies along \(\varphi_{11}\), which is the case after many sweeps. A change of \(10^{-6}\) can hide an error of up to \(10^{-6}\rho/(1-\rho)\): 207 times larger at \(N=31\), 829 times at \(N=63\), \(2.0\times10^{5}\) times at \(N=1000\). The factor is about the iteration count divided by the logarithm in (9.9). A small change per sweep means slow convergence, so a small change does not imply a small error. Second, the change of the slowest component has the size \((1-\rho)a_1\rho^k\varphi_{11}\), so the sweeps needed for the change to fall below tol are \(k=\ln\bigl(c/\mathrm{tol}\bigr)/(-\ln\rho)\) with \(c=(1-\rho)a_1\), smaller than (9.9) with \(\varepsilon=\mathrm{tol}\) by the factor \((1-\rho)\) inside the logarithm. This single-mode count is valid only when the slowest mode dominates the change at the stop, that is when \(\mathrm{tol}\ll c\), so that the argument \(c/\mathrm{tol}\) of the logarithm is much larger than 1; the equality in (9.10) holds in the same regime. When \(\mathrm{tol}\) is comparable to \(c\), the faster components have not yet decayed, the stop comes later than the count says, and the error is below its bound. The table below the listing measures the boundary. To obtain an iteration error of about \(\varepsilon\), set \(\mathrm{tol}=\varepsilon(1-\rho)/\rho\approx\varepsilon\pi^2/(2(N+1)^2)\); (9.10) is stated in the Euclidean norm of the change and the program tests the maximum norm, and the measurements of this chapter show the same factor in the maximum norm. That agreement is the typical case, not a guarantee. In the maximum norm the guaranteed factor is the largest row sum of \(G(\mathrm{Id}-G)^{-1}\), a matrix with non-negative entries, which is 1.45 times \(\rho/(1-\rho)\) (74.2 against 51.0 at \(N=15\), 300.5 against 206.7 at \(N=31\), 1205.8 against 829.2 at \(N=63\); computed from the matrix at \(N=7,15,31\) and by iteration at \(N=63\), a computation made outside the code lab, as in Chapter 4). A program that fixes tol leaves an error that grows as \(N^2\), and its sweep count grows by less than 4 per doubling of \(N\) once \(\mathrm{tol}\) is no longer small against \(c\), because \(c\) falls by 4 with each doubling. A measured growth below 4 per doubling is therefore not evidence against (9.8); it shows that the stopping rule is loosening. The code. The listing is the canonical serial program of this book. jacobi_step(N, u, unew) reads the interior and boundary of u, writes the average of the four neighbours into the interior of unew, never writes the boundary, and returns the largest absolute change over the interior. init_canonical fills an array with 1 in row 0 and 0 elsewhere. jacobi_solve sweeps and swaps the two pointers until the change is below tol or max_iter sweeps are done, returns the number of sweeps, and leaves the latest iterate in *pu and the previous one in *punew. Both arrays must hold the boundary values before the first sweep: the kernel never writes the boundary of the array it fills, so an array that held the boundary only in u would give a second sweep that reads zeros at the top edge. The run checks three things for \(N=7,\dots,127\) and tol \(=10^{-8}\): the centre node must be \(\tfrac14\) within the iteration error, the number of sweeps must match the prediction above, and the centre error divided by tol must match \(\rho/(1-\rho)\). For \(N=31\) it also prints the changes of the last sweeps, and a last table sets tol to multiples of the amplitude \(c\) of the next paragraphs. The program is deterministic, so the check is exact.

#include <stdio.h>
#include <stdlib.h>
#include <math.h>

#define IDX(i,j) ((i)*(N+2)+(j))     /* (N+2)x(N+2) doubles, row-major; interior is 1..N */

/* One Jacobi sweep. Writes the average of the four neighbours of u into the interior of
   unew and returns max |unew - u| over the interior. Boundary values are read, never written. */
double jacobi_step(int N, const double *u, double *unew)
{
    double maxdiff = 0.0;
    for (int i = 1; i <= N; i++)
        for (int j = 1; j <= N; j++) {
            double v = 0.25 * (u[IDX(i-1,j)] + u[IDX(i+1,j)] + u[IDX(i,j-1)] + u[IDX(i,j+1)]);
            double d = fabs(v - u[IDX(i,j)]);
            if (d > maxdiff) maxdiff = d;
            unew[IDX(i,j)] = v;
        }
    return maxdiff;
}

/* u = 1 on the top edge (i = 0), u = 0 on the other three edges and in the interior. */
static void init_canonical(int N, double *u)
{
    for (int i = 0; i < N + 2; i++)
        for (int j = 0; j < N + 2; j++)
            u[IDX(i,j)] = (i == 0) ? 1.0 : 0.0;
}

/* Sweep until the change is below tol or max_iter sweeps are done. Both arrays must hold the
   boundary values. On return *pu is the latest iterate and *punew the one before it. */
static int jacobi_solve(int N, double **pu, double **punew, double tol, int max_iter, double *change)
{
    int k = 0;
    double d = INFINITY;
    while (k < max_iter && d >= tol) {
        d = jacobi_step(N, *pu, *punew);
        double *t = *pu; *pu = *punew; *punew = t;
        k++;
    }
    *change = d;
    return k;
}

    if (!u) exit(1);
    init_canonical(N, u);
    return u;
}

#include <stdio.h>
#include <stdlib.h>
#include <math.h>

#define IDX(i,j) ((i)*(N+2)+(j))     /* (N+2)x(N+2) doubles, row-major; interior is 1..N */

/* One Jacobi sweep. Writes the average of the four neighbours of u into the interior of
   unew and returns max |unew - u| over the interior. Boundary values are read, never written. */
double jacobi_step(int N, const double *u, double *unew)
{
    double maxdiff = 0.0;
    for (int i = 1; i <= N; i++)
        for (int j = 1; j <= N; j++) {
            double v = 0.25 * (u[IDX(i-1,j)] + u[IDX(i+1,j)] + u[IDX(i,j-1)] + u[IDX(i,j+1)]);
            double d = fabs(v - u[IDX(i,j)]);
            if (d > maxdiff) maxdiff = d;
            unew[IDX(i,j)] = v;
        }
    return maxdiff;
}

/* Sweep until the change is below tol or max_iter sweeps are done. Both arrays must hold the
   boundary values. On return *pu is the latest iterate and *punew the one before it. */
static int jacobi_solve(int N, double **pu, double **punew, double tol, int max_iter, double *change)
{
    int k = 0;
    double d = INFINITY;
    while (k < max_iter && d >= tol) {
        d = jacobi_step(N, *pu, *punew);
        double *t = *pu; *pu = *punew; *punew = t;
        k++;
    }
    *change = d;
    return k;
}

Boundary of the results. The rate \(\cos\pi h\) and the spectrum (9.8) belong to the five-point operator on a square with Dirichlet boundary values. The amplitude \(a_1=4/\pi^2\) belongs to the canonical boundary values, and it changes the iteration count by an additive constant in the logarithm, not the rate. Gauss–Seidel iteration, successive over-relaxation, conjugate gradients and multigrid reach the same error in fewer operations (the table of the section on the cost), and Jacobi iteration is a reference whose merit is a sweep that is independent at every node. What the iteration costs, and why one core cannot keep up W3L2 18:00

The work. A solve of \(k\) sweeps on an \(N\times N\) grid performs \(W=5N^2k\) operations. Inserting the sweep count (9.9) with the amplitude \(a_1=4/\pi^2\):

\[ W(N,\varepsilon)=5N^2\,k(\varepsilon)\approx\frac{10}{\pi^2}\,N^4\ln\frac{a_1}{\varepsilon}\;\approx\;13.1\,N^4\quad(\varepsilon=10^{-6}). \tag{9.11} \]

The work grows as \(N^4\) at a fixed tolerance, not as the number of unknowns \(N^2\): there are \(N^2\) point updates per sweep and \(N^2\) sweeps. Doubling \(N\) multiplies the work by 16 (the logarithm does not change at fixed \(\varepsilon\)), and the memory by 4. If the tolerance follows the discretization error, \(\varepsilon\propto h^2\), the logarithm grows with \(N\) and the work is of order \(N^4\ln N\). The accuracy of the answer sets \(N\). For a smooth solution with discretization error \(0.285\,h^2\) (the continuous variant of the previous section), an error \(\delta\) needs \(N\approx0.53/\sqrt\delta\), and the work is proportional to \(N^4\), that is to \(\delta^{-2}\): one more correct digit, \(\delta\to\delta/10\), multiplies the work by about 100. The lecture states that the accuracy required "has direct impact on the effort"; (9.11) gives the size of the impact for this problem.

What parallelism must deliver. Suppose the goal is the \(N=1000\) solve in one minute. The speedup required is \(S=T_1/T_p\approx5240\ \mathrm{s}/60\ \mathrm{s}=87\). For \(N=10^4\) in one day it is \(1.7\times365=620\). By Amdahl's law (9.2), a speedup \(S\) on \(p\) workers needs a serial fraction \(f\le(1/S-1/p)/(1-1/p)\) (chapter 11 derives this form): for \(S=620\) and \(p=1000\), \(f\le6.1\times10^{-4}\), and for unlimited \(p\), \(f\le1/620=1.6\times10^{-3}\). This is a necessary condition only. In the work–span notation of this book the work is \(W=5N^2k\) and the span \(D\) is at least \(k\) sweeps, because sweep \(j+1\) reads the values written by sweep \(j\). The parallelism \(W/D\) is at most the \(5N^2\) operations of one sweep, \(5\times10^6\) at \(N=1000\): the iteration offers parallelism inside each sweep and none between sweeps. What decides whether a machine reaches \(S=620\) is the memory bandwidth (chapter 10), the cost of the global maximum that stops the iteration, and the communication of boundary rows between processors (chapters 15 and 16). The part of the code that no worker can share in a parallel version, the boundary fill, takes of the order of \(N\) operations against \(5N^2k\) in total, a fraction below \(10^{-9}\) at \(N=1000\); the Amdahl bound from it is not the binding limit.

Is iterative more efficient? The lecture says that iterative solvers are more efficient than direct ones for this problem. The listing builds the band, factors it, solves the canonical problem and counts every multiply-subtract (2 operations), division and square root (1 each) as it executes them. It then runs the Jacobi code for an iteration error of \(10^{-6}\) with the tolerance of (9.10) and prints the count of operations of both, the storage of the band, and the largest difference between the two solutions. #include <math.h>

#define IDX(i,j) ((i)*(N+2)+(j))     /* (N+2)x(N+2) doubles, row-major; interior is 1..N */

/* One Jacobi sweep. Writes the average of the four neighbours of u into the interior of
   unew and returns max |unew - u| over the interior. Boundary values are read, never written. */
double jacobi_step(int N, const double *u, double *unew)
{
    double maxdiff = 0.0;
    for (int i = 1; i <= N; i++)
        for (int j = 1; j <= N; j++) {
            double v = 0.25 * (u[IDX(i-1,j)] + u[IDX(i+1,j)] + u[IDX(i,j-1)] + u[IDX(i,j+1)]);
            double d = fabs(v - u[IDX(i,j)]);
            if (d > maxdiff) maxdiff = d;
            unew[IDX(i,j)] = v;
        }
    return maxdiff;
}

/* u = 1 on the top edge (i = 0), u = 0 on the other three edges and in the interior. */
static void init_canonical(int N, double *u)
{
    for (int i = 0; i < N + 2; i++)
        for (int j = 0; j < N + 2; j++)
            u[IDX(i,j)] = (i == 0) ? 1.0 : 0.0;
}

/* Sweep until the change is below tol or max_iter sweeps are done. Both arrays must hold the
   boundary values. On return *pu is the latest iterate and *punew the one before it. */
static int jacobi_solve(int N, double **pu, double **punew, double tol, int max_iter, double *change)
{
    int k = 0;
    double d = INFINITY;
    while (k < max_iter && d >= tol) {
        d = jacobi_step(N, *pu, *punew);
        double *t = *pu; *pu = *punew; *punew = t;
        k++;
    }
    *change = d;
    return k;
}

static double *grid(int N)
{
    double *u = malloc(sizeof(double) * (size_t)(N + 2) * (N + 2));
    if (!u) exit(1);
    init_canonical(N, u);
    return u;
}

/* Direct solve of the same problem. Unknown (i,j) has number m = (i-1)*N + (j-1); the matrix has
   4 on the diagonal and -1 for the four neighbours, so its half-bandwidth is b = N. Banded
   Cholesky A = Gamma Gamma^T stores Gamma in n rows of b+1 numbers: Gamma(i,j) at fac[i*(b+1) + j - i + b]. */
static double flops;                                            /* counted, not estimated */

static double *band_solve(int N)
{
    int n = N * N, b = N, w = b + 1;
    double *fac = calloc((size_t)n * w, sizeof(double)), *x = calloc(n, sizeof(double));
    if (!fac || !x) exit(1);
    #define FAC(i,j) fac[(size_t)(i) * w + (j) - (i) + b]
    for (int m = 0; m < n; m++) {
        FAC(m,m) = 4.0;
        if (m % N) FAC(m,m-1) = -1.0;                            /* west neighbour */
        if (m >= N) FAC(m,m-N) = -1.0;                           /* north neighbour */
        x[m] = (m < N) ? 1.0 : 0.0;                             /* top edge u = 1 moves to the right side */
    }
    for (int i = 0; i < n; i++)
        for (int j = (i - b > 0 ? i - b : 0); j <= i; j++) {
            double s = FAC(i,j);
            for (int k = (i - b > 0 ? i - b : 0); k < j; k++) {
                s -= FAC(i,k) * FAC(j,k);
                flops += 2;
            }
            if (i == j) FAC(i,i) = sqrt(s);
            else FAC(i,j) = s / FAC(j,j);
            flops += 1;
        }
    for (int i = 0; i < n; i++) {                               /* Gamma y = rhs */
        double s = x[i];
        for (int k = (i - b > 0 ? i - b : 0); k < i; k++) { s -= FAC(i,k) * x[k]; flops += 2; }
        x[i] = s / FAC(i,i); flops += 1;
    }
    for (int i = n - 1; i >= 0; i--) {                          /* Gamma^T x = y */
        double s = x[i];
        for (int k = i + 1; k < n && k <= i + b; k++) { s -= FAC(k,i) * x[k]; flops += 2; }
        x[i] = s / FAC(i,i); flops += 1;
    }
    free(fac);
    return x;
}

{

The lecture's statement therefore needs refinement. Dense Cholesky factorization needs about \(n^3/3=N^6/3\) operations and \(N^4\) numbers of storage, against about \(13N^4\) operations for Jacobi iteration: a factor of about \(N^2/39\), \(2.6\times10^{4}\) at \(N=1000\). Demmel's table of the serial cost of solving the discrete Poisson equation with \(n=N^2\) unknowns lists dense LU \(n^3\), band LU \(n^2\), Jacobi \(n^2\), sparse LU \(n^{3/2}\), conjugate gradients \(n^{3/2}\), successive over-relaxation \(n^{3/2}\), FFT \(n\log n\) and multigrid \(n\) (CS 267, Lecture 24, 1995; the notes write \(N\) for the number of unknowns). Jacobi is as costly as band LU, and a sparse direct solver, conjugate gradients, over-relaxation, an FFT solver and multigrid all need fewer operations. So the statement holds for the better iterative methods and for memory, and not for the plain Jacobi iteration of this chapter. Chapter 29 treats these methods and their libraries.

Why one core cannot keep up. The work for a fixed accuracy grows with the fourth power of the number of grid points per side, and one more digit of accuracy costs a factor of 100. A better algorithm changes the exponent (conjugate gradients and multigrid reduce \(N^4\) to \(N^3\) and \(N^2\)) but does not remove the growth, and every realistic simulation (three dimensions, time stepping, many cases) multiplies the work again. The hardware has one lever left: the clock of a single core has not risen since 2004, and the extra transistors arrive as cores. A solve that needs 1.7 years on one core can finish in a day only on a machine that delivers a speedup of 620, and only a parallel program can use such a machine. The lecture's conclusion is correct, and (9.11) with the measured rate of one core supplies the numbers.

Reading the session. The file is an ELF (Executable and Linkable Format) 64-bit object for x86-64: the ISA is named in the file, together with the operating-system interface ("GNU/Linux 3.2.0") and the dynamic loader. It is linked dynamically against libm and libc, so a copy runs on another x86-64 Linux machine only if that machine has compatible versions of these libraries, and it does not run on an ARM machine or, natively, on Windows. This is the content of the lecture's ABI statement: portability holds across machines with the same ISA, operating-system interface and library conventions. The System V AMD64 ABI that governs the file applies to programs running in the 64-bit "long" mode of the architecture (System V Application Binary Interface, AMD64 Architecture Processor Supplement, draft 0.99.6, 2012, §1, p. 9), and its calling convention is visible in the code. jacobi_step(int N, const double *u, double *unew) receives \(N\) in %edi (the test at its start), u in %rsi and unew in %rdx (copied to %rcx and %r8), and returns its double in %xmm0, as §3.2.3 prescribes for arguments of the integer class and a result of the SSE class (the register sequence is in §A.2.1, p. 124 of the draft).

The inner loop answers the lecture's claim about instructions. One iteration of the loop over \(j\), one point update, executes 14 instructions: one load (movsd); three additions and one subtraction that each read one operand from memory, so that five values are read, the four neighbours and the centre; one multiplication; one store; the absolute value (andpd); the maximum (maxsd); two register copies (movapd); and three instructions of loop control (addq, cmpq, jne). The five floating-point operations of \(F=5N^2\) are 5 of the 14. One sweep at \(N=1000\) executes \(1.4\times10^{7}\) instructions in the inner loop, and the solve of the first paragraph of this chapter, with \(2.6\times10^{6}\) sweeps, about \(3.7\times10^{13}\). The lecture's "thousands or even millions" fits one sweep; the whole solve executes about \(4\times10^{7}\) times a million instructions. The instructions handle one double each (movsd, addsd): the baseline x86-64 set with SSE2, although the processor has wider vector instructions. At -O3 the compiler did not vectorize the loop and reports "complicated access pattern" at the loads of line 14. The maximum is a chain: maxsd %xmm2,%xmm1 followed by movapd %xmm1,%xmm2 makes each point's maximum depend on that of the previous point. The same sweep without the maximum (the plain build of the next listing) takes 0.15 to 0.22 ms at \(N=500\) in six runs, against 0.26 to 0.39 ms with the maximum in the timing listing; the chain is a candidate explanation, and this chapter did not isolate it. Chapter 6 treats vector instructions and the dependences that limit them, and chapter 12 the OpenMP reduction clause that handles this maximum.

The two counts, with -march=native and with the default build, show where binary portability ends. With -march=native the compiler defines the macros for AVX2 and FMA, which this processor supports; without it, none. The GCC manual states that -march=cpu-type "allows GCC to generate code that may not run at all on processors other than the one indicated", and that with native "the result might not run on different machines" (GCC manual, x86 Options). A binary built for the ABI is portable across x86-64 machines only if its instruction set level is also available on them. The programs of this book are built without -march, so that the output of a listing does not depend on the processor that compiles it.

Does the compiler parallelize the sweep? The first lecture of the week argues that automatic parallelization has been "a disaster" (W3L1 9:35) and tells an anecdote from about 20 years earlier: a code compiled with an automatically parallelizing compiler on a dual-core machine ran 50 percent slower instead of twice as fast, because the compiler did not understand the algorithm (W3L1 10:06). The anecdote cannot be tested here, since compiler and machine differ, but the claim can be tested with gcc 13.3 on the Jacobi sweep. The session shows that -ftree-parallelize-loops=4 parallelizes the outer loop of init_canonical (line 25) and leaves the sweep (lines 12–17), whose maximum is a reduction, serial. The GCC manual states that parallelization "is only possible for loops whose iterations are independent and can be arbitrarily reordered" and "is only profitable on multiprocessor machines, for loops that are CPU-intensive, rather than constrained e.g. by memory bandwidth" (GCC manual, Optimize Options). The model of this chapter establishes four things. The five-point scheme has an error of order \(h^2\) for smooth solutions, proved by a discrete minimum principle and checked in closed form. Jacobi iteration has the spectral radius \(\cos(\pi/(N+1))\), an iteration count \(2(N+1)^2\ln(a_1/\varepsilon)/\pi^2\) that the programs reproduce to 0.01 % for \(N\ge31\), and a factor \(\rho/(1-\rho)\) between change and error that they reproduce to 0.2 %. The work grows as \(N^4\), and at the measured 1.0 to 2.6 ns per point update one core needs 1.5 hours at \(N=1000\) and 1.7 years at \(N=10^4\). The speedup a parallel machine must deliver follows: 87 for the \(N=1000\) solve in one minute, 620 for the \(N=10^4\) solve in one day. Three quantitative statements of the lectures need correction: the 18-month doubling time, the discretized equation of the slide, and the efficiency of iterative solvers.

The model leaves out most of what a parallel solution needs. It contains no parallel program, so the required speedups are requirements, not measurements; chapters 12, 16, 20 and 24 measure them. It does not model the memory system; the time per point update at \(N\ge1000\) is a measured number whose cause, the move from cache to main memory, chapter 10 analyses. The iteration count (9.9) and the amplitude \(4/\pi^2\) belong to the five-point operator on a square with the canonical boundary values, and the single-mode count for the change holds only when \(\mathrm{tol}\ll(1-\rho)4/\pi^2\); at \(N=1000\) with \(\mathrm{tol}=10^{-6}\) (\(\mathrm{tol}/c=0.50\)) it underestimates the sweeps by 26 %, and for larger \(N\) at the same tolerance it does not apply at all, because \(\mathrm{tol}/c\gt1\) (they are 1.36 times the count, as in Chapter 4), and the stair-step of the successive changes was observed, not derived. The accuracy statements hold for solutions with bounded fourth derivatives; the canonical problem jumps at the corners, and its largest error over the grid was \(7.9\times10^{-3}\) at \(N=7\) and \(7.2\times10^{-3}\) at \(N=15\), 31 and 63. The modelling error of the pipeline was not estimated, and the fits of the trend data say nothing about causes. The timing samples were captured while other jobs ran, on an unknown core of the hybrid processor. The times for \(N\ge4000\) are extrapolations: the largest grid timed was \(N=2000\) and the longest solve run took 16.7 s (\(N=255\)). The node name "3 nm" was not checked, and the ABI discussion covers the x86-64 Linux case of the session.

Exercises

Exercise 1 (derive). In the model of the bag of integers with pairwise addition of the partial sums, \(T(p)=M/p+\log_2p\) (the ceilings dropped), find the team size \(p^*\) that minimizes \(T\), the minimum time and the speedup. Evaluate them for \(M=10^4\), and compare with the model with the ceilings and with the flat combination of (9.1). Say why \(p^*\) grows as \(M\) here and as \(\sqrt M\) in (9.1).

Solution

\(dT/dp=-M/p^2+1/(p\ln2)\) is zero at \(p^*=M\ln2\). The second derivative is \(2M/p^3-1/(p^2\ln2)\), which at \(p^*\) equals \(1/(M^2\ln^32)\gt0\), so this is a minimum. The minimum time is \(T(p^*)=1/\ln2+\log_2(M\ln2)\). For \(M=10^4\): \(p^*=6931\), \(T=1.44+12.76=14.2\) s, speedup \(S=10^4/14.2=704\). The model with the ceilings, \(\lceil M/p\rceil+\lceil\log_2p\rceil\), has the minimum 15 s (speedup 667) for \(3334\le p\le4096\), for \(5000\le p\le8192\) and at \(p=10^4\); just above each power of 2, where \(\lceil\log_2p\rceil\) rises by one, the time is 16 s. The ceilings make the optimum flat and ragged. The flat combination of (9.1) has its minimum of 200 s at \(p=100\): pairwise addition is 13 times faster at its best and uses a team 69 times larger. The optimum grows as \(M\) here because the cost of combining is logarithmic in \(p\). One more person saves about \(M/p^2\) seconds of compute time and adds about \(1/(p\ln2)\) seconds of combining, and the two balance at \(p=M\ln2\). In (9.1) each added person adds a whole second (one more partial sum to add), and the balance \(M/p^2=1\) gives \(p=\sqrt M\). The serial part of a parallel program depends on the algorithm for combining results.

Exercise 2 (compute). For the canonical problem on a grid with \(N=255\), compute the spectral radius, the tolerance tol that, by (9.10), gives an iteration error of \(10^{-8}\) once the slowest mode dominates, the number of sweeps, the number of floating-point operations and the time at 1.1 ns per point update.

Solution

\(h=1/256\), \(\rho=\cos(\pi/256)\), \(1-\rho=7.53\times10^{-5}\) (the approximation \(\pi^2/(2\cdot256^2)=7.53\times10^{-5}\) agrees), \(\rho/(1-\rho)=1.33\times10^{4}\). By (9.10), \(\mathrm{tol}=\varepsilon(1-\rho)/\rho=10^{-8}/13{,}280=7.5\times10^{-13}\) (a guarantee in the maximum norm needs \(5.2\times10^{-13}\), 1.45 times smaller). By (9.9), \(k=\ln(0.405/10^{-8})/(-\ln\rho)=17.52/7.53\times10^{-5}=2.33\times10^{5}\) sweeps. The work is \(W=5N^2k=5\times65{,}025\times2.33\times10^{5}=7.6\times10^{10}\) operations, and the time \(k\,N^2\,t_{\mathrm{pt}}=2.33\times10^{5}\times65{,}025\times1.1\ \mathrm{ns}=16.6\) s. The program of the chapter, run with these values, took 232,634 sweeps (the model gives 232,633), 16.7 s on this machine, and the centre value was within \(1.0\times10^{-8}\) of \(\tfrac14\), the iteration error that the tolerance was chosen to give.

Exercise 3 (counterexample). A student claims: "If no value of the field changes by more than \(10^{-6}\) in a sweep, the iterate is accurate to about \(10^{-6}\)." Construct a starting vector for the plate problem on \(N=999\) for which the first sweep changes nothing by more than \(10^{-6}\) while the error is 0.2.

Solution

Let \(\mathbf U\) be the exact solution of the five-point system and start from \(\mathbf U^0=\mathbf U+\delta\varphi_{11}\), with \(\varphi_{11}(p,q)=\sin(\pi ph)\sin(\pi qh)\) and \(\delta=0.2\). The error is \(\mathbf e^0=\delta\varphi_{11}\), and its largest entry is \(\delta\) at the centre node (\(N=999\) is odd). The eigenvalue of \(G\) for \(\varphi_{11}\) is \(\rho\), so \(\mathbf e^1=\rho\mathbf e^0\) and the change of the first sweep is \(\mathbf U^1-\mathbf U^0=(\rho-1)\delta\varphi_{11}\), with largest entry \((1-\rho)\delta\). For \(N=999\), \(h=10^{-3}\) and \(1-\rho=\pi^2/(2\times10^6)=4.9\times10^{-6}\), so the change is \(0.2\times4.9\times10^{-6}=9.9\times10^{-7}\), below \(10^{-6}\). The solver stops after one sweep with the error \(\rho\delta=0.2\). The ratio of error to change is \(\rho/(1-\rho)=2.0\times10^{5}\), the factor of (9.10). The claim is true only if the factor is of order 1, which it is for a method with a spectral radius far from 1 and not for Jacobi iteration at large \(N\). The measurements of the chapter show the same on a natural start: with \(10^{-3}\) as the tolerance and \(N=31\) the error was 0.156.

Exercise 4 (diagnose an assumption). A student runs the program of the chapter with \(N=63\) and tol \(=10^{-8}\), counts 8958 sweeps, and compares it with the prediction \(\ln(0.25/\mathrm{tol})/(-\ln\rho)=14{,}133\). The student concludes that the formula \(\rho=\cos(\pi/(N+1))\) is wrong. Find the assumption that is wrong, and compute the difference between the two counts.

Solution

The rate is not at fault: the later changes of the program shrink by \(\rho\) per sweep (the two-sweep ratio of the table is \(\rho\) to six digits). The wrong assumption is that the decay of the change starts from the size of the first change, 1/4. The first changes belong to the fast components of the error. The change that remains after those have decayed is that of the slowest component, \((1-\rho)a_1\rho^k\) with \(a_1=4/\pi^2\). For \(N=63\), \(1-\rho=1.205\times10^{-3}\) and \((1-\rho)a_1=4.88\times10^{-4}\), which is 512 times smaller than 1/4. The difference of the counts is \(\ln(512)/(-\ln\rho)=6.238/1.2053\times10^{-3}=5176\) sweeps, equal to \(14{,}133-8958=5175\) up to the rounding of the printed counts. With the amplitude \(4.88\times10^{-4}\) the prediction is 8957.2, within 0.01 % of the measured count. The sum of the lesson: a rate, here \(\rho\), and an amplitude, here \(a_1\), both enter a count, and the amplitude must be that of the slowest component, not that of the first change.

Exercise 5 (design judgment). A group wants the canonical problem on \(N=4000\) (spacing 1/4001) in one hour, with an iteration error of \(10^{-6}\). Use the table of the chapter. State what the machine must deliver, assuming at least 16 bytes of memory traffic per point update (one 8-byte read and one 8-byte write per node, the other neighbours coming from cache), and decide whether the group should buy a larger machine.

Solution

From the table, \(N=4000\) takes \(4.19\times10^{7}\) sweeps and \(3.35\times10^{15}\) operations, 15.5 days on one core at 2.0 ns per point update. The speedup needed for one hour is \(15.5\times24=372\). By (9.2) with \(p=1000\) workers the serial fraction must be at most \((1/372-1/1000)/(1-1/1000)=1.7\times10^{-3}\). The sustained rate is \(3.35\times10^{15}/3600=0.93\) Tflop/s. The memory traffic is \(16N^2=2.6\times10^{8}\) bytes per sweep at \(4.19\times10^{7}/3600=1.16\times10^{4}\) sweeps per second, \(3.0\times10^{12}\) bytes per second. Chapter 10 measures the memory bandwidth of the machine of this book; the requirement is the number to compare with, and for a sweep with 5 operations on 16 bytes the bandwidth decides before the flop rate does. Buying more cores raises the flop rate and not the bandwidth of a node, so it does not solve the problem; a cluster with many nodes does, if the exchange of boundary rows is cheap enough (chapter 16).

The better decision is to ask what accuracy is needed. For the canonical problem itself the largest error is \(7.2\times10^{-3}\) at the nodes next to the top corners, at every size tested (the section on the stencil). Refining from 1000 to 4000 is not expected to reduce it, and an iteration error of \(10^{-6}\) is already 7000 times below it. The argument that follows uses the error away from the corners, or a problem with a smooth solution. The discretization error of a smooth solution is about \(0.285h^2=1.8\times10^{-8}\) at \(N=4000\), far below the requested iteration error of \(10^{-6}\), so the grid is finer than the accuracy requires. Take \(N=1000\): the discretization error is \(2.8\times10^{-7}\), the same order as \(10^{-6}\), and the solve takes 1.5 hours on one core, a speedup of 1.5 for one hour. The work falls by \(4^4=256\) when \(N\) falls by 4. A better algorithm changes the exponent as well (conjugate gradients, multigrid; chapter 29). Resolution should be chosen from the accuracy needed, and the machine from the work that results.

Exercise 6 (implementation and measurement). Change the program of the chapter to Gauss–Seidel iteration, which updates u in place in row order so that the north and west neighbours are already new. For the symmetric five-point matrix in natural ordering the Gauss–Seidel iteration matrix has the spectral radius \(\rho^2\), the square of the Jacobi value. Predict the ratio of the sweep counts and the factor between change and error, and measure both for \(N=15,31,63\) with tol \(=10^{-8}\).

Solution

Theorem 4.16 of Saad (§4.2, p. 126) relates the eigenvalues \(\lambda\) of the SOR iteration matrix with relaxation parameter \(\omega\) to those \(\mu\) of the Jacobi matrix of a consistently ordered matrix by \((\lambda+\omega-1)^2=\lambda\omega^2\mu^2\). Gauss–Seidel iteration is \(\omega=1\), which gives \(\lambda=\mu^2\) for the nonzero eigenvalues, so \(\rho_{\mathrm{GS}}=\rho^2\). The five-point matrix in natural ordering is consistently ordered (this chapter relies on that classical fact and checks it only through the measurement below). Each sweep then damps the slowest error component by \(\rho^2\), so the sweeps for the same reduction are about half. Because \(-\ln\rho^2=2(-\ln\rho)\) and the amplitudes differ, the ratio is slightly above 1/2. For the dominant eigenvector of the Gauss–Seidel matrix, with eigenvalue \(\rho^2\), the change is \((1-\rho^2)\) times the error and the next error \(\rho^2\) times it, so the ratio of error to change is \(\rho^2/(1-\rho^2)\) once that mode dominates. The bound (9.10) itself used the symmetry of \(G\) and does not carry over, because the Gauss–Seidel matrix is not symmetric. The program is deterministic, so the check is exact.

#include <stdio.h>
#include <stdlib.h>
#include <math.h>

#define IDX(i,j) ((i)*(N+2)+(j))

/* Jacobi: reads u, writes unew (the kernel of the chapter). */
static double jacobi_step(int N, const double *u, double *unew)
{
    double maxdiff = 0.0;
    for (int i = 1; i <= N; i++)
        for (int j = 1; j <= N; j++) {
            double v = 0.25 * (u[IDX(i-1,j)] + u[IDX(i+1,j)] + u[IDX(i,j-1)] + u[IDX(i,j+1)]);
            maxdiff = fmax(maxdiff, fabs(v - u[IDX(i,j)]));
            unew[IDX(i,j)] = v;
        }
    return maxdiff;
}

/* Gauss-Seidel: updates u in place, row by row, so the north and west neighbours are already new. */
static double gs_step(int N, double *u)
{
    double maxdiff = 0.0;
    for (int i = 1; i <= N; i++)
        for (int j = 1; j <= N; j++) {
            double v = 0.25 * (u[IDX(i-1,j)] + u[IDX(i+1,j)] + u[IDX(i,j-1)] + u[IDX(i,j+1)]);
            maxdiff = fmax(maxdiff, fabs(v - u[IDX(i,j)]));
            u[IDX(i,j)] = v;
        }
    return maxdiff;
}

static double *grid(int N)
{
    double *u = calloc((size_t)(N + 2) * (N + 2), sizeof(double));
    if (!u) exit(1);
    for (int j = 0; j < N + 2; j++) u[IDX(0,j)] = 1.0;           /* canonical: top edge 1 */
    return u;
}
int main(void)
{
    const double tol = 1e-8, pi = 3.14159265358979323846;
    printf("%4s %10s %12s %10s %14s %12s\n", "N", "Jacobi", "Gauss-Seidel", "GS/Jacobi", "|u_c-1/4|/tol", "r2/(1-r2)");
    for (int N = 15; N <= 63; N = 2 * N + 1) {
        double *a = grid(N), *b = grid(N), *g = grid(N), d = 1;
        int kj = 0, kg = 0;
        while (d >= tol) { d = jacobi_step(N, a, b); double *t = a; a = b; b = t; kj++; }
        d = 1;
        while (d >= tol) { d = gs_step(N, g); kg++; }
        double r2 = pow(cos(pi / (N + 1)), 2);                  /* Gauss-Seidel factor = rho_Jacobi^2 */
        printf("%4d %10d %12d %10.3f %14.1f %12.1f\n", N, kj, kg, (double)kg / kj,
               fabs(g[IDX((N + 1) / 2, (N + 1) / 2)] - 0.25) / tol, r2 / (1 - r2));
        free(a); free(b); free(g);
    }
    return 0;
}

The measured ratios are 0.521, 0.526 and 0.530: just above 1/2, as predicted, and rising slowly with \(N\) because the amplitude of the slowest component differs from that of Jacobi iteration. The error at the centre divided by tol is 25.1, 102.1 and 413.9, against \(\rho^2/(1-\rho^2)=25.3\), 103.1 and 414.3: the stopping-rule factor of Gauss–Seidel is the same expression with \(\rho^2\), 207 at \(N=31\) for Jacobi and 103 for Gauss–Seidel. Gauss–Seidel halves the work, and its sweep cannot be divided among workers as written, because each value needs the new value of its predecessor in the row and in the column above; Demmel's notes state that this update order "cannot be straightforwardly parallelized" and use a red–black ordering instead (CS 267, Lecture 24). The faster method is less parallel, which is the reason for the choice of Jacobi iteration in this book.
