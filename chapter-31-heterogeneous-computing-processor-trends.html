Heterogeneous computing: choosing resources under communication, power, and numerical constraints

A heat solver needs 200 sweeps on a grid with 256 interior points per side. Its two double-precision grids occupy only 1,065,024 bytes, yet choosing the processor still requires more than comparing arithmetic rates. A synthetic budget of 1 millisecond per CPU sweep and 0.1 millisecond per GPU sweep predicts a tenfold kernel advantage. Add 2 milliseconds of transfers on every sweep and the accelerator loses. Keep the arrays resident and it wins. Divide the grid between CPU and GPU and another boundary exchange can reverse the answer again. The useful object is the complete calculation with a stated numerical contract.

The calculation, its data, and its completion condition

A heterogeneous computer contains processing resources with different execution characteristics. Here a central processing unit (CPU) runs control code and shared-memory threads; a graphics processing unit (GPU) runs many device threads. An accelerator is a processor used to execute selected parts of an application. The host is the CPU-side execution environment that launches this device work. These roles describe the program interface, not a claim that the CPU cannot perform arithmetic or that the GPU cannot execute branches.

The running problem is the steady two-dimensional heat equation without internal sources on the unit square. The unknown temperature is sampled at interior indices \(i,j=1,\ldots,N\), with grid spacing \(h=1/(N+1)\). Both arrays u and unew contain \((N+2)^2\) values, including boundary rows and columns. The top edge, \(i=0\), is one, including its two corners; the other boundary values are zero. The corner convention removes ambiguity in full-array checks. Corners are not direct neighbors of any interior point in the five-point stencil.

A sweep applies Jacobi iteration: every new interior value uses four values from the preceding sweep, never partially updated values from the current sweep. With iteration number \(k\),

\[ u^{(k+1)}_{i,j}=\frac14\left(u^{(k)}_{i-1,j}+u^{(k)}_{i+1,j}+u^{(k)}_{i,j-1}+u^{(k)}_{i,j+1}\right). \tag{31.1} \]

The boundary values persist through every swap. Initial interior values are zero. The spatial discretization replaces the Laplacian by a nearest-neighbor difference; the resulting linear system is the mathematical object being iterated. Changing hardware should preserve that object. Changing to a different solver is allowed, but it then changes the performance question and requires a fresh accuracy comparison.

Let \(K\) denote a prescribed number of sweeps. The executable uses max_iter=200 as this fixed budget. It does not claim that 200 sweeps reach the steady solution. A convergence-driven solver would instead stop when a defined criterion falls below a tolerance \(\mathrm{tol}\), subject to a maximum count. Fixed work is useful here because CPU and GPU then execute the same number of updates. It separates implementation comparison from differences in stopping decisions.

Define the dimensionless algebraic residual \(r_{i,j}=4u_{i,j}-u_{i-1,j}-u_{i+1,j}-u_{i,j-1}-u_{i,j+1}\) on the final grid. Its infinity norm \(\|r\|_\infty\) is the largest absolute interior residual. If \(d\) is the maximum change of one additional Jacobi sweep from that final grid, (31.1) gives \(\|r\|_\infty=4d\) in exact arithmetic. The physical finite-difference Laplacian residual has an additional factor \(h^{-2}\). Reporting the dimensionless residual without that distinction would make cross-grid convergence comparisons misleading.

The implementation contract has four parts: every output value must be finite; every boundary must retain its prescribed value; the maximum principle must hold, so all temperatures remain between zero and one; and the full final array must agree with a separately computed serial reference within \(10^{-12}\). The residual/change identity supplies another internal check. Full-array agreement checks implementation equivalence. A small residual would check closeness to the discrete equation. Neither alone establishes the discretization error relative to the continuum solution.

Represent the program as a directed acyclic graph for a finite run: vertices are work units such as sweeps, transfers and reductions, and an edge means that one unit requires another unit’s result. Each data object has a location and a version. A GPU sweep consumes device version \(k\), produces device version \(k+1\), and permits a host consumer only after a completed transfer or a valid shared-memory visibility operation. This versioned view persists through all four programming models. Most errors in composing them are missing edges, stale versions, or two writers claiming the same object.

Scaling limits combine work, bytes, power, and reliability W12L1 0:38

Let \(T_1\) be wall-clock time for a fixed calculation on one processing element, and \(T_p\) its time on \(p\) elements. Speedup is \(S_p=T_1/T_p\); parallel efficiency is \(E_p=S_p/p\). In Amdahl’s model, \(f\) is the fraction of \(T_1\) that must remain serial, all processors have identical useful rates, and the remaining work divides perfectly. Ignoring new overhead gives

\[ T_p=T_1\left(f+\frac{1-f}{p}\right),\qquad S_p=\frac{1}{f+(1-f)/p}. \tag{31.2} \]

If half the time is irreducibly serial, infinite parallel throughput leaves half the original time and limits speedup to two. This is a statement about a specified decomposition and baseline. Moving work into a library, changing the numerical method, or accelerating the supposedly serial stage changes the premises. Calling everything outside one kernel “serial” is often a useful measurement partition; it is not proof that no better algorithm can accelerate it.

Gustafson’s scaled calculation asks a different question. Let \(f_s\) be the serial fraction of the measured parallel runtime, with the remaining fraction doing work on \(p\) processors. If the same work were performed serially at unchanged per-processor rates, its time would be proportional to \(f_s+p(1-f_s)\), giving scaled speedup \(S_p=p-(p-1)f_s\). The two fractions \(f\) and \(f_s\) have different denominators. Substituting one for the other without converting the workload is an error. Growing the mesh also grows Jacobi’s iteration requirement if accuracy is held fixed, so multiplying grid points and processors by the same factor does not automatically preserve solution time.

The next constraint is data supply. A floating-point operation, abbreviated flop, is an arithmetic operation on floating-point numbers. Let \(F\) be their count and \(Q\) the bytes transferred across a specified memory boundary. Arithmetic intensity is \(I=F/Q\), measured in flop per byte. With compute ceiling \(P_{\mathrm{peak}}\) and bandwidth ceiling \(B_{\mathrm{peak}}\), throughput cannot exceed \(\min(P_{\mathrm{peak}},IB_{\mathrm{peak}})\) in the roofline model. The boundary matters: GPU device memory and the host/device link have different bandwidths and different byte counts.

One direct Jacobi update performs three additions and one multiplication, counted as four flops. Counting four double-precision loads and one store gives 40 source-level bytes and intensity 0.1 flop per byte. Double precision here means the usual 64-bit floating-point representation, also called FP64; each stored value uses eight bytes. Neighbor reuse and caching can reduce device-memory traffic below this source-level count. Host/device traffic can be smaller still: a resident implementation uploads initial arrays once and downloads the final result once. Inferring actual bandwidth from 40 bytes per point without measuring transactions confuses a reference-counting model with hardware traffic.

Communication has latency and bandwidth costs. Write \(T_{\mathrm{msg}}(m)=\alpha+\beta m\), where \(m\) is payload bytes, \(\alpha\) is startup latency in seconds and \(\beta\) is seconds per byte. If each of \(p\) ranks communicates only with a fixed number of neighbors, total message count per sweep is proportional to \(p\). An all-to-all exchange has \(p(p-1)\) directed peer relationships. A tree collective has a different critical path. There is no general exponential law for communication overhead. Contention, routing and collective algorithms must be specified before predicting scaling.

Power is energy per time. A simple switched-capacitance model writes dynamic power as \(P_{\mathrm{dyn}}=aCV^2\nu\), where \(a\) is activity factor, \(C\) effective switched capacitance, \(V\) supply voltage and \(\nu\) clock frequency. At fixed voltage and activity, the frequency dependence is linear. Increasing frequency may require a voltage change; leakage and temperature add other terms. Therefore a linear power/frequency relation is a conditional model, not a general prediction for a processor under boost clocks. The later section on dark silicon explains why adding transistors does not remove this constraint.

Facility efficiency introduces another boundary. The Green Grid’s PUE white paper, §3.1, defines power usage effectiveness as total facility energy divided by information-technology equipment energy over the same interval. PUE 1.3 means 0.3 units of infrastructure energy per unit of IT energy; infrastructure includes more than cooling. The denominator includes IT equipment beyond arithmetic units. PUE does not measure useful scientific answers per joule. A less efficient algorithm can waste more IT energy while the facility retains excellent PUE.

For a synthetic example, 10 megawatt-hours of IT energy at PUE 1.3 requires 13 megawatt-hours at the facility boundary. Reducing IT energy to eight at PUE 1.4 requires 11.2 total. The ratio worsened while total energy improved. Conversely, a lower ratio can accompany higher total consumption. These arithmetic comparisons explain why selecting a GPU from runtime alone cannot establish energy savings: energy needs an independently defined power integration and system boundary. No physical energy measurement is made here.

Reliability becomes another scaling constraint. Suppose failures on each of \(p\) nodes are independent Poisson events at rate \(\lambda\) per hour. The probability of no failures during \(t\) hours is \(\exp(-p\lambda t)\). With a deliberately synthetic per-node mean interval of 100,000 hours, \(p=10,000\), and \(t=10\), this probability is \(e^{-1}\), about 0.368. Independence, stationary rates and fatality of every failure are strong assumptions. The calculation motivates checkpoints and recovery; it does not predict a real facility’s reliability. Graceful degradation in a pattern recognizer does not automatically preserve the numerical correctness of a heat solver after data loss.

The search for alternative devices includes neuromorphic systems, which represent computation through neuron-like state and often spikes; optical systems, which use light for signal transport or operations; and quantum systems, which manipulate quantum states. Field-programmable gate arrays (FPGAs) implement reconfigurable logic, whereas application-specific integrated circuits (ASICs) implement hardware designed for particular tasks. These are different specialization choices. An FPGA can implement many designs over its lifetime, but changing a circuit is a different activity from running another CPU executable. Benefits depend on the algorithm, precision, conversion costs, and the surrounding memory system.

Physical limits sit beneath these engineering constraints. Landauer’s 1961 analysis associates logical irreversibility with heat generation. Erasing an unbiased bit at temperature \(\Theta\) has the familiar ideal lower bound \(k_B\Theta\ln2\), with Boltzmann constant \(k_B\). At 300 kelvin it is about \(2.87\times10^{-21}\) joule. That is not the energy of a modern floating-point instruction. Bekenstein’s 1981 paper considers an entropy-to-energy bound for bounded physical systems. Its abstract supplies evidence for a fundamental information constraint, not a specification for accessible random-access memory. Neither bound grants an architectural route around communication, error correction or finite-rate dissipation.

Shared-memory revision: ownership precedes scheduling W12L2 2:48

OpenMP is an application programming interface for parallel programming, expressed through compiler directives, runtime routines and environment controls. In its CPU fork–join model, a thread encountering a parallel region participates in a team executing that region. At its end, execution continues with the encountering thread. The conceptual join does not require the implementation to destroy operating-system threads; a runtime can retain them for reuse. The OpenMP 5.2 parallel construct, §10.1, defines the team and implicit tasks without prescribing a thread-pool implementation.

For Jacobi, assign each output interior point to one writer. Every thread reads the old array, and no thread writes it during that sweep. This is sufficient to make the pointwise update independent of scheduling. The scalar maximum change requires aggregation across writers. A reduction(max:change) creates private contributions and combines them according to the reduction clause, §5.5.8. Protecting every point update with one common critical region would preserve exclusion but serialize the useful loop. An atomic update protects a supported operation on a particular storage location; it does not make an arbitrary multi-statement invariant atomic.

A worksharing loop distributes iterations among a team. A sections region distributes distinct blocks of code, useful when the work units differ. single chooses one participating thread; the older master construct selects the primary thread and differs in synchronization behavior. A barrier is a collective meeting point for the relevant team. These constructs answer different ownership questions. “Only one thread writes the file” does not prove that the data being written has already been produced by the other threads.

In a two-buffer Jacobi loop, finishing all writes must precede the pointer swap and the next sweep’s reads. The worksharing completion barrier supplies that edge unless explicitly removed. A nowait optimization therefore needs a replacement dependency argument. A thread finishing its own rows does not imply that its neighboring rows are ready. Exercise 2 uses this stencil to diagnose the distinction between independent point updates within one sweep and dependent sweeps across time.

Data-sharing clauses control variables rather than physical copies of an entire scientific problem. A shared pointer variable and the array it points to are separate objects. A private pointer can still point into shared storage. firstprivate initializes a private variable from its original value; lastprivate uses the logically last iteration or section defined by the construct, not whichever worker happens to finish last. Initializing an output accumulator is part of correctness. The matrix-product revision’s ownership pattern assigns one \((i,j)\) output to a worker and keeps its inner summation local; collapsing across that summation without a reduction would introduce competing updates.

Scheduling changes assignment and overhead. Static scheduling is a reasonable starting point for uniform Jacobi rows. Dynamic scheduling makes workers request chunks and can help irregular workloads, but its coordination has a cost. Guided scheduling uses decreasing chunk sizes under implementation rules. No scheduling policy repairs an algorithmic race. Nor does a requested team size guarantee exactly that many physical cores: simultaneous multithreading, hybrid core types, affinity and runtime limits affect the mapping. The measured four-thread CPU variant below is a stated implementation choice, not a search for the optimal team size.

There is a useful transfer from matrix multiplication and image filtering to the heat solver. All three can expose independent output locations, but their reuse patterns differ. Matrix multiplication can reuse a tile across many products; a short stencil has much less arithmetic per loaded neighborhood. Convolution near image edges needs an explicit padding rule, just as Jacobi needs boundary conditions. Porting a directive by visual similarity of nested loops misses these semantic and data-movement differences.

Device revision: a block barrier has a bounded scope W12L3 1:45

CUDA, originally named Compute Unified Device Architecture, supplies a host/device programming model for NVIDIA GPUs. A kernel launch creates a grid of thread blocks, each containing threads with indices. A streaming multiprocessor is a hardware execution unit that schedules resident thread blocks and their warps. A warp is a group of 32 CUDA threads. Single-instruction, multiple-thread execution, abbreviated SIMT, exposes individually indexed threads while scheduling grouped instruction execution; it should not be confused with promising independent simultaneous progress for every launched thread.

In the two-dimensional mapping used below, thread coordinates are \(j=1+b_xB_x+t_x\) and \(i=1+b_yB_y+t_y\). Here \(b_x,b_y\) are block indices, \(B_x,B_y\) block dimensions and \(t_x,t_y\) intra-block indices. Ceiling division chooses enough blocks; the bounds test excludes excess threads. Quotient and remainder show uniqueness: each valid \(j-1\) has one quotient \(b_x\) and remainder \(t_x\), and similarly for \(i-1\). Thus every interior output has exactly one writer, including when the grid size is not divisible by the block size.

Memory names carry scope. Registers hold thread-local state; shared memory is explicitly cooperative storage within a block; global memory stores device-accessible arrays; local memory is thread-private address space that may use device memory. Constant and texture facilities serve particular access patterns. A shared-memory tile can reduce repeated global loads, but staging it adds instructions, synchronization and capacity constraints. Occupancy is the fraction of supported active warps that are resident; it is a resource measure, not a direct speedup. More occupancy can leave throughput unchanged once the limiting resource is saturated.

The CUDA synchronization documentation, §10.6, defines __syncthreads() as a barrier for a thread block. It is not a grid-wide barrier. Placing multiple ordinary Jacobi sweeps inside one kernel and inserting only this barrier permits one block to consume another block’s unfinished output. Separate kernels in one ordered stream supply the needed inter-sweep order. The simple kernel below needs no intra-block barrier because a sweep reads an immutable input and writes disjoint output locations.

The revision’s matrix-product sketch illustrates thread indexing and an inner dot product. A complete implementation also needs a bounds guard for partial blocks, valid initialization and allocation, and error handling. Atomic addition is appropriate when several threads deliberately contribute to one value, but it can change floating-point addition order. It is unnecessary for pointwise Jacobi writes. A reduction should express its intended numerical aggregation, not merely eliminate a memory race.

Explicit control lets a CUDA implementation select launch geometry, data placement and synchronization. It does not establish a universal performance ordering over directive-generated code. A compiler can generate the same effective kernel for a regular loop, while a hand-written kernel can make poorer memory choices. Likewise, the fraction of runtime spent transferring data depends on residency and workload. The comparison below measures both a resident interval and a broader copy–compute–copy interval so that neither claim is assumed in advance.

Distributed-memory revision: initiation is not completion W12L4 2:17

The Message Passing Interface (MPI) specifies communication among processes. Each process has a rank within a communicator, which defines a group and a communication context. Distinct ranks can execute on one machine or on different nodes. A compiler wrapper such as mpicc adds the implementation’s include and link settings to a normal compiler. The launcher establishes processes; MPI_Init initializes MPI within a process already launched, and rank and size inquiries describe its communicator. These are separate layers of the execution model.

Partition Jacobi into horizontal strips. A rank owns some interior rows and stores neighboring boundary rows called halos. Before updating a strip’s edge, it needs the adjacent rank’s current edge values. This is a data-version requirement: a correctly sized message from the wrong sweep is still wrong data. Matching uses communicator, source, tag and compatible data descriptions. A global barrier cannot manufacture a missing halo exchange.

A blocking standard send permits reuse of its send buffer when it completes; it need not wait for the matching receive to complete. Buffering behavior can depend on message size and implementation. Conversely, a nonblocking call returns a request representing an operation still potentially in progress. Completion through a suitable wait or test must precede modifying its send buffer or consuming its receive buffer. The MPI 4.1 communication modes, §4.4 distinguishes safe send-buffer reuse from receive completion; the standard’s completion semantics must be preserved when replacing a blocking exchange.

Collectives encode another dependency pattern. Broadcast distributes root data. Scatter distributes distinct pieces, gather collects pieces, reduce combines contributions at a root, and all-reduce makes the combined result available to every participant. For a convergence test, all-reduce of local maximum changes gives a common global decision. Reduce does not mean that only one rank performs all combining arithmetic; an implementation may use a tree. A collective also is not generally an implicit substitute for a barrier or for completion of unrelated nonblocking operations.

The strip model predicts a strong-scaling limit even with perfectly balanced point counts. Each rank computes roughly \(N^2/p\) updates but exchanges rows of length \(N\). With two neighboring messages its unoverlapped communication budget is approximately \(2\alpha+16\beta N\) seconds per sweep for double-precision rows, ignoring end-rank differences. The local compute decreases as ranks increase while this row budget does not. A two-dimensional decomposition changes the boundary length; it does not remove latency. Exercise 4 distinguishes this prediction from an asserted exponential overhead.

Nonblocking communication can overlap interior work with halo movement only when the implementation makes progress and the dependency graph supplies useful independent work. The interior excludes points whose inputs are in flight. A correct sequence posts receives and sends, computes that interior, completes communication, then computes edge rows. Its ideal time is the maximum of independent compute and communication plus dependent edge work. Calling MPI_Isend alone does not prove that this maximum rather than a sum is achieved.

MPI profiling and debugging must preserve these distinctions. Timing only one rank can miss the slowest participant, while a barrier inserted for measurement can change the program’s waiting behavior. Memory checkers find invalid accesses; tracing tools expose ordering and waiting; neither replaces a mathematical decomposition check. No MPI benchmark or inter-node experiment is performed in this chapter. Its communication results are analytical budgets, which remain useful without pretending that one laptop is a cluster.

Directive revision: residency is an algorithmic decision W12L5 2:18

OpenACC describes accelerator work with directives for compute, loops and data. A parallel region expresses programmer-specified parallel execution; a kernels region lets the compiler analyze regions for possible kernels. Neither keyword proves that an arbitrary loop is independent. The gang, worker and vector hierarchy expresses levels of parallelism. Analogies with CUDA blocks, warps and threads help on particular implementations, but the specification does not make those hardware mappings universal identities.

The decisive construction for repeated Jacobi sweeps is a data region spanning the iteration loop. The OpenACC 3.3 specification, §§2.6–2.7, separates allocation lifetime and data actions. copyin requests input data transfer, copyout output transfer and create device storage without ordinary initialization. present requires an existing mapping; it does not refresh stale contents. An update explicitly synchronizes selected data in a direction. The region must include both evolving buffers with correctly initialized boundary values.

Suppose a device sweep costs \(g\) seconds and moving the required state costs \(M\) seconds. Mapping and copying each sweep costs roughly \(K(g+M)\); a persistent region can approach \(Kg+M\), with the exact initial and final directions counted separately. The gain grows with \(K\), even if the generated arithmetic kernel is unchanged. This is why profiling a first incremental port can reveal transfers as the dominant cost while profiling the mature resident version reveals kernel work or launch overhead instead.

Collapsing nested loops exposes a larger iteration space, but it must preserve independent outputs and data locality. A collapse of Jacobi’s two spatial loops is different from collapsing its time loop: the latter has sweep-to-sweep dependencies. Reductions, cache hints and asynchronous queues can refine a correct implementation. Asynchrony requires a wait before a host consumer reads results or a producer overwrites a live input. Exercise 5 asks the reader to repair a stale-data design without relying on an imagined coherent copy.

Portability has several layers. A source program may compile on two systems yet require different compiler support, mapping choices or library backends. Performance portability additionally requires that both generated versions use their resources well. Incremental directives can reduce code duplication and development effort, but the standard does not promise a fixed fraction of a hand-tuned CUDA program’s speed. The revision examples of matrix products, filtering, stencil flow calculations and Monte Carlo simulation share a requirement to identify independent outputs; their intensity, convergence and random-number requirements still differ.

OpenMP synchronizes shared writers; CUDA orders device work and memory visibility; MPI completes communication between separately addressed processes; OpenACC maintains mappings and data lifetime. Combining them adds edges between models. Correctness comes from proving those edges, not from accumulating more directives. That observation is the basis for choosing a hybrid design.

Choose a hybrid model by its critical path W12L6 4:24

A hybrid program combines programming models or processor types. OpenMP plus CUDA can use CPU threads for independent host work and launch device kernels. MPI plus CUDA partitions a large problem across processes and accelerates each local partition. OpenMP plus OpenACC uses directives for shared-memory work and accelerator regions. MPI plus OpenMP plus CUDA adds all three layers. Hardware availability determines which combinations are possible; the dependency graph determines which combinations are useful.

Two CPU threads launching kernels to one GPU do not create two GPUs. They may improve submission or overlap independent work, but their kernels still share device execution and memory resources. Similarly, an OpenMP task that merely enqueues a kernel may finish on the host before the kernel finishes on the device. A dependent CPU task needs a device completion event, an appropriate synchronization operation, or a task integration mechanism with the required semantics. The host task’s return is insufficient evidence that its promised numerical output exists.

First consider sequential phases: CPU preparation, accelerated sweeps, CPU consumption. Let \(c\) be CPU time per sweep, \(g\) device compute time per sweep, \(\ell\) unhidden launch and coordination cost per sweep, \(M\) one-time transfer cost, and \(T_s\) unchanged serial work. These are fitted or hypothetical times for one fixed implementation, not hardware constants. With no overlap,

\[ T_C=T_s+Kc,\qquad T_G=T_s+M+K(g+\ell). \tag{31.3} \]

The resident accelerator wins only if \(K(c-g-\ell)\gt M\). If \(c\le g+\ell\), no positive sweep count amortizes the transfer in this model. If \(c\gt g+\ell\), the break-even condition is \(K\gt M/(c-g-\ell)\). This shows why “large enough” needs a unit and a workload: increasing sweep count amortizes setup, while increasing grid size changes both compute and transfers. An eager implementation that moves state each sweep instead has a term \(KM\), changing the asymptotic coefficient.

For heterogeneous Amdahl accounting, let the accelerated fraction of baseline time be \(1-f\), its acceleration factor be \(a_g\), and new overhead be \(H\) seconds. Assuming the serial part is unchanged and phases remain sequential gives \(S=1/[f+(1-f)/a_g+H/T_1]\). The factor \(a_g\) is an effective speedup for a specified portion, not the number of GPU cores. With \(f=0.1\), \(a_g=10\), and \(H/T_1=0.02\), the result is \(1/0.21\approx4.762\). Accelerating the kernel by ten does not accelerate the application by ten.

Now suppose CPU and GPU compute different fractions of the same sweep concurrently. Let \(x\) be the fraction assigned to CPU, with both fractions continuously divisible and costs proportional to assigned work. Their compute durations are \(xc\) and \((1-x)g\). The ideal shared completion time is their maximum, minimized where they are equal:

\[ x^*=\frac{g}{c+g},\qquad t^*=\frac{cg}{c+g}. \tag{31.4} \]

Equivalently, with useful rates \(r_C=1/c\) and \(r_G=1/g\) in full sweeps per second, aggregate ideal rate is \(r_C+r_G\). Equal point counts are balanced only when the rates are equal. With CPU ten times slower, it should receive one-eleventh of the divisible work, not half. Real strip widths are integers, boundary work is nonuniform and the resources can contend for shared power or memory, so this optimum is a model to test.

Let \(h_b\) be additional unhidden CPU/GPU halo and synchronization time per sweep. A deliberately simple hybrid budget is \(T_H=T_s+M+K[t^*+\ell+h_b]\). Against the resident GPU, compute saves \(g-t^*=g^2/(c+g)\) per sweep. The hybrid wins only when the added boundary cost is smaller than that saving, under the stated equal setup assumption. For \(c=1\) ms and \(g=0.1\) ms, the maximum saving is only about 0.009091 ms. A 0.05 ms boundary cost overwhelms it. Keeping an otherwise idle CPU out of the stencil can therefore be the best application decision.

The following program accepts no input and writes a synthetic budget table. It uses exact rational arithmetic to check balancing and ordering before formatting decimal milliseconds. It creates no external files and performs no hardware measurement. The hypotheses are \(T_s=5\) ms, \(K=100\), \(c=1\) ms, \(g=0.1\) ms, \(\ell=0.03\) ms, \(M=2\) ms and \(h_b=0.05\) ms.

from fractions import Fraction as F
# All times are synthetic milliseconds, not measurements.
serial, cpu, gpu, launch, transfer, halo = map(F, (5,1,'0.1','0.03',2,'0.05'))
K=100
x=gpu/(cpu+gpu)  # fraction of divisible sweep work given to CPU
cpu_only=serial+K*cpu
resident=serial+transfer+K*(gpu+launch)
eager=serial+K*(transfer+gpu+launch)
hybrid=serial+transfer+K*(max(x*cpu,(1-x)*gpu)+launch+halo)
assert x*cpu==(1-x)*gpu
assert resident<hybrid<cpu_only<eager
threshold=transfer/(cpu-gpu-launch)
print('synthetic_ms; no hardware measurements')
print(f'CPU fraction = {x}; balanced compute = {x*cpu} ms/sweep')
for name,t in [('CPU',cpu_only),('resident GPU',resident),('eager GPU',eager),('CPU+GPU',hybrid)]:
 print(f'{name}: {float(t):.6f} ms')
print(f'resident wins when K > {float(threshold):.6f}')
print('PASS: faster aggregate compute can lose after halo overhead')

The ordering is informative because the arithmetic kernel is identical in the two GPU budgets. The eager design takes 218 ms; residency reduces the model to 20 ms. The hybrid improves ideal compute throughput yet takes about 24.091 ms after its boundary term. These are consequences of selected assumptions, not observed device speeds. Equations (31.3) and (31.4) identify which assumptions determine the threshold. Exercise 1 separately connects heterogeneous Amdahl accounting to a power-limited core budget.

Overlap changes sums into maxima only for independent work. If a transfer for the next independent problem takes \(m\) and its current compute takes \(g\), a pipeline might approach \(\max(m,g)\) per problem after filling. Consecutive Jacobi sweeps are dependent, so they cannot be overlapped that way without changing the decomposition or algorithm. Multiple CUDA streams order separate work queues; they do not remove true dependencies or guarantee concurrent execution. Task scheduling can expose independent subproblems, but “task-based” is not itself a proof of lower runtime than a loop.

On multiple nodes, a logical ring, grid or torus describes desired neighbor relationships. Physical network topology and rank placement determine the actual routes and contention. Mapping a strip decomposition to a ring communicator does not physically rewire the cluster into a ring. A maintainable design records ownership, placement and completion at each level, profiles the complete application, and adds a programming layer only when a measured bottleneck or capacity requirement justifies it. Unified frameworks can help express these choices: Kokkos’s programming model, for example, explicitly distinguishes execution spaces, memory spaces and layouts. Such abstractions organize the same decisions rather than abolishing them.

Measure the same payload, then name each timing boundary W12L6 15:22

The next self-contained program implements (31.1) on one CPU thread, four OpenMP threads, and one actual GPU. It uses \(N=64\) and \(N=256\), 200 sweeps, one discarded warm-up and five retained repetitions per path. Each CPU timing includes resetting two preallocated arrays and all sweeps, including the maximum-change reduction and team-region costs. Each GPU wall timing includes two initial full-grid uploads, ordered kernel launches, completion, and a final full-grid download. It excludes device allocation, context creation, compilation, and numerical validation. These exclusions make it a warm repeated-work comparison, not application startup latency.

A separate GPU event interval starts after the uploads and ends after the ordered sweep sequence. It is a resident interval, including device timeline gaps between launches; it is not a sum of isolated kernel instruction times. The host wall clock and device events measure different scopes. The CPU implementation computes a change reduction during each sweep; the GPU implementation checks the final residual on the CPU after downloading. That difference is explicit: this is a comparison of two fixed-sweep implementations, not a claim that the GPU measured a convergence test every sweep. A production convergence solver should measure the reduction and stopping policy it actually uses.

Inputs and boundaries are deterministic. The program allocates two device arrays, at most 1,065,024 bytes together, and no file payload. Every retained CPU and GPU result receives the full contract checks from the model section outside the timed interval. CPU reference construction is also outside timing. A failure returns a nonzero status. The printed timings vary, so the code checker uses return-code semantics: this verifies the program’s assertions and successful execution, not byte-for-byte timing reproduction. CUDA errors are checked at allocation, launch, synchronization, transfer and cleanup.

More transistors require better organization, not a promised deadline W12L7 0:16

Moore-style transistor-count trends and Dennard-style electrical scaling are different statements. A trend in integrated component count does not guarantee constant power density, higher clock frequency or a proportional improvement in solution time. Forecasts of an exact year when Moore’s law “ends” depend on which density, cost and product measures are chosen. Process names such as “3 nm” are product-generation labels rather than a complete geometric description of every transistor dimension. The architectural lesson needs no universal extinction date: integration capacity, power delivery, heat removal and useful parallelism impose distinct constraints.

Dennard and colleagues’ 1974 paper develops scaling relationships for small metal–oxide–semiconductor field-effect transistors, or MOSFETs; its publicly opened abstract describes fabricated devices and scaling analysis. To expose the constant-field idea, consider an ideal scaling factor \(s\gt1\): linear dimensions and voltage shrink by \(1/s\), capacitance scales by \(1/s\), and frequency increases by \(s\). Substituting into the switched-capacitance model yields per-device dynamic power scaling as \(1/s^2\). Device area also scales as \(1/s^2\), leaving ideal power density unchanged. This calculation is an ideal model, not an extraction of modern foundry parameters from a node name.

If voltage instead stops scaling while capacitance and frequency follow those ideal factors, their product stays constant and per-device dynamic power stays constant. Packing \(s^2\) devices into the former area then increases the dynamic-power density by \(s^2\). Real technologies change several assumptions, but the algebra identifies the missing benefit. A smaller switch no longer automatically buys the full combination of more switches and proportionally faster operation at unchanged power density.

Esmaeilzadeh and colleagues, “Dark Silicon and the End of Multicore Scaling” (2011), combine device, core and workload models under area and power limits. “Dark” denotes underutilized transistor capacity under those constraints, rather than defective silicon. Its numerical projections through 2024 belong to that historical model and benchmark set; they are not measurements of the present laptop or universal percentages for current chips. The paper’s important distinction is between fitting circuitry on a chip and being able to use all of it effectively at once.

An original core-budget example makes the distinction operational. Suppose a package has a 100-watt budget, 20 watts of unavoidable background consumption, and 5 watts per active identical core at one fixed operating point. At most \(\lfloor(100-20)/5\rfloor=16\) cores can be active, whether area permits 16 or 64. In the latter case three quarters of the cores cannot be active under this model. Reducing per-core power, using a different operating point or specializing selected operations changes the calculation. Claiming that exactly three quarters of an actual chip is dark would require measurements or its real design model.

Single-core improvements still matter for the critical path. An instruction set architecture, or ISA, defines software-visible instructions and behavior; microarchitecture describes how a processor implements them. Speculation and out-of-order execution seek useful instruction work before every earlier operation finishes, subject to architectural correctness. More cores expose thread parallelism, while wider vector operations expose data parallelism within a core. None of these automatically removes the memory limit of a low-intensity stencil. A design can improve the serial stage and bandwidth while leaving transistor-count growth as only one contributor.

Domain-specific processors specialize the operation mix, dataflow or numeric formats for a workload. The historical examples include Google’s tensor processing units, Apple’s Neural Engine and Tesla’s Dojo. Their useful lesson is specialization, not interchangeability. Training adjusts a model from data; inference evaluates an already trained model. For a concrete documented distinction, Tesla’s April 22, 2026 update, printed page 7, places Dojo development under AI training infrastructure and separately discusses inference compute. Dojo should therefore not be identified as the in-vehicle inference chip. A scientific FP64 solver also cannot substitute a low-precision matrix throughput number without a numerical-error argument.

RISC means reduced instruction set computing. RISC-V International’s specifications library identifies RISC-V as an open standard ISA. An open specification is distinct from an open-source processor implementation; a proprietary chip can implement an open ISA. RISC-V and Arm are distinct ISA families, even though both are associated with RISC design principles. Source portability, binary compatibility, compiler maturity and library support must be evaluated separately. An ISA label alone supplies no power-per-answer ranking.

Memory technology and packaging address another part of the budget. High-bandwidth memory (HBM) places many memory connections near processing logic; double-data-rate memory generations describe interface families; persistent memory retains information without ordinary volatile refresh behavior. The recording’s HBM, DDR5, Optane and magnetic random-access memory examples form a lecture-era taxonomy, not a verified list of products presently available for purchase. Capacity, bandwidth, latency, persistence and cost are separate axes. A capacity improvement can allow a formerly impossible solve without making each sweep faster.

A die is one fabricated piece of semiconductor. A chiplet is a modular die intended to participate in a larger packaged system. Two-dimensional placement, interposers and three-dimensional stacking provide different interconnect geometries. The packaging examples—AMD 3D V-Cache, Intel Foveros, and TSMC CoWoS and InFO—illustrate this design space as presented in the recording. Their names do not establish equal stacking methods or equal efficiency. Moving components closer can reduce some communication distances, but the complete path includes interfaces, routing, coherence and thermal constraints.

A simple original yield argument explains one attraction of modularity. In a toy model with independent area-distributed defects at density \(\rho_d\), the probability that a die of area \(A\) has no defect is \(e^{-\rho_d A}\). Smaller independently tested dies can permit reuse of good pieces rather than discarding one large monolithic piece. But packaging yield, interconnect area, test cost and the number of required pieces affect the final economics. Yield alone does not prove a cheaper or faster system. Stacking also shortens some wires while making heat extraction and power delivery more difficult. The constraint moves rather than vanishes.

Integration must be described precisely. NVIDIA’s November 2022 Grace Hopper architecture description joins a Grace CPU and Hopper GPU with coherent NVLink-C2C, a chip-to-chip link. “Superchip” does not mean that the two processors are on one die. Hardware coherence can make memory sharing easier while CPU-local and GPU-local memory still differ physically. The device wall is therefore not simply erased: placement, bandwidth, contention and synchronization continue to determine cost. Shared addressing removes some explicit-copy obligations; it does not imply uniform access time.

Cloud computing changes provisioning and accounting. Renting a resource can replace a large initial purchase with usage charges, but queueing, storage, network transfer, software licenses and idle reservations enter the full cost. The recording’s Graviton, Axion, TPU and Azure HBv3 names are historical examples, not a benchmark comparison or current service catalog. Cloud resources can include bare-metal configurations, so virtualization should not be assumed universal. For tightly coupled Jacobi partitions, the actual network and placement matter more than the mere fact that the machines are rented.

Dynamic voltage and frequency scaling changes operating points in response to demand. Power gating deactivates unused circuitry. Both fit the lesson of using only the resources justified by the work, but an application must measure useful progress and total energy over a stated boundary to evaluate them. Security adds constraints: speculative and shared-resource behavior can create side channels; isolation mechanisms have threat models and are not guarantees against every attack. Post-quantum cryptography means classical algorithms designed to resist quantum attacks, not cryptography that requires a quantum processor. NIST’s August 2024 announcement documents its first finalized standards; it does not predict a date for a cryptographically capable quantum computer.

Artificial intelligence can assist design and tuning. Google Research’s chip-placement report, updated in June 2021, describes reinforcement-learning methods for placement. Placement is one stage of chip design, not autonomous proof that a complete chip is correct. Likewise, an automatically tuned kernel still needs full-payload and numerical checks. Edge computing moves processing near the data source, potentially avoiding a remote-network round trip; it adds constraints on local energy, updates and security. The useful tradeoff depends on how much raw data must move and how much can be reduced locally.

The remaining directions include optical interconnects and computation, quantum/classical workflows, and portable frameworks such as SYCL, oneAPI, Kokkos and RAJA. These are research and software directions with different maturity and device support, not one replacement for all scientific computing. A quantum subroutine can accelerate an application only if the full preparation, execution, sampling and classical processing costs fit its numerical task. A neuromorphic pattern recognizer does not become a drop-in Laplace solver. Existing exascale systems illustrate combinations of CPUs and accelerators, but a system’s peak operation count does not establish time to solution for this chapter’s workload. The road ahead preserves the same discipline: define the answer, map its dependencies, and measure the entire path needed to obtain it.

What these models and runs establish

The synthetic costs assume linear work partitioning and separately specified overhead. The real comparison uses one laptop GPU and two small grids. Neither establishes a universal architecture ranking, a multi-node scaling curve, or energy efficiency. The finite-sweep arrays are implementation checks, not certified continuum solutions. FP64 agreement does not prove that every compiler or future device will reproduce identical bits.

A useful next investigation changes one decision at a time: measure the actual convergence reduction, increase the sweep budget while preserving array residency, or compare an improved numerical method at equal residual and discretization targets. Each changes a named part of the model. A larger accelerator, more host threads or another programming layer is justified by the resulting application budget, rather than by the availability of hardware alone.

Six integrated exercises

1. Derive a heterogeneous speedup bound with a power constraint

Use the scaling and processor-trend material of W12L1 and W12L7. A baseline takes one second, with serial fraction \(f=0.1\). Its accelerated portion becomes ten times faster but adds 0.02 seconds overhead. Compute application speedup. Then suppose area permits 64 identical CPU cores but a 100-watt budget includes 20 watts background and 5 watts per active core. Under ideal Amdahl scaling, what CPU-only speedup does that power model permit, and why is it not a measured dark-silicon fraction?

Solution

The unchanged serial stage takes 0.1 s, accelerated work takes \(0.9/10=0.09\) s and new overhead takes 0.02 s. Total is 0.21 s and speedup is \(1/0.21\approx4.762\). The CPU power budget permits at most \(\lfloor80/5\rfloor=16\) active cores. Applying (31.2) with that count gives \(S_{16}=1/(0.1+0.9/16)=6.4\). This CPU calculation assumes identical rates, ideal divisibility, unchanged serial time and no overhead; it cannot be compared to the accelerator as though both assumptions were measured facts.

Only 16 of the area-permitted 64 cores can be active in the toy power model, leaving 48 inactive. That is a 75 percent inactive core-count fraction at the selected operating point. It is neither a measured transistor-area fraction nor a universal prediction from the dark-silicon paper. Core areas, leakage, operating points and shared circuitry would be needed to make the connection quantitative. The power constraint limits usable concurrency even before software scaling is considered.

2. Diagnose an OpenMP race after an apparently safe optimization

Using W12L2, a programmer assigns Jacobi rows with a worksharing loop inside a persistent parallel region, adds nowait, and has one thread swap u and unew. Every point has one writer. Is the iteration correct? Would putting only the swap inside a critical region repair it? Also explain why collapsing a matrix-product summation index is different from collapsing its two output indices.

Solution

One writer per point proves independence only within one sweep. Without a completion edge, the swap can occur while another thread is still writing the output array. A fast thread can then read a neighbor’s old or unfinished value in the next sweep. Critical exclusion around the swap prevents simultaneous swaps but does not make unfinished point updates complete. A valid structure completes the worksharing loop, performs exactly one swap and reduction decision, then ensures all workers observe those results before beginning the next sweep. The exact barriers depend on which OpenMP constructs are used.

For a matrix product, output indices \(i,j\) identify independent cells if inputs do not alias the output. The summation index \(k\) contributes repeatedly to the same cell. Distributing different \(k\) values across workers requires a reduction or another correct aggregation. Merely collapsing all three loops creates competing updates to C[i][j]. Initialization of each output is still required. Independence follows from data ownership, not the number of syntactically nested loops.

3. Construct a CUDA counterexample to block-local synchronization

Using W12L3, map \(N=65\) interior points per side to \(16\times16\) blocks. Count launched and useful threads. Then consider fusing two Jacobi sweeps inside one ordinary kernel with __syncthreads() between them. Give a dependency that this barrier fails to enforce.

Solution

Ceiling division gives five blocks along each axis, 25 blocks and \(25\times256=6400\) launched threads. Useful interior outputs number \(65^2=4225\), leaving 2175 excess threads. The bounds guard excludes them from loads and stores. The quotient/remainder mapping assigns each valid point uniquely. A guard is still needed even though the earlier example sizes were divisible by sixteen.

Take two adjacent points on opposite sides of a block boundary. The second-sweep update in the left block requires the first-sweep value produced by the right block. A block barrier in the left block waits only for left-block threads; the right block may not have executed yet. Thus the dependency can be violated even when every block reaches its own barrier. Two ordered kernel launches supply grid completion between these sweeps. Specialized grid-synchronization facilities have additional launch and residency requirements and are not implicitly supplied by an ordinary block barrier.

4. Compute an MPI strong-scaling threshold and reject an unsafe buffer reuse

Using W12L4, suppose one sweep costs \(10^{-8}\) seconds per point, \(N=1024\), two halo messages each have latency \(\alpha=5\) microseconds, and inverse bandwidth is \(\beta=10^{-9}\) seconds per byte. In the unoverlapped strip model, estimate where compute and halo costs become equal. Can a rank overwrite the sent row after MPI_Isend returns?

Solution

Full-grid compute is \(1024^2\times10^{-8}=0.01048576\) s per sweep. Two double rows contain \(16N=16384\) bytes. The communication model gives \(2\alpha+16\beta N=10^{-5}+1.6384\times10^{-5}=2.6384\times10^{-5}\) s. Equating compute per rank to that cost yields \(p\approx0.01048576/(2.6384\times10^{-5})\approx397.43\). This is a model crossover, not an optimal measured process count. End ranks, integer partitioning, collective residual checks, contention and overlap can change it.

The nonblocking send’s return reports initiation, not completion. Overwriting the row before completing its request can change data still being transmitted. The rank must wait or test successfully before reuse, or send from another buffer whose lifetime extends through completion. There are only a fixed number of neighbors per strip; this model therefore gives no exponential message-count law. Its scaling failure comes from shrinking local compute against nearly fixed halo cost.

5. Repair data residency and judge a packaging proposal

Using W12L5 and W12L7, an OpenACC solver creates two device grids, updates only the host top boundary, runs sweeps with present, and writes the host grid without an update. Identify both stale-version errors. A colleague proposes a coherent CPU/GPU package to avoid all such costs. What must still be evaluated?

Solution

Ordinary create leaves device storage uninitialized. Updating host memory does not initialize its device counterpart. Both device grids need valid boundaries and initial interiors before any sweep, through suitable copy-in, device initialization or explicit update. At the other end, present establishes a mapping requirement, not host freshness. The final active buffer must be transferred to its host consumer, with completion before writing. Pointer swaps make it necessary to identify which allocation holds the final version.

A coherent package can change how sharing and visibility are expressed, but accesses still move data through physical memory and links. Evaluate capacity, local versus remote bandwidth, coherence traffic, synchronization, thermal limits, software support and the real ownership schedule. Chiplets and stacking can shorten some paths while adding others. Neither a coherent address space nor a packaging name guarantees uniform latency or higher scientific answers per joule. The correct design judgment is to re-estimate the complete path under the new memory system.

6. Reconstruct the CPU/GPU measurement contract

Run the two listings on compatible hardware within their stated bounds. Using W12L6’s profiling perspective, compare CPU reset-plus-sweeps time with GPU copy–compute–copy time, and distinguish the resident event interval. Explain the full-payload tests and why a passing 200-sweep run cannot establish convergence or energy superiority. If measuring a tolerance-driven solver, specify the additional policy needed.

Solution

The synthetic listing validates only its selected rational cost model. The CUDA listing checks every array entry against a fixed-work serial reference; checks finite values, range and all boundaries; and verifies \(\|r\|_\infty=4d\) within its numeric tolerance. Successful execution requires every tested repetition to pass. Timings are summarized by minimum, median and maximum over five retained repetitions after warm-up. The resident interval excludes uploads and download, whereas the GPU wall interval includes them. Neither includes allocation or context startup. The CPU path also performs a per-sweep change reduction absent from the GPU kernel, so the implementations’ measured work is explicitly different in that respect.

A finite residual is not a convergence certificate. Compare the reported residual with a problem-appropriate threshold, and distinguish its dimensionless form from the Laplacian residual scaled by \(h^{-2}\). A tolerance-driven comparison must use the same mathematical stopping requirement, specify reduction frequency, count extra sweeps between checks, and include reduction and decision costs. It must preserve equivalent accuracy even if floating-point orders differ. Energy requires measured power integrated over the chosen device or system boundary; a shorter runtime alone supplies no such measurement. A different machine may change the ranking without invalidating either the numerical checks or the synthetic derivation.
