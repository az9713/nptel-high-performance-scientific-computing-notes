Hierarchical memory and scalable architectures

A matrix of 4096 × 4096 doubles (134 MB) is summed twice, once along the rows and once along the columns of its row-major storage. Both loops perform the same 16.8 million additions on the same numbers. On this chapter's machine the row-order loop takes 0.79 ns per element and the column-order loop 13.8 ns, a ratio of 17.5 (13.7 to 22.0 in five runs). Two smaller matrices, whose sizes differ by 5 %, show slowdowns that differ by a factor of 4: with 512 columns (2.1 MB) the column-order loop is 4.5 times slower than the row-order loop, and with 500 columns (2.0 MB) it is 1.08 times slower. The two loops differ only in the order in which they visit memory. This chapter defines the objects that explain the difference (lines, sets, ways, reuse distance), derives the miss rates that the geometry of a cache predicts, and checks the prediction against two independent simulators and against measurements. It then asks the same question at the scale of many processors: what a processor pays to read a location that another processor has written, a location in the memory of another socket, and a location in another computer.

The objects of the chapter and the running case W2L5 0:06

The memory of a computer is a sequence of bytes, each with a non-negative integer address. An access is one load or one store of a word (here 8 bytes, one double) at an address \(x\). A trace is the sequence of addresses that a program accesses, in program order. Every claim of this chapter is a claim about a trace and a machine.

A cache is a small, fast memory that holds copies of aligned blocks of memory. The block is a line of \(b\) bytes; \(b=64\) on the machine of this chapter. The line number of the address \(x\) is \(\ell(x)=\lfloor x/b\rfloor\), and the offset of \(x\) in its line is \(x \bmod b\). The cache is organised in \(S\) sets of \(a\) ways each. A line \(\ell\) may be held only in the set with index \(\ell \bmod S\) and occupies one of the \(a\) ways of that set. The remaining part of the line number, \(\lfloor \ell/S\rfloor\), is the tag that tells which of the lines that share a set is the resident one. The capacity of the cache is \(C=aS\) lines, or \(M=abS\) bytes. The extreme cases have names: \(a=1\) is a direct-mapped cache, \(S=1\) a fully associative cache, and the case between them an \(a\)-way set-associative cache. An access hits if its line is resident and misses otherwise; after a miss the line is fetched from the next level and replaces a resident line of the same set chosen by the replacement policy. This chapter uses least recently used (LRU): the victim is the line of the set whose last use is oldest. A real processor may use an approximation of LRU, which the sources opened for this chapter do not specify.

Three quantities describe the cost of a cache. The hit time \(t_h\) is the time of an access that hits. The miss rate \(m_r\) is the number of misses divided by the number of accesses, and \(h=1-m_r\) is the hit rate that the lecture uses. The miss penalty \(t_m\) is the extra time that a miss adds. They combine into the average memory access time, derived in the section on hit rate:

\[ \mathrm{AMAT}=t_h+m_r\,t_m. \tag{7.1} \]

The second half of the chapter changes the question from "how long does one access take" to "which processors can reach which memory, and at what cost". Let \(p\) be the number of processors. Let \(t(i,x)\) be the time that processor \(i\) needs to complete a read of address \(x\) that misses in all its caches. A machine has uniform memory access (UMA) if \(t(i,x)\) is the same for every processor \(i\) and address \(x\), and non-uniform memory access (NUMA) if the processors share one address space and \(t(i,x)\) depends on \(i\) and \(x\). A machine has distributed memory if each processor reaches only its own memory by loads and stores and reaches the memory of the others by sending messages. The time of a message of \(m\) bytes is modelled as \(T_{\text{msg}}(m)=\alpha+\beta m\), with the latency \(\alpha\) in seconds and the inverse bandwidth \(\beta\) in seconds per byte, as in the book-wide notation. The concurrency of a system that completes \(X\) requests per second with a latency of \(L\) seconds per request is \(\lambda=XL\) requests in flight (Little's law, used in the section on hit rate).

The running case is the sum of the elements of an \(N\times N\) matrix of doubles \(A\) stored row by row (row-major), so that \(A_{ij}\) lies at byte address \(8(iN+j)\) relative to the start of the array. The row-order sum visits \(A_{i0},A_{i1},\dots\) for \(i=0,1,\dots\), that is, consecutive addresses. The column-order sum visits \(A_{0j},A_{1j},\dots\) for \(j=0,1,\dots\), that is, addresses \(8N\) bytes apart. Both loops perform \(N^2\) additions, and both read each element once. The book's other running problems (Jacobi iteration, midpoint \(\pi\)) return in later chapters; the matrix sum is used here because its two orders have identical arithmetic and the largest possible difference in memory behaviour. In the last section the matrix is distributed over \(p\) computers and the sum becomes a reduction.

Memory technologies, the processor–memory gap and two hardware remedies W2L5 0:39

The lecture compares four storage technologies in one table (slide at W2L5 1:15). Static RAM (SRAM) stores a bit in a flip-flop, is volatile, and reads in "> 10 nanoseconds"; its stated advantage is the fastest access and its disadvantages are density and power; its use is the cache. Dynamic RAM (DRAM) stores a bit in a capacitor, is volatile, reads in "~ 40 nanoseconds", has the best density and capacity and the disadvantage of speed; its use is main memory. Flash stores a bit in a transistor, retains data without power, reads faster than a hard disk and slower than RAM, writes slower than it reads, and serves as solid-state drive and for the boot firmware. A hard disk stores a bit in a magnetic material, retains data, reads in "10s of milliseconds", has the highest capacity and is the secondary storage. The lecture then describes how a processor uses memory (W2L5 2:21): in a read, the load instruction is decoded, the address is placed on the address bus, the memory sees the read signal and places the data on the data bus, and the processor accepts it; in a write, the store instruction places the address on the address bus and the data on the data bus, and the memory stores the data at that address. The model of this chapter keeps one property of these two cycles: an access is a transaction whose duration is set by the memory that answers it, not by the processor that asks.

Why not all memory is SRAM. Drepper (2007, §2.1.1–2.1.2, pp. 5–6) gives the cell structures behind the lecture's table. An SRAM cell has six transistors that form two cross-coupled inverters; its state is stable while power is applied and is available as soon as the word line is raised. A DRAM cell has one transistor and one capacitor; the capacitor leaks, so each cell must be refreshed (for most chips every 64 ms); reading discharges the capacitor, so every read is followed by a recharge; and the small charge needs a sense amplifier. Drepper concludes that the cell of a DRAM occupies "many times" less chip area than that of an SRAM and that "the (quite dramatic) difference in cost wins". These statements agree with the lecture's entries for density and power, and they show that "speed" for DRAM is a consequence of the charge-sensing step, not an independent property. The cost argument is the reason for the hierarchy of this chapter: a machine with only SRAM would be faster and would cost more per bit by the ratio of the cell areas, and the lecture states the same trade-off in words at W2L5 4:31.

The numbers of the slide against the measured ones. The slide's read times are properties of a memory device. A program observes the time from the issue of a load to the arrival of its data, which includes the caches that the load passes, the memory controller and the translation of the address. The pointer-chase measurement of the next section gives, on this machine, about 1.2 to 1.5 ns for data in the L1 cache (1.19 to 1.53 ns over five runs), 3.7 to 4.4 ns in the L2 cache, and 123 to 162 ns for data that must come from DRAM (five runs; one outlier of 267 ns excluded). The last figure is 3.1 to 4.1 times the slide's 40 ns, and the first is 6.5 to 8.4 times smaller than the slide's "> 10 ns" for SRAM; the slide's numbers therefore describe neither the cache nor the memory as a program sees them on this machine. Drepper's table for a Pentium M (2007, §3.2, p. 16) gives 1, 3, 14 and 240 cycles for a register, the L1 data cache, the L2 cache and main memory: the ratio of main memory to the L1 data cache was \(240/3=80\) on that processor, against 108 to 118 on this one in the fifth run (129 to 141 ns over 1.2 ns).

The gap. The lecture states that early memory parts were faster than the processors that used them (a processor needing data in 150 ns could be served by a memory that delivered it in 120 ns), and that processor speed then grew by 52 % per year while memory speed grew more slowly, so that the processor waits (W2L5 6:04). The slide gives the rates as "Processor 52% annually" and "Memory 7% annually" on a logarithmic plot from 1980 to 2010 and credits the figure to a web site (rankred.com). The sources opened for this chapter do not state these rates (Hennessy and Patterson was not opened), so they are lecture claims. The plot does allow an internal check. A constant 52 % per year for 30 years is a factor \(1.52^{30}=2.9\times10^{5}\), and a constant 7 % per year is \(1.07^{30}=7.6\). The plotted memory curve ends near 7, as 7 % per year predicts, and the plotted processor curve ends near \(2\times10^{4}\) (read from the slide, uncertain by a factor of about 1.5), which is about 14 times below \(2.9\times10^{5}\). The label "52 % annually" therefore describes a part of the period, and the plotted gap at 2010 is about \(2\times10^{4}/7\approx3\times10^{3}\), not \(2.9\times10^{5}/7.6\approx3.8\times10^{4}\). The gap that the lecture describes is real for latency (the measurement above), but the single growth rate on the slide should not be extrapolated. The title of Wulf and McKee (1995) gave the effect its common name, the "memory wall". Their paper was not opened. Ertl's critique, which was opened, describes its argument as assuming a fixed miss probability. The row-order and column-order sums of this chapter show a miss rate of 0.125 and 1.0 for one matrix on one machine, which is a direct counterexample to a miss rate that is fixed independently of the access pattern.

Remedy 1: interleaved banks. The lecture's first remedy (W2L5 7:12) places even addresses in one bank and odd addresses in another, so that the memory delays of consecutive accesses overlap (the slide's wording). The model is this. A memory has \(n_{\mathrm{b}}\) banks and word \(w\) lives in bank \(w \bmod n_{\mathrm{b}}\). A bank that starts an access is busy for \(\tau\) cycles. The processor issues one request per cycle, in order, and stalls when the bank it needs is busy. For a stream of words at addresses \(0,\sigma,2\sigma,\dots\) (stride \(\sigma\)), the banks visited are \(k\sigma \bmod n_{\mathrm{b}}\). The multiples of \(\sigma\) modulo \(n_{\mathrm{b}}\) form a cyclic group with \(n_{\mathrm{b}}/\gcd(n_{\mathrm{b}},\sigma)\) elements, so the stream uses \(\kappa=n_{\mathrm{b}}/\gcd(n_{\mathrm{b}},\sigma)\) distinct banks, in a fixed cyclic order. A bank is revisited after \(\kappa\) requests. If \(\kappa\ge\tau\), the bank is free again when it is needed, no request stalls, and the rate is one word per cycle. If \(\kappa\lt\tau\), a block of \(\kappa\) requests takes \(\tau\) cycles, since the first bank of the block is the one that limits when the next block can start. The steady-state rate is therefore

\[ r=\min\!\Bigl(1,\ \frac{\kappa}{\tau}\Bigr),\qquad \kappa=\frac{n_{\mathrm{b}}}{\gcd(n_{\mathrm{b}},\sigma)}\ \text{words per cycle}. \tag{7.2} \]

The program simulates the model with \(\tau=6\) cycles for 1 to 16 banks and strides 1, 2, 8 and 16, measures the rate between request 500 and request 1000, and prints it beside (7.2). The run checks all 20 entries exactly.

"""Interleaved memory banks: words per cycle for a stream with a constant stride.

Model: n banks; word w lives in bank w mod n; a bank is busy for BUSY cycles after it starts an access;
the processor issues one request per cycle, in order, and stalls when the bank it needs is busy.
"""
from math import gcd

BUSY = 6


def finish(banks, stride, words):
    """Cycle at which the last of `words` accesses completes."""
    free = [0] * banks                    # first cycle at which each bank can start a new access
    issue = 0
    end = 0
    for k in range(words):
        bank = (k * stride) % banks
        start = max(issue, free[bank])
        free[bank] = start + BUSY
        end = start + BUSY
        issue = start + 1
    return end

Two banks give 0.333 words per cycle at stride 1, twice the 0.167 of one bank, and still 3 times below the issue rate of 1 word per cycle; \(n_{\mathrm{b}}\ge\tau\) banks are needed for the full rate, which is 8 banks for \(\tau=6\) if \(n_{\mathrm{b}}\) is a power of two. The table also shows the failure that the lecture does not mention. At stride 8 with 8 banks, \(\gcd(8,8)=8\), so \(\kappa=1\): every request goes to bank 0, and the rate is 0.167, the rate of a single bank. A power-of-two stride on a power-of-two number of banks defeats interleaving. The same arithmetic, with sets in place of banks, defeats caches in the section on the cache and is the cause of the 4.5-fold slowdown of the 512-column matrix in the lead. Interleaving raises the throughput of independent requests. It does not shorten the latency of one request, which is why it does not appear in the pointer-chase measurement.

Remedy 2: wider paths. The second remedy keeps the access time and moves more bits per access. The lecture's example is the Pentium, a 32-bit processor with a 64-bit data path to memory, which fetches two words per cycle (W2L5 8:16). The bandwidth of a path is its width in bytes times the number of transfers per second, so doubling the width doubles the bandwidth of a stream. It does not change the time of a single dependent access. The Intel ARK page of this machine lists "Max # of Memory Channels: 2", which is the same remedy applied to the channels: the processor reaches memory over two independent paths. A program uses the added bandwidth only if it keeps enough accesses in flight, a condition that the section on hit rate states with Little's law. The third remedy, the cache, is the subject of the remaining sections of the single-processor part.

Locality, reuse distance and the memory hierarchy W2L5 9:52

The lecture states the requirement (W2L5 4:00): programmers want an unlimited amount of fast memory, fast memory is costly, and an all-SRAM memory is unviable because of its power and price. It then observes that programs show a principle of locality (W2L5 5:01) and that a memory system can use it to appear both fast and large. The slide (W2L5 17:15) gives two kinds. Temporal locality: a referenced location is likely to be referenced again in the near future. Spatial locality: a referenced location makes a nearby location likely to be referenced in the near future. The loop-counter example of the lecture (the variable \(i\) is accessed in every iteration) is temporal locality, and the array example (consecutive elements are accessed one after another) is spatial locality.

Denning (2005, p. 23) records how locality was defined from 1980: an object \(x\) is in the locality set at time \(t\) if its distance \(\delta(x,t)\) from the processor (written \(D(x,t)\) in the article) is at most a threshold \(T\), where the distance can be a time (the time since the last reference) or a space (the number of addresses away). The definition makes both kinds of locality quantities that can be measured. This chapter counts the time distance in lines.

Reuse distance. Let a trace of line numbers be \(\ell_1,\ell_2,\dots\). For the access \(t\) let \(u\lt t\) be the previous access to the same line, \(\ell_u=\ell_t\). The reuse distance \(d_t\) is the number of distinct lines among \(\ell_{u+1},\dots,\ell_{t-1}\); if there is no such \(u\), then \(d_t=\infty\). Temporal locality is a small reuse distance. Spatial locality appears as reuse distance 0, because two consecutive accesses to neighbouring words of one line are two accesses to one line. Once the unit is the line, one number carries both kinds.

Theorem 1 (stack property, after Mattson et al. 1970). In a fully associative cache of \(C\) lines with LRU replacement, starting empty, the access \(t\) hits if and only if

\[ d_t \lt C. \tag{7.3} \]

Proof. Keep a list, the stack, of all lines used so far, ordered from the most recently used to the least recently used. The claim is that the cache holds exactly the first \(C\) entries of the stack. It is true at the start (both are empty). Suppose it is true before access \(t\) to the line \(\ell\). If \(\ell\) is among the first \(C\) entries, the access hits, the cache does not change, and moving \(\ell\) to the front permutes only the first \(C\) entries among themselves, so the claim stays true. If \(\ell\) is deeper in the stack or absent, the access misses, the cache removes its least recently used line, which is the entry number \(C\) of the old stack, and inserts \(\ell\); these are the first \(C\) entries of the new stack, because \(\ell\) moves to the front and the old entry number \(C\) moves to position \(C+1\). It remains to locate \(\ell\) in the stack. Exactly the distinct lines used since the previous use of \(\ell\) stand in front of it, so \(\ell\) is at depth \(d_t+1\), and it is among the first \(C\) entries if and only if \(d_t+1\le C\). \(\square\)

The theorem says that a cache of \(C\) lines turns every access with a reuse distance below \(C\) into a hit and every other access into a miss. The proof uses full associativity (one stack for the whole cache) and LRU. For a set-associative cache the same argument applies to each set separately, with \(C=a\) and with the reuse distance counted only over lines of that set; the next section uses this form. A real processor may use a different replacement policy, so the theorem is exact for the model and approximate for the hardware.

The program checks the theorem. It builds the trace of two sweeps over a \(32\times32\) matrix of doubles (8 KiB, 128 lines), once in row order and once in column order, computes every reuse distance with a stack, simulates a fully associative LRU cache directly with an ordered dictionary for five capacities, and compares the number of hits with the number of accesses whose distance is below \(C\). The program is deterministic, so the check is exact.

"""Reuse distance and LRU: an access hits in a fully associative LRU cache of C lines iff its reuse distance is below C.

Trace: two sweeps over a 32 x 32 matrix of doubles (8 KiB = 128 lines of 64 bytes), summed in row order or column order.
The reuse distance of an access is the number of distinct other lines used since the previous use of its line.
"""
from collections import OrderedDict

N, SWEEPS = 32, 2
INF = float("inf")


def trace(order):
    lines = []
    for _ in range(SWEEPS):
        for outer in range(N):
            for inner in range(N):
                i, j = (outer, inner) if order == "row" else (inner, outer)
                lines.append((i * N + j) * 8 // 64)
    return lines


def reuse_distances(lines):
    stack, result = [], []                 # stack[0] is the most recently used line
    for line in lines:
        if line in stack:
            k = stack.index(line)          # k distinct lines were used since the last use of this line
            result.append(k)
            stack.pop(k)
        else:
            result.append(INF)             # first use: infinite reuse distance
        stack.insert(0, line)
    return result


def lru_hits(lines, capacity):
    cache, hits = OrderedDict(), 0
    for line in lines:
        if line in cache:
            hits += 1
            cache.move_to_end(line)
        else:
            if len(cache) == capacity:
                cache.popitem(last=False)  # evict the least recently used line
            cache[line] = True
    return hits


print(f"{'order':>5} {'C':>4} {'LRU hits':>9} {'distance < C':>13}  agree")
for order in ("row", "col"):
    lines = trace(order)
    dist = reuse_distances(lines)
    for capacity in (16, 31, 32, 127, 128):
        simulated = lru_hits(lines, capacity)
        predicted = sum(d < capacity for d in dist)
        print(f"{order:>5} {capacity:4d} {simulated:9d} {predicted:13d}  {simulated == predicted}")
    finite = sorted({d for d in dist if d != INF})
    print(f"{order:>5} distinct finite reuse distances: {finite}, first uses: {sum(d == INF for d in dist)}")

All ten pairs agree. The row-order trace has two reuse distances: 0 (for the 7 of every 8 accesses that use the line fetched by the previous one) and 127 (for the second sweep, after all other 127 lines). It has 128 first uses. It therefore has 1792 hits for every capacity from 1 to 127 (7/8 of 2048 accesses) and 1920 at \(C=128\), when the second sweep also hits. The column-order trace has the distances 31 and 127. The distance 31 arises because the access to \(A_{ij}\) with \(j\bmod8\ne0\) uses the line used by \(A_{i,j-1}\), and between the two accesses the loop touched the 31 other lines of a column. The column order has 0 hits at \(C=16\) and \(C=31\) and 1792 at \(C=32\). For a matrix of \(N\) rows the distance is \(N-1\), so the column-order sum reuses lines if and only if \(C\ge N\). The cache that is large enough for the column sweep must hold the \(N\) lines that the inner loop touches, which is the working set of that loop in Denning's sense (the distinct items referenced in a window of the recent past). For the L1d of this machine, \(C=768\), so Theorem 1 predicts that the column-order sum of a matrix with \(N\ge769\) misses on every access in a fully associative L1d. A 1000 × 1000 matrix is such a case.

The hierarchy. The lecture's slide (W2L5 9:52, picture at W2L5 12:04) draws seven levels: registers (level 0), L1, L2 and L3 caches, main memory, local hard disk and remote storage. Each level holds the units retrieved from the level below it: registers hold words from the L1 cache, the caches hold lines, main memory holds blocks from the local disk, and the local disk holds files from remote servers. Towards the processor the levels are smaller, faster and costlier per byte. The goal is to provide the capacity of the cheapest level, with the speed of the fastest level for the accesses that hit in it. The slide labels the registers as level 0 of the hierarchy. This chapter does not treat them as a cache: the compiler assigns values to registers, while a cache holds lines without any instruction naming it, which is the property that makes the effect of caches visible only as time. The lecture also says that the levels from the registers to the L3 cache are SRAM, which agrees with the cost argument of the previous section.

The hierarchy can be measured with a program whose accesses cannot overlap. In a pointer chase the loaded value is the address of the next load. The program below allocates \(n\) lines, stores in each line the index of the next line along one random cycle through all lines (Sattolo's shuffle with a fixed seed), and times \(3\times10^{6}\) to \(2\times10^{7}\) dependent loads for working sets from 4 KiB to 128 MiB. /* Pointer chase: every load needs the address returned by the previous load, so loads cannot overlap. */
static uint64_t state = 88172645463325252ULL;
static uint64_t next_random(void)            /* xorshift64, fixed seed */
{
    state ^= state << 13; state ^= state >> 7; state ^= state << 17;
    return state;
}

/* ns per dependent load over one random cycle through all 64-byte lines of a working set. */
static double chase(size_t bytes)
{
    size_t n = bytes / 64;                              /* one pointer per line */
    size_t *order = malloc(n * sizeof *order);
    size_t *next = aligned_alloc(64, n * 64);
    for (size_t i = 0; i < n; i++) order[i] = i;
    for (size_t i = n - 1; i > 0; i--) {                /* Sattolo's shuffle: one cycle through all lines */
        size_t j = next_random() % i;
        size_t t = order[i]; order[i] = order[j]; order[j] = t;
    }
    for (size_t i = 0; i < n; i++)
        next[order[i] * 8] = order[(i + 1) % n] * 8;    /* word index of the next line */

        double t = omp_get_wtime() - t0;

    }
    if (p == (size_t)-1) printf("never\n");             /* keeps the loop alive */
    free(order); free(next);
    return best * 1e9 / loads;
}

Inside a cache: lines, tags, sets and the conflict capacity W2L5 13:46

The lecture describes the cache as a small, fast buffer between the processor and main memory that holds copies of portions of main memory. When the processor asks for a word, its address is checked in the cache. If the word is present, it is returned at once. If it is not, the cache controller sends the address to main memory, which answers with a block, a few 32-bit words in the lecture's example, and the neighbouring words are brought in because they are likely to be accessed next (W2L5 15:25). A cache has three parts (slide at W2L5 18:38): a directory store with one tag per line that records where in main memory the line came from, a data section, and status bits, among them a valid bit and a dirty bit. The picture of the lecture (W2L5 19:42) shows lines with the tags 100, 300 and 580, each holding the words that start at that address. The cache controller is hardware that copies the information automatically and intercepts reads and writes before they reach the memory controller; it works without any involvement of the processor or the software (W2L5 21:15). The lecture's read algorithm (W2L5 22:23) is: look at the address, search the tags; on a match return the data (a hit); otherwise read a line from main memory, return the data to the processor and update the cache, which raises the question "which line do we replace?". The lecture names the mapping schemes (direct mapped, \(n\)-way set associative, fully associative) and states that there is no time to treat them (W2L5 23:29). This section develops what the lecture omits, because the mapping scheme decides the miss rate in the lead.

The size of the line. The lecture's example block is a few words. Drepper (2007, §3.2, p. 15) states that early caches had lines of 32 bytes and that "nowadays the norm is 64 bytes"; the machine of this chapter reports 64 bytes (session in the first section), which is 16 words of 32 bits or 8 doubles. The size can be observed. The program below reads every \(\sigma\)-th double of a 128 MiB array with four independent sums, for \(\sigma=1,2,4,\dots,64\), and prints the time per element that it touches. If a miss fetches a whole line of 8 doubles, the number of lines fetched per touched element is \(\sigma/8\) for \(\sigma\le8\) (every line is touched, and \(8/\sigma\) touched elements share it) and 1 for \(\sigma\ge8\) (each touched element is in a line of its own). A cost that is proportional to the lines fetched therefore grows in proportion to \(\sigma\) up to \(\sigma=8\), the doubling of the time per element with each doubling of the stride, and then stays constant. The knee of the curve at \(\sigma=8\) measures the line size: \(8\times8\ \mathrm{B}=64\ \mathrm{B}\). The run is checked by its return code, and the output is one sample.

Status bits and the tag. The valid bit says that a line holds data (after power-up every line is invalid). The dirty bit says that the line has been written and that the next level has not been updated. The lecture associates the dirty bit with "non-coherency" in multiprocessor systems; Drepper (2007, §3.2, p. 16) defines it more generally: a line that "has been written to and which has not been written back to main memory is said to be dirty". A dirty line therefore exists in a single-processor machine whenever the cache is write-back, and the bit is a property of the write policy; the next-but-one section returns to it. The reason for a line, and not a word, as the unit is the tag: for a 32-bit word the tag "might need 32 bits or more" (Drepper, p. 15), an overhead of 100 % or more, whereas a line of 64 bytes carries one tag. For an address of \(w_a\) bits, a line of \(b=2^{o}\) bytes and \(S=2^{s}\) sets, the tag has \(w_a-s-o\) bits. For the L1d of this machine (\(o=6\), \(s=6\)) and an assumed address width of \(w_a=40\) bits, the tag has 28 bits per 512 bits of data, an overhead of 5.5 %; the processor's actual physical address width was not determined.

Address decomposition and associativity. The model of the first section fixes where a line may go. For \(b=2^{o}\) and \(S=2^{s}\), the low \(o\) bits of an address are the offset in the line, the next \(s\) bits are the set index and the remaining bits are the tag (Drepper, §3.2, pp. 15–16). The size of the cache is

\[ M=b\,a\,S\quad\text{bytes},\qquad C=aS\ \text{lines}. \tag{7.4} \]

The extreme designs differ in the number of tag comparisons per lookup. A fully associative cache compares the address tag with the tags of all \(C\) lines. Drepper (§3.3.1, pp. 17–18) works out that a 4 MB cache with 64-byte lines has 65 536 entries and that full associativity is "practical for small caches" only, a few dozen entries at most, such as the translation lookaside buffers of some processors. A direct-mapped cache (\(a=1\)) needs one comparator and is fast, but "only works well if the addresses used by the program are evenly distributed" over the index bits. A set-associative cache compares \(a\) tags in parallel and is the compromise. Drepper's measurement of a compiler run (Table 3.1, p. 19) shows the misses falling with associativity, and he states that for an 8 MB cache "going from direct mapping to 2-way set associative cache saves almost 44% of the cache misses" and that above 8 ways the gain is small for a single thread (p. 19). The guest reports 12, 10 and 8 ways for the L1d, L2 and L3 of this machine.

The conflict capacity. Associativity matters for the running case through the following lemma. Consider a loop that reads \(K\) lines at line numbers \(\ell_0,\ell_0+\sigma,\dots,\ell_0+(K-1)\sigma\), with the stride \(\sigma\) a whole number of lines, and then reads them again in the same order. The column-order sum has this form, with \(K=N\) and \(\sigma=N/8\) when \(N\) is a multiple of 8, because the next column reads the same lines again for 7 of every 8 columns.

Lemma 2 (conflict capacity). In an LRU cache with \(S\) sets and \(a\) ways, every access of the second and later passes over \(K\) lines of stride \(\sigma\) lines hits if and only if

\[ K\le C_{\mathrm{eff}}(\sigma)=\frac{a\,S}{\gcd(S,\sigma)}. \tag{7.5} \]

Proof. The set index of line \(\ell_0+k\sigma\) is \((\ell_0+k\sigma)\bmod S\). As \(k\) increases, this index repeats with the period \(q=S/\gcd(S,\sigma)\): the multiples of \(\sigma\) modulo \(S\) are the elements of the subgroup of the integers modulo \(S\) generated by \(\sigma\), and that subgroup has \(q\) elements. The \(K\) lines are therefore spread in turn over \(q\) sets, and the fullest set receives \(\lceil K/q\rceil\) of them. Within one set the lines are read in the same cyclic order in every pass, so each access has a reuse distance, counted over the lines of the set, equal to the number of lines of that set minus one. By Theorem 1 applied to the set (capacity \(a\)), the accesses to a set hit if and only if the set receives at most \(a\) lines. Every set receives at most \(a\) lines if and only if \(\lceil K/q\rceil\le a\), which is \(K\le aq\). \(\square\)

Equation (7.5) explains the lead. For the L1d (\(a=12\), \(S=64\)) and \(N=512\): \(\sigma=64\) lines, \(\gcd(64,64)=64\), so \(C_{\mathrm{eff}}=12\) lines. All 512 lines of a column fall into one set, which holds 12, and the column-order sum misses on every access although the 512 lines would fit in the 768 lines of the L1d. For \(N=1024\), \(\sigma=128\), the capacity is again 12. For \(N=1000\), \(\sigma=125\) and \(\gcd(64,125)=1\), so \(C_{\mathrm{eff}}=768\), and \(N=1000\gt768\) is a capacity miss, predicted by Theorem 1 as well. In the L2 (\(a=10\), \(S=2048\)), \(N=512\) gives \(\gcd(2048,64)=64\) and \(C_{\mathrm{eff}}=10\times32=320\lt512\): the L2 misses too. For \(N=1000\) the L2 has \(C_{\mathrm{eff}}=20480\ge1000\) and hits. The classification of the misses follows Kelly's lecture notes (after Hennessy and Patterson): a compulsory miss is a miss in an infinite cache, a capacity miss is a miss in a fully associative cache of the same size, and a conflict miss is a miss in the \(a\)-way cache that is a hit in the fully associative cache of the same size. The 512-column matrix suffers conflict misses (a fully associative L1d would hit, since \(512\le768\)), and the 1000-column matrix suffers capacity misses. For \(N=500\) the row length is 4000 bytes, which is 62.5 lines, not a whole number, so the lemma does not apply directly; the rows spread over the sets nearly evenly and the prediction is that the sum behaves like a fully associative cache.

"""Trace-driven simulation of a 3-level LRU cache hierarchy on row-order and column-order matrix sums.

Geometry: the sizes, associativities and 64-byte lines that the WSL guest reports for this machine.
Every level uses LRU replacement inside a set. A level is consulted only when the level above misses.
Only reads are simulated (the matrix sum reads each element once).
"""
LINE = 64
LEVELS = [("L1d", 48 * 1024, 12), ("L2", 1280 * 1024, 10), ("L3", 12 * 1024 * 1024, 8)]


class Cache:
    def __init__(self, size, ways):
        self.ways = ways
        self.sets = size // (ways * LINE)    # cache size = line size x associativity x number of sets
        self.rows = [[] for _ in range(self.sets)]   # one list of line numbers per set, LRU first
        self.misses = 0

    def access(self, line):
        row = self.rows[line % self.sets]    # set index = line number mod number of sets
        if line in row:
            row.remove(line)
            row.append(line)
            return True
        self.misses += 1
        if len(row) == self.ways:
            row.pop(0)                       # evict the least recently used line of the set
        row.append(line)
        return False


def simulate(n, order):
    caches = [Cache(size, ways) for _, size, ways in LEVELS]
    last, accesses = -1, 0
    for outer in range(n):
        for inner in range(n):
            i, j = (outer, inner) if order == "row" else (inner, outer)
            line = (i * n + j) * 8 // LINE
            accesses += 1
            if line == last:                 # the line of the previous access is in L1: a hit
                continue
            last = line
            for cache in caches:
                if cache.access(line):
                    break
    return accesses, [c.misses for c in caches]

The lecture measures the efficiency of a cache by the hit rate, the number of cache hits divided by the number of memory requests (times 100 for a percentage), counted over read hits, write hits or both, and it names two further quantities, the hit time and the miss penalty (slide at W2L5 24:15). It adds that the cost can be stated in cycles for a hit and for a miss. The three quantities combine into one number, the average memory access time. Kelly's lecture notes, which follow Hennessy and Patterson (6th edition, appendix B.3, p. B-22), write it as \(\mathrm{AMAT}=t_h+m_r t_m\). The derivation is short. Every access pays the hit time \(t_h\), because the cache is searched first. The fraction \(m_r\) of the accesses misses and pays the miss penalty \(t_m\) in addition. The expected time of an access is (7.1). For a hierarchy of caches the miss penalty of one level is the average access time of the next, so with the local miss rates \(m_1,m_2,m_3\) (misses of a level divided by the accesses that reach it), the hit times \(t_1,t_2,t_3\) of the three cache levels (the time that consulting a level adds) and the memory time \(t_{\text{mem}}\) (the time that a memory access adds),

\[ \mathrm{AMAT}=t_1+m_1\bigl(t_2+m_2\,(t_3+m_3\,t_{\text{mem}})\bigr). \tag{7.6} \]

The sensitivity to the miss rate follows from (7.1): \(\partial\,\mathrm{AMAT}/\partial m_r=t_m\). With the hit time of 1.2 ns and the DRAM latency of about 130 ns that the pointer chase measured (the fifth run: 129 to 132 ns for 16 to 64 MiB), one percentage point of miss rate adds 1.3 ns, which is more than the hit time itself. A miss rate of 0.125, the compulsory rate of the row-order sum, gives \(1.2+0.125\times130=17.5\) ns, 14.5 times the hit time. For a dependent chain of loads, the model is exact by construction: in the pointer chase at 128 KiB all loads are served by the L2 (Theorem 1) and the average time is the L2 service time, 3.7 ns in the fifth run. That is a check of the bookkeeping, not of the model's reach.

Where the model fails. The sum loop gives a test that is not circular. At \(N=4096\) the simulator and Lemma 2 predict that the row-order sum misses once per line, \(m_r=0.125\), and the column-order sum misses on every access, \(m_r=1\), with the misses served by DRAM in the model (for the column order at \(N=4096\): \(\sigma=512\) lines, \(C_{\mathrm{eff}}=12\), 40 and 384 lines in L1, L2 and L3 under the modulo mapping, against 4096 lines needed). Equation (7.1) with \(t_h=1.2\) ns and \(t_m=130\) ns predicts 17.5 ns per element for the row order and 131 ns for the column order. The sample shows 0.79 ns and 13.8 ns (table below), which is 22 and 9.5 times shorter. The model also fails for loops that always hit: for \(N=250\) and 500 the sum takes 0.46 to 0.50 ns per element, 2.4 to 2.6 times less than the hit time of 1.2 ns. The assumption that fails is the one in the derivation: each access completes before the next one starts. The latency \(t_h\) of 1.2 ns is the time of a load whose address depends on the previous load. In the sum loop the loads are independent of each other; only the additions form a chain, and the processor can have many loads in flight while the additions wait. A latency model describes dependent accesses. For independent accesses the quantity that limits the loop is a rate.

Little's law connects the two. A system that completes \(X\) accesses per second with a latency of \(L\) seconds each has on average \(\lambda=XL\) accesses in flight. Let a loop produce \(\mu\) line misses per element, each with a latency \(L\), and let \(c\) be the average number of misses in flight. Then misses complete at the rate \(c/L\) and the time per element cannot be less than

\[ t_{\text{elt}}\ \ge\ \max\Bigl\{t_{\text{add}},\ \frac{\mu L}{c}\Bigr\}, \tag{7.7} \]

where \(t_{\text{add}}\) is the time per element of the dependent chain of additions (0.46 ns in the sample, the value for the matrices that fit in the L1 or L2 cache). The bound (7.7) is not a prediction, because \(c\) is not known in advance. Solved for \(c\), it gives the average concurrency that a measurement implies. For the row-order sum at \(N=4096\), \(\mu=1/8\), \(L=130\) ns and \(t_{\text{elt}}=0.79\) ns, so \(c=0.125\times130/0.79=20.6\) lines in flight; the loop reads 8 bytes per 0.79 ns, 10.1 GB/s from a single thread. For the column-order sum, \(\mu=1\) and \(t_{\text{elt}}=13.8\) ns, so \(c=130/13.8=9.4\). This value assumes that every column miss goes to DRAM, which holds only for the modulo-mapped L3 of the simulator. A hashing L3 of 12 MiB can hold the 256 KiB of one column between passes; if it does, \(L\) is the L3 latency, which the pointer chase did not measure, and the implied concurrency is \(L_3/13.8\) ns, lower than 9.4. These are implied averages under the assumption that every miss waits 130 ns for DRAM. They are not measured concurrencies. The sources opened for this chapter do not describe the hardware prefetchers or the limit of the processor on outstanding misses, and the chapter does not separate the contribution of the out-of-order execution of the loop from that of the prefetchers. The row-order stream moves 8 bytes per 0.79 ns; whether the 10.1 GB/s is a bandwidth limit of the memory system or of a single thread was not determined, and the treatment of bandwidth-bound loops, with the STREAM benchmark and the roofline model, belongs to chapter 10.

Writes, coherence and snooping W2L5 24:38

The lecture states the coherency problem in three sentences (slide at W2L5 25:15). It arises when the data in a cache differ from the data in main memory, so that one of them is stale. It concerns systems in which more than one entity uses the memory, such as multiprocessors, and not a single processor. It is avoided by a write-through policy, in which main memory is updated whenever the processor updates the cache, together with snooping: the cache controller of one processor watches the memory bus for writes to locations that it holds in its cache and updates the cache when required. The lecture does not treat write-back caches, and the earlier statement that the dirty bit "indicates non-coherency" belongs to them. This section separates the write policy from coherence and counts what each costs.

Write policies. A write-through cache sends every store to the next level at once, so the cache and the memory never differ and a line can be discarded at any time. A write-back cache changes only its own copy, sets the dirty bit, and writes the line to the next level when it evicts it. Drepper (2007, §3.3.3, p. 25) calls write-through "the simplest way to implement cache coherency" and "not very fast", since a program that changes a local variable over and over would send the traffic of every change to the bus, and write-back "significantly better performing, which is why most memory in a system with a decent processor is cached this way". A store to a line that is not resident first loads the line, because no instruction changes a whole line at once (Drepper, §3.2, p. 16). In a write-back cache a line that differs from memory is normal, in a single-processor machine too. The dirty bit records this, and it is not a sign of incoherence.

Coherence. Coherence is a property of several caches: the processors must not see different values for the same location. Drepper (2007, §3.2, p. 16) states the rules that a coherent set of caches maintains: "A dirty cache line is not present in any other processor's cache" and "Clean copies of the same cache line can reside in arbitrarily many caches". A cache line is thus either modifiable in exactly one cache or readable in many, and the line, not the word, is the unit. The protocol that implements the rules in most processors is MESI (Drepper, §3.3.4, pp. 25–26). Each line in each cache is in one of four states: modified (changed locally, the only copy), exclusive (unchanged, known to be the only copy), shared (unchanged, possibly in other caches) and invalid. Each cache snoops the requests of the others. Table 7.2 lists the transitions that Drepper describes.

def run(ops, cores=2):

    for core, op in ops:
        others = [c for c in range(cores) if c != core]
        if op == "R":
            if state[core] == "I":
                bus_reads += 1
                if any(state[c] == "M" for c in others):
                    transfers += 1                        # the owner sends the line; memory is updated

                for c in others:

                        state[c] = "S"

                ownership += 1
                if any(state[c] == "M" for c in others):
                    transfers += 1                        # the owner sends the line and becomes invalid
                for c in others:
                    state[c] = "I"
            state[core] = "M"                              # E -> M is silent: no bus transaction
        # invariant: a modified or exclusive copy is the only valid copy
        assert not (any(s in "ME" for s in state) and sum(s != "I" for s in state) > 1), state
    return writes, bus_reads, ownership, transfers

Shared memory: SMP, UMA and NUMA W2L5 26:22

The lecture recalls the multiple-instruction, multiple-data (MIMD) machine of the previous lecture and asks how its memory is implemented. There are two ways: shared memory, also called tightly coupled, with the variants SMP and NUMA, and distributed memory, also called loosely coupled, of which the cluster is the example. The slide on symmetric multiprocessing (SMP, W2L5 26:56) defines it as a stand-alone computer with two or more processors of comparable compute power that share the same memory and input-output facilities, are connected by a bus or another interconnection scheme "such that memory access time for all processors is almost the same", can all perform the same function, and are controlled by one integrated operating system. The block diagram shows processors with private caches on a shared bus that leads to one main memory and to the input-output adapters. The slide on non-uniform memory access (W2L5 29:05) defines uniform memory access (UMA) by two equalities, the access time of a processor is the same for all parts of memory and is the same for different processors, calls SMP "a type of UMA architecture", and defines NUMA as the case in which every processor reaches all of main memory but with an access time that depends on the part accessed, so that for each processor a different region is fast and a different region is slow. The slide "Why NUMA is needed" (W2L5 31:17) gives the reason: SMP has a practical limit on the number of processors and the amount of memory, set by "electrical/PCB design constraints", "typically 64 processors maximum, most expensive machines around"; NUMA keeps the flat address space and the single operating-system image and extends the limit "to hundreds to thousands of physical processors/cores", with "SGI's Altix ICE 8400 (> 64K cores)" as the example. The picture (W2L5 31:50) shows two nodes, each with a processor and local memory, joined by an inter-socket connection, with local access to the memory of the same node and remote access to the other, and a server board with four processors and one memory per processor.

The cost of non-uniformity. The definitions of the first section make the lecture's statement quantitative. Let \(t_{\text{loc}}\) be the time of a miss served by the memory of the processor's own node and \(t_{\text{rem}}\) the time of a miss served by another node. The ratio \(\rho=t_{\text{rem}}/t_{\text{loc}}\) is the NUMA factor (Drepper 2007, §5.1, pp. 42–43). If a fraction \(r\) of the misses of a processor go to remote memory, the average miss time is the weighted mean

\[ \bar t=(1-r)\,t_{\text{loc}}+r\,\rho\,t_{\text{loc}}=t_{\text{loc}}\bigl(1+r(\rho-1)\bigr). \tag{7.8} \]

For an assumed factor \(\rho=1.5\) (an illustrative value, not a measurement), a processor with no remote accesses has \(\bar t=t_{\text{loc}}\), one with half of its misses remote has \(1.25\,t_{\text{loc}}\), and one with all its misses remote has \(1.5\,t_{\text{loc}}\). The lecture states "which region is fast and which is slow is different" for each processor; (7.8) shows that the program, through \(r\), decides how much of the difference it pays. The value of \(\rho\) depends on the machine. Drepper (§5.1, p. 43) describes the large shared-memory machines of SGI as making a "reasonably low" factor possible but, with several thousand processors and a limited interconnect capacity, as having a factor that is "dynamic and can reach unacceptable levels depending on the workload".

The operating system decides \(r\) when it places the pages of an array. The Linux kernel documentation (NUMA memory policy) states that the system default policy, once the system is running, is "local allocation": a page is allocated on the node of the processor on which the allocation takes place (during boot the default interleaves allocations across the nodes). Linux allocates the physical page when a process first touches it (the author's statement of demand paging; the policy document speaks of "page allocations"), so under this policy the thread that first touches a page decides its node. A matrix initialised by one thread lies entirely on that thread's node, and in the parallel sum every thread on another node has \(r=1\). Initialising the matrix with the same thread-to-block assignment as the later loops gives \(r\approx0\). Drepper (§5.2, p. 44) describes the default of 2007 differently: the memory was striped over all nodes ("by default, not allocated exclusively on the local node"). The two statements concern different kernel versions, and a reader of a current kernel should rely on the documentation, not on the 2007 text. The kernel documentation also lists other policies that a process may select; the chapter does not use them.

The limit of the bus. The lecture's argument for the limit of an SMP is electrical. A bandwidth argument gives the same limit from the quantities of this chapter. Let a shared bus (or a single memory controller) deliver at most \(B_{\text{bus}}\) bytes per second to the \(p\) processors, and let one processor, running its program, demand \(g\) bytes per second from memory (the line size times its miss rate times its rate of accesses). While \(pg\le B_{\text{bus}}\) each processor receives \(g\), and when \(pg\gt B_{\text{bus}}\) each receives at most \(B_{\text{bus}}/p\). The bus saturates at \[ p^{*}=\frac{B_{\text{bus}}}{g}\tag{7.9} \] processors. Caches act on \(g\): by (7.1) and the definition of the miss rate, a program with a higher hit rate has a smaller \(g\) and a larger \(p^{*}\), so the processor caches of the lecture's block diagram are what makes a shared bus usable at all. For an illustration, the row-order sum of this chapter reads 10.1 GB/s from one thread; a bus that supplies four times that, 40 GB/s, saturates at \(p^{*}=4\) such threads, while the same threads working in cache (the 0.46 ns per element of Table 7.1) would demand almost no bus. The value \(B_{\text{bus}}\) of this machine was not measured and the peak memory bandwidth was not determined, so the numbers illustrate the saturation arithmetic of (7.9) and are not a measurement. Drepper measured the effect on a four-processor machine with one shared bus (§3.3.4, p. 27): four threads that only read were up to 34 % slower than one, and four threads that increment were up to 93 % slower, the effect that the previous section quoted. The lecture's "64 processors" is a claim about a class of expensive machines; no source opened for this chapter states it, and the bandwidth limit above shows only that some limit exists, not its value.

Clusters, the interconnect and the cost of distance W2L5 32:26

The lecture defines a cluster as a switching fabric, a fast network of high bandwidth, that connects \(n\) compute nodes, each of which is itself a multiprocessor, NUMA or SMP. It lists four benefits (slide at W2L5 33:15): extreme scalability, thousands of machines; incremental scalability, nodes can be added as the need grows (for example, a cluster of 100 nodes can be extended by 100 more); high availability, since the failure of a node "does not affect overall loss of service" and software can handle the fault tolerance; and superior price and performance, since commodity building blocks give the compute power of a single large machine "at a much lower cost". The slide on the attributes of the network (W2L5 34:02) states that its objective is to move data from the memory of one node to the memory of another. Bandwidth is the amount of data transferred per unit time and depends on the raw data rate of the physical layer (the lecture adds that it is set by the speed of the link from the node to the switch). Latency is "time taken for a packet to reach destination from source", which matters for many small messages and for processors that wait for control and synchronisation messages. The last attribute is offloading: the network interface card takes over the transfer, the check of correctness and the retransmission, which frees the host processor for computation. The lecture closes by stating that the cluster is the most common architecture of supercomputers because of its scalability and cost effectiveness (W2L5 35:39).

The message model. In distributed memory the data of another node arrive in a message. The time of a message of \(m\) bytes is modelled as

\[ T_{\text{msg}}(m)=\alpha+\beta m, \tag{7.10} \]

with the latency \(\alpha\) and the inverse bandwidth \(\beta\) (the bandwidth is \(1/\beta\)). The rate that a message of \(m\) bytes achieves is \(m/T_{\text{msg}}(m)=\beta^{-1}\,m/(m+\alpha/\beta)\), which reaches half of the bandwidth at the message size \(m_{1/2}=\alpha/\beta\): then \(T_{\text{msg}}=2\alpha\) and the rate is \(m_{1/2}/(2\alpha)=1/(2\beta)\). Messages much shorter than \(m_{1/2}\) take about \(\alpha\) and are limited by latency; messages much longer take about \(\beta m\) and are limited by bandwidth. This is the lecture's statement that latency matters for small messages and bandwidth for large amounts of data, with a number attached. Chapter 14 fits \(\alpha\) and \(\beta\) from a ping-pong measurement; this chapter uses assumed values for a 100 Gbit/s link, \(\alpha=1.5\ \mu\mathrm{s}\) and \(1/\beta=12.5\ \mathrm{GB/s}\), which are illustrations and not measurements of any system. Then \(m_{1/2}=18.75\) KB. One double (8 bytes) takes \(1.5\ \mu\mathrm{s}\), a rate of 5.3 MB/s, 0.04 % of the bandwidth; a message of 1 MB takes \(1.5+80=81.5\ \mu\mathrm{s}\), a rate of 12.3 GB/s, 98 % of it. The latency of 1.5 µs is 11.5 times the DRAM latency of 130 ns that this chapter measured, so the memory of another node is one more level of the hierarchy, larger and slower than the local DRAM, and the locality arguments of the earlier sections apply to it with a larger penalty.

The matrix sum on \(p\) nodes. Distribute the \(N\times N\) matrix of the running case over \(p\) nodes by blocks of \(N/p\) rows. Each node sums its \(N^2/p\) elements at the row-order rate \(t_{\text{elt}}\), and the \(p\) partial sums are combined by a reduction in \(\lceil\log_2p\rceil\) rounds of one 8-byte message each (chapter 15 derives the reduction trees). If the data already lie distributed,

\[ T_p=\frac{N^2}{p}\,t_{\text{elt}}+\lceil\log_2p\rceil\,(\alpha+8\beta). \tag{7.11} \]

With \(N=4096\), the sample row-order time \(t_{\text{elt}}=0.79\) ns (one thread of this machine, standing for a node) and the assumed \(\alpha\) and \(\beta\): \(T_1=16\,777\,216\times0.79\ \mathrm{ns}=13.25\) ms; for \(p=64\), the compute time is 0.207 ms, the reduction is \(6\times(1.5\ \mu\mathrm{s}+0.64\ \mathrm{ns})=9.0\ \mu\mathrm{s}\), and \(T_{64}=0.216\) ms, a speedup of 61.3 and an efficiency of 0.96. The result depends on where the data are. If the matrix starts on one node, that node must send \((p-1)/p\) of its \(8N^2=134.2\) MB through its own link, and the time cannot be less than \(\tfrac{63}{64}\times134.2\ \mathrm{MB}\times\beta=10.57\) ms. Then \(T_{64}\ge10.57+0.207+0.009=10.79\) ms, a speedup of 1.23. Moving the data takes 80 % as long as summing them on one node. The cluster pays off only if the data are produced where they are used, which is the distributed-memory form of the first-touch rule of the previous section. The same arithmetic shows why the clusters of the lecture scale: each node brings its own memory system, so the aggregate memory bandwidth grows in proportion to \(p\), whereas the bandwidth of a shared bus is divided among the processors, (7.9).

Availability. The lecture's claim of high availability concerns a service that continues when a node fails. For independent node failures with exponentially distributed times and a mean time between failures \(\Theta\) per node, the failure rate of \(p\) nodes is \(p/\Theta\) and the system fails on average every \(\Theta/p\). For \(p=10\,000\) and an assumed \(\Theta=5\) years \(\approx43\,800\) h that is 4.4 h. A job whose processes depend on one another does not survive the loss of one of them unless the program has saved its state, so the claim holds for a service that moves work to another node and not for a tightly coupled job without checkpoints. The model and the value of \(\Theta\) are assumptions of this chapter.

Topology and bisection width. The lecture treats the network as one switching fabric. The shape of the fabric limits how much data can cross it, and a number summarises the limit. Remove links from a network of \(p\) nodes until it falls into two halves of \(p/2\) nodes. The smallest number of links that must be removed over all such splits is the bisection width \(\omega\). The program finds it by exhaustive search over all splits of 16 nodes for five topologies, together with the number of links and the diameter (the largest number of links on a shortest path between two nodes). The search is deterministic, and the check is exact. This subsection is an extension of the chapter's author: the lecture does not mention topologies.

"""Bisection width, diameter and link count of interconnection networks, by exhaustive search for 16 nodes.

Bisection width: the fewest links whose removal splits the nodes into two halves of equal size.
"""
from itertools import combinations
from collections import deque


def ring(n):
    return {frozenset((i, (i + 1) % n)) for i in range(n)}


def grid(rows, cols, wrap):
    edges = set()
    for r in range(rows):
        for c in range(cols):
            if c + 1 < cols or wrap:
                edges.add(frozenset((r * cols + c, r * cols + (c + 1) % cols)))
            if r + 1 < rows or wrap:
                edges.add(frozenset((r * cols + c, ((r + 1) % rows) * cols + c)))
    return edges


def hypercube(d):
    return {frozenset((v, v ^ (1 << b))) for v in range(1 << d) for b in range(d)}


def complete(n):
    return {frozenset(e) for e in combinations(range(n), 2)}


def bisection(n, edges):
    best = len(edges)
    for rest in combinations(range(1, n), n // 2 - 1):     # node 0 is always in the first half
        half = {0, *rest}
        best = min(best, sum((a in half) != (b in half) for a, b in map(tuple, edges)))
    return best


def diameter(n, edges):
    adj = {v: [] for v in range(n)}
    for a, b in map(tuple, edges):
        adj[a].append(b)
        adj[b].append(a)
    worst = 0
    for s in range(n):
        dist, queue = {s: 0}, deque([s])
        while queue:
            v = queue.popleft()
            for w in adj[v]:
                if w not in dist:
                    dist[w] = dist[v] + 1
                    queue.append(w)
        worst = max(worst, max(dist.values()))
    return worst


print(f"{'topology':<18} {'nodes':>5} {'links':>5} {'diameter':>8} {'bisection':>9}  formula for the bisection width")
cases = [

    ("4 x 4 mesh", 16, grid(4, 4, False), "sqrt(n) = 4"),
    ("4 x 4 torus", 16, grid(4, 4, True), "2 sqrt(n) = 8"),
    ("hypercube, d = 4", 16, hypercube(4), "n/2 = 8"),
    ("fully connected", 16, complete(16), "n^2/4 = 64"),
]
for name, n, edges, formula in cases:

The values agree with the formulas stated in the last column for \(p=16\): a ring has \(\omega=2\), a \(\sqrt p\times\sqrt p\) mesh \(\sqrt p\), the torus (the mesh with wrap-around links) \(2\sqrt p\), the hypercube \(p/2\) and the fully connected network \(p^2/4\). The program verifies \(p=16\) only; the formulas for other \(p\) are the standard ones and are not proved here. The cost grows with the bisection width: 16 links for the ring against 32 for the torus and the hypercube and 120 for the fully connected network, while the diameter falls from 8 to 4 and 1. A bound on the time of a communication pattern follows. If each node of one half sends \(m\) bytes to a node of the other half, \(pm/2\) bytes cross the cut. The cut has \(\omega\) links, each carrying \(1/\beta\) bytes per second in each direction, so

\[ T\ \ge\ \frac{p\,m\,\beta}{2\,\omega}. \tag{7.12} \]

For \(p=1024\), \(m=1\) MB and the assumed \(1/\beta=12.5\) GB/s, (7.12) gives 20.5 ms for a ring (\(\omega=2\)), 0.64 ms for a \(32\times32\) torus (\(\omega=64\)) and 0.08 ms for a hypercube of dimension 10 (\(\omega=512\)); the hypercube needs 5120 links and 10 per node, the torus 2048 links and 4 per node, and the fully connected network would need 523 776 links. Large clusters use another design, the fat tree. Al-Fares et al. (2008, §3, p. 66) show that a fat tree built from \(k\)-port switches connects \(k^3/4\) hosts, which is 27 648 hosts for \(k=48\), and they define the oversubscription of a network as the ratio of the worst-case aggregate bandwidth that the hosts can achieve to the total bisection bandwidth (§2.1, p. 64); a ratio of 1:1 means that every host can communicate with any other at the full rate of its interface. Bound (7.12) is a lower bound for one pattern. It ignores the latency that grows with the number of hops, the contention of several flows on one link and the routing that a real network uses. Chapter 10 treats the organisation of large systems, and chapter 16 uses \(\alpha\) and \(\beta\) for the halo exchange of a domain decomposition.

The models establish the following results. A fully associative LRU cache hits exactly when the reuse distance is below its capacity (Theorem 1, checked on ten cases of two traces). A set-associative cache retains a constant-stride pattern only up to \(aS/\gcd(S,\sigma)\) lines (Lemma 2), and this predicts the L1d miss rates of the row-order and column-order sums, as two simulators agree, and the direction of the L2 and L3 results. The average memory access time \(t_h+m_rt_m\) describes dependent accesses. For independent accesses the time per element is bounded below by \(\mu L/c\), and the concurrency \(c\) must be measured. The interleaved-bank rate is \(\min(1,\kappa/\tau)\). The mean latency under non-uniform memory access is \(t_{\text{loc}}(1+r(\rho-1))\). The message time is \(\alpha+\beta m\), and the bisection width of a network bounds the time of a pattern that crosses it. The coherence traffic of a line depends on how the writes of the cores alternate.

The models leave out much. Replacement is LRU; real processors use approximations of it that the opened sources do not specify, and a cyclic scan over one line more than the capacity defeats exact LRU entirely (exercise 3). The simulators model reads only, one line size, no hardware prefetch, no translation of virtual addresses (page tables and the translation lookaside buffer, which add time that grows with the working set), and no write traffic of the matrix sum. The L2 and L3 are indexed by virtual line number; the hardware L2 is physically indexed and the L3 hashes addresses over slices, so L2 and L3 results are directional. The coherence model has two cores and one line, snooping and no directory, and it says nothing about the order in which writes to different locations become visible (chapter 13). The overlap bound (7.7) has an unmeasured concurrency, and the chapter does not separate the out-of-order execution of the loop from the prefetchers.

The measurements have their own limits. They come from one machine, a hybrid processor in a virtual machine, with other jobs running; the thread may run on a performance core or an efficient core, so run-to-run variation is large (the ratio of column to row order at \(N=2048\) ranged from 10.7 to 19.1). The pointer chase does not show an L3 plateau, and the chapter has no explanation of it. The sizes and associativities are those that the guest reports, and the guest's view is synthetic. This machine has one NUMA node, so the NUMA factor was not measured and the NUMA section is a model plus documentation. The values \(\alpha=1.5\ \mu\mathrm{s}\), \(1/\beta=12.5\) GB/s, \(\rho=1.5\) and \(\Theta=5\) years are assumptions used for arithmetic, not data about any system, and the cluster results that depend on them (the speedups of 61.3 and 1.23, the bisection times, the system failure interval) are illustrations of the models. The topology program verifies \(p=16\) only. The hierarchy below the main memory (flash, disk, remote storage), virtual memory, high-bandwidth memories and the memory of accelerators are not treated: chapter 10 treats the memory wall, the STREAM measurement and the roofline model, chapter 21 the memory types of GPUs.

Exercise 1 (derive). An \(N\times N\) matrix of doubles with \(N=512\) is stored with a row length (leading dimension) of \(\mathrm{ld}\) doubles, \(\mathrm{ld}\ge N\), and is summed in column order. Take \(\mathrm{ld}\) to be a multiple of 8, so that the row stride is a whole number \(\sigma=\mathrm{ld}/8\) of 64-byte lines. (a) Use Lemma 2 to derive the condition on \(\sigma\) under which all 512 lines of a column survive in the L1d (\(a=12\), \(S=64\)) until the next column. (b) List the values of \(\mathrm{ld}\) between 512 and 576 that satisfy it. (c) Derive the corresponding condition for the L2 (\(a=10\), \(S=2048\)) and say which of the values of \(\mathrm{ld}\) from (b) and of \(\mathrm{ld}\in\{512,528,576\}\) satisfy it.

Solution

(a) Lemma 2 requires \(K=512\le aS/\gcd(S,\sigma)=768/\gcd(64,\sigma)\). The gcd of 64 with any integer is a power of 2, and \(768/2=384\lt512\), so the condition holds if and only if \(\gcd(64,\sigma)=1\): \(\sigma\) must be odd. (The condition \(N\le768\) of Theorem 1 is met.) (b) \(\mathrm{ld}=8\sigma\) with \(\sigma=65,\dots,72\) and \(\sigma\) odd gives \(\mathrm{ld}=520,536,552,568\). The even values fail: \(\sigma=66\) (\(\mathrm{ld}=528\)) has \(\gcd=2\) and \(C_{\mathrm{eff}}=384\); \(\sigma=68\) has 192; \(\sigma=72\) (\(\mathrm{ld}=576\)) has \(\gcd=8\) and 96; and \(\sigma=64\) (\(\mathrm{ld}=512\)) has 12. (c) For the L2, \(512\le10\times2048/\gcd(2048,\sigma)\) means \(\gcd(2048,\sigma)\le40\), that is, \(\gcd\le32\), so \(\sigma\) may be divisible by 32 but not by 64. \(\sigma=64\) (\(\mathrm{ld}=512\)) has \(\gcd=64\) and fails, with \(C_{\mathrm{eff}}=320\). \(\sigma=66\) (528) has \(\gcd=2\) and \(\sigma=72\) (576) has \(\gcd=8\); both pass, with 10240 and 2560 lines. In the L1 only \(\mathrm{ld}=520\), 536, 552 and 568 keep the column; in the L2 every \(\mathrm{ld}\) of the list except 512 does. The prediction for a column-order sum of the four values 512, 520, 528 and 576 is therefore: 512 is served by the L3 or memory, 528 and 576 are served by the L2, and 520 hits in the L1.

Exercise 2 (compute). A program has an L1 miss rate of 4 % and an L2 local miss rate of 25 %. The L1 hit time is \(t_1=1.2\) ns, an L2 hit adds \(t_2=2.5\) ns, and a memory access adds \(t_{\text{mem}}=126\) ns. (a) Compute the average memory access time with (7.6) (two cache levels). (b) Compute it if the L2 local miss rate is halved. (c) Compute it if the L1 miss rate is halved instead. (d) Which change is better, and by how much of the miss penalty?

Solution

With two cache levels (7.6) reads \(\mathrm{AMAT}=t_1+m_1(t_2+m_2t_{\text{mem}})\). (a) \(t_2+m_2t_{\text{mem}}=2.5+0.25\times126=34.0\) ns and \(\mathrm{AMAT}=1.2+0.04\times34.0=1.2+1.36=2.56\) ns, 2.1 times the hit time. (b) \(2.5+0.125\times126=18.25\) ns and \(\mathrm{AMAT}=1.2+0.04\times18.25=1.93\) ns. (c) \(\mathrm{AMAT}=1.2+0.02\times34.0=1.88\) ns. (d) The miss term \(m_1(t_2+m_2t_{\text{mem}})\) of (a) is 1.36 ns. Halving \(m_1\) removes 0.68 ns of it. Halving \(m_2\) removes \(0.04\times15.75=0.63\) ns. The two changes are nearly equal, and halving \(m_1\) is better by 0.05 ns, because \(m_1\) multiplies the whole penalty of the next level and \(m_2\) multiplies only its memory part.

Exercise 3 (counterexample). A student claims: "A fully associative cache with LRU replacement never has more misses than a direct-mapped cache of the same capacity." Give a trace that refutes the claim and compute the numbers for a cache of \(C=8\) lines.

Solution

Take the cyclic trace of \(C+1=9\) lines, \(0,1,\dots,8,0,1,\dots,8,\dots\), repeated 100 times (900 accesses). Every access after the first pass has the reuse distance 8, since the 8 other lines are used in between. By Theorem 1 the fully associative LRU cache of \(C=8\) lines hits only if \(d\lt8\), so it misses on all 900 accesses. The direct-mapped cache has 8 sets, and line \(\ell\) goes to set \(\ell\bmod8\). Lines 1 to 7 are alone in their sets and hit after their first miss. Lines 0 and 8 share set 0 and evict each other, so each pass has 2 misses. The misses are \(9\) in the first pass and \(2\) in each of the other 99 passes: \(9+198=207\). A short simulation of both caches (not part of the listings) gave 900 and 207. The claim is false because LRU evicts the line that a cyclic scan needs next, while the direct-mapped cache happens to keep seven of the nine lines. The pointer chase of the section on locality is this trace, and the sharp step at the cache size is the same effect: a working set of \(C+1\) lines misses on every access.

Exercise 4 (diagnose an assumption). A student runs a latency-bound loop over a large array on a machine with 2 sockets and 8 threads per socket, with equal static shares of the iterations. The array was initialised by thread 0 before the loop. The speedup of the 16 threads over one thread is 9.8, and the student expected about 16. Assume for the arithmetic that a thread on the node that holds the array has the miss time \(t_{\text{loc}}\), that the NUMA factor is \(\rho=1.6\) (hypothetical numbers, not a measurement), and that nothing else limits the loop. (a) Name the assumption of the student's expectation that fails. (b) Compute the speedup that the model predicts. (c) Compute it if the array is initialised by the 16 threads with the same assignment as the loop, and if its pages are interleaved evenly over the two nodes.

Solution

(a) The expectation \(T_{16}=T_1/16\) assumes uniform memory access: every thread proceeds at the speed of the thread that was measured alone. Under the policy "local allocation" the thread that first touches a page decides its node (section on shared memory), so the whole array lies on the node of thread 0. (b) The 8 threads on that node have \(r=0\) and a miss time \(t_{\text{loc}}\). The 8 threads on the other node have \(r=1\) and by (7.8) a miss time \(\rho\,t_{\text{loc}}=1.6\,t_{\text{loc}}\). With equal shares of the work, the loop ends when the slowest thread ends, so the time is 1.6 times that of an all-local run, and the speedup is \(16/1.6=10.0\), against the measured 9.8 (the same structure as \(S_p=p\,v_{\min}\) of chapter 11, with \(v_{\min}=1/\rho\)). (c) With parallel initialisation every thread has \(r=0\) and the speedup is 16. With interleaved pages every thread has \(r=\tfrac12\), the miss time is \(t_{\text{loc}}(1+0.5\times0.6)=1.3\,t_{\text{loc}}\) for every thread, and the speedup is \(16/1.3=12.3\). The model assumes a latency-bound loop. A loop limited by the bandwidth of the inter-socket link would give other numbers.

Exercise 5 (design judgment). A time step of a simulation needs, in each process, \(10^{5}\) values of 8 bytes that lie in the memory of other processes; the indices of the values are known at the start of the step. Compare (i) a cluster with the assumed \(\alpha=1.5\ \mu\mathrm{s}\) and \(1/\beta=12.5\) GB/s that fetches the values one at a time, with the requests serialised, each fetch being a request message and a reply message of 8 bytes; (ii) the same cluster with all requests batched into one request message (4 bytes per index) and one reply message; (iii) a NUMA machine with \(t_{\text{loc}}=130\) ns and an assumed \(\rho=2.5\), fetching the values (a) one after another and (b) with 10 reads in flight at a time. Give the time of the communication part of the step for each and say which design to choose. Then say what changes if each index depends on the value fetched before it.

Solution

(i) Each fetch is a request and a reply, \(2(\alpha+8\beta)\approx3.0\ \mu\mathrm{s}\), so \(10^{5}\) serialised fetches take 300 ms. (ii) The request message has \(4\times10^{5}\) bytes: \(\alpha+\beta m=1.5\ \mu\mathrm{s}+4\times10^{5}\times80\ \mathrm{ps}=1.5+32=33.5\ \mu\mathrm{s}\). The reply has \(8\times10^{5}\) bytes: \(1.5+64=65.5\ \mu\mathrm{s}\). The total is 99 µs, which is about 3030 times shorter than (i). (iii) A remote read takes \(2.5\times130=325\) ns. (a) Reads one after another take \(10^{5}\times325\ \mathrm{ns}=32.5\) ms; (b) with 10 in flight the bound \(\mu L/c\) of (7.7) gives 3.25 ms. If the indices are known in advance, the batched cluster (99 µs) is 33 times faster than the NUMA machine with overlap (3.25 ms), and the choice is the cluster, with the cost that the programmer must collect the indices and exchange them. If each index depends on the value fetched before it, batching is impossible: the cluster needs \(10^{5}\) dependent request–reply pairs, at least 300 ms, against 32.5 ms for the NUMA machine, so the NUMA machine is 9.2 times faster, and the choice reverses. The decision depends on whether the access pattern allows batching, not on the nominal bandwidth of either machine. The numbers are those of assumed parameters.

Exercise 6 (implementation and measurement). Change the column-order sum of rowcol.c to use a leading dimension: allocate \(N\times\mathrm{ld}\) doubles and read a[i * ld + j]. For \(N=512\) and \(\mathrm{ld}\in\{512,520,528,576\}\), predict the order of the four times with the result of exercise 1, run the program, and compare. State what the measurement can and cannot distinguish.

Solution

The change is the signature sum_cols(const double *a, int n, int ld), the index (size_t)i * ld + j, the allocation malloc((size_t)n * ld * sizeof(double)) and a fill loop over all \(N\times\mathrm{ld}\) elements. The prediction of exercise 1 is: 512 slowest (served by the L3 or memory), then 528 and 576 (served by the L2), and 520 fastest (hits in the L1). The simulator of the section on the cache, run with the row length \(N+8=520\) instead of \(N\), gives the miss rates 0.1250 in all three levels for the column order at \(N=512\), which is the compulsory rate. In three runs of the changed program (minimum of 7 repetitions each) the column-order times in ns per element were: \(\mathrm{ld}=512\): 2.29, 2.78, 2.40; 520: 1.09, 0.83, 0.62; 528: 0.91, 1.33, 0.76; 576: 0.96, 1.07, 0.79. The measurement separates 512 from the other three: within each run its time is 2.1 to 3.9 times theirs, and the model says that the L3 serves it. It does not separate 520 from 528 and 576: the three ranges, 0.62 to 1.09, 0.76 to 1.33 and 0.79 to 1.07 ns, overlap. This agrees with the model only in part. The model says that 528 and 576 are served by the L2 and 520 by the L1, and the section on hit rate showed that an L2-served column costs only 1.2 to 1.7 times a row, a difference of the size of the run-to-run variation. The prediction of the order of the last three values is therefore not tested by this measurement.
