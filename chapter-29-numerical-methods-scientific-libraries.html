Numerical methods and scientific libraries

A heat calculation with 31 interior points in each direction has 961 unknowns. Storing its five-point operator densely takes about 7.4 MB in binary64 arithmetic; doubling the resolution increases dense storage by roughly sixteen, even though the local stencil still touches only five points. Replacing a slow Jacobi loop with a library call can remove thousands of interpreted operations while introducing an inappropriate dense algorithm. The useful decision is therefore larger than choosing a faster function: choose a discretization, a solver, a data representation, and an error target together. The running case separates those choices and checks every library result against a transparent calculation.

The mathematical problem, its discrete representation, and the answer we can check

Let \(u(x,y)\) be a steady temperature on the unit square, with a specified temperature on its boundary. The differential equation is \(-\nabla^2u=s\), where \(\nabla^2\) is the sum of the second spatial derivatives and \(s(x,y)\) is a prescribed source. Coordinates and temperature are nondimensional here. With \(N\) interior points per direction, spacing \(h=1/(N+1)\), and row-major index \(k=iN+j\) for zero-based interior indices, the five-point discretization gives a real linear system \(A_hx_h=b_h\) with \(n=N^2\) unknowns. A subscript \(h\) identifies the mesh; \(n\) is the total number of algebraic unknowns.

\[ 4x_{i,j}-x_{i-1,j}-x_{i+1,j}-x_{i,j-1}-x_{i,j+1}=h^2s_{i,j}. \tag{29.1} \]

Boundary values are moved to the right-hand side. Thus \(A_h\) has diagonal 4 and neighboring entries −1; it is the dimensionless stencil matrix, not the differential operator scaled by \(1/h^2\). The book's heat case has top-edge value one, other edges zero, and zero interior source. The corners do not enter any interior five-point stencil. Two different equations must not be compared using an unlabelled residual tolerance: multiplying (29.1) by \(1/h^2\) changes the residual's magnitude without changing the solution.

The vector \(x_h\) denotes the exact real-arithmetic solution of the discrete system with its stated data. The vector \(u_h\) contains samples of the exact continuous solution, when one is known. An iterative algorithm produces exact-arithmetic iterates \(x_h^{(k)}\) in a mathematical analysis, whereas its computer implementation produces \(\widehat x_h^{(k)}\). This distinction supports an exact bookkeeping identity:

\[ \widehat x_h^{(k)}-u_h=(x_h-u_h)+(x_h^{(k)}-x_h)+(\widehat x_h^{(k)}-x_h^{(k)}). \tag{29.2} \]

The three terms are discretization error, iteration error, and the effect of finite-precision implementation, respectively. Input rounding belongs in the last term if the ideal discrete data are specified before rounding; alternatively one can define \(x_h\) for the stored data and keep input error as a separate term. State the choice. In the top-boundary example all nonzero matrix and right-hand-side entries are small integers and exactly representable. In the manufactured sine example, evaluating sine, π, and products already rounds the right-hand side.

There is no reason for the three terms to be equal. Refining the mesh reduces an appropriate discretization error but generally worsens conditioning and increases computational work. Iterating longer reduces the algebraic error until rounding and stopping-test limitations intervene. Using a different precision changes the last term without repairing the physical model. A result accurate to twelve digits for the discrete equations can still be a poor approximation to the continuous temperature near an unresolved feature.

A separate smooth test makes mesh accuracy measurable. Set zero boundary values and choose \(u(x,y)=\sin(\pi x)\sin(\pi y)\), so that \(s=2\pi^2u\). This manufactured solution means that we choose the answer first and derive the source from it. It tests assembly, solution, and refinement against known values; it does not validate heat-transfer assumptions in a real material. The discontinuous boundary data of the top-edge case are useful for code continuity across the book, but they do not justify a global smooth-solution second-order error claim at the corners.

Consistency, stability, and finite precision answer different questions W11L3 4:22

The opening numerical-method motivation separates machine throughput from algorithmic efficiency. A floating-point rate counts arithmetic per second; application efficiency depends on how much arithmetic and communication the chosen formulation needs for a stated result. A historical peak-rate trend or one Gordon Bell application curve does not establish a universal trend in useful scientific throughput. More processors cannot compensate indefinitely for an iteration count that grows with the mesh or a communication pattern that leaves each process too little local work.

Consistency asks whether the discrete equations approximate the differential equation as the mesh is refined. For a function with bounded fourth derivatives, Taylor expansion at an interior point gives \([u(x+h)-2u(x)+u(x-h)]/h^2=u''(x)+h^2u^{(4)}(x)/12+O(h^4)\), with the higher-order remainder requiring additional smoothness. Applying the formula in both directions gives a local differential-operator defect of order \(h^2\). The statement concerns substitution of a smooth exact function into a formula. It does not yet bound the computed solution.

For the steady problem, let \(L_h=A_h/h^2\), let \(f_h\) include the appropriately scaled source and boundary data, and define the truncation defect \(\tau_h=L_hu_h-f_h\). Subtracting \(L_hx_h=f_h\) yields \(x_h-u_h=-L_h^{-1}\tau_h\). In a stated family of norms, a bound \(\|L_h^{-1}\|\le C\) independent of sufficiently small \(h\), together with \(\|\tau_h\|\le C_1h^2\), gives \(\|x_h-u_h\|\le CC_1h^2\). This is the hinge: a small equation defect becomes a small solution error only when the inverse does not amplify it without control.

For time-dependent problems, stability instead controls propagation of perturbations over a fixed physical time interval, uniformly as the discretization changes under the stated time-step restriction. Merely observing finite values in one finite run is too weak: even an unstable method can remain finite before its error has grown conspicuously. Trefethen, §4.2, Theorem 4.1, states the classical equivalence for consistent approximations of well-posed linear initial-value problems. It is not a universal theorem for arbitrary nonlinear conservation laws, geometries, boundary closures, and limiting procedures. Nonlinear problems need their own stability and convergence arguments.

Floating-point stability is another use of the word. A backward-stable algorithm returns an answer that solves a nearby input problem, with perturbations bounded relative to the data under a stated model. This differs from a stable discretization of a partial differential equation. Both can matter in one computation. A careful convergence report specifies which limit changes: mesh spacing, iteration count, or precision. A graph against iteration number alone says nothing about convergence as \(h\) approaches zero.

Binary32, often called FP32, represents ordinary real numbers with 24 significant binary digits including the implicit leading bit; binary64, or FP64, has 53. Under round-to-nearest with ties to even, a normal elementary arithmetic result with no overflow or underflow satisfies \(\operatorname{fl}(a\circ b)=(a\circ b)(1+\delta)\), \(|\delta|\le\epsilon_r\), where \(\epsilon_r=2^{-24}\) or \(2^{-53}\) is the unit roundoff. This relative model needs qualification for subnormal results and exceptional values. It is a local rounding bound, not a promise of that relative accuracy after a long calculation. NVIDIA's floating-point guide, §§2.1–2.3, explains the formats, rounding order, and fused multiply-add operation, which rounds \(ab+c\) once rather than twice.

Near \(2^{24}\), binary32 spacing is two. Adding one lands halfway between representable values and rounds back to \(2^{24}\). Reordering the operations can preserve the one. This is a small counterexample to exact associativity, with no random data, concurrency, or compiler race. The following program checks both binary32 association and a binary64 cancellation example. Its inputs are embedded constants; it allocates only tiny arrays, creates no files, and prints deterministic results. The accurate sum is a reference for these three values, not a universal replacement for every reduction algorithm.

import math
import numpy as np
values = [1e16, 1.0, -1e16]
ordinary = 0.0
for value in values:
    ordinary += value
accurate = math.fsum(values)
assert ordinary == 0.0 and accurate == 1.0
x = np.float32(2**24)
left = np.float32(np.float32(x + np.float32(1)) - x)
right = np.float32(x + np.float32(np.float32(1) - x))
assert left == 0 and right == 1
print(f"binary64 ordinary={ordinary:.0f} fsum={accurate:.0f}")
print(f"binary32 left={left:.0f} right={right:.0f}")
print("same inputs, different rounding paths: checked")

binary64 ordinary=0 fsum=1
binary32 left=0 right=1
same inputs, different rounding paths: checked

The mathematical sum is one in both examples. A parallel reduction may change the addition tree and therefore change the last bits without violating a library contract. Reproducibility requires controlling the algorithm, precision, compiler transformations, and often thread count; scientific accuracy requires checking the resulting error against the intended quantity. Bitwise agreement with an inaccurate serial order is a different target.

Finite volumes make conservation local; reconstruction can widen communication W11L3 9:16

A conservation law describes accumulation as the balance of flux through a boundary and sources inside it. Write \(\partial_tq+\nabla\cdot \mathcal F(q)=S(q)\), where \(q\) is a conserved quantity per unit volume, \(\mathcal F\) its flux, and \(S\) a source. Integration over a fixed control volume \(K\), followed by the divergence theorem, gives \(d\int_Kq\,dV/dt=-\int_{\partial K}\mathcal F\cdot n\,dA+\int_KS\,dV\). Here \(n\) is the outward unit normal. A finite-volume method evolves cell averages using approximations to these face fluxes. If neighboring cells use equal and opposite versions of one shared interface flux, internal contributions cancel in a global sum.

This cancellation explains conservation; it does not specify accuracy. A high-order reconstruction estimates face values from surrounding cell data, and some reconstructions reach beyond immediately adjacent cells. The inspected stencil frame illustrates this broad dependency pattern. A halo is the imported layer of neighboring data needed by a process that owns only part of the mesh. When reconstruction widens the stencil, the process needs a wider halo, additional communication, or a different arrangement of the calculation. The exact trade depends on the reconstruction and mesh. High order does not logically require every finite-volume method to use the same wide stencil.

For an explicit two-dimensional model, suppose each process owns an \(m\times m\) square of interior cells and imports a halo \(w\) cells wide. Including corners, the extra cells number \((m+2w)^2-m^2=4wm+4w^2\), whereas the owned cells number \(m^2\). Thus the halo-to-owned ratio is \(4w/m+4(w/m)^2\). Face-only stencil exchange can omit some corner cells, but retains the leading surface-to-volume dependence. If the global square is fixed and split over \(p\) processes, then \(m\) is approximately \(N/\sqrt p\). Increasing \(p\) reduces useful local work faster than the leading communication volume.

Let \(\alpha\) be latency in seconds per message, \(\beta\) inverse transfer bandwidth in seconds per byte, and \(b\) bytes per cell state. A four-neighbor face-exchange model is \(T_{\mathrm{comm}}\approx4\alpha+4\beta bwm\); a local update model is \(T_{\mathrm{work}}\approx c m^2\), where \(c\) is seconds per updated cell. The ratio grows like \(1/m^2\) for latency and \(w/m\) for payload. This simple model omits overlap, packing, network contention, and global reductions, but identifies why faster arithmetic alone eventually ceases to reduce wall-clock time. A solver with a reduction every iteration has another latency term outside this halo model.

The lecture's OpenFOAM plot is evidence about a particular code, problem family, partition, machine, and baseline. It is not an upper bound on finite-volume methods. Likewise, its high-order NUMA plots do not constitute a controlled comparison at identical physical error against that OpenFOAM experiment. Fair method comparisons hold the scientific output and error target fixed, then include the number of unknowns, time steps, iterations, and communication costs needed to reach them. Comparing only the best parallel efficiency rewards algorithms that perform unnecessary work efficiently.

Define speedup \(S_p=T_1/T_p\) and efficiency \(E_p=S_p/p\), where \(T_p\) is wall-clock time for the same task on \(p\) processing elements. Values \(S_p\gt p\) can occur when partitioning improves cache residency and therefore lowers the work's cost per element. They can also reflect a changed algorithm, a different stopping criterion, or a poor baseline. Cache locality is a plausible mechanism, not a diagnosis established by the shape of a speedup curve. Repeated runs, cache or memory measurements, and matched numerical termination are needed to distinguish these explanations.

Element polynomials reorganize work into local algebra and interface fluxes W11L3 15:09

A Galerkin method chooses a finite-dimensional trial space for the approximate solution and a test space against which its equation defect is made orthogonal. In the standard Galerkin choice these spaces are the same. Partition the domain into elements \(K_e\) and write \(q_h|_{K_e}=\sum_j a_j^{(e)}(t)\phi_j^{(e)}(x)\), where \(\phi_j^{(e)}\) are basis functions and \(a_j^{(e)}\) are coefficients. Continuous Galerkin methods couple neighboring elements by shared continuity constraints. Discontinuous Galerkin, abbreviated DG, permits different traces on the two sides of an interface and couples them through a numerical flux.

The degree of the local polynomial will be \(p_e\), distinct from the processing-element count \(p\). The mesh size \(h\) measures element diameter; refining \(h\) means making elements smaller. Increasing \(p_e\) enriches the approximation within each element. The lecture's schematic map from finite elements to spectral elements is a useful organizational picture, but it is not a theorem that arbitrary finite-volume and DG schemes become identical simply by moving along two axes. Basis choice, quadrature, fluxes, continuity, and limiting remain part of the method.

A one-dimensional scalar advection equation exposes the construction without a shallow-water system's extra notation. Let \(\partial_tq+a\partial_xq=0\) with constant speed \(a\), on an element \(K=[x_L,x_R]\). Multiply by a test function \(v\), integrate, and integrate the flux derivative by parts. Replacing the two boundary fluxes by a common numerical flux \(\widehat f\) gives

\[ \int_Kv\,\partial_tq_h\,dx-\int_Ka q_h\,\partial_xv\,dx +v(x_R)\widehat f_R-v(x_L)\widehat f_L=0. \tag{29.3} \]

The interior integrals use only this element's coefficients. For \(a\gt0\), an upwind flux takes \(\widehat f=a q_h^-\) from the left trace; for \(a\lt0\) it uses the right trace. A trace is the limiting value from a specified side of the interface. These rules encode the direction of information travel. Using one shared flux also makes adjacent boundary contributions cancel when the constant test function is admissible. Stability still depends on flux choice, integration, time stepping, and boundary conditions.

With \(v=\phi_i\), define mass-matrix entries \(M_{ij}=\int_K\phi_i\phi_j\,dx\) and derivative entries \(G_{ij}=\int_Ka\phi_j\partial_x\phi_i\,dx\). Equation (29.3) becomes a local system \(M\dot a=Ga-g_{\mathrm{face}}\), with the face vector containing the numerical boundary flux terms. This is the algebraic form behind the lecture's local-matrix discussion. One may precompute a factorization of a fixed small mass matrix, exploit a diagonal form when justified by the method, or apply a reference-element inverse. Writing \(M^{-1}\) in the mathematics is not an instruction to form a large global inverse in production code.

Counting basis coefficients is essential before calling a matrix “small.” A tensor-product scalar polynomial space of degree \(p_e\) in each of three coordinates has \((p_e+1)^3\) coefficients: degree three gives 64, degree eight gives 729. A two-dimensional triangle with total polynomial degree \(p_e\) has \((p_e+1)(p_e+2)/2\) coefficients: degrees one, two, and three give 3, 6, and 10. Systems with several physical fields add components. These explicit counts prevent an ambiguous phrase such as “third order” from being mistaken for a unique matrix dimension.

For a three-dimensional tensor element, stored coefficients scale like \((p_e+1)^3\), while face traces scale like \((p_e+1)^2\) per face. Their ratio grows linearly with \(p_e+1\). This is a geometric explanation for increasing local work relative to communication. It does not establish execution time: a naive dense local matrix application costs the square of the number of coefficients, while tensor structure can reduce work by applying one-dimensional operators successively. Register capacity, intermediate storage, and memory access can reverse a simplistic “more arithmetic is better” conclusion.

Kelly and Giraldo (2012), abstract, describe continuous and discontinuous atmospheric discretizations and report near-ideal DG scaling to 32,768 cores in their experiments. This supports the possibility demonstrated in the lecture, under those conditions. It supplies neither a universal DG scaling guarantee nor the laptop GPU speedups shown in other lecture plots. Dense-looking blocks in a sparsity figure suggest local coupling; they do not by themselves establish cache residency, global sparsity cost, or accuracy per second.

A faster numerical kernel changes the feasible ensemble, not the certainty of the inputs W11L3 23:28

The shallow-water application adds physical meaning to this cost discussion. The depth-averaged state contains a water-height variable and horizontal momentum; bathymetry is the spatially varying depth or bed geometry. Gravity drives surface waves, while rotation, wind stress, and bottom friction can enter source terms. The lecture follows this application through Indian Ocean tsunami propagation, comparisons with observations, storm surge, and inundation maps. Those examples motivate accurate geometry and many possible source scenarios; the present chapter does not reproduce their hazard predictions.

Agreement in wave arrival time does not imply agreement in wave height, and neither alone validates inundation at street scale. The observed and simulated curves shown in the lecture have location-dependent differences. Measurement location, bathymetry, uncertain forcing, and omitted processes can affect those differences alongside numerical error. Before interpreting a mismatch as a need for a finer mesh, distinguish uncertainty in the physical inputs from the three numerical contributions in (29.2). Refining an inaccurately specified coastline does not recover missing information about it.

The lecture's inundation slide describes a 50–100 m resolution context and a desired urban scale around 5 m. These are dated motivation values from the slide, not an assessment of the current state of hazard modeling. A dimensional budget still makes their computational consequence clear. At fixed mapped area, going from 50 m to 5 m increases horizontal cells by 100. For an explicit wave scheme whose stable time step is proportional to cell width at fixed wave speed, the same physical duration requires about ten times as many steps. The leading update count therefore rises by roughly 1000, before adding urban geometry, source ensembles, or solver overhead.

High-order representation can reduce spatial error efficiently for smooth resolved waves, yet coastlines, wetting fronts, discontinuities, and positivity constraints require additional treatment. A time-step restriction can also become tighter as polynomial degree rises. The useful objective is cost to obtain specified output accuracy over the needed scenarios. That objective joins numerical analysis to parallel architecture: a method with better local algebra may make the ensemble affordable, while still requiring uncertainty quantification and observational validation.

Use an algorithmic abstraction while retaining a checkable data contract W11L4 1:20

Thrust expresses operations such as sorting, reduction, scan, and transformation using containers and iterators rather than explicit launch geometry. An iterator identifies a position in a sequence and supports the operations an algorithm needs. A host vector owns host-accessible storage; a device vector owns storage associated with its selected device system. Container construction, copying, and destruction carry allocation, data transfer, and lifetime behavior. Fewer source lines do not mean those costs disappear.

NVIDIA's CUDA Core Compute Libraries repository identifies Thrust as part of CCCL and documents its header-based use through the toolkit. The Thrust systems documentation describes active host and device systems and explicit execution policies. A policy selects an implementation backend; it does not make a host pointer valid device storage. Source portability also does not establish performance portability or identical floating-point reductions. Compiler support and available backends must be checked for the installed release.

The lecture's sorting example allocates millions of integers. This bounded teaching version uses twelve, including duplicates and negative values. It copies the complete result back and compares each position with the C++ standard library's independently executed host sort. A test that checks only that the GPU call returned would miss a missing copy or incorrectly sorted payload. The expected sequence is also printed, making order, multiplicity, and sign visible. The program handles exceptions and waits for device completion before accepting the calculation.

#include <thrust/device_vector.h>
#include <thrust/host_vector.h>
#include <thrust/sort.h>
#include <thrust/copy.h>
#include <cuda_runtime.h>
#include <algorithm>
#include <iostream>
#include <stdexcept>
#include <vector>
int main() {
    try {
        const int input[] = {9,-2,5,5,0,17,-2,1,8,3,4,7};
        std::vector<int> reference(input,input+12);
        std::sort(reference.begin(),reference.end());
        thrust::host_vector<int> h(input,input+12);
        thrust::device_vector<int> d=h;
        thrust::sort(d.begin(),d.end());
        if (cudaDeviceSynchronize()!=cudaSuccess) throw std::runtime_error("CUDA execution");
        thrust::copy(d.begin(),d.end(),h.begin());
        for (int i=0;i<12;++i) if(h[i]!=reference[i]) throw std::runtime_error("full payload mismatch");
        std::cout << "all 12 device-sort entries match std::sort\n";
        std::cout << "sorted:";
        for (int x:h) std::cout << ' ' << x;
        std::cout << '\n';
    } catch (const std::exception& e) {
        std::cerr << e.what() << '\n'; return 1;
    }
}

The compiled architecture is explicitly \(\mathrm{sm\_86}\), the local GPU's machine-code target. Compute capability 8.6 identifies a hardware feature target; it is different from the CUDA toolkit version. The installed CUDA 13.3 toolkit and driver-reported CUDA compatibility must be treated as separate facts. A successful native-code example does not prove that every intermediate-code or library path is supported. Its device payload is 48 bytes, plus library/runtime overhead; it is intentionally a correctness demonstration, not a sorting benchmark.

BLAS levels organize the amount of reuse available to an implementation W11L4 9:33

BLAS means Basic Linear Algebra Subprograms: a collection of interfaces for basic linear-algebra kernels. A kernel here is a reusable computational routine, not necessarily a GPU launch. Netlib's BLAS overview distinguishes vector operations, matrix–vector operations, and matrix–matrix operations as Levels 1, 2, and 3. The interface specifies what is computed; an implementation chooses blocking, vector instructions, threading, and architecture-specific code. The existence of a BLAS interface therefore does not identify which implementation a program actually loads.

The naming system communicates several parts of the contract. The initial letters S and D traditionally identify single- and double-precision real arithmetic, while C and Z identify the corresponding complex arithmetic. In DGEMM, GE denotes general matrices and MM matrix multiplication. DTRMV operates on a real double-precision triangular matrix and a vector. DSYR2K updates a symmetric matrix using a rank-2k form. A Hermitian matrix equals its complex conjugate transpose; a symmetric real matrix equals its transpose. Choosing a structural routine is a promise about the input, not permission to pass an arbitrary array and hope the library detects its mathematical structure.

A matrix's shape, physical storage order, leading dimension, and transpose flag are separate concepts. A leading dimension describes the stride between stored columns in the conventional Fortran interface, not the number of rows in the logical result after a transpose. C interfaces may also provide a row-major option. Array libraries often handle these details but may create temporary copies for unsuitable strides. Before comparing timings, specify whether conversion, packing, and allocation are included. A nonsquare test catches mistakes that a square identity matrix can hide.

Arithmetic intensity is \(I=F/Q\), floating-point operations divided by bytes moved between the specified memory levels. A floating-point operation, or flop, counts one real addition or multiplication; a fused multiply-add conventionally counts two. For binary64 AXPY, \(y\leftarrow\alpha x+y\), a simple streaming model uses \(2n\) flops, reads \(x\) and \(y\), and writes \(y\): \(Q\approx24n\) bytes and \(I\approx1/12\) flop/byte. This count omits write-allocation effects and assumes no useful prior cache residence. It explains why changing arithmetic throughput alone rarely transforms a long vector update.

A dense matrix–vector product uses approximately \(2n^2\) flops and must read \(8n^2\) bytes of matrix entries, even if the vector remains cached. Its leading intensity approaches \(1/4\) flop/byte. By contrast, a matrix–matrix product \(C=AB\) does approximately \(2n^3\) flops. An idealized one-read-per-input, one-write-per-output traffic model gives \(Q\approx24n^2\) and \(I\approx n/12\). If the old \(C\) is also read for \(C\leftarrow\alpha AB+\beta C\), the analogous minimum is \(32n^2\) bytes. These are lower traffic models, not guaranteed cache behavior.

The extra reuse comes from using one tile of \(A\) with several columns of \(B\), and one tile of \(B\) with several rows of \(A\). Cache capacity prevents retaining arbitrary whole matrices, so blocked algorithms arrange repeated use of small tiles. Let \(b_t\) be a tile side and suppose three binary64 tiles fit in a cache of usable capacity \(M\) bytes: the rough constraint is \(24b_t^2\le M\). Real kernels also need registers, associativity headroom, packing buffers, and alignment. A capacity inequality helps understand blocking but does not determine an optimal tile size.

The lecture's rank-update example connects the levels algebraically. With \(X\) an \(m\times k\) matrix, \(Y\) an \(n\times k\) matrix, and \(A\) an \(m\times n\) matrix, \(A\leftarrow A+XY^T\) equals the sum of \(k\) outer-product updates. Repeated rank-one calls may stream through \(A\) repeatedly. One matrix–matrix call can retain blocks and combine several updates before writing them. The benefit requires enough work and useful reuse; for tiny matrices, small \(k\), costly packing, or a specialized fused application kernel, the supposedly higher-level option need not always win.

The following program compares an explicit Python product with NumPy's matrix multiplication for a 96-by-96 case. Every input is a small integer divided by a power of two. Products and all intermediate sums fit exactly in binary64 for this bounded data, so exact agreement is meaningful here. The reference uses explicit indexing and math.fsum for each entry. A separate 5-by-7 times 7-by-3 update checks all fifteen entries and includes scaling and subtraction. It is not enough to compare one checksum: two different wrong matrices can have the same sum.

import math
import statistics
import time
import numpy as np

n = 96
A = np.array([[((3*i+5*k)%17-8)/8 for k in range(n)] for i in range(n)], dtype=np.float64)
B = np.array([[((7*k+2*j)%19-9)/16 for j in range(n)] for k in range(n)], dtype=np.float64)
a,b = A.tolist(),B.tolist()
def transparent():
    return np.array([[math.fsum(a[i][k]*b[k][j] for k in range(n)) for j in range(n)] for i in range(n)])
reference = transparent()
C = A@B
assert np.array_equal(C,reference)
naive_times, library_times = [],[]
for repeat in range(3):
    start=time.perf_counter()
    R=transparent()
    naive_times.append(time.perf_counter()-start)
    start=time.perf_counter()
    C=A@B
    library_times.append(time.perf_counter()-start)
    assert np.array_equal(C,R)
# A separate nonsquare layout check catches transpose and dimension assumptions.
X=A[:5,:7].copy()
Y=B[:7,:3].copy()
D=np.full((5,3),0.5)
result=2*(X@Y)-D
expected=np.array([[2*math.fsum(float(X[i,k])*float(Y[k,j]) for k in range(7))-0.5 for j in range(3)] for i in range(5)])
assert np.array_equal(result,expected)
print(f"all {n*n} product entries and 15 update entries: exact match")
print(f"transparent median seconds={statistics.median(naive_times):.6f}")
print(f"numpy matmul median seconds={statistics.median(library_times):.6f}")
print(f"transparent range seconds={min(naive_times):.6f}..{max(naive_times):.6f}")
print(f"numpy matmul range seconds={min(library_times):.6f}..{max(library_times):.6f}")
print("timings include Python call and result allocation; no GPU used")

Factorization turns elimination into reusable matrix operations W11L4 18:15

Gaussian elimination solves a linear system by eliminating entries below each pivot and then substituting backward through an upper-triangular system. Without pivoting, one step partitions the matrix around a nonzero scalar pivot \(a_{11}\). The multipliers are \(\ell=a_{21}/a_{11}\), and the trailing matrix becomes \(A_{22}-\ell a_{12}\). This is a rank-one update, directly connecting elimination to the BLAS vocabulary. The multipliers can occupy the storage below the diagonal because the eliminated zeros need not be stored explicitly.

A zero or very small pivot changes the numerical question. For example, \(\begin{bmatrix}0&1\\1&1\end{bmatrix}\) is nonsingular, yet the first unpivoted elimination divides by zero. Partial pivoting exchanges rows to choose an entry with largest magnitude in the current pivot column. It avoids that elementary failure and controls the multipliers, but intermediate entries can still grow. The rounding-error bounds for LU factorization depend on that growth; a blanket promise that every general solve is backward stable independently of its matrix would be too strong.

Blocking replaces repeated scalar updates by panel factorizations and larger updates. In the simplified unpivoted block algebra, assuming the leading block is invertible, eliminate the first block column and form the Schur complement

\[ S=A_{22}-A_{21}A_{11}^{-1}A_{12}. \tag{29.4} \]

Compute the required action of \(A_{11}^{-1}\) with triangular solves from its factorization. Do not form the inverse merely because the notation contains one. The large trailing update then becomes a matrix–matrix operation. Pivoted implementations must also apply the recorded row permutations consistently; the clean two-block formula is an explanation of the update, not a complete pivoted algorithm.

For a dense \(n\times n\) general matrix, LU factorization requires approximately \(2n^3/3\) flops, whereas solving for one right-hand side after factorization costs order \(n^2\). Reusing factors for many sources is therefore different from repeatedly calling a driver that refactorizes the same matrix. Cholesky factorization exploits a symmetric positive-definite matrix and reduces the leading factorization work to about \(n^3/3\). Positive definite means \(z^TAz\gt0\) for every nonzero real vector \(z\); symmetry alone is insufficient. LAPACK Users' Guide, “Linear Equations”, distinguishes the supported factorizations and separate routines for factoring, solving, condition estimation, and refinement.

The Poisson matrix in (29.1) is symmetric positive definite with Dirichlet boundary conditions, but a dense representation still discards its sparsity. Sparse means that only a small fraction of entries are nonzero. At \(N=31\), a dense binary64 matrix needs \(8N^4=7,388,168\) bytes. At \(N=63\) it needs 126,023,688 bytes. A stencil representation stores a few coefficients or applies them implicitly, using order \(N^2\) storage. Dense LAPACK is an excellent small reference here; it is not the proposed large-grid production solver.

A library can solve the stored discrete equations accurately without solving the continuous problem accurately. Let \(\widehat x\) be a computed vector and define the exact residual \(r=b-A\widehat x\). For nonsingular \(A\), \(x-\widehat x=A^{-1}r\). In a subordinate norm, with nonzero \(b\) and \(x\), define the condition number \(\kappa(A)=\|A\|\|A^{-1}\|\). Then

\[ \frac{\|x-\widehat x\|}{\|x\|}\le\kappa(A)\frac{\|r\|}{\|b\|}. \tag{29.5} \]

The first bound is \(\|x-\widehat x\|\le\|A^{-1}\|\|r\|\); the second ingredient is \(\|b\|=\|Ax\|\le\|A\|\|x\|\). A small relative residual therefore gives a useful forward-error bound only with a controlled condition number. A conditioning statement belongs to the problem and chosen norm. A convergence statement belongs to a method and its stopping assumptions. Neither can be inferred from a successful return code.

A normalized residual often used as a normwise backward-error indicator is \(\eta=\|r\|_\infty/(\|A\|_\infty\|\widehat x\|_\infty+\|b\|_\infty)\). The infinity norm of a vector is its largest absolute entry; the induced matrix infinity norm is its largest absolute row sum. With exact residual evaluation, this quantity characterizes the smallest simultaneous unstructured normwise relative perturbation of \(A\) and \(b\) making \(\widehat x\) exact. “Unstructured” matters: the permitted perturbation need not preserve stencil sparsity or symmetry. A residual evaluated in binary64 also has its own rounding error, so a tiny computed indicator is not an independently certified bound.

For the two-dimensional five-point matrix, sine-product eigenvectors have eigenvalues \(4-2\cos(r\pi h)-2\cos(s\pi h)\), for integers \(1\le r,s\le N\). The smallest and largest are \(4-4\cos(\pi h)\) and \(4+4\cos(\pi h)\). Since the matrix is symmetric positive definite, its two-norm condition number is their ratio, approximately \(4/(\pi^2h^2)\) as \(h\to0\). The differential scaling \(1/h^2\) cancels from that ratio. This is why mesh refinement can make a small algebraic residual progressively less informative about solution error.

                b[k] += 1.0
            if source is not None:
                b[k] += h*h*source((i+1)*h, (j+1)*h)
    return A,b

LAPACK problem contracts extend beyond square solves W11L4 22:35

A square nonsingular system asks for the unique vector satisfying \(Ax=b\). A rectangular matrix instead may represent more equations than unknowns, or fewer. Let \(A\) have \(m\) rows and \(n\) columns, \(b\) have \(m\) entries, and \(x\) have \(n\) entries. The Euclidean norm \(\|z\|_2=(\sum_j|z_j|^2)^{1/2}\) measures a vector's length. Least squares minimizes \(\|Ax-b\|_2\), allowing a nonzero residual when the equations cannot all be satisfied. With \(m\ge n\) and linearly independent columns, the minimizer is unique. Netlib's least-squares driver documentation distinguishes this contract from exact satisfaction of a square system.

For an original two-equation example, take \(A=(1,1)^T\) and \(b=(0,2)^T\). A single scalar \(x\) cannot equal both zero and two. Its squared residual is \(x^2+(x-2)^2=2(x-1)^2+2\). The unique least-squares answer is therefore \(x=1\), with residual \(b-Ax=(-1,1)^T\) and norm \(\sqrt2\). The nonzero residual is the best possible mismatch, not evidence that a solver stopped too early. With \(m\lt n\) and independent rows, the system has many exact solutions; minimum norm selects the one with smallest \(\|x\|_2\). For example, \(A=(1\;1)\), \(b=2\) has solutions \((1+t,1-t)^T\), whose squared norms are \(2+2t^2\), minimized at \((1,1)^T\). For rank-deficient data, one can likewise select the minimum-norm vector among all least-squares minimizers.

Define \(\operatorname{Id}_d\) as the \(d\times d\) identity matrix for any positive integer \(d\). A superscript \(^*\) denotes conjugate transpose, which reduces to ordinary transpose for real matrices. For a tall full-column-rank matrix, a thin QR factorization is \(A=\mathsf Q_1\mathsf R\), where \(\mathsf Q_1\) is \(m\times n\), \(\mathsf Q_1^*\mathsf Q_1=\operatorname{Id}_n\), and \(\mathsf R\) is nonsingular upper triangular of size \(n\times n\). The columns of \(\mathsf Q_1\) are orthonormal: mutually perpendicular with unit length. Extend them to a square orthogonal matrix \(\mathsf Q\) in the real case, or unitary matrix in the complex case, so \(\mathsf Q^*\mathsf Q=\operatorname{Id}_m\). Multiplication by \(\mathsf Q^*\) preserves Euclidean length, splitting the least-squares objective into a triangular solve and an unavoidable orthogonal residual. The least-squares solution satisfies \(\mathsf R x=\mathsf Q_1^*b\). The distinct typeface keeps \(Q\) reserved for byte traffic.

For a wide full-row-rank matrix, the corresponding LQ factorization is \(A=\mathsf L\mathsf Q_1\), where \(\mathsf L\) is \(m\times m\) nonsingular lower triangular and \(\mathsf Q_1\) is \(m\times n\) with orthonormal rows, \(\mathsf Q_1\mathsf Q_1^*=\operatorname{Id}_m\). It is the transposed, or conjugate-transposed, shape counterpart of QR. Solve \(\mathsf L y=b\), then choose \(x=\mathsf Q_1^*y\). The null space of \(A\) consists of vectors \(z\) satisfying \(Az=0\). Any additional vector from that space is orthogonal to this selected vector and increases its squared norm, so this construction gives the minimum-norm solution under the stated rank assumption.

An eigenproblem asks, for square \(A\), for a scalar eigenvalue \(\lambda\) and nonzero eigenvector \(v\) satisfying \(Av=\lambda v\). A real nonsymmetric matrix can have complex eigenpairs. A singular value decomposition, or SVD, applies also to rectangular matrices: \(A=\mathsf U\Sigma\mathsf V^*\), with square orthogonal or unitary factors \(\mathsf U\) of size \(m\times m\) and \(\mathsf V\) of size \(n\times n\). The \(m\times n\) rectangular diagonal matrix \(\Sigma\) has nonnegative diagonal entries \(\sigma_j\), the singular values, conventionally ordered from largest to smallest. The first \(\min(m,n)\) columns of the two square factors give paired left and right singular vectors; any remaining columns complete their orthonormal bases. Singular values describe how the matrix stretches directions between two spaces; they are different objects from eigenvalues of a square matrix.

The lecture also includes generalized problem contracts. An equality-constrained least-squares problem minimizes \(\|c-Ax\|_2\) subject to \(B_cx=d\), where \(A\) is \(m\times n\), \(B_c\) is \(k_c\times n\), and \(c,d\) have \(m,k_c\) entries. A generalized linear model instead minimizes \(\|y\|_2\) subject to \(d=Ax+B_cy\), with \(A\) of size \(m\times n\), \(B_c\) of size \(m\times k_c\), and \(d\) of length \(m\). These are different constrained optimization problems, with separate rank and dimension assumptions for their drivers, described in Netlib's generalized least-squares documentation.

These problems explain LAPACK's three routine levels. A driver orchestrates a complete requested problem; for example, the driver overview includes linear solves, least squares, eigenproblems, and SVD. A computational routine performs a distinct stage, such as factorization or solution using already computed factors. Auxiliary routines support lower-level tasks such as scaling, norm evaluation, or constructing transformations. A factorization routine alone need not return the requested solution vector. These additional problem contracts and hand-derived examples are explanations, not additional locally executed library calls; the five verified programs retain their original execution scope.

Choose a library layer that preserves the mathematical structure W11L4 23:43

The lecture moves from LAPACK to CPU and accelerator libraries, then to PETSc. Vendor packages are implementations and collections, not additional mathematical levels of BLAS. A CPU package may provide BLAS, factorizations, transforms, and other routines; a GPU package adds device-memory, execution, and synchronization contracts. NVIDIA's cuBLAS reference documents its GPU BLAS interface. Merely finding its shared library does not establish a successful cuBLAS computation. This chapter executed NumPy's CPU algebra and the separately checked Thrust sort; it did not execute cuBLAS, cuFFT, or an Intel-specific binding.

WSL Python was 3.12.3 and NumPy was 1.26.4. Imports for SciPy, petsc4py, pyFFTW, and CuPy were unavailable. The examples use the installed environment read-only and install nothing. In particular, NumPy's presence does not imply SciPy sparse solvers or a Python GPU array interface. Historical vendor names, license descriptions, and processor examples in the lecture are not used as current purchasing or compatibility guidance.

PETSc, the Portable, Extensible Toolkit for Scientific Computation, raises the abstraction from individual algebra kernels to distributed vectors, matrices, solver contexts, and application composition. Its KSP manual describes an interface through which different linear solution techniques can be selected. A Krylov subspace generated by an operator \(A\) and initial residual \(r_0\) is the span of \(r_0,Ar_0,A^2r_0,\ldots\); iterative methods search related spaces rather than explicitly factorizing a dense global matrix. Matrix–vector applications, vector updates, inner products, and preconditioner applications become the recurring operations.

A preconditioner is an efficiently applicable approximation to the difficult part of solving with \(A\). If \(M\) is invertible, left preconditioning rewrites the system as \(M^{-1}Ax=M^{-1}b\). The goal is a more favorable iterative problem at acceptable setup and application cost. It is not automatically a reduction of every chosen norm's condition number. For symmetric positive-definite \(A\) and \(M\), a symmetric transformation \(M^{-1/2}AM^{-1/2}\) preserves positive definiteness and gives a clean setting for preconditioned conjugate gradients. An arbitrary nonsymmetric preconditioner does not satisfy that argument. The PETSc CG documentation states the corresponding matrix and preconditioner restrictions.

For the constant-coefficient Poisson case, scalar Jacobi preconditioning uses \(M=4\operatorname{Id}_n\), where \(\operatorname{Id}_n\) is the \(n\times n\) identity matrix. It merely rescales the matrix, leaving its condition-number growth unchanged. Block Jacobi instead approximately solves independent diagonal blocks, while more global approaches can address long-wavelength errors that local relaxations remove slowly. Naming a preconditioner is therefore insufficient: specify its block structure, setup, accuracy, and parallel communication. A multilevel approach needs a suitable hierarchy and transfer operators; invoking “multigrid” is not a proof of mesh-independent convergence for every operator.

A distributed matrix object also contains ownership and communication information. The application can request \(y=Ax\) through a common interface while the implementation imports needed vector entries. This hides many explicit Message Passing Interface, or MPI, calls from the application code. It does not abolish communication, collective participation requirements, or data layout. Compatible objects must have compatible communicators and layouts; an application may use more than one communicator. The lecture's schematic object stack should not be read as requiring every object in an entire program to share one universal communicator.

A practical solver report records convergence reason, iteration limit, the norm used for termination, and an independently recomputed residual of the original equations. PETSc's tolerance documentation explicitly distinguishes residual norms, possibly preconditioned, from solution error. A residual transformed by \(M^{-1}\) can look small because of scaling. Compare methods using the same original-equation accuracy target and include preconditioner setup, communication, and memory. No PETSc execution or distributed-solver speedup is claimed here, because the required local binding was absent.

Transform libraries add another convention boundary

Fourier transforms are a research extension to the lecture's library survey. For samples \(x_0,\ldots,x_{n-1}\), define the discrete Fourier transform, or DFT, by \(X_k=\sum_{j=0}^{n-1}x_j\exp(-2\pi\mathrm{i}jk/n)\), where \(\mathrm{i}^2=-1\). The inverse uses the opposite sign and a factor \(1/n\). The direct formula costs order \(n^2\) arithmetic; fast Fourier transform algorithms exploit structure to achieve order \(n\log n\) work for standard transforms. This change of algorithm can exceed gains from distributing the direct formula across additional processors.

FFTW's one-dimensional tutorial distinguishes planning from repeated execution and specifies that its forward and backward transforms are both unnormalized. Their composition returns \(nx\). NumPy 1.26's FFT documentation specifies a default inverse normalized by \(1/n\). These conventions must be reconciled before comparing results. A missing normalization can produce a large numerical discrepancy even though both implementations satisfy their contracts.

The next listing runs NumPy's FFT, checks all eight complex coefficients against the explicit DFT, and checks every reconstructed sample. Multiplying the NumPy inverse by eight illustrates the unnormalized convention; it does not call FFTW. The thresholds allow roundoff in complex exponentials and summation. An inverse-only round trip would be weaker, since two mutually compensating sign or normalization errors could cancel. The direct-reference check fixes the forward convention independently.

import math

Six exercises with reasoned solutions

1. Derive the smooth Poisson refinement ratio

For the zero-boundary sine problem, derive the discrete eigenvalue, the amplitude error, and the expected error ratio when \(h\) is halved. State why the same argument does not automatically cover the top-edge boundary case.

Solution

In one dimension, \(\sin(\pi(x+h))+\sin(\pi(x-h))=2\cos(\pi h)\sin(\pi x)\). Apply this in both directions of (29.1): the eigenvalue of the dimensionless matrix is \(4-4\cos(\pi h)=8\sin^2(\pi h/2)\). The source vector is \(2\pi^2h^2u_h\), so the discrete solution is \(a_hu_h\) with \(a_h=\pi^2h^2/[4\sin^2(\pi h/2)]\). Using \(\sin z/z=1-z^2/6+O(z^4)\) gives \(a_h-1=\pi^2h^2/12+O(h^4)\). On grids containing the sine maximum, the maximum error is \(|a_h-1|\), and its ratio approaches four. The top-edge data have corner discontinuities; the smoothness hypothesis used by this expansion and a global second-order argument is not supplied there.

2. Compute a communication budget

A process owns a 64-by-64 region. Compare full halos of widths one and four, including corners. Then halve the owned side at width four. Interpret the changes without claiming a measured wall-clock slowdown.

Solution

The formula \(4wm+4w^2\) gives 260 extra cells for \(m=64,w=1\), and 1088 for \(m=64,w=4\). Relative to 4096 owned cells these are about 6.35% and 26.56%. At \(m=32,w=4\), the halo contains 576 cells relative to 1024 owned cells, or 56.25%. The payload-to-work ratio increases even though the absolute payload decreases. Four message latencies need not decrease at all. Face-only exchange changes the corner term, and overlap, bandwidth, and reconstruction cost affect time, so these counts identify pressure on scaling rather than a measured performance ratio.

3. Construct a small-residual counterexample

Let \(A=\operatorname{diag}(1,10^{-8})\), \(b=(1,10^{-8})^T\), and \(\widehat x=(1,0)^T\). Compute the infinity-norm relative residual, relative forward error, and condition number.

Solution

The exact solution is \(x=(1,1)^T\). The residual is \((0,10^{-8})^T\), so its relative infinity norm is \(10^{-8}/1=10^{-8}\). The solution error has infinity norm one, as does \(x\), so the relative forward error is one. Since \(\|A\|_\infty=1\) and \(\|A^{-1}\|_\infty=10^8\), the condition number is \(10^8\). Equation (29.5) permits an error as large as one and is attained here. The tiny second equation is satisfied poorly in relative component terms even though it contributes little to the global norm. This also motivates componentwise diagnostics when physical variables have very different scales.

4. Diagnose a stability claim

A consistent time-discretization runs for 100 steps without infinities. Its designer concludes that it is stable and therefore convergent for a nonlinear conservation law. Identify the missing assumptions and propose a meaningful check.

Solution

Finite values after 100 steps establish neither a uniform perturbation bound nor a limit as the mesh and time step change. The classical linear equivalence theorem requires a well-posed linear initial-value problem and an appropriate consistent linear approximation family; those hypotheses do not follow from the described nonlinear experiment. Specify the norm, physical time interval, mesh family, time-step relation, and boundary treatment. A perturbation-growth experiment over successively refined meshes and a fixed physical interval can test a proposed bound, while an independently known solution can test convergence. Neither finite experiment proves a universal theorem, but either is more relevant than checking only for overflow.

5. Choose a solver representation

A two-dimensional Dirichlet Poisson grid has 1000 interior points per side and only one right-hand side. Should the dense library reference in this chapter become the production solver? Discuss memory, work, and a plausible alternative without promising unmeasured speedup.

Solution

There are \(n=10^6\) unknowns. A dense binary64 coefficient matrix alone requires \(8n^2=8\times10^{12}\) bytes, or 8 TB in decimal units. General dense LU's leading work is about \(2n^3/3\approx6.7\times10^{17}\) flops. Neither estimate exploits the roughly five nonzeros per row. Retain the stencil or a sparse representation and consider a compatible iterative solver with a suitable preconditioner, such as a validated multilevel construction for this elliptic operator. Assess setup and solve time, memory, iteration growth, and original-equation residual at the desired discretization error. A sparse solver can still fail or scale poorly if its preconditioner and communication are inappropriate; the estimates reject the dense choice without proving a specific replacement's performance.

6. Design a library test and measurement

Implement an independent nonsquare check of C=2XY−D for a 5-by-7 matrix X, a 7-by-3 matrix Y, and a 5-by-3 matrix D whose entries are 0.5. Then design a timing protocol for transferring the experiment to a new backend. Explain why a successful API call is insufficient.

Solution

The nonsquare part of the matrix-product listing is one complete implementation: X and Y are copied slices of deterministic inputs, and each reference entry is twice the accurately accumulated seven-term indexed product minus 0.5. The library result has shape 5-by-3, and the retained run checked all fifteen entries exactly. The bounded power-of-two data make exact comparison justified here. For a new backend, start with nonsquare dimensions and deterministic small data, including negative entries, zero entries, and a nontrivial old output. Compute every reference element using transparent indexed loops and a justified accumulation method. Check the exact operation, including transpose flags, scaling, storage layout, and output shape; then use tolerances justified by precision and the sum of absolute products for general floating-point data. Test small boundary dimensions separately. Retain a second check such as a known manufactured linear system when moving to a solver. For a GPU backend, explicitly complete work and copy back the full payload before accepting it.

Separate initialization and data conversion from repeated execution, then report both the desired kernel interval and the complete application interval if both matter. Warm up consistently, repeat bounded runs, report ranges as well as medians, and retain raw failures and outputs. If only an interpreted reference is available, label the comparison accordingly. A successful call with an unchecked output, or a host timer stopped before GPU completion, is insufficient evidence of either correctness or speed.
