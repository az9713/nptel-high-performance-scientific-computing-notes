Domain decomposition, an MPI solver, and performance analysis

A \(1000\times1000\) grid contains one million interior temperatures. Four row strips give each rank 250 000 updates per sweep, but an interior rank also needs two rows of 1000 values owned by its neighbours. Changing to sixteen square patches reduces the length of each communicated face while increasing the number of neighbours. Neither partition is automatically faster. The decision requires an ownership map, a correct halo protocol, a comparison against the serial numerical algorithm, and a cost model that distinguishes message count from byte count. A speedup of 4.71 on eight processes is also ambiguous: it can arise from genuinely serial work or from overhead in an otherwise parallel algorithm.

Grounded in NPTEL High Performance Scientific Computing, IIT Bombay: W5L4, Domain Decomposition; W5L5, Parallelization of example code using MPI; and W5L6, Performance Analysis Frameworks for Parallel Programming. Lecture material: structured patches and halos, overlap, irregular meshes, graph cuts and compressed adjacency, METIS, the four-strip heat program, timing and reproducibility, serial/parallel/overhead decomposition, Amdahl, Gustafson–Barsis and Karp–Flatt. Research extensions: the METIS manual specifies graph representation and partition objectives; MPI 4.1 specifies Cartesian neighbours, derived datatypes, requests and collectives; Gustafson's 1988 paper supplies the scaled-work argument; Karp and Flatt's 1990 paper supplies the effective serial metric and its diagnostic purpose. Original teaching constructions: remainder-aware geometry, the canonical-boundary MPI solver and pointwise serial comparison, surface-to-volume and isoefficiency derivations, checked graph and metric programs, controlled local captures, and six worked exercises.

The numerical state and its owner

The physical model is steady conduction on a unit square with constant conductivity and no internal heat source. Temperature \(u\) is normalized so that the hot top boundary has value 1 and the other three boundaries have value 0. There are \(N\) interior grid points along each coordinate, with spacing \(h=1/(N+1)\). A serial grid contains \((N+2)^2\) doubles in row-major order. The index \(i\) increases downwards and \(j\) to the right; the top edge is \(i=0\), the bottom \(i=N+1\), and the side edges \(j=0,N+1\). Corners are zero and are not read by an interior five-point stencil.

The discrete Laplace equation at an interior point is \(u_{i-1,j}+u_{i+1,j}+u_{i,j-1}+u_{i,j+1}-4u_{i,j}=0\). Jacobi iteration constructs a new array entirely from the old one:

\[ u^{(k+1)}_{i,j}=\tfrac14\left(u^{(k)}_{i-1,j}+u^{(k)}_{i+1,j} +u^{(k)}_{i,j-1}+u^{(k)}_{i,j+1}\right),\qquad 1\le i,j\le N. \tag{16.1} \]

The integer \(k\) counts sweeps, not physical time. The initial interior is zero; boundary values remain fixed. The arrays are named u and unew, and a driver swaps their pointers after a sweep. The serial kernel jacobi_step returns the update norm \(\delta_k=\max_{i,j}|u^{(k+1)}_{i,j}-u^{(k)}_{i,j}|\). A tolerance tol can stop the iteration when this quantity is small, or max_iter can prescribe a fixed sweep count.

The update norm is not the residual of the differential equation. Define the discrete Laplacian \((\Delta_hu)_{i,j}=(u_{i-1,j}+u_{i+1,j}+u_{i,j-1}+u_{i,j+1}-4u_{i,j})/h^2\). Subtract the old value from equation (16.1) to obtain \(u^{(k+1)}-u^{(k)}=(h^2/4)\Delta_hu^{(k)}\). Therefore

\[ \|\Delta_hu^{(k)}\|_\infty=\frac{4\delta_k}{h^2}. \tag{16.2} \]

The subscript infinity means the largest absolute component. Equation (16.2) concerns the old iterate that generated the update. Its factor grows as the grid is refined: a fixed update tolerance does not enforce a fixed differential-equation residual tolerance across different \(N\). It also does not directly measure error against the continuous solution; discretization error remains even when the discrete system is solved accurately.

Let \(p\) denote the number of MPI processes, and let an owned patch be the interior grid cells assigned uniquely to one rank. A halo, or ghost layer, stores copies of adjacent cells owned elsewhere. A physical boundary is prescribed data; a process boundary is an artificial cut across a mathematically continuous interior. Treating a process boundary as a zero-temperature wall would solve a different problem. The central invariant is that, before an interface update, its halo values belong to the same old iterate \(k\) as the locally owned inputs.

For performance, \(T_1\) denotes a stated one-process baseline and \(T_p\) a parallel wall time. Speedup is \(S_p=T_1/T_p\); efficiency is \(E_p=S_p/p\). Work \(W\) remains an operation count. For a fixed number of sweeps it is proportional to \(N^2\). A message of \(m\) bytes has the model cost \(\alpha+\beta m\), where \(\alpha\) is startup seconds and \(\beta\) seconds per byte. A local update takes model time \(c\) seconds. These coefficients depend on hardware, placement and implementation.

The measured execution environment is the earlier Intel Core i5-12450H laptop, gcc 13.3 and Open MPI under WSL 2 Ubuntu 24.04. Its four performance cores and four efficient cores supply twelve unequal logical processors. All inter-rank traffic here is explicitly forced through TCP on the loopback interface, with the self transport available and process binding disabled. These are local transport and scheduling experiments, neither shared-memory-transport measurements nor inter-node cluster measurements. Raw commands, source hashes, UTC times and monotonic endpoints are retained for each capture.

From a global grid to local patches and halos W5L4 1:15

A structured decomposition chooses \(p_r\) process rows and \(p_c\) process columns, with \(p=p_rp_c\). A process has coordinates \((a,z)\), where \(0\le a\lt p_r\) and \(0\le z\lt p_c\). These are logical coordinates; they do not promise physical proximity on a machine. A simple row-major rank map is \(a p_c+z\), but an MPI Cartesian communicator can maintain the mapping and determine neighbours without embedding arithmetic rank assumptions throughout the solver.

The lecture initially assumes exact divisibility. The implementation also handles remainders. Along one dimension divided into \(d\) parts, let \(q=\lfloor N/d\rfloor\) and \(r=N-dq\). Coordinate \(a\) owns \(b_a=q+[a\lt r]\) points beginning at offset \(o_a=aq+\min(a,r)\), where a bracket equals 1 when its condition is true. Consecutive offsets satisfy \(o_{a+1}=o_a+b_a\), the first is zero and the final endpoint is \(N\). Apply the construction independently along rows and columns to tile all \(N^2\) interior cells without duplication or gaps.

A rank with \(b_r\) owned rows and \(b_c\) owned columns allocates \((b_r+2)(b_c+2)\) entries per array. Local owned indices are \(1,\ldots,b_r\) and \(1,\ldots,b_c\); index zero and the final index in each coordinate hold halos or physical boundaries. Local cell \((i,j)\) corresponds to global cell \((o_r+i,o_c+j)\). That translation decides which initial and boundary conditions apply. An interior rank must not independently invent global boundary values for its artificial edges.

For example, \(N=31\) on a \(2\times2\) process grid gives lengths 16 and 15 along each dimension. Patch areas are 256, 240, 240 and 225, whose sum is 961. Equal coordinate spans are impossible because 31 is odd. The imbalance is small in this example, but a timing model must use the largest assigned work, not simply the average \(N^2/p\), when the difference matters. The program rejects decompositions with a process-grid dimension larger than \(N\), avoiding zero-cell patches.

The five-point stencil needs only face neighbours. It does not read diagonal halo corners, even though a rectangular allocation reserves them. A nine-point stencil that includes diagonal entries would need corner information too. A wider stencil needs a thicker halo, and its communication volume grows accordingly. The geometry of dependencies, rather than the shape of an allocation alone, determines which values must move.

A row-major row segment is contiguous, but a column is not. Its successive elements are separated by a stride of \(b_c+2\) doubles. Passing the address of its first entry with a count of \(b_r\) MPI_DOUBLE elements would send a contiguous segment crossing the first row, not the intended column. Either pack the column into a contiguous buffer or describe its layout with a derived datatype. The listing uses MPI_Type_vector(b_r, 1, b_c+2, MPI_DOUBLE, &column), then commits the type before communicating it. The count is the number of blocks, the block length is one, and the stride is in extents of the old datatype, as specified by MPI 4.1, §5.1.

The receive layout may differ from the send layout if their basic-type signatures match. Here both sides use equivalent column descriptions, because horizontal neighbours share the same owned row count. Vertical neighbours share the same owned column count and send contiguous rows. Thus a remainder-aware decomposition still matches message lengths along each interface. Derived datatypes specify memory locations; they do not prove that an implementation avoids internal packing or that they outperform explicit packing.

MPI_Cart_shift supplies north, south, west and east ranks. At a nonperiodic edge it returns MPI_PROC_NULL. A receive from that null process leaves its buffer unchanged, so the preinitialized physical boundary remains in place. This makes the same communication code work at corners, edges and interior patches. If rank reordering were enabled, the program would need to use the Cartesian rank consistently; this implementation disables reordering and still queries coordinates through MPI.

The halo invariant suggests the iteration order exchange–update–swap. Exchange current u faces, compute unew from that complete old state, determine a global update norm, then swap. The lecture's program instead computes new owned values, exchanges their faces, and copies them into the old state. Those orders can represent the same Jacobi sequence if initialization and halo generations are correct. Mixing them carelessly can cause the first sweep or later boundaries to use stale data.

Nonblocking communication offers a legal overlap region. A cell at least one owned cell away from every process face reads no arriving halo. Initiate receives and sends, compute those strictly interior cells, wait for the requests, then compute the patch boundary. Send buffers remain unchanged while active, receive buffers remain unaccessed, and all writes go to unew. When a patch is one or two cells wide, the strict interior can be empty. A correct overlap implementation must still update every owned cell exactly once.

Having work available during communication is different from obtaining a time saving. Progress may require MPI calls, and computation can compete with message handling for memory bandwidth or CPU resources. The lower-bound ideal is roughly the maximum of communication time and independent computation time, plus the dependent boundary work; a nonoverlapped schedule resembles their sum. Neither expression includes all real overhead. The program compares both schedules while checking identical numerical results, leaving any performance conclusion to actual measurements.

Irregular meshes become weighted graph problems W5L4 12:13

Geometric cuts work well when work density is nearly uniform. An unstructured mesh can place many small tetrahedra around a feature and few large ones elsewhere. Equal physical volumes then contain unequal numbers of elements. If each element costs approximately the same to process, balancing volume fails to balance computation. If element costs differ because of polynomial degree, chemistry or nonlinear iterations, even balancing element counts can fail.

Represent the computation as a graph \(G=(V,\mathcal E)\). A vertex \(v\in V\) represents one element or unknown block; an edge \(\{v,w\}\in\mathcal E\) represents an interaction requiring data. The choice of graph matters. In a face-adjacent dual graph of a conforming tetrahedral mesh, an interior tetrahedron has at most four face neighbours because it has four faces. This bound does not hold for every graph built from that mesh, such as a node-adjacency graph. It is therefore a property of the modeling choice, not of all unstructured calculations.

A partition function \(P:V\to\{0,\ldots,p-1\}\) assigns vertices to processes. A vertex weight \(a_v\) can estimate computational cost. Process \(k\)'s modeled load is \(A_k=\sum_{P(v)=k}a_v\); balancing seeks to keep \(\max_k A_k\) close to the mean \(\sum_va_v/p\). An edge weight \(w_{vw}\) can estimate communication volume or another penalty for separating its endpoints. The weighted cut is \(\sum_{\{v,w\}\in\mathcal E,\ P(v)\ne P(w)}w_{vw}\), counting each undirected edge once.

The two objectives compete. Assigning all vertices to one process makes the cut zero and generally destroys balance. Assigning equal numbers of vertices arbitrarily balances counts while potentially cutting many interactions. A practical formulation constrains allowable imbalance and then minimizes a cut or communication-volume objective. The METIS 5.1 manual, §§3 and 5.7, distinguishes these objectives and supports vertex and edge weights. A heuristic partition is a useful candidate, not a certificate of a globally optimal layout.

Communication volume and cut edges are also not identical in every application. Several cut edges can need the same remote vertex value, which might be sent once in an aggregated message. Conversely, one cut edge might carry a large block or be exercised repeatedly during an iteration. Message startup depends on the number of peer messages after aggregation, not merely the edge count. A graph weight model should approximate the algorithm's actual exchange, and a resulting partition should still be evaluated in the program.

The adjacency structure is sparse: most pairs of elements do not interact directly. With \(n_v=|V|\) vertices and \(n_e=|\mathcal E|\) undirected edges, a dense adjacency matrix has \(n_v^2\) entries. Compressed sparse row, or CSR, stores an offset array xadj of length \(n_v+1\) and a neighbour array adjncy of length \(2n_e\). Vertex \(v\)'s neighbours occupy the half-open interval adjncy[xadj[v]:xadj[v+1]]. Its degree is the difference of those offsets. Every undirected edge is stored in both directions.

The lecture's example has three rows and five columns of vertices, numbered row by row from 0 to 14. It has \(3(5-1)+5(3-1)=22\) undirected edges and 44 neighbour entries. Thus CSR needs \(16+44=60\) integer entries, compared with 225 dense entries, excluding optional weights and container overhead. For a million tetrahedra with degree at most four, the adjacency entries grow linearly rather than quadratically. The exact byte saving depends on integer width and representation; counting entries avoids pretending that a Python list has C-array storage cost.

The following pure-Python program reconstructs that graph and its CSR offsets, checks symmetry and round-trip adjacency, then compares two explicit three-way partitions. Row strips have five vertices each. Column strips of widths two, two and one have loads six, six and three. The latter may cut fewer edges while having worse balance. The program does not call METIS and makes no claim that either candidate is an optimal partition.

"""Construct the lecture's 3-by-5 graph; compare two declared partitions."""
rows, cols = 3, 5
neighbors = []
for i in range(rows):
    for j in range(cols):
        ids = []
        for di, dj in ((-1, 0), (1, 0), (0, -1), (0, 1)):
            a, b = i + di, j + dj
            if 0 <= a < rows and 0 <= b < cols:
                ids.append(a * cols + b)
        neighbors.append(sorted(ids))
xadj = [0]
adjncy = []
for ids in neighbors:
    adjncy.extend(ids)
    xadj.append(len(adjncy))
assert xadj[-1] == 44
assert all(v in neighbors[u] for v, ns in enumerate(neighbors) for u in ns)
assert all(adjncy[xadj[v]:xadj[v+1]] == neighbors[v] for v in range(15))
edges = [(u, v) for u, ns in enumerate(neighbors) for v in ns if u < v]
print("vertices:", len(neighbors), "undirected edges:", len(edges))
print("xadj:", xadj)
print("CSR entries:", len(xadj)+len(adjncy), "dense entries:", 15*15)
for name, labels in [
    ("row strips", [v // cols for v in range(15)]),
    ("column strips", [min((v % cols) // 2, 2) for v in range(15)]),
]:
    loads = [labels.count(k) for k in range(3)]
    cut = sum(labels[u] != labels[v] for u, v in edges)
    print(f"{name}: loads={loads} cut={cut} max/mean={max(loads)/5:.2f}")

vertices: 15 undirected edges: 22
xadj: [0, 2, 5, 8, 11, 13, 16, 20, 24, 28, 31, 33, 36, 39, 42, 44]
CSR entries: 60 dense entries: 225
row strips: loads=[5, 5, 5] cut=10 max/mean=1.00
column strips: loads=[6, 6, 3] cut=6 max/mean=1.20

The comparison is a small diagnostic of the formulation. A low cut is insufficient without the loads, and equal loads are insufficient without the cut. In a real mesh the vertex weights, edge weights and constraints can represent different physical workloads, memory footprints and message sizes. The METIS manual's graph format supplies arrays for those quantities; choosing meaningful weights remains part of the simulation's design.

The partitioner also does not create MPI communication by itself. Once a partition assigns ownership, the application must build local numbering, identify remote neighbours, allocate halos, and establish the send and receive lists. Repartitioning a changing mesh adds migration costs. For a static structured problem those preparations can be done once, while adaptive calculations may need to revisit whether the expected savings justify moving data.

A distributed Jacobi sweep must preserve the serial recurrence W5L5 3:54

The heat demonstration uses four row strips, 1000 interior rows and columns, and 1000 fixed iterations. Its boundary conditions differ from this book's canonical case: the top and left are zero, while the right and bottom vary linearly towards 100. Its arrays are single precision. The implementation below instead retains the book's top-one, other-edges-zero conditions and doubles. Its output therefore is not a reproduction of the lecture's final temperature trace; it tests the same decomposition mechanism on a deliberately standardized numerical problem.

The displayed update reads four neighbours from told and writes t. This is Jacobi averaging. The introductory description calls it successive over-relaxation, but the displayed two-array recurrence does not implement a general SOR update with a relaxation parameter and sequentially updated neighbours. The classification matters: communication schedules legal for Jacobi need not preserve Gauss–Seidel or SOR semantics.

The displayed halo code also issues blocking sends before its receives. If standard sends happen to buffer the 1000-float rows, the example can finish. If sends require matching receives, adjacent ranks can wait on each other before reaching those receives. A barrier after the exchange cannot repair a deadlock before it. The listing uses MPI_Sendrecv for blocking mode or posts all nonblocking receives and sends before waiting, following the safe patterns of Chapter 14.

Configuration is read by World rank 0 and broadcast. The parameters are \(N\), max_iter, communication mode, update tolerance and a timing flag. Modes 0 and 1 use row strips; modes 2 and 3 use a near-square Cartesian grid. Even modes exchange before all computation; odd modes compute the strict interior while requests are active. Sizes and iteration counts are bounded, and the process grid must have nonempty patches. The initial physical boundaries are installed in both arrays so they survive pointer swaps.

Each sweep computes a local maximum update, then MPI_Allreduce with MPI_MAX supplies one common global norm. Every rank therefore makes the same stopping decision. A rank stopping on its local norm alone could leave a neighbour waiting for the next halo. The collective is retained even in fixed-sweep timing runs, so its cost is part of the measured algorithm. A production fixed-iteration benchmark could omit it, but that would be a different measured kernel.

The full serial reference runs on rank 0 before the timed MPI kernel. After the distributed solve, each rank packs its owned cells and MPI_Gatherv collects the variable counts. Rank 0 reconstructs global positions from Cartesian coordinates and compares every interior value with the serial iterate, checks that the iteration counts and update norms agree, and rejects nonfinite results. The comparison tolerance is \(10^{-14}\). A checksum alone would not detect compensating errors in different cells.

The listing combines nine correctness cases and eight timed configurations. It covers unequal blocks, one-cell patches, one rank, all four modes and convergence. Timed configurations use 200 sweeps; they do not claim a converged physical solution. Printed timing lines are capture 4 of four sequential captures, and variable timings are checked by return code. Numerical checks inside the program still fail the job on an incorrect result. Each run writes only standard output; no grid files or external inputs are needed.

#include <mpi.h>
#include <math.h>
#include <stdio.h>
#include <stdlib.h>

#define IDX(i,j) ((size_t)(i) * (N + 2) + (j))
#define AT(i,j) ((size_t)(i) * stride + (j))

static int block_size(int N, int parts, int coord)
{
    return N / parts + (coord < N % parts);
}

static int block_start(int N, int parts, int coord)
{
    int rem = N % parts;
    return coord * (N / parts) + (coord < rem ? coord : rem);
}

double jacobi_step(int N, const double *u, double *unew)
{
    double delta = 0;
    for (int i = 1; i <= N; ++i)
        for (int j = 1; j <= N; ++j) {
            double v = 0.25 * (u[IDX(i-1,j)] + u[IDX(i+1,j)]
                             + u[IDX(i,j-1)] + u[IDX(i,j+1)]);
            unew[IDX(i,j)] = v;
            delta = fmax(delta, fabs(v - u[IDX(i,j)]));
        }
    return delta;
}

static double update_region(int stride, const double *u, double *unew,
                            int i0, int i1, int j0, int j1)
{
    double delta = 0;
    for (int i = i0; i <= i1; ++i)
        for (int j = j0; j <= j1; ++j) {
            double v = 0.25 * (u[AT(i-1,j)] + u[AT(i+1,j)]
                             + u[AT(i,j-1)] + u[AT(i,j+1)]);
            unew[AT(i,j)] = v;
            delta = fmax(delta, fabs(v - u[AT(i,j)]));
        }
    return delta;
}

static double *new_grid(size_t count, MPI_Comm comm)
{
    double *a = calloc(count, sizeof *a);
    if (!a) MPI_Abort(comm, 2);
    return a;
}

static void exchange(double *u, int nr, int nc, int stride,
                     const int peer[4], MPI_Datatype column, MPI_Comm comm)
{
    MPI_Sendrecv(&u[AT(1,1)], nc, MPI_DOUBLE, peer[0], 10,
                 &u[AT(nr+1,1)], nc, MPI_DOUBLE, peer[1], 10,
                 comm, MPI_STATUS_IGNORE);
    MPI_Sendrecv(&u[AT(nr,1)], nc, MPI_DOUBLE, peer[1], 11,
                 &u[AT(0,1)], nc, MPI_DOUBLE, peer[0], 11,
                 comm, MPI_STATUS_IGNORE);
    MPI_Sendrecv(&u[AT(1,1)], 1, column, peer[2], 12,
                 &u[AT(1,nc+1)], 1, column, peer[3], 12,
                 comm, MPI_STATUS_IGNORE);
    MPI_Sendrecv(&u[AT(1,nc)], 1, column, peer[3], 13,
                 &u[AT(1,0)], 1, column, peer[2], 13,
                 comm, MPI_STATUS_IGNORE);
}

static void start_exchange(double *u, int nr, int nc, int stride,
                           const int peer[4], MPI_Datatype column,
                           MPI_Comm comm, MPI_Request req[8])
{
    MPI_Irecv(&u[AT(nr+1,1)], nc, MPI_DOUBLE, peer[1], 10, comm, &req[0]);
    MPI_Irecv(&u[AT(0,1)], nc, MPI_DOUBLE, peer[0], 11, comm, &req[1]);
    MPI_Irecv(&u[AT(1,nc+1)], 1, column, peer[3], 12, comm, &req[2]);
    MPI_Irecv(&u[AT(1,0)], 1, column, peer[2], 13, comm, &req[3]);
    MPI_Isend(&u[AT(1,1)], nc, MPI_DOUBLE, peer[0], 10, comm, &req[4]);
    MPI_Isend(&u[AT(nr,1)], nc, MPI_DOUBLE, peer[1], 11, comm, &req[5]);
    MPI_Isend(&u[AT(1,1)], 1, column, peer[2], 12, comm, &req[6]);
    MPI_Isend(&u[AT(1,nc)], 1, column, peer[3], 13, comm, &req[7]);
}

int main(int argc, char **argv)
{
    MPI_Init(&argc, &argv);
    int world_rank, p;
    MPI_Comm_rank(MPI_COMM_WORLD, &world_rank);
    MPI_Comm_size(MPI_COMM_WORLD, &p);
    int config[4] = {31, 200, 0, 0};
    double tol = 0;
    if (world_rank == 0) {
        if (argc > 1) config[0] = atoi(argv[1]); /* N: interior grid size */
        if (argc > 2) config[1] = atoi(argv[2]); /* max_iter */
        if (argc > 3) config[2] = atoi(argv[3]); /* 0/1 strips; 2/3 tiles; odd=overlap */
        if (argc > 4) tol = atof(argv[4]);      /* 0: fixed sweep count */
        if (argc > 5) config[3] = atoi(argv[5]); /* print variable timings */
    }
    MPI_Bcast(config, 4, MPI_INT, 0, MPI_COMM_WORLD);
    MPI_Bcast(&tol, 1, MPI_DOUBLE, 0, MPI_COMM_WORLD);
    int N = config[0], max_iter = config[1], mode = config[2], timed = config[3];
    if (N < 1 || N > 1024 || max_iter < 1 || max_iter > 20000 ||
        mode < 0 || mode > 3 || !isfinite(tol) || tol < 0 || p > 64)
        MPI_Abort(MPI_COMM_WORLD, 1);
    int dims[2] = {0, 0}, periodic[2] = {0, 0};
    if (mode < 2) { dims[0] = p; dims[1] = 1; }
    else MPI_Dims_create(p, 2, dims);
    if (dims[0] > N || dims[1] > N) MPI_Abort(MPI_COMM_WORLD, 1);
    MPI_Comm comm;
    MPI_Cart_create(MPI_COMM_WORLD, 2, dims, periodic, 0, &comm);
    int rank, coord[2], peer[4];
    MPI_Comm_rank(comm, &rank);
    MPI_Cart_coords(comm, rank, 2, coord);
    MPI_Cart_shift(comm, 0, 1, &peer[0], &peer[1]); /* north, south */
    MPI_Cart_shift(comm, 1, 1, &peer[2], &peer[3]); /* west, east */
    int nr = block_size(N, dims[0], coord[0]);
    int nc = block_size(N, dims[1], coord[1]);
    int row0 = block_start(N, dims[0], coord[0]);
    int stride = nc + 2;
    double *u = new_grid((size_t)(nr+2)*stride, comm);
    double *unew = new_grid((size_t)(nr+2)*stride, comm);
    if (row0 == 0)
        for (int j = 1; j <= nc; ++j) u[AT(0,j)] = unew[AT(0,j)] = 1;
    MPI_Datatype column;
    MPI_Type_vector(nr, 1, stride, MPI_DOUBLE, &column);
    MPI_Type_commit(&column);

    double *reference = NULL, serial_delta = 0, serial_seconds = 0;
    int serial_iters = 0;
    if (rank == 0) {
        reference = new_grid((size_t)(N+2)*(N+2), comm);
        double *next = new_grid((size_t)(N+2)*(N+2), comm);
        for (int j = 1; j <= N; ++j) reference[IDX(0,j)] = next[IDX(0,j)] = 1;
        double start = MPI_Wtime();
        do {
            serial_delta = jacobi_step(N, reference, next);
            double *swap = reference; reference = next; next = swap;
            ++serial_iters;
        } while (serial_iters < max_iter && (tol == 0 || serial_delta >= tol));
        serial_seconds = MPI_Wtime() - start;
        free(next);
    }

    MPI_Barrier(comm); /* align the beginning of the measured kernel */
    double start = MPI_Wtime(), delta = 0;
    int iter = 0;
    do {
        double local_delta;
        if (mode % 2 == 0) {
            exchange(u, nr, nc, stride, peer, column, comm);
            local_delta = update_region(stride, u, unew, 1, nr, 1, nc);
        } else {
            MPI_Request req[8];
            start_exchange(u, nr, nc, stride, peer, column, comm, req);
            local_delta = update_region(stride, u, unew, 2, nr-1, 2, nc-1);
            MPI_Waitall(8, req, MPI_STATUSES_IGNORE);
            local_delta = fmax(local_delta, update_region(stride, u, unew, 1, 1, 1, nc));
            if (nr > 1)
                local_delta = fmax(local_delta, update_region(stride, u, unew, nr, nr, 1, nc));
            for (int i = 2; i < nr; ++i) {
                local_delta = fmax(local_delta, update_region(stride, u, unew, i, i, 1, 1));
                if (nc > 1)
                    local_delta = fmax(local_delta, update_region(stride, u, unew, i, i, nc, nc));
            }
        }
        MPI_Allreduce(&local_delta, &delta, 1, MPI_DOUBLE, MPI_MAX, comm);
        double *swap = u; u = unew; unew = swap;
        ++iter;
    } while (iter < max_iter && (tol == 0 || delta >= tol));
    double seconds = MPI_Wtime() - start, parallel_seconds;
    MPI_Reduce(&seconds, &parallel_seconds, 1, MPI_DOUBLE, MPI_MAX, 0, comm);

    double *packed = new_grid((size_t)nr*nc, comm);
    for (int i = 1; i <= nr; ++i)
        for (int j = 1; j <= nc; ++j)
            packed[(size_t)(i-1)*nc+j-1] = u[AT(i,j)];
    int *counts = NULL, *displs = NULL;
    double *all = NULL;
    if (rank == 0) {
        counts = malloc(p * sizeof *counts);
        displs = malloc(p * sizeof *displs);
        if (!counts || !displs) MPI_Abort(comm, 2);
        int offset = 0;
        for (int k = 0; k < p; ++k) {
            int xy[2];
            MPI_Cart_coords(comm, k, 2, xy);
            counts[k] = block_size(N, dims[0], xy[0]) * block_size(N, dims[1], xy[1]);
            displs[k] = offset;
            offset += counts[k];
        }
        if (offset != N*N) MPI_Abort(comm, 3);
        all = new_grid((size_t)N*N, comm);
    }
    MPI_Gatherv(packed, nr*nc, MPI_DOUBLE, all, counts, displs, MPI_DOUBLE, 0, comm);
    int good = 1;
    if (rank == 0) {
        double error = 0;
        int compared = 0;
        for (int k = 0; k < p; ++k) {
            int xy[2];
            MPI_Cart_coords(comm, k, 2, xy);
            int rows = block_size(N, dims[0], xy[0]), cols = block_size(N, dims[1], xy[1]);
            int r0 = block_start(N, dims[0], xy[0]), c0 = block_start(N, dims[1], xy[1]);
            for (int i = 0; i < rows; ++i)
                for (int j = 0; j < cols; ++j) {
                    double v = all[displs[k] + i*cols+j];
                    if (!isfinite(v)) good = 0;
                    error = fmax(error, fabs(v-reference[IDX(r0+i+1,c0+j+1)]));
                    ++compared;
                }
        }
        good &= error <= 1e-14 && delta == serial_delta && iter == serial_iters;
        good &= compared == N*N;
        printf("N=%d p=%d grid=%dx%d mode=%d iterations=%d checked=%d error=%.1e status=%s\n",
               N, p, dims[0], dims[1], mode, iter, compared, error, good ? "ok" : "FAILED");
        if (timed)
            printf("timing serial_s=%.9f mpi_max_s=%.9f serial_over_mpi=%.4f\n",
                   serial_seconds, parallel_seconds, serial_seconds/parallel_seconds);
    }
    MPI_Bcast(&good, 1, MPI_INT, 0, comm);
    free(all); free(counts); free(displs); free(reference);
    free(packed); free(u); free(unew);
    MPI_Type_free(&column);
    MPI_Comm_free(&comm);
    if (!good) MPI_Abort(MPI_COMM_WORLD, 4);
    MPI_Finalize();
    return 0;
}

Time the operation the speedup is meant to describe W5L5 22:23

The lecture places a barrier in each iteration and prints individual process times. The barrier ensures every rank has entered before any returns. It does not transfer halos or make incompatible message tags match. In this solver, completed neighbour exchanges establish the data needed by each update, and the all-reduce establishes a common stopping norm. An additional end-of-sweep barrier is unnecessary for the algorithm's data dependencies. Removing every synchronization would be wrong; retaining the necessary communication is the reason the extra barrier can be omitted.

The timing starts after a barrier, immediately before the sweep loop, and ends before the maximum-time reduction and final gather. The maximum of the ranks' own elapsed durations is reported as mpi_max_s. No subtraction of timestamps from different clocks is used. Barrier-return skew means this is a maximum local kernel duration after start alignment, not a perfectly reconstructed global trace. Setup, reference computation, packing, verification, allocation and launcher startup are excluded.

The printed serial reference time measures the ordinary jacobi_step driver for the same numerical work. Its ratio to the MPI time is labeled serial_over_mpi. In multi-rank jobs the other ranks wait for rank 0 at the start barrier and may consume CPU time in MPI progress; this reference timing is therefore not an isolated serial-process benchmark. That reference is rerun in every job and can vary with placement, frequency and cache conditions. For a strong-scaling curve, use a single declared baseline within a capture: the one-rank MPI strip kernel at \(N=512\). Do not silently select each job's different serial time as the numerator of one curve.

Surface, volume and the terms that stop scaling W5L6 4:45

The performance lecture separates inherently sequential work, divisible parallel work and parallel overhead. Write these times as \(\sigma(N)\), \(\phi(N)\) and \(\kappa(N,p)\), respectively. The first two are durations in a one-process reference execution; \(\kappa\) is additional elapsed time in the parallel run. Under the idealized assumptions of identical processing rates and perfectly balanced divisible work, \(T_1=\sigma+\phi\) and \(T_p=\sigma+\phi/p+\kappa\). Imperfect balance can increase \(T_p\); a faster cache regime can invalidate the unchanged-rate assumption.

The lecture's image-processing example applies a \(3\times3\) template, with nine multiply-add contributions per pixel. If one contribution takes \(t_c\) seconds, serial cost is \(9t_cN^2\), not nine floating-point operations unless the counting convention says so. Two adjacent strips exchange a layer of pixels with their neighbours. This mirrors the Jacobi ownership pattern, although a true nine-point dependency also requires corner information at two-dimensional patch junctions. The cost model must follow the actual stencil rather than reusing a five-point communication list blindly.

For one Jacobi sweep, ignore physical-edge savings initially and consider a strip with two neighbours. It owns approximately \(N^2/p\) cells and sends two rows of \(N\) values. Let \(b=8\) bytes per double. The outgoing face data are \(2bN\) bytes, giving communicated values per owned cell \(2p/N\). A square interior patch has side \(N/\sqrt p\), four neighbours and outgoing data \(4bN/\sqrt p\), giving ratio \(4\sqrt p/N\). This is the surface-to-volume argument: boundary length grows more slowly than area for compact patches.

Message count modifies that conclusion. Assume directional traffic can proceed bidirectionally without doubling the per-face cost, distinct faces are serialized for costing, and contention is absent. Then approximate halo times are \(H_{\mathrm{strip}}=2\alpha+2b\beta N\) and \(H_{\mathrm{tile}}=4\alpha+4b\beta N/\sqrt p\). These are interior-patch models; physical-edge ranks have fewer neighbours, and actual overlap or full-duplex behaviour can alter the phase count. For the \(2\times2\) process grid every patch lies at a physical corner and has two neighbours, so charging four real messages per rank there would be incorrect.

A global maximum adds its own cost. A simple logarithmic model uses \(\tau\log_2p\), where \(\tau\) is seconds per reduction level. This is a model, not a guarantee that a particular MPI implementation always uses that exact algorithm. Combining the terms gives

\[ T_p^{\mathrm{sweep}}\approx \frac{cN^2}{p}+H(N,p)+\tau\log_2p. \tag{16.3} \]

At fixed \(N\), compute time shrinks with \(p\), while startup and reduction can remain or grow. Strip payload per interior rank does not shrink at all. A two-dimensional decomposition reduces the payload, but its four startups can dominate short messages. The correct question is whether the saved byte cost exceeds the extra startup cost under the assumptions of equation (16.3).

The next program uses declared hypothetical coefficients: \(\alpha=10\ \mu\mathrm{s}\), \(\beta=0.1\ \mathrm{ns/byte}\), \(c=2\ \mathrm{ns/cell}\), and \(\tau=5\ \mu\mathrm{s}\). With \(N=1024,p=16\), both decompositions have interior ranks. The script compares the model costs and solves the equality of their halo terms. None of these coefficients is fitted to the local benchmark.

Amdahl bounds one fixed problem under a stated baseline W5L6 9:17

Define the serial fraction \(f=\sigma/T_1\), measured relative to the one-process execution time for the fixed problem. Ignoring nonnegative overhead and assuming the parallel part divides perfectly gives \(T_p\ge T_1(f+(1-f)/p)\). Dividing \(T_1\) by this expression yields

\[ S_p\le\frac{1}{f+(1-f)/p}. \tag{16.4} \]

If \(f\gt0\), taking \(p\) arbitrarily large gives the limiting bound \(1/f\). For finite \(p\) and a nonzero parallel fraction, the speedup is strictly below that limit. When \(f=0\), the bound is \(p\), and writing \(1/f\) is meaningless. When \(f=1\), the bound is one. These endpoint cases prevent an algebraic expression from being applied beyond its domain.

The lecture's 90%-parallel example has \(f=0.1\). At eight processes the bound is \(1/(0.1+0.9/8)=4.705882\), while its infinite-process limit is ten. Increasing process count cannot remove time spent in the unchanged serial component. Positive communication and synchronization costs reduce the achieved result further within the model.

A second example sets \(\sigma(n)=18\,000+n\) microseconds and \(\phi(n)=n^2/100\) microseconds, where \(n\) is that illustrative problem-size parameter, distinct from the grid dimension \(N\). At \(n=10\,000\), \(\sigma=28\,000\), \(\phi=1\,000\,000\), and \(T_1=1\,028\,000\) microseconds. The limiting speedup is \(T_1/\sigma=36.714286\); at eight processes it is \(1\,028\,000/(28\,000+125\,000)\approx6.719\). A larger problem can have a smaller serial fraction because its parallel component grows faster, without contradicting the fixed-problem bound.

The fraction is a fraction of reference execution time, not automatically a fraction of source lines or floating-point operations. Different operations cost different amounts, and memory stalls can dominate. The simple model also presumes comparable processing rates. Cache effects can make a subdivided workload faster per cell and yield a measured speedup above \(p\) relative to a particular baseline. Such a result calls for explaining the baseline and changed rate; it does not turn \(f\) into a negative fraction of genuinely sequential instructions.

The derivation is reconstructed here from the time decomposition. Gustafson's original 1988 paper explicitly contrasts the fixed-size formula with a scaled-size alternative. The two viewpoints ask different workload questions. Neither is a machine-independent promise that every algorithm reaches the optimistic bound.

Scaled work and weak scaling require the work to be specified W5L6 15:46

Suppose a parallel execution of a chosen larger job spends time \(t_s\) in inherently serial work and \(t_q\) in parallel work across \(p\) identical processors, ignoring overhead. Its duration is \(t_s+t_q\). A hypothetical one-process execution of that same larger job would take \(t_s+pt_q\). Define the scaled serial fraction \(f_s=t_s/(t_s+t_q)\), measured in the parallel run. Then

\[ S_{\mathrm{scaled}}=\frac{t_s+pt_q}{t_s+t_q} =f_s+p(1-f_s)=p-(p-1)f_s. \tag{16.5} \]

For \(p=64,f_s=0.05\), equation (16.5) gives 60.85. This does not insert 0.05 into equation (16.4): the denominators defining \(f\) and \(f_s\) differ. For the same idealized job, \(f=f_s/[f_s+p(1-f_s)]\). Substituting that relation makes the two speedup expressions agree. Their distinction is how problem families and runtime budgets are chosen, not a contradiction in arithmetic.

Strong scaling holds the problem and numerical workload fixed while increasing \(p\). The \(N=512\), 200-sweep strip series is such a test. Weak scaling grows work approximately in proportion to \(p\), ideally keeping work per process and runtime fixed. For a two-dimensional fixed-sweep stencil, \(N^2/p\) is a useful local-work measure; square patches keep their side length fixed when \(N\) grows as \(\sqrt p\).

A full converged solve is a different workload. For the standard Jacobi error iteration on this square, its slowest eigenvalue magnitude is \(\rho=\cos(\pi/(N+1))\). For an error component in that slow mode, reducing it by a fixed factor requires a sweep count proportional to \(1/(1-\rho)\). Since \(1-\cos x\sim x^2/2\), the count grows like \(N^2\). The fixed-accuracy solve can therefore require work proportional to \(N^4\), even though one sweep costs \(N^2\). This statement concerns asymptotic Jacobi convergence under the stated grid and error-mode model, not a fixed iteration count or a universal property of all solvers.

Consequently, keeping cells per rank constant need not keep time to a converged solution constant. Tolerances must also be compared at matching residual or error scales, because equation (16.2) changes with \(h\). A weak-scaling report should identify the number of sweeps, stopping criterion, mesh family and accuracy target. A faster multigrid or Krylov solver can change the algorithmic scaling more than rearranging the same Jacobi messages.

Effective serial fractions diagnose symptoms, not unique causes W5L6 19:42

Given an observed speedup \(S_p\) for \(p\gt1\), define the Karp–Flatt effective serial fraction

\[ e_p=\frac{1/S_p-1/p}{1-1/p}. \tag{16.6} \]

It is the value that makes an Amdahl-shaped curve pass through that measurement. Starting from \(1/S_p=e_p+(1-e_p)/p\), move \(1/p\) to the left and divide by \(1-1/p\). No assumption about the actual source of overhead is needed for this algebra. Its diagnostic interpretation depends on using a consistent baseline and comparable problem sizes. Karp and Flatt (1990), pp. 539–540, introduce this experimentally determined quantity and discuss effects of imbalance and synchronization.

Under the earlier additive model, \(T_p/T_1=f+(1-f)/p+\kappa/T_1\). Substituting into (16.6) gives \(e_p=f+\kappa/[T_1(1-1/p)]\). The denominator factor matters. The lecture slide initially writes an effective fraction as \((\sigma+\kappa)/(\sigma+\phi)\), then later derives equation (16.6). Those are not generally identical under its own stated time model. The corrected expression follows directly from substitution and makes the two definitions consistent.

The first lecture table lists speeds 1.82, 2.50, 3.08, 3.57, 4.00, 4.38 and 4.71 for two through eight processes. The corresponding effective fractions are approximately 0.1, with small differences caused by the rounded speed inputs. The second table ends at the same 4.71 but has an effective fraction rising from about 0.07 to 0.1. The next program recomputes both tables and the earlier law examples from their stated numbers. Increasing \(e_p\) can signal growing overhead, but can also reflect imbalance, changing processor rates, cache effects or an inconsistent baseline. Negative \(e_p\) is possible when a chosen baseline gives superlinear speedup; it is not a negative amount of serial code. Treat the metric as a compact description of the timing curve, then use profiles, message counts and controlled experiments to test causal explanations.

Isoefficiency extension. The lecture announces this topic but does not develop it in the supplied discussion. An isoefficiency function asks how total work must grow with \(p\) to retain a fixed efficiency \(0\lt E_\star\lt1\). For \(T_1=cN^2\) per sweep and nonnegative overhead \(H+\tau\log_2p\), equation (16.3) gives \(E_p=1/[1+p(H+\tau\log_2p)/(cN^2)]\). Fixing \(E_p=E_\star\) therefore fixes the overhead-to-useful-work ratio, rather than fixing local cell count by assumption.

For strips, its byte term requires \(N^2\) to grow at least proportionally to \(pN\), so \(N=\Omega(p)\) and per-sweep work \(W=\Omega(p^2)\), with fixed positive coefficients. Startup alone requires \(N^2=\Omega(p)\); the logarithmic collective requires \(N^2=\Omega(p\log p)\). The strip byte constraint dominates these asymptotically. The notation \(\Omega(g(p))\) means an eventual lower bound by a positive constant times \(g(p)\) in this model.

For square tiles, the byte term requires \(N^2=\Omega(N\sqrt p)\), hence \(N^2=\Omega(p)\), and startup has the same requirement. If the global norm is reduced every sweep with the logarithmic cost, it strengthens this to \(W=\Omega(p\log p)\). Without that collective term the idealized tile model needs only \(W=\Omega(p)\). These conclusions depend on serialized face costs, stable per-cell rates and the assumed reduction model; they do not predict the full convergence work or prove that real networks remain contention-free as \(p\) grows.

A barrier is needed at every sweep end.The data dependencies require completed halos and a coordinated stopping rule. An extra barrier is unnecessary in the supplied implementation.
Effective serial fraction equals \((\sigma+\kappa)/(\sigma+\phi)\).Inconsistent with the subsequent Karp–Flatt inversion when \(\kappa\ne0\). The corrected expression has overhead factor \(1/(1-1/p)\).
Constant effective fraction proves inherent sequential work.Consistent with that explanation but not unique; an explicit overhead-only model gives the same curve.

Pointwise agreement establishes preservation of the reference iteration for the tested inputs. It does not prove the continuous boundary-value solution or a universal floating-point accuracy bound. The canonical boundary values, precision, safe exchange and configurable decomposition differ from the lecture demonstration, so its temperature trace and approximately 2.61-second displayed timing are not direct comparison targets.

Strong and weak results are local TCP-loopback samples with fixed sweeps, a reduction every sweep and unbound processes on a hybrid CPU. The repeat ranges demonstrate variability and do not provide confidence intervals. The surface model uses declared hypothetical coefficients, and the isoefficiency statements hold within its assumptions. Multi-node transport, bandwidth contention, fault tolerance, adaptive repartitioning and convergence-accelerating solvers remain unmeasured.

Exercises

Exercise 1 (derive). Generalize the halo ratio to a \(d\)-dimensional grid with \(N\) owned interior points per coordinate. Assume \(p\) is a perfect \(d\)-th power, patches are cubes, the stencil needs one face layer, and the patch has neighbours on all \(2d\) faces. Compare with a slab decomposition that splits only one coordinate.

Solution

The cube side is \(N/p^{1/d}\), and its owned volume is \(N^d/p\). Each face has \((N/p^{1/d})^{d-1}\) values, so outgoing halo values are \(2dN^{d-1}/p^{(d-1)/d}\). Dividing by owned volume gives \(2dp^{1/d}/N\). A slab has volume \(N^d/p\) but two communicated faces of \(N^{d-1}\) values, giving ratio \(2p/N\). Multiply either count by bytes per value to obtain outgoing payload bytes.

Compact patches therefore improve the asymptotic byte ratio with process count, at the price of more neighbour messages. Fixed local cube side keeps this face ratio constant as \(p\) grows. That alone does not prove constant iteration time: global reductions, routing contention and process startup are absent from the ratio. Physical-edge patches have fewer real faces, and wider or diagonal stencils change the payload calculation.

Exercise 2 (compute). A fixed job has \(T_1=10\) seconds and \(T_8=2.5\) seconds. Compute speedup, efficiency and Karp–Flatt fraction. If independent profiling identifies true serial fraction \(f=0.05\) and the additive model otherwise applies, find the overhead \(\kappa\). Check by reconstructing the time.

Solution

The speedup is \(S_8=10/2.5=4\), efficiency \(E_8=4/8=0.5\), and \(e_8=(1/4-1/8)/(1-1/8)=1/7\approx0.142857\). From \(e_8=f+\kappa/[T_1(1-1/8)]\), obtain \(\kappa=(1/7-0.05)(10)(7/8)=0.8125\) seconds. Reconstructing gives serial time \(0.5\), parallel useful time \(9.5/8=1.1875\), plus overhead \(0.8125\), totaling 2.5 seconds.

The shortcut \((\sigma+\kappa)/T_1\) would give \((0.5+0.8125)/10=0.13125\), which differs from the metric actually inferred from the speedup. This numerically checks the missing factor. The inferred overhead is conditional on the independent serial-fraction estimate and the unchanged-rate additive model; two elapsed times alone cannot supply all those causal quantities.

Exercise 3 (counterexample). Construct two different time decompositions that give constant effective fraction 0.2 for every \(p\gt1\). In one, the overhead is zero; in the other, the true serial fraction is zero. Explain what an observed constant metric can establish.

Solution

Normalize \(T_1=1\). The first model has \(f=0.2,\kappa=0\), giving \(T_p=0.2+0.8/p\). The second has \(f=0\) and \(\kappa=0.2(1-1/p)\), giving \(T_p=1/p+0.2(1-1/p)=0.2+0.8/p\). Its overhead is nonnegative, vanishes at one process and grows towards 0.2. Substitution into equation (16.6) gives \(e_p=0.2\) in both cases.

The entire timing curve is identical, so neither adding more process counts nor reducing timing noise distinguishes these models. The observation establishes consistency with an Amdahl-shaped curve, not a unique serial-code fraction. Additional evidence could measure time in a known serial phase or alter the communication protocol while preserving the numerical work.

Exercise 4 (diagnose an assumption). Two solves stop when the update norm is below \(10^{-5}\), first at \(N=31\), then at \(N=127\). A report says they have the same residual accuracy. Evaluate that claim and choose update tolerances that enforce a discrete-Laplacian maximum norm below \(10^{-3}\) for the old iterate.

Solution

Equation (16.2) multiplies the update by \(4(N+1)^2\). The two update thresholds imply old-iterate residual bounds \(4(32)^2(10^{-5})=0.04096\) and \(4(128)^2(10^{-5})=0.65536\), differing by sixteen. Equal update thresholds therefore do not enforce equal residual thresholds.

For a target \(\epsilon_r=10^{-3}\), choose \(\texttt{tol}=\epsilon_r/[4(N+1)^2]\). This gives \(2.44140625\times10^{-7}\) at \(N=31\) and \(1.52587890625\times10^{-8}\) at \(N=127\). These translate the residual criterion for the iterate generating the update. They do not remove discretization error or supply an error bound against the continuum solution; that requires additional numerical analysis.

Exercise 5 (design judgment). A programmer proposes replacing safe halo exchange by blocking synchronous sends on all ranks, then receives, then a barrier. Another proposes letting each rank stop on its local update maximum. Assess both changes and give a safe alternative.

Solution

With send-first synchronous exchange, two adjacent ranks can each wait for a receive the other has not reached. In a chain, the end rank's send can participate in the same adjacent cycle. A later barrier cannot execute until the blocked calls finish and therefore cannot break the deadlock. Retain Sendrecv shifts or post all receives and sends before waiting.

A local maximum below tolerance says nothing about another rank's patch. If one exits while a neighbour continues, the continuing rank can wait forever for the next halo. Compute a global maximum with Allreduce and use the same stopping condition everywhere, or execute a globally agreed fixed sweep count. Correct halo generations and common termination solve different obligations; neither is replaced by a bare barrier.

Exercise 6 (implementation and measurement). Specify and execute a test plan that detects ownership, halo-generation and overlap edge errors in the supplied solver. Include an uneven decomposition, a patch without strict interior, convergence, and a comparison of one and several ranks. State exactly what the observed checks establish.

Solution

The listing implements the plan in its command: \(N=31\) on four ranks exercises remainder blocks in strip and tile modes; \(N=17\) on six ranks exercises a \(3\times2\) grid with unequal dimensions; \(N=2\) on four tile ranks gives one owned cell per patch, so strict-interior work is empty. \(N=1\) on one rank checks the smallest physical-boundary case. The \(N=31\), four-rank nonblocking tile run uses max_iter\(=5000\) and tol\(=10^{-5}\), checking a common convergence decision.

For each run, compute the serial iterate with the same stopping criterion, gather each patch's owned values, translate local coordinates with block_start, and compare every reconstructed interior against the serial grid. The program also checks finite values, total comparison count, identical global update norm and identical iteration count. All nine dedicated cases passed with zero printed pointwise error; the convergence case used 1094 sweeps. The fixed-size timing series separately compares one, two, four and eight ranks for exactly 200 sweeps.

This plan catches many communication and indexing defects that a short diagonal trace or checksum can miss. Swapping two different cells, for example, preserves their sum while failing the pointwise comparison. The finite suite still does not prove every possible \(N,p\) combination correct, and sharing a stencil formula with the reference is not independent verification of the continuum model. The decomposition proof, halo invariant and numerical discretization analysis supply those separate layers of reasoning.
