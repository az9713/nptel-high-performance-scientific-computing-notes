Processes, text processing, memory and networking from the command line

A Jacobi solver for the Laplace problem on an interior grid of \(N=16\) points per side needs 515 sweeps to bring the largest change per sweep below \(10^{-6}\) and writes a log of 12 lines. The same solver at \(N=1000\) holds two grids of 15.3 MiB. In a separate run on this machine it stopped after 191,001 sweeps, 10.6 minutes at 3.3 ms per sweep, with a maximum error of 0.17 (the mode expansion of this chapter gives that error exactly), because its stopping rule bounds the change per sweep and not the error. A run that brings the error itself below \(10^{-6}\) needs about 2.6 million sweeps by the estimate derived in this chapter, which is 2.4 hours at the same speed. A person who starts such a run from a terminal on a shared login node must answer four questions with commands. Is the process alive, and in which state? How fast does the residual fall, and when will the run end? How much memory does the process hold? How do the log and the result reach another machine? The two lectures give the commands (ps, kill, grep, awk, sort, free, ping, ssh, scp and others) and illustrate the process and text commands on small files. This chapter defines the objects that the commands act on, runs the commands on the solver's own log, and tests the lectures' statements against the specifications and against runs on one machine. Among the tests: the residual ratio read from the log agrees with \(\cos(\pi/(N+1))\) to \(2\times10^{-7}\) in relative terms, and the mode expansion of the iteration reproduces the logged residuals in every printed digit, for \(N=16\) and for a separate 10-minute run at \(N=1000\).

The objects of the chapter and the running case

The chapter studies what a person can learn about a running numerical program from the command line. Seven kinds of object occur. A byte stream is a finite sequence of bytes read or written in order. A line is a sequence of zero or more bytes other than the newline byte, followed by one newline byte (POSIX.1-2017, Base Definitions §3.206). A text file is a stream that is a concatenation of lines. A filter is a program that reads one stream (standard input) and writes one stream (standard output); it also has an exit status and may write a second stream (standard error), which this section sets aside. A pipeline of filters \(f_1,\dots,f_k\) is the program that feeds the standard output of \(f_i\) to the standard input of \(f_{i+1}\) for \(i=1,\dots,k-1\). Viewed as a map on streams, its action is the composition \(f_k\circ\cdots\circ f_1\). A process is an executing instance of a program. It has a process identifier (PID), the identifier of its parent (PPID), the identifier of its user (UID) and a state. A signal is a numbered notification that the kernel or another process delivers to a process. The model of this section has one limit that later sections lift: the composition describes which bytes flow, and says nothing about timing, exit statuses, standard error or the concurrency of the stages.

The running case is the book's Jacobi iteration for the Laplace equation on the unit square. The grid has \((N+2)\times(N+2)\) points of type double, of which the \(N\times N\) interior points are updated. The value is 1 on the top edge and 0 on the other three edges, and the interior starts at 0. One sweep replaces each interior value by the mean of its four neighbours, and the residual \(r_k\) after \(k\) sweeps is the largest absolute change of any interior value in sweep \(k\). The solver stops when \(r_k\lt\mathrm{tol}\) with \(\mathrm{tol}=10^{-6}\). The listing below is the serial kernel of the book with a driver that writes a progress line at a fixed interval of sweeps. Its inputs are \(N\) and that interval, the second argument. Its outputs are the log on standard output and one diagnostic line on standard error. It has no other effect. The run in the listing sends the two streams to two files and prints both, so that the two streams stay visible as two streams.

#include <stdio.h>
#include <stdlib.h>
#include <string.h>

#define IDX(i, j) ((i) * (N + 2) + (j))

/* One Jacobi sweep: write the 5-point average into the interior of unew,
   return max |unew - u| over the interior. */
static double jacobi_step(int N, const double *u, double *unew)
{
    double change = 0.0;
    for (int i = 1; i <= N; i++)
        for (int j = 1; j <= N; j++) {
            unew[IDX(i, j)] = 0.25 * (u[IDX(i - 1, j)] + u[IDX(i + 1, j)] +
                                      u[IDX(i, j - 1)] + u[IDX(i, j + 1)]);
            double d = unew[IDX(i, j)] - u[IDX(i, j)];
            if (d < 0.0) d = -d;
            if (d > change) change = d;
        }
    return change;
}

int main(int argc, char **argv)
{
    int N = argc > 1 ? atoi(argv[1]) : 16;
    int every = argc > 2 ? atoi(argv[2]) : 50;
    double tol = 1.0e-6;
    int max_iter = 20000;
    size_t cells = (size_t)(N + 2) * (N + 2);
    double *u = calloc(cells, sizeof *u), *unew = calloc(cells, sizeof *unew);
    if (!u || !unew) return 1;
    for (int j = 0; j < N + 2; j++) u[IDX(0, j)] = unew[IDX(0, j)] = 1.0;   /* top edge */

    fprintf(stderr, "jacobi_log: two grids of %zu doubles, %zu bytes\n", cells, 2 * cells * sizeof(double));
    printf("# jacobi N=%d tol=%.1e max_iter=%d\n", N, tol, max_iter);
    int k = 0;
    double r = 1.0;
    while (k < max_iter && r >= tol) {
        r = jacobi_step(N, u, unew);
        double *t = u; u = unew; unew = t;
        k++;
        if (k % every == 0) printf("iter %5d residual %.6e\n", k, r);
    }
    printf("# %s iter=%d residual=%.6e\n", r < tol ? "converged" : "stopped", k, r);
    return 0;
}

Processes, states and signals W1L5 0:06

The lecture defines a process as an executing instance of a program and lists its attributes: the PID, the PPID, the UID and the state (slide at W1L5 0:40). Process management, in the lecture's words, consists of creation, monitoring and control. This chapter treats monitoring and control. Chapter 2 treats creation (fork, exec, wait) and the kernel's scheduler, and chapter 5 uses exit statuses and $! inside shell scripts; signals and job control are treated only here.

Background and foreground

The lecture distinguishes two kinds of process. A foreground process occupies the terminal until it ends. A background process lets the terminal accept further commands. The lecture starts a background process by ending a command with &, as in sleep 100 &, and the shell answers with a job number and a PID ([1] 19883 on the slide). It brings the job back with fg %1. POSIX defines the mechanism. A command terminated by & runs as an asynchronous list: the shell does not wait for it, and the PID of its last command becomes available as $! (POSIX.1-2017, Shell Command Language §2.9.3). If job control is disabled, as in a script, the standard input of the asynchronous command is /dev/null; if job control is enabled, as in an interactive shell, the standard input remains the terminal. A background process that then reads the terminal receives SIGTTIN, whose default action is to stop it (signal(7)). The lecture describes sleep as putting the CPU into an idle state; that needs one correction. sleep blocks the calling process until the time has passed. The process uses no processor time and is in the sleeping state, but the processor is idle only if no other process is runnable.

A background process still belongs to the terminal's session. When the terminal closes, the kernel sends SIGHUP to the controlling process of the terminal, the shell (POSIX.1-2017, General Terminal Interface §11.1.10). An interactive Bash then resends SIGHUP to all its jobs, running or stopped (Bash manual, "Signals"), and the default action of SIGHUP is to terminate. nohup runs a command with hangup signals ignored, so that it continues after logout; if its standard output is a terminal, the output goes to nohup.out (GNU coreutils manual, nohup). The script below starts one ordinary background job and one job under nohup, sends SIGHUP to both, and reports what happens. It inspects only processes that it started, through the PIDs it captured in $!. Its outputs do not vary from run to run, so the check is exact. The lecture's fg is not part of the script, because fg needs an interactive terminal with job control, which the code lab does not provide.

cd "$(mktemp -d /tmp/hpsc-demo.XXXXXX)"

sleep 30 &                      # an ordinary background job
plain=$!
nohup sleep 30 > /dev/null 2>&1 &   # the same job, started under nohup
immune=$!
sleep 0.2

echo "standard input of the background job: $(readlink /proc/$plain/fd/0)"

States

The lecture's slide at W1L5 6:40 lists four states with their ps letters: running (R), sleeping (S), stopped (T) and zombie (Z). The slide's definitions are correct: running means running or ready to run; sleeping means waiting for an event such as the completion of input or output; stopped means stopped by a signal such as SIGSTOP; a zombie has finished but still has an entry in the process table, awaiting cleanup by its parent. The spoken explanation differs from the slide in two places. The speaker says that a process goes to the waiting state because a higher-priority process arrives, and that a zombie is a finished process whose memory has not been cleaned. Both statements are tested below. The ps manual lists further codes: D, uninterruptible sleep, usually input or output; I, an idle kernel thread; and t, stopped by a debugger.

The program below creates one child per state and reads each state the way ps does, from the third field of /proc/PID/stat (proc_pid_stat(5)). A busy loop never blocks. A process in pause() sleeps until a signal arrives. SIGSTOP and SIGCONT stop and resume the sleeper. A child that exits at once and is not waited for becomes a zombie, and the program also tests whether its /proc/PID/status has a VmRSS line, the line that reports resident memory. The second part sends SIGTERM and SIGKILL, shows a SIGTERM that a process handles, and asks the kernel to install a handler for SIGKILL and for SIGSTOP. The third part pins two busy loops to logical processor 0 with sched_setaffinity and reads their states. Every output line is the same in every run, because each state is read 200 ms after the event that causes it and nothing else competes for the states. The check is exact.

#define _GNU_SOURCE
#include <errno.h>
#include <sched.h>
#include <signal.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/wait.h>
#include <time.h>
#include <unistd.h>

/* State letter of a process: the field after the command name in /proc/PID/stat. */
static char state_of(pid_t pid)
{
    char path[64], buf[512];
    snprintf(path, sizeof path, "/proc/%d/stat", (int)pid);
    FILE *f = fopen(path, "r");
    if (!f) return '?';
    size_t n = fread(buf, 1, sizeof buf - 1, f);
    fclose(f);
    buf[n] = 0;
    char *p = strrchr(buf, ')');          /* the command name may contain blanks */
    return p ? p[2] : '?';
}

/* 1 if /proc/PID/status has a VmRSS line (a process that still owns user memory), else 0. */
static int has_vmrss(pid_t pid)
{
    char path[64], line[256];
    int found = 0;
    snprintf(path, sizeof path, "/proc/%d/status", (int)pid);
    FILE *f = fopen(path, "r");
    if (!f) return -1;
    while (fgets(line, sizeof line, f))
        if (strncmp(line, "VmRSS:", 6) == 0) found = 1;
    fclose(f);
    return found;
}

static void settle(void)                  /* give the children 200 ms to reach their steady state */
{
    struct timespec ts = {0, 200 * 1000 * 1000};
    nanosleep(&ts, NULL);
}

static volatile sig_atomic_t got_term;
static void on_term(int sig) { (void)sig; got_term = 1; }

static pid_t spawn(int kind)
{
    pid_t pid = fork();
    if (pid) return pid;
    if (kind == 0) { volatile unsigned long x = 0; for (;;) x++; }      /* busy */
    if (kind == 1) { for (;;) pause(); }                                /* sleeping */
    if (kind == 2) _exit(0);                                            /* ends at once */
    signal(SIGTERM, on_term);                                           /* kind 3: handles SIGTERM */
    while (!got_term) pause();
    _exit(7);
}

static void report(const char *what, pid_t pid)
{
    int st;
    waitpid(pid, &st, 0);
    if (WIFSIGNALED(st))
        printf("%-28s killed by signal %d (%s)\n", what, WTERMSIG(st), strsignal(WTERMSIG(st)));
    else
        printf("%-28s exited with status %d\n", what, WEXITSTATUS(st));
}

int main(void)
{
    pid_t busy = spawn(0), sleeper = spawn(1);
    settle();
    printf("busy loop: %c   waiting in pause(): %c\n", state_of(busy), state_of(sleeper));
    kill(sleeper, SIGSTOP); settle();
    printf("after SIGSTOP: %c\n", state_of(sleeper));
    kill(sleeper, SIGCONT); settle();
    printf("after SIGCONT: %c\n", state_of(sleeper));

    pid_t zombie = spawn(2);
    settle();
    printf("child that exited, not waited for: %c, has a VmRSS line: %s\n",
           state_of(zombie), has_vmrss(zombie) ? "yes" : "no");
    report("zombie after waitpid:", zombie);
    printf("/proc entry of the zombie after waitpid: %s\n", state_of(zombie) == '?' ? "gone" : "present");

    kill(sleeper, SIGTERM); report("sleeper, SIGTERM:", sleeper);
    kill(busy, SIGKILL);    report("busy loop, SIGKILL:", busy);

    pid_t handler = spawn(3);
    settle();
    kill(handler, SIGTERM); report("handler installed, SIGTERM:", handler);

    struct sigaction sa;
    memset(&sa, 0, sizeof sa);
    sa.sa_handler = on_term;
    errno = 0; sigaction(SIGKILL, &sa, NULL); printf("sigaction(SIGKILL): %s\n", strerror(errno));
    errno = 0; sigaction(SIGSTOP, &sa, NULL); printf("sigaction(SIGSTOP): %s\n", strerror(errno));

    pid_t a = spawn(0), b = spawn(0);               /* two busy loops share one logical processor */
    cpu_set_t one;
    CPU_ZERO(&one); CPU_SET(0, &one);
    sched_setaffinity(a, sizeof one, &one);
    sched_setaffinity(b, sizeof one, &one);
    settle(); settle();
    printf("two busy loops on processor 0: %c %c\n", state_of(a), state_of(b));
    kill(a, SIGKILL); kill(b, SIGKILL); waitpid(a, NULL, 0); waitpid(b, NULL, 0);
    return 0;
}

The first block confirms the slide: R for the busy loop, S for the process in pause(), T after SIGSTOP and S again after SIGCONT, since the process is still waiting. The zombie shows the correction of the spoken statement. The child has finished, its state is Z, and its status file has no VmRSS line: it owns no user memory. The kernel keeps its PID, its termination status and its resource-usage information so that the parent can collect them with wait, and the zombie occupies one slot of the process table until then; when the table is full, no process can be created (wait(2), NOTES). After waitpid the /proc entry is gone. A zombie therefore costs a process-table slot and its kernel bookkeeping, and no user memory, and the remedy is to make the parent wait, or to end the parent so that init waits (wait(2)).

The second block shows the lecture's signals. kill without an argument sends SIGTERM, number 15, whose default action is to terminate the process; kill(1) advises SIGTERM before SIGKILL because a process may install a handler for SIGTERM and clean up, as the fourth child does, which exits with status 7 instead of dying. SIGKILL, number 9, cannot be caught, blocked or ignored, and neither can SIGSTOP (signal(7)): sigaction fails with EINVAL, "Invalid argument", for both. The lecture's numbers 15, 9, and the pair of stop and continue agree with the manual for x86 and ARM: SIGSTOP is 19 and SIGCONT is 18, and the numbers differ on Alpha, SPARC, MIPS and PA-RISC (signal(7)), so scripts should use the names.

The third block tests the other spoken statement. Two busy loops share one logical processor, so at any instant at most one of them runs, and both are in state R. A preempted process stays runnable; it does not enter the sleeping state. The sleeping state means waiting for an event, and the scheduler's preference for another process does not create such an event. The same block makes precise the lecture's description of an HPC run in which each process, or each thread, works on one core. That layout is a choice, not a default: the affinity mask of a thread is the set of processors on which it may run, and the default allows all of them; sched_setaffinity narrows it (sched_setaffinity(2)). Without such a call, the kernel places and moves runnable threads among the allowed processors. Chapter 11 returns to the choice of binding for OpenMP threads, and chapter 8 treats concurrency.

Monitoring

The lecture's monitoring commands are ps, ps -e, ps -ef and top. By default ps selects the processes that have the same effective user ID as the caller and the same terminal; -e selects all processes, and -f adds columns including the parent PID and the command arguments (ps(1)). Multitasking, multiprocessing and multithreading W1L5 16:30

The lecture closes the process topic with three terms, presented as the operating-system support on which OpenMP and MPI programs rest. Multitasking is the execution of several processes over the same period: the kernel switches a processor from one runnable process to another (a context switch), so on \(p\) logical processors at most \(p\) processes run at any instant and the other runnable processes wait in state R. Multiprocessing, in the lecture's sense, is an application made of several processes, each with its own address space, which the kernel schedules and which exchange data through inter-process communication (pipes, signals, sockets, shared memory); an MPI program (chapter 14) has this structure. The word also has a hardware sense, a machine with several processors. Multithreading is one process that contains several threads: the threads share the address space and the open files of the process, and each has its own registers, stack and scheduling state; Linux schedules each thread as a separate task (clone(2), CLONE_THREAD). An OpenMP program (chapter 11) has this structure. The third block of states.c shows multitasking on one processor: two runnable processes share processor 0 and both are in state R.

grep and the language of a regular expression W1L5 21:56

The lecture introduces grep as the command that searches for a string or pattern in files or input streams. Its example file has four lines, two of which contain the word Ved; grep "Ved" file3 prints those two lines, grep -n prefixes each with its line number, and grep -r "Ved" * searches the files and directories below the current directory. The lecture calls the argument a string or pattern and does not say what patterns exist. This section defines them.

The language of an expression

Let \(\Sigma\) be a finite alphabet, here the set of characters. A regular expression is built by the grammar \(r,s::=\varnothing\mid\varepsilon\mid a\mid rs\mid r+s\mid r^{*}\) with \(a\in\Sigma\). Its language \(\mathcal L(r)\subseteq\Sigma^{*}\) is the set of strings given by \(\mathcal L(\varnothing)=\varnothing\), \(\mathcal L(\varepsilon)=\{\varepsilon\}\), \(\mathcal L(a)=\{a\}\), \(\mathcal L(rs)=\{uv: u\in \mathcal L(r),\,v\in \mathcal L(s)\}\), \(\mathcal L(r+s)=\mathcal L(r)\cup \mathcal L(s)\) and \(\mathcal L(r^{*})=\{\varepsilon\}\cup \mathcal L(rr^{*})\), an equation whose least solution is \(\mathcal L(r^{*})=\bigcup_{n\ge0}\mathcal L(r)^{n}\) with \(\mathcal L^{0}=\{\varepsilon\}\) and \(\mathcal L^{n+1}=\{uv:u\in \mathcal L,\,v\in \mathcal L^{n}\}\) (Owens, Reppy and Turon 2009, Definitions 2.1 and 2.2). The notation of grep -E abbreviates these operators: \(r|s\) is \(r+s\); \(r?\) is \(\varepsilon+r\); \(r^{+}\) is \(rr^{*}\); . is the sum of all characters; a bracket expression such as [ab] is the sum of its members; an interval such as a{2,3} is a finite sum of concatenations. POSIX writes the same constructs as the extended regular expression (ERE) grammar and, with other escapes, as the basic regular expression (BRE) grammar (POSIX.1-2017, Base Definitions §9.3 to §9.5). The anchors ^ and $ do not describe sets of strings but positions at the start and end of a line.

What grep does with a language is a search. A line \(\ell\) is selected if \(\ell=xyz\) for some strings \(x,y,z\) with \(y\in \mathcal L(r)\). With the option -x the line is selected only if \(\ell\in \mathcal L(r)\). The two statements are connected by \(\ell\) being selected by \(r\) exactly when \(\ell\in \mathcal L(\texttt{.*(}r\texttt{).*})\). For an expression whose match is wanted, not only the decision, POSIX adds a rule: the search starts at the beginning of the string and stops at the first sequence that matches, "first" meaning "begins earliest", and if several sequences begin there, the longest is matched (POSIX.1-2017, Base Definitions §9.1). The rule matters for grep -o and for sed, which print or replace the match; it does not change which lines grep selects.

A matcher that is the definition

The decision "is \(u\in \mathcal L(r)\)" can be computed from the definition by derivatives. The derivative of a language \(\mathcal L\) by a character \(a\) is \(\partial_a \mathcal L=\{w: aw\in \mathcal L\}\). Two functions on expressions compute it. The function \(\nu\) tests whether \(\varepsilon\in \mathcal L(r)\): \(\nu(\varepsilon)=\nu(r^{*})=\mathrm{true}\), \(\nu(\varnothing)=\nu(a)=\mathrm{false}\), \(\nu(rs)=\nu(r)\wedge\nu(s)\), \(\nu(r+s)=\nu(r)\vee\nu(s)\). The derivative of an expression is

\[ \partial_a(\varnothing)=\partial_a(\varepsilon)=\varnothing,\quad \partial_a(b)=\begin{cases}\varepsilon&b=a\\ \varnothing&b\ne a,\end{cases}\quad \partial_a(r+s)=\partial_a r+\partial_a s,\quad \partial_a(r^{*})=(\partial_a r)\,r^{*}, \tag{4.1} \] \[ \partial_a(rs)=\begin{cases}(\partial_a r)\,s+\partial_a s&\nu(r)\\ (\partial_a r)\,s&\text{otherwise,}\end{cases} \tag{4.2} \]

(Owens, Reppy and Turon 2009, §3.1, due to Brzozowski 1964; the paper of 1964 was not opened, and its bibliographic data were checked in Crossref). For a string \(u=a_1\cdots a_n\), \(u\in \mathcal L(r)\) exactly when \(\nu(\partial_{a_n}\cdots\partial_{a_1}r)\) holds (§3.2 of the same paper). Two facts carry the proof. The first is the definition: \(u\in \mathcal L(r)\iff\varepsilon\in\partial_u \mathcal L(r)\), where \(\partial_{a_1\cdots a_n}=\partial_{a_n}\circ\cdots\circ\partial_{a_1}\). The second is that the rules compute the derivative of the language, \(\mathcal L(\partial_a r)=\partial_a \mathcal L(r)\), by induction on \(r\). Only concatenation and star need care. If \(aw\in \mathcal L(r)\mathcal L(s)\), either the part from \(\mathcal L(r)\) is \(au'\) with \(u'v=w\) and \(v\in \mathcal L(s)\), so that \(w\in(\partial_a\mathcal L(r))\mathcal L(s)\), or the part from \(\mathcal L(r)\) is empty, which requires \(\varepsilon\in \mathcal L(r)\) and gives \(w\in\partial_a\mathcal L(s)\); this is (4.2). A string of \(\mathcal L(r)^{*}\) that begins with \(a\) has a first non-empty factor \(au'\in \mathcal L(r)\) followed by a string of \(\mathcal L(r)^{*}\), so \(\partial_a\mathcal L(r^{*})=(\partial_a\mathcal L(r))\,\mathcal L(r^{*})\), the last rule of (4.1). Since \(\nu(r)\) is true exactly when \(\varepsilon\in \mathcal L(r)\), the two facts give the matching rule. # ('any',) any one character of the alphabet; ('cat', r, s); ('alt', r, s); ('star', r).
ALPHABET = "ab"


def parse(p):
    """Parse the ERE subset  a b . ( ) | * + ?  into the syntax above."""
    pos = 0

    def peek():
        return p[pos] if pos < len(p) else None

    def alt():
        nonlocal pos
        r = cat()
        while peek() == "|":
            pos += 1
            r = ("alt", r, cat())
        return r

    def cat():
        r = ("eps",)
        while peek() not in (None, "|", ")"):
            r = rep() if r == ("eps",) else ("cat", r, rep())
        return r

    def rep():
        nonlocal pos
        if peek() == "(":
            pos += 1
            r = alt()
            pos += 1                                   # the closing parenthesis
        elif peek() == ".":
            pos += 1
            r = ("any",)
        else:
            r = ("chr", p[pos])
            pos += 1
        while peek() in ("*", "+", "?"):
            op = p[pos]
            pos += 1
            r = ("star", r) if op == "*" else ("cat", r, ("star", r)) if op == "+" else ("alt", r, ("eps",))
        return r

    return alt()


def nullable(r):
    k = r[0]
    if k == "eps" or k == "star":
        return True
    if k in ("empty", "chr", "any"):
        return False
    if k == "cat":
        return nullable(r[1]) and nullable(r[2])
    return nullable(r[1]) or nullable(r[2])             # alt


def deriv(r, a):
    k = r[0]
    if k in ("empty", "eps"):
        return ("empty",)
    if k == "chr":
        return ("eps",) if r[1] == a else ("empty",)

    return ("alt", first, deriv(r[2], a)) if nullable(r[1]) else first


def matches(r, u):
    for a in u:

Cost: automata against backtracking

The derivative matcher of the listing is a teaching device and not how grep works. Cox (2007) describes two families of implementations. One simulates a nondeterministic finite automaton built from the expression, the construction that Thompson published in 1968, or builds a deterministic one; Cox lists GNU grep and GNU awk among the implementations that build deterministic automata. The simulation takes time \(O(|r|n)\) for an expression of length \(|r|\) and a text of length \(n\). The other family tries the alternatives one after another and backtracks on failure; Perl and the languages that copied it do this, and Cox's example is the expression \(a?^{n}a^{n}\) (\(n\) optional a followed by \(n\) required ones) against the string \(a^{n}\), on which backtracking takes time exponential in \(n\), while the automaton takes microseconds. The listing repeats the experiment with the backtracking matcher of Python's re module and with grep -E. Where the notation leaves the regular languages

A back-reference such as \1 matches the text that an earlier group matched. GNU grep accepts it in both syntaxes (GNU grep manual, §3.5), and POSIX specifies it for BRE; the ERE grammar of POSIX has no back-reference. The pattern ^(.+)\1$ selects the strings of the form \(ww\), the squares. The set of squares is not a regular language, so no expression built from \(\varnothing,\varepsilon,a,rs,r+s,r^{*}\) describes it, and a matcher for back-references cannot be a finite automaton. Cox states that, with back-references, the best known implementations need exponential search in the worst case. The shell script of the next section shows the pattern at work. The other places where GNU grep departs from the model are these. In BRE the characters ?, +, {, |, ( and ) lose their special meaning (GNU grep manual, §3.6). POSIX BRE has the groups \( and \) and the intervals \{ and \}; the forms \+, \? and \| are GNU extensions, and POSIX.1-2017 §9.3 defines none of the three. A bracket range such as [a-z] is defined by the collation order of the locale; POSIX specifies it only for the POSIX locale (Base Definitions §9.3.5). The machine used here offers only the locales C, C.utf8 and POSIX, so the chapter does not test other collation orders. A script that parses a log should set LC_ALL=C so that the character classes and the sort order do not depend on the user's locale.

The pipe as defined, and as it runs

The lecture draws the pipe as "command 1, output, input, command 2" and says that the pipe passes the output of one command as input to another. POSIX states the definition used in the model section: for each command but the last, the shell connects the standard output of the command to the standard input of the next "as if by creating a pipe", and the exit status of the pipeline is the exit status of its last command (POSIX.1-2017, Shell Command Language §2.9.2). POSIX.1-2024 adds the pipefail option to §2.9.2: with the option enabled, the status is zero if all commands returned 0, and otherwise the status of the rightmost command that returned a non-zero status. POSIX also states that the shell waits for the last command and "may also wait for all commands". The composition of the model section therefore describes data and not time. In Linux the commands run at the same time, and a pipe is a buffer of limited capacity: a writer blocks when it is full, a reader blocks when it is empty, and a write to a pipe that no process reads from raises SIGPIPE (pipe(7)). Since Linux 2.6.11 the capacity is 16 pages of memory unless it is changed, which is 65,536 bytes with the 4096-byte pages of this machine (pipe(7); pages are defined in the memory section). From the residual history to the convergence rate

The question a person asks of a residual history is when the run will end. This section answers it for the running case in three steps: a closed form for the rate at which the iteration converges, an estimator of that rate from the log, and a test of both against the logs of \(N=8,16,32\) and later of larger runs. The section is an original construction; the only external input is the value of the rate, which Demmel's 1996 Berkeley lecture notes state and which is derived here.

The eigenmodes of the iteration

Let \(u^{k}\) be the interior values after \(k\) sweeps and \(u^{*}\) the fixed point of the iteration, that is, the discrete solution of the Laplace problem with the stated boundary values. A sweep is \(u^{k+1}_{ij}=\tfrac14\bigl(u^{k}_{i-1,j}+u^{k}_{i+1,j}+u^{k}_{i,j-1}+u^{k}_{i,j+1}\bigr)\) for \(i,j=1,\dots,N\). Boundary values enter as constants and are the same for \(u^{k}\) and \(u^{*}\), so the error \(e^{k}=u^{k}-u^{*}\) obeys the same averaging with zero boundary values: \(e^{k+1}=Be^{k}\), where \(B\) is the linear map that averages the four neighbours and treats the boundary as zero. Let \(\theta=\pi/(N+1)\). For integers \(s,t\in\{1,\dots,N\}\) define \(v^{(s,t)}_{ij}=\sin(s\,i\theta)\sin(t\,j\theta)\). The trigonometric identity \(\sin(s(i-1)\theta)+\sin(s(i+1)\theta)=2\cos(s\theta)\sin(s\,i\theta)\) holds for every \(i\), and at \(i=0\) and \(i=N+1\) the sine is zero, which is the zero boundary condition. Applying the averaging to \(v^{(s,t)}\) therefore gives

\[ Bv^{(s,t)}=\mu_{st}\,v^{(s,t)},\qquad \mu_{st}=\tfrac12\bigl(\cos s\theta+\cos t\theta\bigr). \tag{4.3} \]

The \(N^{2}\) vectors \(v^{(s,t)}\) are products of the one-dimensional sine vectors, which are a basis of \(\mathbb R^{N}\), so they are a basis of the space of interior grids. Expand the initial error \(e^{0}=-u^{*}\) as \(e^{0}=\sum c_{st}v^{(s,t)}\). Then \(e^{k}=\sum c_{st}\mu_{st}^{k}v^{(s,t)}\). Every \(\mu_{st}\) lies strictly between \(-1\) and 1, and the one of largest magnitude is attained at \(s=t=1\) and, with the opposite sign, at \(s=t=N\):

\[ \rho=\max_{s,t}|\mu_{st}|=\cos\frac{\pi}{N+1}. \tag{4.4} \]

This is the value stated by Demmel (CS267 lecture notes of 1996, on the discrete Poisson equation: \(\rho_{\mathrm{Jacobi}}(n)=\cos(\pi/(n+1))\)), for the error in the root-sum-of-squares norm. For large \(N\), \(\rho\approx1-\pi^{2}/(2(N+1)^{2})\), so the factor tends to 1 as the grid is refined, and the number of sweeps for a fixed reduction grows in proportion to \(N^{2}\).

The solver logs the change per sweep, which it calls the residual. The change in one sweep is \(d^{k}=u^{k+1}-u^{k}=e^{k+1}-e^{k}=\sum c_{st}(\mu_{st}-1)\mu_{st}^{k}v^{(s,t)}\), and the residual logged after \(k+1\) sweeps is \(r_{k+1}=\max_{ij}|d^{k}_{ij}|\). The change per sweep is a scaled residual of the linear system. Write the discrete problem as \(\mathsf Au=b\), with 4 on the diagonal of \(\mathsf A\), \(-1\) for each interior neighbour, and the boundary values in \(b\). Then \(B=I-\tfrac14\mathsf A\), one sweep is \(u^{k+1}=u^{k}+\tfrac14(b-\mathsf Au^{k})\), and \(d^{k}=\tfrac14(b-\mathsf Au^{k})\). The logged \(r_{k+1}\) is one quarter of \(\lVert b-\mathsf Au^{k}\rVert_\infty\), so the name is exact up to the factor 4, and a log of the system residual has the same factor \(\rho\). Each mode keeps its eigenvalue, so the modes with \(|\mu|\) smaller than \(\rho\) die out faster than the leading one. The expansion therefore predicts

\[ r_{k}\approx A\rho^{k}\quad\text{for large }k,\qquad A=\frac{|c_{11}|\,(1-\rho)\,\max_{ij}|v^{(1,1)}_{ij}|}{\rho}\propto(1-\rho), \tag{4.5} \]

where the factor \(1/\rho\) comes from the index shift \(r_k=\max|d^{k-1}|\). The mode \(s=t=N\) has the eigenvalue \(-\rho\), the same decay factor in magnitude with alternating sign; its coefficient vanishes for even \(N\), as the check below shows. Equation (4.5) states an asymptote and a proportionality. It does not say after how many sweeps the asymptote is reached.

Estimating the factor and the end of the run from the log

For two logged points \((k_1,r_1)\) and \((k_2,r_2)\) with \(k_2\gt k_1\), define the observed factor per sweep \(\hat\rho=(r_2/r_1)^{1/(k_2-k_1)}\). This is the geometric mean of the ratios of consecutive sweeps, and equation (4.5) predicts \(\hat\rho\to\rho\) when both points lie in the asymptotic range. With the exact \(\rho\) known, the sweep at which the run ends follows from solving \(r_{k}=\mathrm{tol}\) with \(r_1\) as the base point:

\[ k_{\mathrm{end}}\approx k_1+\frac{\ln(\mathrm{tol}/r_1)}{\ln\rho}, \qquad \ln\rho=\ln\cos\frac{\pi}{N+1}. \tag{4.6} \]

Two estimates of \(\hat\rho\) are of interest: \(\hat\rho_{\mathrm{window}}\), computed from the first and last progress line, and \(\hat\rho_{\mathrm{last}}\), computed from the last two. The first uses points that include the transient, and the second uses points in the asymptotic range. import numpy as np

N = 16
theta = np.pi / (N + 1)
i = np.arange(1, N + 1)
S = np.sin(np.outer(i, np.arange(1, N + 1)) * theta)      # S[i-1, p-1] = sin(p i theta)
mu = 0.5 * (np.cos(np.arange(1, N + 1) * theta)[:, None] + np.cos(np.arange(1, N + 1) * theta)[None, :])

# Exact solution u* of the discrete Laplace problem: u = 1 on the top edge (row 0), 0 on the other edges.
A = np.zeros((N * N, N * N)); b = np.zeros(N * N)
for r in range(N):
    for c in range(N):
        k = r * N + c
        A[k, k] = 4.0
        for dr, dc in ((-1, 0), (1, 0), (0, -1), (0, 1)):
            rr, cc = r + dr, c + dc
            if 0 <= rr < N and 0 <= cc < N:
                A[k, rr * N + cc] = -1.0
            elif rr < 0:
                b[k] += 1.0                                 # the neighbour is on the top edge
ustar = np.linalg.solve(A, b).reshape(N, N)

# Initial error e0 = u0 - u* = -u*; coefficients in the sine basis (S is orthogonal up to a factor).
c = (2.0 / (N + 1)) ** 2 * S.T @ (-ustar) @ S
print(f"rho = cos(pi/{N + 1}) = {np.cos(theta):.6f}; largest |mu| = {np.abs(mu).max():.6f}")
print("coefficient of the mode s = t = N below 1e-12 in magnitude:", "yes" if abs(c[-1, -1]) < 1e-12 else "no")
print("iteration   residual in the log   residual from the modes   ratio")

The end of the run follows from the amplitude of (4.5). Solving \(A\rho^{k}=\mathrm{tol}\) gives

\[ k_{\mathrm{end}}\approx\frac{\ln(A/\mathrm{tol})}{-\ln\rho},\qquad A\approx a\,(1-\rho),\quad a=\frac{4}{\pi^{2}}. \tag{4.7} \]

The amplitude \(A\), computed from the last logged point as \(r\rho^{-k}\), is 0.0247, 0.00692, 0.00184 and 0.000473 for \(N=8,16,32,64\). The quotient \(A/(1-\rho)\) is 0.410, 0.406, 0.406 and 0.405, constant within 1.1 %, as the proportionality \(A\propto1-\rho\) of (4.5) predicts. The limit has a closed form. As \(N\) grows, \(|c_{11}|\) tends to the coefficient of \(\sin\pi x\sin\pi y\) in the continuous solution, with \(x=ih\) the distance from the top edge and \(y=jh\), \(h=1/(N+1)\): the edge value 1 has the sine coefficient \(4/\pi\), and the profile \(\sinh(\pi(1-x))/\sinh\pi\) projects onto \(\sin\pi x\) with coefficient \(1/\pi\), so \(|c_{11}|\to4/\pi^{2}=0.40528\), and \(\max|v^{(1,1)}|/\rho\to1\). The exact discrete values of \(|c_{11}|\) are 0.39708, 0.40298, 0.40467 and 0.40513 for \(N=8,16,32,64\). """Predict the sweep at which the Jacobi run stops from N alone, and compare with the run.

The prediction is k_end = ln(a (1 - rho) / tol) / (-ln rho) with rho = cos(pi/(N+1)) and a = 4/pi^2 = 0.40528,
the limit of the quotient A/(1 - rho). The runs use NumPy; the arithmetic of one
sweep is the same as in the C solver, so the sweep counts are the same.
"""
import math

import numpy as np

TOL, A_OVER = 1.0e-6, 4.0 / math.pi ** 2


def sweeps(N):
    u = np.zeros((N + 2, N + 2)); u[0, :] = 1.0
    unew = u.copy()
    k, r = 0, 1.0
    while r >= TOL:
        unew[1:-1, 1:-1] = 0.25 * (u[:-2, 1:-1] + u[2:, 1:-1] + u[1:-1, :-2] + u[1:-1, 2:])
        r = np.abs(unew[1:-1, 1:-1] - u[1:-1, 1:-1]).max()
        u, unew = unew, u
        k += 1
    return k

What the residual does not bound

The last column of the output of end_prediction.py states a consequence that the log hides. The stopping rule bounds the change per sweep, \(r_k\lt\mathrm{tol}\), and not the error \(\lVert u^{k}-u^{*}\rVert_{\infty}\). For the leading mode the change and the error are linked by the factor \(\mu-1\) of the expansion of \(d^{k}\): \(d^{k}=(\mu_{11}-1)e^{k}\), so

\[ \lVert e^{k}\rVert_{\infty}\approx\frac{r_{k+1}}{1-\rho}. \tag{4.8} \]

Equation (4.8) is an estimate, not a bound. Two exact statements hold. Since \(e^{k}=-(I-B)^{-1}d^{k}\) and the eigenvalues of the symmetric map \(B\) lie in \([-\rho,\rho]\), the root-sum-of-squares norm satisfies \(\lVert e^{k}\rVert_{2}\le\lVert d^{k}\rVert_{2}/(1-\rho)\), with equality for the leading mode. In the max-norm the guaranteed constant is the largest row sum of \((I-B)^{-1}\), which is 23.15, 84.43, 320.18 and 1244.31 for \(N=8,16,32,64\), that is 1.40 to 1.45 times \(1/(1-\rho)\) (a computation made outside the code lab). A stopping rule that must guarantee \(\lVert e\rVert_\infty\lt\delta\) therefore needs \(\mathrm{tol}\approx\delta(1-\rho)/1.45\).

The factor \(1/(1-\rho)\approx2(N+1)^{2}/\pi^{2}\) grows with the square of \(N\). At the stopping sweep of the \(N=16\) run, the modal computation of the last line of modal_check.py gives an error of \(5.761\times10^{-5}\) against \(r/(1-\rho)=5.861\times10^{-5}\) from (4.8), which differ by 1.7 %. The error at the stop is therefore 58 times the tolerance for \(N=16\), and the last column of the output of end_prediction.py gives \(\mathrm{tol}/(1-\rho)=1.66\times10^{-5}\), \(5.87\times10^{-5}\), \(2.21\times10^{-4}\), \(8.56\times10^{-4}\) and \(2.07\times10^{-3}\) for \(N=8\) to 100. At \(N=1000\) the factor is \(2\times10^{5}\), and the run of the previous subsection stopped with an error of 0.167. To bring the error below \(\delta\), the tolerance on the change must be about \(\delta(1-\rho)\), and (4.7) then gives \(k_{\mathrm{end}}\approx\ln(a/\delta)/(-\ln\rho)\): for \(N=1000\) and \(\delta=10^{-6}\), \(\ln(4.053\times10^{5})/(4.925\times10^{-6})=2.62\times10^{6}\) sweeps, which is 2.4 hours at the 3.3 ms per sweep of the run above, against 191,001 sweeps for the rule \(r\lt10^{-6}\). The guaranteed max-norm constant of 1.45 changes that count by \(\ln1.45/(4.925\times10^{-6})=7.5\times10^{4}\) sweeps, about 3 %. The ratio \(A/\mathrm{tol}\) is \(a/\delta=4.05\times10^{5}\) in this case, so (4.7) is in its range of validity there. The error discussed here is the iteration error with respect to the discrete solution \(u^{*}\), not the discretization error of \(u^{*}\) as an approximation of the continuous solution. The relation (4.8) holds in the asymptotic range, where one mode dominates; it was tested at \(N=16\) (1.7 % above the exact error) and at \(N=1000\) (22 % above), and the second test is outside the asymptotic range.

The boundary of the result is the problem. The closed form (4.4) holds for the Jacobi iteration on a square grid with equal spacing in both directions and constant Dirichlet values on each edge. Gauss–Seidel has the factor \(\rho^{2}\) (Demmel), and conjugate gradients do not converge at a constant factor. The estimator \(\hat\rho\) assumes a log in which the residual is the same measure at every line. A log that mixes measures, for instance the change per sweep on some lines and \(\lVert b-\mathsf Au^{k}\rVert_\infty\), four times larger for Jacobi, on others, gives wrong ratios across the switch. The cost of the run follows from (4.4): the number of sweeps grows with \(N^{2}\), and the work per sweep also grows with \(N^{2}\), so the total work grows with \(N^{4}\), a fact that returns in chapter 9.

Virtual size and resident size

A process addresses virtual memory: a set of mappings from ranges of virtual addresses to storage. The kernel divides memory into pages, 4096 bytes on this machine (the machine listing prints it). A page that is present in RAM is resident. The kernel reports two sizes per process in /proc/PID/status: VmSize, the size of the virtual address space, and VmRSS, the resident set size, which is the sum of the lines RssAnon, RssFile and RssShmem. The manual marks the values as inaccurate, because of a kernel-internal scalability optimization, and names /proc/PID/smaps and /proc/PID/smaps_rollup as the slower, accurate sources (proc_pid_status(5), proc_pid_statm(5)). The two sizes differ because the kernel allocates RAM for an anonymous mapping, the kind that malloc uses for a large request, only when a page is first written, which is called demand paging. A program can therefore hold a large virtual size and a small resident size. The slide's statement that virtual memory lets a process use more memory than the physical RAM follows from this: a process may map more than it ever touches, and the kernel may move rarely used pages to swap. Virtual memory also gives each process a private address space, which the slide does not mention.

The prediction for the running case is simple. The solver holds two grids of \((N+2)^{2}\) doubles, which is \(16(N+2)^{2}\) bytes. For \(N=16\) that is 5184 bytes, the number on the diagnostic line of the solver. For \(N=1000\) it is 16,064,064 bytes (15.3 MiB), and for \(N=4000\) it is 256,256,064 bytes (244.4 MiB). The program below allocates the two grids of \(N=4000\) with malloc and reads VmSize and VmRSS before the allocation, after it, and after it has written every element once. The stores go through a pointer to volatile double, because otherwise the compiler removes the allocation and the stores, and the program measures nothing. The output is deterministic at the resolution that the program prints, and the check is exact. The program checks, in its last line, that the growth of VmRSS is within 1 MiB of the prediction.

#include <math.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

/* Read one "Name: value kB" line of /proc/self/status; return the value in kB. */
static long status_kb(const char *name)
{
    char line[256];
    long value = -1;
    FILE *f = fopen("/proc/self/status", "r");
    if (!f) return -1;
    size_t len = strlen(name);
    while (fgets(line, sizeof line, f))
        if (strncmp(line, name, len) == 0 && line[len] == ':') value = atol(line + len + 1);
    fclose(f);
    return value;
}

int main(void)
{
    const int N = 4000;
    size_t cells = (size_t)(N + 2) * (N + 2);
    double predicted_mib = 2.0 * cells * sizeof(double) / (1024.0 * 1024.0);
    printf("prediction: 2 x %d x %d x 8 bytes = %.1f MiB\n", N + 2, N + 2, predicted_mib);

    long size0 = status_kb("VmSize"), rss0 = status_kb("VmRSS");
    double *u = malloc(cells * sizeof *u), *unew = malloc(cells * sizeof *unew);
    long size1 = status_kb("VmSize"), rss1 = status_kb("VmRSS");
    volatile double *pu = u, *pn = unew;      /* volatile: the compiler must perform every store */
    for (size_t i = 0; i < cells; i++) { pu[i] = 0.0; pn[i] = 0.0; }   /* first touch of every page */
    long size2 = status_kb("VmSize"), rss2 = status_kb("VmRSS");

    printf("after malloc:      VmSize +%4ld MiB   VmRSS +%4ld MiB\n",
           lround((size1 - size0) / 1024.0), lround((rss1 - rss0) / 1024.0));
    printf("after first touch: VmSize +%4ld MiB   VmRSS at %ld %% of the prediction\n",
           lround((size2 - size0) / 1024.0), lround(100.0 * (rss2 - rss0) / 1024.0 / predicted_mib));
    printf("growth of VmRSS within 1 MiB of the prediction: %s\n",
           fabs((rss2 - rss0) / 1024.0 - predicted_mib) < 1.0 ? "yes" : "no");
    return 0;
}

Interfaces, and the cost of a message

A host in this section is a machine with a set of network interfaces, each with an IPv4 address of 32 bits written as four decimal bytes. RFC 1122 reserves the addresses whose first byte is 127 as the internal host loopback address and requires that they never appear outside the host (§3.2.1.3, p. 31). The block 127.0.0.0/8 is therefore the loopback address space, and 127.0.0.1 is the one address that the interface lo carries by default; the first output block of the listing below prints lo UNKNOWN 127.0.0.1/8, where the prefix length 8 means that the whole block is local. The WSL guest configures a second address on lo, which the listing does not print because it keeps only the first three fields. The current manual describes ip as showing and manipulating routing, network devices, interfaces and tunnels (ip(8)); the lecture's description names routing, devices and policy routing.

The cost of sending a message of \(m\) bytes between two hosts is modelled in this book as \(T_{\mathrm{msg}}(m)=\alpha+\beta m\), where \(\alpha\) is the latency in seconds and \(\beta\) is the inverse bandwidth in seconds per byte. ping measures a round trip. It sends an ICMP echo request and waits for the echo reply; RFC 792 defines the echo message as type 8 and the reply as type 0, and requires that the data received in the echo message be returned in the reply (pp. 14–15). The default payload is 56 data bytes, which with the 8-byte ICMP header gives the 64 bytes that ping prints (ping(8)). If both directions cost the same, the round-trip time is \(\mathrm{RTT}(m)=2\alpha+2\beta m\). The loopback interface does not use a network card, so \(\alpha\) here is the time of the kernel's software path, and \(\beta^{-1}\) is the rate at which the kernel copies the payload. The listing measures both on this machine and then fetches a file through the interface with wget.

The script prints the loopback interface, then sends 100 echo requests at 10 ms spacing for each of five payload sizes and keeps the minimum round-trip time, which suppresses interference from other processes at the cost of hiding variability. The least-squares line through the five minima gives an intercept and a slope. A second part starts the Python module http.server on a free port of the loopback address, fetches a small file with wget, compares it with the original by cmp, then fetches 200 MB of zeros and divides by the elapsed time. The script starts one server, keeps its PID in $! and ends it with kill on that PID. The printed timings are one sample run; the check is the return code.

In five other runs the intercept was 24.3, 24.3, 26.6, 26.6 and 27.0 µs and the slope 0.0003, 0.0005 and 0.0003 µs/B (three earlier runs, which printed four decimals) and 0.00029 and 0.00018 µs/B (two later runs, five decimals), so \(\alpha\) lies between 11.6 and 13.5 µs and \(\beta^{-1}=2/\text{slope}\) between 4.0 and 11.1 GB/s over the six runs, including the sample's 8.8 GB/s. The slope is not resolved by this method. Each minimum has a resolution of 1 µs, the five minima do not increase monotonically (in this sample the minimum at 16,000 B, 19 µs, is below the one at 16 B, 26 µs), and the slope is the difference of numbers of that resolution. The measurement determines \(\alpha\) to within about 15 % and \(\beta\) only to within a factor of 2.8. The file transfer gives a second bound: 200 MB in 0.10 s is 2.06 GB/s in this sample (2.1 to 2.3 GB/s in three other runs on an otherwise idle machine; in a run made while other processes were active it fell to 1.07 GB/s, with \(\alpha=10.1\ \mu\mathrm{s}\) and \(\beta^{-1}=4.45\) GB/s), which is a lower bound on the rate of the loopback path, because the figure includes the Python server and wget, and it depends on the load. With \(\alpha=12\ \mu\mathrm{s}\) and a bandwidth between 1.1 and 11.1 GB/s, the message size at which the latency equals the transfer time, \(m_{1/2}=\alpha/\beta\), lies between 13 kB and 133 kB. The numbers describe the software path inside one machine. They say nothing about a physical network, whose latency and bandwidth depend on the cable, the card and the switch, and which chapters 14 and 28 measure with MPI.

Remote login and copying

The lecture's ssh example logs in from a local machine to a server with the command ssh user@address; the server asks for a password, and after it accepts, the prompt shows that the commands now run on the server and the directory listing is that of the server. RFC 4251 describes the protocol as three components: the transport layer protocol provides server authentication, confidentiality and integrity; the user authentication protocol authenticates the client to the server; and the connection protocol multiplexes the encrypted tunnel into logical channels (§1). The ssh manual describes the program as one for logging into a remote machine and for executing commands on it (ssh(1)); with a command after the host name it runs that command and returns its output without an interactive login. The test machine has no SSH server, so the chapter does not demonstrate a login. The option -G makes ssh print the configuration that it would use for a connection and exit, which lets a person check the user, the host and the port that a command line selects before connecting.

The lecture states that scp copies files securely between hosts. The manual states that scp uses the SFTP protocol over an ssh connection and the same authentication and security as a login session (scp(1)). That was not always so: the OpenSSH 9.0 release notes (April 2022) record the switch of scp from the legacy scp/rcp protocol to SFTP by default, and note that the legacy protocol expanded wildcards in remote file names through the remote shell, which made double quoting of shell characters necessary. The machine here has OpenSSH 9.6, so the new behaviour applies. The script below uses only commands that need no server. ssh -G shows the connection that a command line selects, scp between two local paths shows that the command line is the same as for a remote copy, and a name with a colon shows the rule by which scp reads the text before a colon as a host name. The output is deterministic, and the check is exact.

cd "$(mktemp -d /tmp/hpsc-demo.XXXXXX)"

echo "== the connection ssh would make, without making it"
ssh -G -p 2222 alice@login.example.org 2> /dev/null | grep -E '^(user|hostname|port) '

echo "== scp between two local paths uses the same command line as a remote copy"
printf 'iter 500 residual 1.291163e-06\n' > run.log
scp run.log run_copy.log && cmp run.log run_copy.log && echo "run_copy.log is identical to run.log"

echo "== a colon in the first path makes scp read a host name"
echo data > a:b.log
scp a:b.log . > /dev/null 2>&1; echo "scp a:b.log . exit status: $? (the host a could not be reached)"
scp ./a:b.log c.log && echo "./a:b.log is read as a local path"

== the connection ssh would make, without making it
user alice
hostname login.example.org
port 2222
== scp between two local paths uses the same command line as a remote copy
run_copy.log is identical to run.log
== a colon in the first path makes scp read a host name
scp a:b.log . exit status: 255 (the host a could not be reached)
./a:b.log is read as a local path

The command line ssh -p 2222 alice@login.example.org selects the user alice, the host login.example.org and port 2222, as -G prints. The local copy produces an identical file. A file name with a colon, a:b.log, is read as the file b.log on a host named a; the attempt fails with status 255 because the host cannot be reached, and the path ./a:b.log is read as a local file. The practical rule for a log or result with a colon in its name, for example a timestamp, is to give the path a leading ./. The chapter did not test password or key authentication, host-key checking or wget against a remote server; the lecture's example uses a password, and a cluster's access policy decides whether keys are required.

Exercises

Exercise 1 (derive). Let \(k_{10}\) be the number of sweeps in which the residual of the Jacobi iteration falls by a factor of 10 in the asymptotic range. Express \(k_{10}\) through (4.4), show that \(k_{10}\approx2(N+1)^{2}\ln10/\pi^{2}\) with a relative error of about \(\theta^{2}/6\) where \(\theta=\pi/(N+1)\), and evaluate both forms for \(N=16\) and \(N=1000\). Compare the exact value for \(N=16\) with the number of sweeps per decade that the log of the first listing shows between sweep 100 and sweep 400.

Solution

In the asymptotic range \(r_{k+k_{10}}=\rho^{k_{10}}r_k\), so \(\rho^{k_{10}}=1/10\) and \(k_{10}=\ln10/(-\ln\rho)\) with \(\rho=\cos\theta\). The series \(-\ln\cos\theta=\theta^{2}/2+\theta^{4}/12+\cdots\) gives \(-\ln\rho=(\theta^{2}/2)(1+\theta^{2}/6+\cdots)\), so \(k_{10}=(2\ln10/\theta^{2})(1-\theta^{2}/6+\cdots)\), and the leading term \(2(N+1)^{2}\ln10/\pi^{2}\) overestimates by the relative amount \(\theta^{2}/6\). For \(N=16\), \(\theta=0.18480\), \(\theta^{2}/6=0.0057\); the exact value is \(134.08\) sweeps and the approximation is \(134.85\), 0.57 % higher. For \(N=1000\), \(\theta^{2}/6=1.6\times10^{-6}\), the exact value is \(467{,}534.2\) sweeps and the approximation is \(467{,}535.0\). The log of the first listing has \(r_{100}=1.296030\times10^{-3}\) and \(r_{400}=7.191545\times10^{-6}\), a ratio of 180.2 over 300 sweeps, which is \(300/\log_{10}180.2=133.0\) sweeps per decade, 0.8 % below the exact 134.08 because the window starts in the transient, as the window estimate of the section on convergence did.

Exercise 3 (counterexample). A script finds the smallest residual of a log with grep '^iter' solver.log | awk '{print $4}' | sort -n | head -n 1 and counts the distinct residual values with uniq | wc -l. Give a three-line input on which the first command returns the largest residual and a three-line input on which the second reports 3 for a file with two distinct lines.

Solution

For the first command take the residual column 1.2e-03, 9.5e-05, 4.0e-05. sort -n reads only the leading numeric strings 1.2, 9.5 and 4.0, because it does not recognize the exponent (GNU coreutils manual), orders them as 1.2, 4.0, 9.5, and head -n 1 returns 1.2e-03, the largest value. The listing of the pipeline section shows the same effect for four values. The command that gives the right answer is sort -g | head -n 1, which returns 4.0e-05. For the second command take the lines 1e-3, 5e-4, 1e-3. uniq removes only adjacent repeats, the two equal lines are not adjacent, and uniq | wc -l prints 3 for two distinct lines. The right commands are sort -u | wc -l or sort | uniq | wc -l, which print 2.

Exercise 4 (diagnose an assumption). A script contains grep '^iter' missing.log | tail -n 1 | awk '{print $4}' followed by if [ $? -eq 0 ]; then echo "last residual read"; fi. The file missing.log does not exist. State what the script prints, name the false assumption and give two repairs. Then say what a script sees if it sets set -o pipefail and ends a pipeline that reads a large input with head.

Solution

The script prints last residual read. The grep fails with status 2 and a message on standard error (the file does not exist), tail and awk succeed on empty input, and the status of the pipeline is the status of the last command, 0 (POSIX.1-2017, Shell Command Language §2.9.2). The false assumption is that the status of a pipeline reports the failure of any stage. In Bash, echo "${PIPESTATUS[@]}" directly after the pipeline prints 2 0 0 for this case. The first repair is set -o pipefail, under which the status is the status of the rightmost failing command, here 2. The second repair is to test the input first, with [ -r missing.log ] or with the status of grep in a separate command. With pipefail a pipeline that ends in head and reads more than head consumes (the first section of pipes.sh) reports 141, the status of a seq killed by SIGPIPE, although every line that head printed was correct. A script that enables pipefail must therefore either avoid head at the end of a long pipeline or accept 141 as success for that stage.

Exercise 5 (design judgment). A run with \(N=1000\) that must bring the error below \(10^{-6}\) needs about 2.6 million sweeps, which is 2.4 hours at the 3.3 ms per sweep measured in this chapter. The only machine available is a shared login node. Choose among starting the solver with a plain &, starting it with nohup, starting it in a terminal multiplexer, and submitting it to the batch scheduler. Give the quantitative facts of this chapter that bear on the choice, and say what to log and at what interval.

Solution

A plain & is the worst choice: when the terminal closes, SIGHUP terminates the job, and wait would report status 129 (jobs_demo.sh). nohup survives the hangup and writes to nohup.out if the output is not redirected, so, after changing max_iter to at least 2,700,000 and tol to \(4.9\times10^{-12}\) in the source (neither is a command-line argument), the command should be nohup ./jacobi_log 1000 1000 > run.log 2> run.err & with the PID kept from $! for later ps and kill commands. A terminal multiplexer keeps the session alive in the same way and adds the ability to reattach; the chapter did not test one. The batch scheduler is the correct choice on a shared node: the run holds one processor for hours, and the lecture's own motivation for top is the load that a process puts on a shared system; chapter 30 treats the scheduler. The memory is not a constraint, since two grids need 15.3 MiB. The stopping rule needs a change: the solver of the first listing stops at \(r\lt10^{-6}\), which for \(N=1000\) ends the run after 191,001 sweeps with an error of 0.167; for an error below \(10^{-6}\) the tolerance must be about \(10^{-6}(1-\rho)=4.9\times10^{-12}\) by (4.8) (\(3.4\times10^{-12}\) for a guaranteed max-norm bound, which needs the factor 1.45). The log size follows from the interval: with a line every 1000 sweeps the log has about 2600 lines; with a line every 50 sweeps it has 52,000 lines of about 35 bytes, about 1.8 MB. A line every 1000 sweeps is enough to estimate the factor from the last two lines with (4.4) and to predict the end with (4.6), provided that the run is past the transient. The transient does not shorten for a large grid: the ratio of the second eigenvalue \(\mu_{21}\) to \(\rho\) is about \(1-3\theta^{2}/4\), so the transient lasts a number of sweeps that grows as \(N^{2}\), like the run itself. A residual line with the iteration number, written with fflush or to a file, lets tail -n 2 and one awk program report the state of the run at any time.

Exercise 6 (implementation and measurement). Write an awk program that reads a log of the format of the first listing and prints \(\hat\rho_{\mathrm{last}}\), \(\rho\), the end predicted by (4.6) from the last progress line, the end predicted from the first progress line, and the sweep at which the run converged. Run the solver with ./jacobi_log 64 500 and apply the program. State how far each prediction is from the observed end.

Solution

The program reads \(N\) and the tolerance from the header, keeps the first and the last two progress lines, and reads the final sweep from the last line of the log:

awk '/^# jacobi/ { split($3, a, "="); N = a[2]; split($4, b, "="); tol = b[2] }
     /^iter/ { if (!n++) { k0 = $2; r0 = $4 } kp = k1; rp = r1; k1 = $2; r1 = $4 }
     /^# converged/ { split($3, a, "="); kc = a[2] }
     END { rho = cos(atan2(0, -1) / (N + 1)); rhat = (r1 / rp) ^ (1 / (k1 - kp))
           printf "rho_hat_last=%.6f rho=%.6f predicted=%.1f from_first=%.1f converged=%d\n", rhat, rho,
                  k1 + log(tol / r1) / log(rhat), k0 + log(tol / r0) / log(rho), kc }' solver.log

The solver with \(N=64\) and a line every 500 sweeps writes ten progress lines and converges at sweep 5272 with residual \(9.997952\times10^{-7}\). The program prints rho_hat_last=0.998832 rho=0.998832 predicted=5271.8 from_first=5719.4 converged=5272. The factor from the last two lines equals \(\rho\) to the six printed digits. The prediction from the last progress line (sweep 5000, \(r=1.373855\times10^{-6}\)), using \(\hat\rho_{\mathrm{last}}\) in place of \(\rho\) in (4.6), is 5271.8, 0.2 sweeps below the observed end. The prediction from the first line (sweep 500, \(r=4.452550\times10^{-4}\)), using \(\rho\), is 5719.4, which is 447 sweeps or 8.5 % above the observed end: the early residual lies above the asymptote \(A\rho^{k}\), and extrapolating from it with the asymptotic factor overestimates the remaining work. The overestimate is 3.4 % for \(N=16\) (first line at sweep 50) and 9.1 % for \(N=32\) (first line at sweep 100), so it does not fall as the grid is refined (3.4 %, 9.1 % and 8.5 % for \(N=16,32,64\)); it depends on how early in the run the first line lies. The numbers of this solution come from running the solver and the program on this machine in a separate session; the code lab does not run exercise solutions.
