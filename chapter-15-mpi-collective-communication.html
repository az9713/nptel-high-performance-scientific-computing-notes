MPI II: collective communication and global numerical decisions

Split a 16 × 16 heat grid across four processes. On the first Jacobi sweep, the process touching the hot edge sees a maximum update of 0.25, while the other three see zero. A local stopping test would let three processes declare success before heat has reached their rows. The correct decision is one global maximum, returned to every process. That scalar occupies eight bytes on the verification machine; the difficulty is coordinating its meaning and completion, not storing it. The same choices decide whether an eight-element dot product includes all eight elements and whether a distributed transpose actually changes the matrix.

Grounded in W5L3, Collective Communication in MPI, W6L1, Examples of Collective Communication in MPI, Part 1, and W6L2, Part 2, from the NPTEL course High Performance Scientific Computing (Prof. Shivasubramanian Gopalakrishnan, IIT Bombay). Lecture material: collective matching, barrier, broadcast, scatter, gather, all-gather, all-to-all, reduction operators and scans; nonblocking collectives; stencil decomposition and physical versus partition boundaries; dot products, vector normalization and matrix transposition. Research extensions: MPI 4.1, official PDF chapter 6, fixes the semantic guarantees; the Forum's explicitly unofficial HTML rendering numbers the corresponding collective chapter 7. Thakur, Rabenseifner and Gropp (2005) motivate message-size-dependent collective algorithms; Open MPI 4.1.6 source identifies concrete all-reduce selection and fallback rules. Original teaching constructions: the distributed-data model, coverage proofs for variable partitions, numerical stopping counterexample, complete verification programs, block-transpose derivation, analytic cost comparisons, fresh TCP-loopback captures and six worked exercises.

The objects of the chapter and the running case W5L3 0:36

An MPI process has its own address space. A communicator identifies a group of processes and a communication context; its ranks are the integers \(r=0,\ldots,p-1\), where \(p\) is the group size. This chapter uses intracommunicators, whose communicating processes belong to one group. A root is a rank chosen consistently by all participants as a source or destination for a rooted collective. The root need not be rank zero.

A collective is a group operation in which the participating processes make matching calls. It does not mean that one process calls a routine which remotely forces other processes to enter theirs. Describe its mathematical input as a distributed tuple \((x_0,\ldots,x_{p-1})\), with x_r stored at rank r. A block is an ordered sequence of elements; its element count, datatype and byte size are different attributes. The collective defines a transformation of distributed tuples, while the library chooses how to implement that transformation.

The running scientific object is the canonical Jacobi grid. There are \(N\) interior cells per direction, spacing \(h_g=1/(N+1)\), a unit top boundary, zero other edges and an initially zero interior. The arrays u and unew hold successive iterates. A sweep sets each interior new value to the average of four old neighbors. Define the maximum update \(r_k=\max_{i,j}|u^{(k+1)}_{i,j}-u^{(k)}_{i,j}|\). This is an update norm, not the differential-equation residual; the old grid's maximum discrete Laplacian is \(4r_k/h_g^2\).

Rank r owns a set of cells \(\Omega_r\). The ownership sets are disjoint and together cover every interior cell. Its local maximum is \(r_{k,r}=\max_{(i,j)\in\Omega_r}|u^{(k+1)}_{i,j}-u^{(k)}_{i,j}|\), with zero for an empty owned set. Then \(r_k=\max_r r_{k,r}\). Every process must use that same global value for the stop decision. The equation identifies Allreduce with MAX as the required operation without committing to a communication algorithm.

The cost model uses message latency \(\alpha\) in seconds and inverse bandwidth \(\beta\) in seconds per byte: a message carrying m bytes costs \(\alpha+\beta m\). A reduction adds \(\gamma\), seconds per byte of local combine work. These are model parameters for a stated transport and regime, not universal constants. Later sections assume identical links and one simultaneous send and receive per process. Local experiments use processes on one laptop with TCP over loopback plus self transport, rather than shared-memory message transport or a physical inter-node network.

Matching and local completion determine legal programs W5L3 3:02

Collectives use a communicator and a consistent call order instead of application message tags. They do not match ordinary point-to-point messages. Count and datatype arguments must have the required matching type signatures between sending and receiving participants; identical byte counts alone do not establish a type match. A type signature is the ordered sequence of basic MPI types described by the datatype and count. Distinct memory layouts can describe the same signature.

MPI 4.1 HTML §7.1 distinguishes local completion from group synchronization. Returning from a blocking data collective makes the caller's relevant buffers usable according to that operation. It does not generally prove that every other process has completed, or even entered, its call. Thus the W5L3 description of blocking broadcast as waiting until every recipient has received is too strong. It is legitimate for a root to finish its participation before a delayed receiver starts.

A barrier, HTML §7.3, has the explicit entry guarantee: it cannot return to a process until all communicator members have entered. Even this does not promise simultaneous return. Nor does it order text arrival from different operating-system output streams. To produce stable output, the programs collect results at one rank and print them there. A barrier is a distributed execution condition, not a terminal-output ordering service.

A useful dataflow argument explains why some calls often appear to synchronize. If rank j needs an output that depends on a still-undetermined input at rank i, j cannot correctly produce that output before the contribution is available. But availability of contributions, completion of local buffers, entry to calls and simultaneous continuation are distinct statements. Barrier has no data buffer, so a send-buffer counterfactual is not its proof. Use the operation's documented synchronization contract rather than classifying all data collectives as interchangeable barriers.

For an invalid matching example, rank zero calls Bcast followed by Barrier while rank one calls Barrier followed by Bcast on the same communicator. The routine order disagrees. A small-message broadcast that happens to finish early can conceal the defect; a synchronizing implementation can expose it as a hang. The valid repair is the same collective order on all ranks, or a deliberately separated communicator context for independent collective streams. Merely changing message size is not a correctness repair.

The first program delays rank one by 100 ms before each of four operations. Rank zero times its own Bcast-root, Reduce-nonroot, Allreduce and Barrier calls. Each case begins with a barrier to avoid carrying an earlier case's delay into the next interval. The operation results are checked. The displayed times are one capture, not predictions of early completion: an implementation is allowed to synchronize a broadcast too. Allreduce receives the delayed rank's contribution before its result is consumed.

#define _POSIX_C_SOURCE 200809L
#include <mpi.h>
#include <stdio.h>
#include <time.h>
int main(int argc,char **argv) {
    int r,p;MPI_Init(&argc,&argv);MPI_Comm_rank(MPI_COMM_WORLD,&r);MPI_Comm_size(MPI_COMM_WORLD,&p);
    if(p<2)MPI_Abort(MPI_COMM_WORLD,2);
    const char *names[]={"Bcast root0","Reduce root1","Allreduce","Barrier"};
    for(int op=0;op<4;++op) {
        int x=7,y=0;MPI_Barrier(MPI_COMM_WORLD);
        if(r==1){struct timespec delay={0,100000000};nanosleep(&delay,NULL);}
        double t=MPI_Wtime();
        if(op==0)MPI_Bcast(&x,1,MPI_INT,0,MPI_COMM_WORLD);
        if(op==1)MPI_Reduce(&x,&y,1,MPI_INT,MPI_SUM,1,MPI_COMM_WORLD);
        if(op==2)MPI_Allreduce(&x,&y,1,MPI_INT,MPI_SUM,MPI_COMM_WORLD);
        if(op==3)MPI_Barrier(MPI_COMM_WORLD);
        t=MPI_Wtime()-t;
        if((op==0&&x!=7)||(op==1&&r==1&&y!=7*p)||(op==2&&y!=7*p))MPI_Abort(MPI_COMM_WORLD,3);
        if(r==0)printf("%-13s rank0 elapsed=%.3f ms\n",names[op],1000*t);
    }
    MPI_Finalize();return 0;
}

Specify the destination layout before selecting a collective W5L3 4:02

Broadcast replicates one root buffer. Scatter partitions a root buffer into equal-size destination blocks, whereas Gather concatenates source blocks at the root. MPI 4.1 HTML §7.6 states Scatter's per-destination count; HTML §7.5 states Gather's per-source receive count. Confusing a per-rank count with the total count causes buffer overruns. The library cannot infer the allocation size of a C pointer.

For four ranks, a direct root-to-others broadcast uses three network messages, each with a matching receive. The root retains its own data without requiring a network transfer to itself. W5L3 counts three such pairs, while the later recap counts four. Four is a count including the root's conceptual participation, not the minimal direct message count. An algorithm may forward data through a tree instead of issuing those three root sends; the conceptual transformation does not prescribe a transport schedule.

Allgather, HTML §7.7, gives every rank the rank-ordered list of all source blocks. If each input block occupies m bytes, each result occupies pm bytes. Summing replicated result storage over p ranks gives p²m bytes, an original consequence of the per-rank scaling noted in W6L2. With 10000 ranks and eight-byte contributions, that is 80000 bytes per rank and 800000000 bytes over all ranks. Allreduce can instead return only the combined scalar when the full list is unnecessary.

Alltoall, HTML §7.8, sends different destination blocks from every source. If source i stores blocks x_i,0 through x_i,p−1, destination j receives x_0,j through x_p−1,j. This transposes a table of blocks; it does not necessarily transpose the elements inside each block. That second mapping is central to the matrix example below.

The verification program uses root value 73, scatter blocks 10+r, an all-gather of ranks, and all-to-all blocks encoded as 100i+j. It checks every received integer before combining success flags with an Allreduce of MIN. Only rank zero prints. This exercises layout and matching with a small exact dataset; it measures neither network efficiency nor internal point-to-point message count.

#include <mpi.h>
#include <stdio.h>
#include <stdlib.h>
int main(int argc,char **argv) {
    int r,p;MPI_Init(&argc,&argv);
    MPI_Comm_rank(MPI_COMM_WORLD,&r);MPI_Comm_size(MPI_COMM_WORLD,&p);
    int *send=malloc((size_t)p*sizeof *send),*recv=malloc((size_t)p*sizeof *recv);
    if(!send||!recv)MPI_Abort(MPI_COMM_WORLD,2);
    int ok=1,value=r==0?73:0,part=0;
    MPI_Bcast(&value,1,MPI_INT,0,MPI_COMM_WORLD);ok&=value==73;
    for(int j=0;j<p;++j)send[j]=10+j;
    MPI_Scatter(send,1,MPI_INT,&part,1,MPI_INT,0,MPI_COMM_WORLD);ok&=part==10+r;
    MPI_Gather(&part,1,MPI_INT,recv,1,MPI_INT,0,MPI_COMM_WORLD);
    if(r==0)for(int j=0;j<p;++j)ok&=recv[j]==10+j;
    MPI_Allgather(&r,1,MPI_INT,recv,1,MPI_INT,MPI_COMM_WORLD);
    for(int j=0;j<p;++j)ok&=recv[j]==j;
    for(int j=0;j<p;++j)send[j]=100*r+j;
    MPI_Alltoall(send,1,MPI_INT,recv,1,MPI_INT,MPI_COMM_WORLD);
    for(int j=0;j<p;++j)ok&=recv[j]==100*j+r;
    int allok;MPI_Allreduce(&ok,&allok,1,MPI_INT,MPI_MIN,MPI_COMM_WORLD);
    if(r==0)printf("p=%d broadcast/scatter/gather/allgather/alltoall verified\n",p);
    free(send);free(recv);MPI_Finalize();return allok?0:1;
}

The vector variants, named Scatterv, Gatherv, Allgatherv and Alltoallv, permit differing block sizes. Counts give elements, while displacements locate blocks in units of the relevant datatype's extent. For the basic contiguous types used here, extent equals the spacing between successive array elements. Byte displacements and element displacements must not be confused. We use small int counts; large-count APIs and arbitrary derived datatypes require additional representation checks.

For N elements over p ranks, let q be the integer quotient N/p and \(n_{\rm rem}\) the remainder N mod p. Assign \(c_r=q+1\) when \(r\lt n_{\rm rem}\) and \(c_r=q\) otherwise, with displacement \(d_r=rq+\min(r,n_{\rm rem})\). There are \(n_{\rm rem}\) larger blocks, so their sum is \(pq+n_{\rm rem}=N\). Also \(d_{r+1}=d_r+c_r\), starting at zero and ending at N. These identities prove that the half-open intervals \([d_r,d_r+c_r)\) are disjoint and cover every index exactly once. Empty blocks when p exceeds N are legitimate; the code supplies valid allocation objects even for zero counts.

Reduction is algebra plus a numerical ordering choice W5L3 11:23

A reduction combines corresponding elements from every participant. MPI 4.1 HTML §7.9.1 specifies Reduce's root result; HTML §7.9.6 specifies Allreduce's result at every rank and requires identical results among participants in that operation. Neither routine concatenates the input vectors. Reducing vectors of length n produces n combined elements, whereas gathering p such vectors produces pn elements.

The built-in operator families include SUM and PROD for arithmetic, MAX and MIN for extrema, logical AND/OR/exclusive-OR, and bitwise AND/OR/exclusive-OR. An operation's allowed datatype matters: logical combination is not interchangeable with addition or arbitrary structure reduction. The predefined-operator table, HTML §7.9.2, gives the allowed pairs. User-defined combining operations require the stated algebraic properties and an appropriate datatype; passing a C function does not make an arbitrary order-sensitive calculation a valid associative reduction.

In exact arithmetic, associativity lets the library choose a tree. With a commutative operation, operand order may also change. Floating-point addition models an associative mathematical sum but is not itself associative. For binary64 round-to-nearest arithmetic, take \(a=2^{53}\), the point beyond which adjacent integers are not all representable. Then \((a+1)+(-a)=0\) after the first addition rounds, whereas \(a+(1-a)=1\). A changed last bit is therefore not sufficient evidence of an MPI race or a wrong mathematical partition.

Correct numerical verification should identify both the mathematical answer and an error criterion. For midpoint π, rank r handles indices r,r+p,r+2p and so forth below n. Every nonnegative integer index has exactly one remainder modulo p, proving complete disjoint coverage. Each rank computes its partial sum and Reduce adds those sums at the root. The integrand is \(4/(1+x^2)\), the width is \(\Delta=1/n\), and \(x_i=(i+1/2)\Delta\). The truncation error is from the quadrature formula; additional rounding error depends on the order of local and global additions. Changing p can change the latter without changing the sample set.

Scans retain rank-prefix results. Scan, HTML §7.11.1, includes the caller's contribution, while Exscan, HTML §7.11.2, excludes it. Rank zero's Exscan receive value is undefined, so explicitly set it to the desired empty-prefix identity before using it. Summing distributed counts this way produces offsets for packed data: rank r's offset is the total count of all lower ranks.

MAXLOC returns a value and an attached index. HTML §7.9.4 defines tie-breaking toward the smaller index. Supplying each process's rank as that index finds the first rank holding the maximum. Supplying a global cell index instead can locate the first maximum cell, provided the datatype matches that pair representation. A rank and a numerical array index are different identifiers.

The following program verifies integer sum, inclusive and exclusive prefixes, MAXLOC tie-breaking, and a 100000-step π estimate whose absolute error must be below \(10^{-9}\). All integer values fit the C int type for the requested four ranks. It prints assertions rather than pretending that one particular MPI sum order is portable. Its exact stdout check is possible because the varying low bits of π are not printed.

#include <mpi.h>
#include <stdio.h>
#include <math.h>
int main(int argc,char **argv) {
    int r,p;MPI_Init(&argc,&argv);MPI_Comm_rank(MPI_COMM_WORLD,&r);MPI_Comm_size(MPI_COMM_WORLD,&p);
    int x=r+1,sum=0,prefix=0,offset=0,ok=1;
    MPI_Allreduce(&x,&sum,1,MPI_INT,MPI_SUM,MPI_COMM_WORLD);
    MPI_Scan(&x,&prefix,1,MPI_INT,MPI_SUM,MPI_COMM_WORLD);
    MPI_Exscan(&x,&offset,1,MPI_INT,MPI_SUM,MPI_COMM_WORLD);
    if(r==0)offset=0;
    ok&=sum==p*(p+1)/2;ok&=prefix==(r+1)*(r+2)/2;ok&=offset==r*(r+1)/2;
    struct {double value;int rank;} in={r%2==0?9.0:4.0,r},out;
    MPI_Allreduce(&in,&out,1,MPI_DOUBLE_INT,MPI_MAXLOC,MPI_COMM_WORLD);
    ok&=out.value==9.0&&out.rank==0;
    const long num_steps=100000;
    double local=0.0,pi=0.0,h=1.0/num_steps;
    for(long i=r;i<num_steps;i+=p){double z=(i+0.5)*h;local+=4.0/(1.0+z*z);}
    MPI_Reduce(&local,&pi,1,MPI_DOUBLE,MPI_SUM,0,MPI_COMM_WORLD);
    if(r==0)ok&=fabs(pi*h-acos(-1.0))<1e-9;
    int allok;MPI_Allreduce(&ok,&allok,1,MPI_INT,MPI_MIN,MPI_COMM_WORLD);
    if(r==0)printf("p=%d sum/scans/MAXLOC verified; midpoint pi error below 1e-9\n",p);
    MPI_Finalize();return allok?0:1;
}

Reduce-scatter combines before distributing. In HTML §7.10.1, Reduce_scatter_block reduces equal full input vectors and gives rank r the r-th equal block of the result. The variable-count version uses a common array of receive block lengths. This is useful when the reduced vector itself should remain distributed. It avoids materializing a complete reduced vector at every process merely to discard most of it.

Global convergence and nonblocking completion are different obligations W5L3 14:17

Nonblocking collectives return a request that must later be completed. MPI 4.1 HTML §7.12 requires preserving send data and input argument arrays, and not accessing receive buffers, until completion. Blocking and nonblocking collectives do not match each other; all participants must initiate them in the same order on the communicator. Nonblocking gives an opportunity for useful independent work, not a guarantee of communication/computation overlap or improved time.

The next program starts an integer Iallreduce, computes an unrelated checksum, then waits before examining the global sum. The checksum is deliberately not a performance workload and the compiler may simplify it. The check demonstrates legal buffer ownership and completion, without claiming asynchronous progress or measured overlap. A progress experiment would need independently observable work and timings that distinguish initiation, computation and wait.

#include <mpi.h>
#include <stdio.h>
#include <stdint.h>
int main(int argc,char **argv) {
    int r,p;MPI_Init(&argc,&argv);MPI_Comm_rank(MPI_COMM_WORLD,&r);MPI_Comm_size(MPI_COMM_WORLD,&p);
    int local=r+1,global=0;MPI_Request request;
    MPI_Iallreduce(&local,&global,1,MPI_INT,MPI_SUM,MPI_COMM_WORLD,&request);
    uint64_t checksum=0;
    for(uint64_t i=0;i<100000;++i)checksum+=i;
    MPI_Wait(&request,MPI_STATUS_IGNORE);
    int ok=global==p*(p+1)/2&&checksum==UINT64_C(4999950000),allok;
    MPI_Allreduce(&ok,&allok,1,MPI_INT,MPI_MIN,MPI_COMM_WORLD);
    if(r==0)printf("p=%d Iallreduce completed; independent checksum=4999950000\n",p);
    MPI_Finalize();return allok?0:1;
}

For time modeling, if communication takes C seconds and independent computation H seconds, perfect overlap would cost roughly \(\max(C,H)\), while no overlap costs roughly C+H, plus initiation and completion overhead. The maximum ideal saving is \(\min(C,H)\). Obtaining it depends on progress, resources and data independence. Running a second Jacobi sweep that overwrites a still-active reduction's send buffer is not a legal way to manufacture overlap.

W5L3 moves from nonblocking collectives to a five-point mesh and its partitioning. The global geometry is fixed; partition boundaries are artifacts of assigning cells to processes. Physical boundaries carry the prescribed heat data. Internal boundaries require neighbor data, not a new physical boundary condition. A process grid with \(P_x\) subdivisions in x and \(P_y\) in y has \(p=P_xP_y\) processes. Divisibility makes equal rectangular blocks easy; it is a convenience, not a condition for solving a PDE in parallel.

On the 3-by-3 process-grid slide the center process has four adjacent neighbors, edge processes three and corners two. Naming an absent outside neighbor as MPI_PROC_NULL simplifies communication control but does not install a temperature value. The application must initialize and preserve physical boundary data. The next chapter develops efficient halo exchange; the present question is what every process must learn to stop the iteration consistently.

The global update norm is exactly the maximum of local update norms because the ownership sets partition the interior. Taking max over each subset and then over subsets includes every candidate and introduces none. For finite nonnegative floating-point updates without NaNs, selecting a maximum does not accumulate rounding error as a sum does. If each cell uses the same arithmetic expression and old neighbor values as serial, an induction on sweeps proves identical cell values: initialization agrees, all required old values agree, and therefore each new expression agrees. The maximum then agrees too. This proof is about the implemented discrete iteration under the stated arithmetic, not the continuum PDE error.

We verify that argument using a deliberately simple communication design. Each rank owns rows for computation but retains a full grid replica; Allgatherv assembles newly computed rows at every rank after each sweep. An Allreduce of MAX produces the stopping value. This is a verification construction whose full-grid replication and communication are expensive. It keeps the collective question separate from halo implementation and is not presented as the scalable production solver.

The program uses N=16, an update threshold of \(10^{-6}\) and a 5000-sweep cap. It executes a serial reference sweep alongside every distributed sweep, checking all cells and the global norm at every iteration. It also records the first iteration on which each rank's local norm is below the threshold while continuing safely with the global stop. It never actually lets an early local success terminate neighbor participation.

#include <mpi.h>
#include <stdio.h>
#include <stdlib.h>
#include <math.h>
#define N 16
#define PITCH (N+2)
#define IDX(i,j) ((i)*PITCH+(j))
int main(int argc,char **argv) {
    int r,p;MPI_Init(&argc,&argv);MPI_Comm_rank(MPI_COMM_WORLD,&r);MPI_Comm_size(MPI_COMM_WORLD,&p);
    int *counts=malloc((size_t)p*sizeof *counts),*displs=malloc((size_t)p*sizeof *displs),start=0,rows=0;
    if(!counts||!displs)MPI_Abort(MPI_COMM_WORLD,2);
    for(int q=0;q<p;++q){int c=N/p+(q<N%p);counts[q]=c*PITCH;displs[q]=(start+1)*PITCH;if(q==r)rows=c;start+=c;}
    start=displs[r]/PITCH;
    double *local=calloc((size_t)(rows?rows:1)*PITCH,sizeof *local);
    double u[PITCH*PITCH]={0},unew[PITCH*PITCH]={0},ref[PITCH*PITCH]={0},next[PITCH*PITCH]={0};
    if(!counts||!displs||!local)MPI_Abort(MPI_COMM_WORLD,2);
    for(int j=0;j<PITCH;++j)u[j]=unew[j]=ref[j]=next[j]=1.0;
    double global=1.0;int iter=0,first=0,ok=1;
    while(global>=1e-6&&iter<5000) {
        double diff=0.0;
        for(int i=0;i<rows;++i)for(int j=1;j<=N;++j) {
            int q=IDX(start+i,j);
            double v=0.25*(u[q-PITCH]+u[q+PITCH]+u[q-1]+u[q+1]);
            local[IDX(i,j)]=v;diff=fmax(diff,fabs(v-u[q]));
        }
        MPI_Allgatherv(local,rows*PITCH,MPI_DOUBLE,unew,counts,displs,MPI_DOUBLE,MPI_COMM_WORLD);
        MPI_Allreduce(&diff,&global,1,MPI_DOUBLE,MPI_MAX,MPI_COMM_WORLD);
        double serialdiff=0.0;
        for(int i=1;i<=N;++i)for(int j=1;j<=N;++j) {
            int q=IDX(i,j);next[q]=0.25*(ref[q-PITCH]+ref[q+PITCH]+ref[q-1]+ref[q+1]);
            serialdiff=fmax(serialdiff,fabs(next[q]-ref[q]));
        }
        for(int q=0;q<PITCH*PITCH;++q){ok&=next[q]==unew[q];u[q]=unew[q];ref[q]=next[q];}
        ok&=serialdiff==global;++iter;if(first==0&&diff<1e-6)first=iter;
    }
    ok&=iter<5000;
    int *firsts=malloc((size_t)p*sizeof *firsts),allok;
    if(!firsts)MPI_Abort(MPI_COMM_WORLD,2);
    MPI_Gather(&first,1,MPI_INT,firsts,1,MPI_INT,0,MPI_COMM_WORLD);
    MPI_Allreduce(&ok,&allok,1,MPI_INT,MPI_MIN,MPI_COMM_WORLD);
    if(r==0){printf("p=%d N=16 global_stop=%d local_first:",p,iter);for(int q=0;q<p;++q)printf(" %d",firsts[q]);puts("; every grid/norm matched serial");}
    free(counts);free(displs);free(local);free(firsts);MPI_Finalize();return allok?0:1;
}

p=4 N=16 global_stop=515 local_first: 493 1 1 1; every grid/norm matched serial

Both three and four processes stop at sweep 515 and match every serial grid and norm. With four processes the first local threshold crossings are 493,1,1,1. A local maximum need not stay below the threshold after its first crossing: heat can reach an initially unchanged block later. Therefore “this rank has once converged” is not a persistent certificate. The global test supplies one consistent stop decision for the current iterate.

Checking the global norm only every b sweeps can save reductions. If the stopping measure decreases monotonically and the checked iteration meets the threshold, at most b−1 additional sweeps occur after its first threshold crossing. Without monotonicity that overshoot argument is not valid. If a reduction costs \(T_c\) per check and a sweep costs \(T_s\) excluding that check, checking every b sweeps contributes approximately \(T_c/b\) per sweep before considering changed stopping work. This simple accounting is not a justification for every pipelined stopping scheme.

The dot product must cover all elements for every process count W6L1 2:24

For vectors \(\mathbf a\) and \(\mathbf b\) of length N, the dot product is \(\sum_{i=0}^{N-1}a_ib_i\). Partition corresponding indices identically, compute local products and sums, then Reduce with SUM. Scatter need not be followed by a Gather of all partial scalars when the only desired result is their sum. The collective should express the required mathematical result directly.

The lecture sets \(a_i=i+1\) and \(b_i=2(i+1)\) for N=8. The exact dot product is \(2\sum_{j=1}^8j^2=2(8\cdot9\cdot17/6)=408\). For four processes, pairs of terms produce local sums 10,50,122,226, whose sum is 408. These integers are small enough that integer overflow cannot explain an incorrect answer in this example.

Its editor allocates local arrays of N/4 elements and computes the send count as integer N/p. At six ranks, that count is one and the first six elements alone contribute \(2\sum_{j=1}^6j^2=182\), matching the terminal output. The last two elements were omitted. At three ranks the same first six elements are included through two-element blocks. At five ranks the partial coverage gives 110, and at seven gives 280. With one or two ranks the requested local receive count exceeds the two-element local allocation, so executing that reconstruction would have undefined behavior rather than a meaningful “wrong answer.”

Dynamic allocation alone does not fix omitted remainders. Allocate according to the count assigned by the quotient/remainder partition, and use Scatterv with those counts and displacements. The proof in the movement section then certifies complete coverage. With more processes than elements, some ranks receive zero elements and contribute the additive identity zero; they still participate in the collective sequence.

The general program retains N=8 so the result remains transparent and tests p=1,3,6,9. These cases cover the ordinary serial allocation, a remainder, the lecture's problematic process count and zero-length blocks. Only the root uses the reduced total; it broadcasts the success flag so every process returns a consistent status. All four launches must report 408.

Normalization needs one global scalar, not every partial sum W6L2 0:38

The Euclidean norm of a nonzero vector is \(\|\mathbf v\|_2=(\sum_iv_i^2)^{1/2}\); normalization divides each component by that norm. The value must be global: using one norm per partition changes the vector and produces several locally unit-length pieces rather than one globally unit-length vector.

The lecture scatters the vector, computes local sums of squares, all-gathers those sums to every process, has the root add them and take a square root, broadcasts the norm, normalizes local pieces, and gathers the final vector. This can be correct under its fixed-size assumptions, but the Allgather gives every rank more information than it uses. One Allreduce of SUM directly supplies the total to every process; each then takes the square root locally. It replaces both the gathered scalar list and the extra broadcast.

For the vector (1,2,…,8), the squared norm is 204 and the norm is about 14.28285686. The normalized components rounded to three decimals are 0.070,0.140,0.210,0.280,0.350,0.420,0.490,0.560. The lecture's six-rank terminal output instead ends with untouched 7 and 8, with earlier values consistent with normalizing only 1 through 6 by \(\sqrt{91}\). Integer N/p omits the remainder, and the fixed four-element gathered-sums array is too small for six contributions. Because that array access is out of bounds, the displayed output is an observation, not a guaranteed outcome of invalid C execution.

The revised listing uses the same variable partition as the dot product, an Allreduce of local squared sums, and a Gatherv only to display/check the resulting full vector at the root. It verifies every component against \((i+1)/\sqrt{204}\) and verifies the final squared norm against one within \(10^{-14}\). Four and six ranks should satisfy the same numerical criterion.

Alltoall transposes ownership; local indexing finishes the matrix transpose W6L2 11:03

For a square matrix A of order N, the transpose B satisfies \(B_{j,i}=A_{i,j}\). With one row per rank and N=p, each source i sends A_i,j to destination j. Alltoall delivers destination j a receive vector indexed by source i, so its vector is row j of B. This is exactly the four-by-four demonstration whose received rows start 1,5,9,13 and 2,6,10,14.

The editor then stores transposed[i][rank]=recv_buf[i]. At destination r, receive element i equals A_i,r, so that assignment writes A_i,r into position (i,r), reconstructing a column of A rather than storing row r of B. The printed receive vector is a valid transposed row, but the separate two-dimensional storage assignment does not follow that mapping. A correct row storage is B[rank][i]=recv_buf[i].

For multiple rows per process, let q=N/p and assume divisibility for this program. Rank r owns input rows rq through (r+1)q−1. It packs one q-by-q block for each destination d: entry (i,j) of that block is \(A_{rq+i,dq+j}\). After Alltoall, destination d receives from source r the same q-by-q block in row-major order. To store output rows dq+j, write that received entry to \(B_{dq+j,rq+i}\). The communication exchanges blocks; the local placement transposes the within-block indices.

The code sets q=2 and therefore N=2p. This tests a genuine block case rather than only scalars. Each matrix entry is encoded as row×N+column+1, making the expected transpose computable without gathering the input matrix. The program checks every element of its owned output rows, then reduces success flags. Tests with three and four ranks cover N=6 and N=8.

Derive collective cost from rounds, bytes and local combinations

The recordings describe collectives through their effects. The following algorithm model is a research extension. Thakur, Rabenseifner and Gropp (2005), §3–4, explain why implementations need different algorithms for short and long messages. We derive idealized costs below from explicit schedules. A model can guide a design without identifying which algorithm an uninstrumented library call actually executes.

Assume p is a power of two and write \(\ell=\log_2p\). Each process can send one message and receive one message simultaneously in a round. Every participating pair has the same α and β, independent of competing transfers; communication and local reduction costs add; topology, packing, protocol changes and contention are omitted. Let s be the byte size of the full vector being broadcast or reduced, and γ the combine time per byte. A bound under this model is not a hardware guarantee.

For dissemination, one informed process can inform at most one new process per round. Starting from one root, the number of informed processes at most doubles, requiring at least ℓ rounds to inform p processes. For aggregation, a process that exchanges with at most one partner per round can at most double the number of original inputs incorporated into its state. An output depending on all p contributions likewise needs at least ℓ rounds. These are dual arguments; broadcast does not require every recipient to depend on every sender's independent input.

A binomial-tree broadcast sends the whole s-byte message across each critical-path edge, for ℓ rounds and cost \(\ell\alpha+\ell s\beta\). The total data sent over all tree edges is (p−1)s, just as in a direct root-to-each schedule; what improves is the critical path and root injection schedule, not the total number of data bytes. Alternatively, scatter equal pieces down a tree and recursively all-gather them. Each phase moves \((p-1)s/p\) bytes per critical path, for \(2\ell\alpha+2(p-1)s\beta/p\). For p=4 the bandwidth coefficients are 2 versus 1.5, but the latter uses twice as many latency rounds. At p=2 the bandwidth coefficients are equal. These comparisons are explicitly for powers of two.

For all-gather, let m be the byte size contributed by one rank, so the final vector has s=pm bytes. A ring passes one m-byte block per round for p−1 rounds: cost \((p-1)\alpha+(p-1)m\beta\). Recursive doubling exchanges accumulated blocks whose sizes are m,2m,4m,…,(p/2)m. The geometric sum is (p−1)m, so its cost is \(\ell\alpha+(p-1)m\beta\). In this ideal model the same bandwidth term accompanies fewer latency rounds. Real algorithms must also respect rank layout, non-power-of-two groups and memory-copy cost.

Pairwise all-to-all exchanges one destination block per partner for p−1 rounds, giving \((p-1)(\alpha+m\beta)\) for m bytes per destination. A bit-routing approach such as Bruck reduces the round count to \(\lceil\log_2p\rceil\), rather than “halving” it. For p=8 the change is seven rounds to three, and for p=64 it is 63 to six. It may forward additional data and require local rearrangement; fewer rounds do not establish lower time for large blocks. This explains why a short-message choice can be unsuitable once bandwidth dominates.

Allreduce combines an aggregation phase with a distribution requirement. Recursive doubling exchanges and reduces the entire s-byte vector at every round. A ring instead performs a reduce-scatter phase and an all-gather phase, each with p−1 rounds on blocks of size s/p. Rabenseifner's power-of-two schedule uses recursive halving for reduce-scatter and recursive doubling for all-gather. Summing the message and combine sizes gives

\[ \begin{aligned} T_{\mathrm{RD}}(s)&=\ell\alpha+\ell s\beta+\ell s\gamma,\\ T_{\mathrm{ring}}(s)&=2(p-1)\alpha+2\frac{p-1}{p}s\beta+\frac{p-1}{p}s\gamma,\\ T_{\mathrm{Rab}}(s)&=2\ell\alpha+2\frac{p-1}{p}s\beta+\frac{p-1}{p}s\gamma. \end{aligned} \tag{15.1} \]

The ring combines one received s/p-byte block during each of p−1 reduce-scatter rounds, hence its γ coefficient (p−1)/p. Recursive halving combines block sizes s/2,s/4,…,s/p, whose sum is the same. The all-gather phases copy but do not reduce, so they add bandwidth without another γ term. Recursive doubling repeatedly combines a full vector, explaining its larger bandwidth and reduction coefficients.

At p=8 the latency counts are 3,14,6; bandwidth coefficients are 3,7/4,7/4; reduction coefficients are 3,7/8,7/8. Ring and Rabenseifner therefore have the same large-vector terms in this model, but Rabenseifner has fewer latency rounds. This prediction omits implementation-specific advantages of a ring, segmentation, topology and pipelining. A theoretical comparison should not be promoted into a universal ranking of library algorithms.

Setting recursive-doubling and ring costs equal gives the model crossover

\[ s_* = \frac{[2(p-1)-\ell]\alpha}{[\ell-2(p-1)/p]\beta+[\ell-(p-1)/p]\gamma}, \tag{15.2} \]

when the denominator is positive. For the hypothetical parameters α=2 µs, β=1 ns/byte and γ=0.5 ns/byte at p=8, the numerator is 22 µs and the denominator 2.3125 ns/byte, yielding about 9513.5 bytes. These are invented model inputs for arithmetic, not fitted machine characteristics. The following Python program uses exact rational coefficients and evaluates the formulas at three vector sizes.

Six worked exercises

1. Derive a correct uneven partition

Distribute N=17 elements over p=6 ranks with the quotient/remainder rule. Find counts and displacements, prove coverage, and state how to generate the displacements from distributed counts using Exscan.

Solution

The quotient is two and the remainder five, so counts are (3,3,3,3,3,2) and displacements (0,3,6,9,12,15). Each displacement equals the previous displacement plus its count; the last endpoint is 15+2=17. Thus the half-open intervals meet without overlapping and cover indices zero through sixteen. An Exscan of SUM gives each rank the sum of preceding counts. Set rank zero's output explicitly to zero because its Exscan receive value is undefined. Counts and displacements are elements for the contiguous datatype, not bytes.

2. Diagnose a collective-completion counterexample

Rank zero broadcasts a configuration and then sends a point-to-point “everyone ready” notification to another subsystem. Explain why Bcast return alone does not justify that phrase. Give a valid protocol if every recipient must finish a local setup step before notification.

Solution

The root's local completion permits reuse of its buffer; it does not generally certify that all recipients have entered or returned. Even a completed receiver may still be doing setup. Each participant must finish its own setup, then all must enter a barrier on the agreed communicator. Rank zero sends the notification after its barrier returns. The barrier proves all participants reached that post-setup point, while the broadcast supplied the configuration. A Reduce of explicit readiness flags could encode an alternative acknowledgment protocol, but a broadcast alone cannot acknowledge work it did not describe.

3. Compare all-reduce algorithms without a fitted machine claim

For p=8, α=2 µs, β=1 ns/byte and γ=0.5 ns/byte, compute the recursive-doubling/ring crossover. At s=1024 bytes, which has the lower modeled cost? Explain why a measured switch at another size would not refute MPI correctness.

Solution

The latency difference is (14−3)α=22 µs. The byte-cost difference is (3−1.75)β+(3−0.875)γ=1.25+1.0625=2.3125 ns/byte. Therefore s*=22000/2.3125≈9513.5 bytes. At 1024 bytes, recursive doubling costs 3(2+1.024+0.512)=10.608 µs; ring costs 28+1.75×1.024+0.875×0.512=30.240 µs. The model omits topology, protocol, copying and scheduling, and the parameters are hypothetical. An implementation may use a third algorithm or a tuned threshold. MPI correctness concerns the result and semantic guarantees, not minimizing this model at every message size.

4. Construct a floating-point reduction counterexample

Use binary64 round-to-nearest arithmetic and a=2⁵³ to compare (a+1)−a with a+(1−a). What does this imply for exact equality between serial and parallel sums? Contrast a finite maximum reduction.

Solution

At a, adjacent representable values above it are two units apart. The exact a+1 is a midpoint and rounds to a under ties-to-even, so the first expression becomes zero. The integer 1−a=−9007199254740991 is exactly representable, making the second expression one. Changing parenthesization can therefore change a valid floating sum. A test should use an appropriate error criterion unless the arithmetic order is fixed deliberately. A maximum of finite values merely selects one input value, so changing its associative grouping does not add rounding error. NaNs and special ordering conventions require separate treatment and are excluded from the Jacobi proof.

5. Choose the collective that matches a norm

Each of 10000 ranks holds one local sum of squares. Compare result storage for all-gathering those eight-byte sums with all-reducing them to one eight-byte sum per rank. Explain what information the norm computation needs and identify a remaining numerical hazard.

Solution

Allgather returns 10000×8=80000 bytes per rank, or 800000000 bytes over all ranks. Allreduce returns eight bytes per rank, or 80000 bytes overall. The norm needs the combined scalar, not the entire list, so Allreduce matches the required information. The ratio of result storage is 10000. This is not a claim about every internal implementation buffer. Naively squaring very large or tiny components can still overflow or underflow; collective selection does not repair that numerical issue. A scaled norm algorithm is needed when input magnitude demands it.

6. Implement and measure a block transpose safely

Extend the q=2 transpose program to another small q, retain p=3 and p=4, and describe a verification that catches a missing within-block transpose. Design five timing trials without using terminal print order as synchronization evidence.

Solution

Set N=qp and allocate p blocks of q² elements per rank. Pack source rank r, destination d, local row i and local column j as A_(rq+i,dq+j). After Alltoall, destination d stores the received value from source r into local output row j and global output column rq+i. Check each output B_(dq+j,k) against the encoded A_(k,dq+j)=kN+dq+j+1. Choosing q greater than one makes swapped within-block indices observable; q=1 cannot reveal that defect.

Initialize and allocate before timing, run warmups consistently, and time the same packing/communication/unpacking interval in every trial. Each rank records its own interval; combine their durations with MAX after the interval and report all five values or a declared summary. Check results after timing, reduce success flags, and let one rank print the report. A barrier can align trial entry but does not order independent output streams. Record process count, q, compiler, MPI version and transport, and retain raw captures rather than inferring an inter-node rate from a loopback run.
