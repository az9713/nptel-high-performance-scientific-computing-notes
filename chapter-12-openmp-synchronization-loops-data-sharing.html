OpenMP II: synchronization, parallel loops, reductions and data-sharing attributes

One Jacobi sweep on a 2000 × 2000 grid performs \(4\times10^6\) updates and takes 6.2–8.4 ms with the serial kernel in four captures. It must also return the update norm \(\max|u^{\text{new}}-u|\) for the convergence test. A critical region around every comparison makes the twelve-thread sweep 56–86 times slower than serial. Removing protection corrupts the norm in all 40 runs of a smaller test; one capture falls below \(10^{-21}\) instead of the correct \(2.42\times10^{-3}\). A private maximum merged once per thread, and reduction(max:diff), reproduce the serial norm. At four threads they gain about 1.2–1.7 over serial. The sections below derive the ordering guarantees and costs behind these differences.

Grounded in two recordings of the NPTEL course High Performance Scientific Computing (Prof. Shivasubramanian Gopalakrishnan, IIT Bombay): W4L2, Synchronization and Parallel Loops in OpenMP, and W4L3, Storage attributes of different variables in OpenMP. Lecture material: the padded partial-sum array; critical and barrier; the \(\pi\) program with one critical update; the worksharing loop and schedule; loop-carried dependences; reduction; the cost of synchronization; nowait; default storage attributes and the clauses shared, private, firstprivate, default(none). The objects of the chapter and the running case

Chapter 11 defined the team of \(p\) threads, the parallel region, program order, the fork and the join, and the data race: two operations on one memory unit by different threads, at least one a write, with no order between them. This chapter adds ways to create order, to divide the iterations of a loop, and to say which variables the threads share.

Ordering edges. For events \(a\) and \(b\) of different threads, \(a\prec b\) means that a construct forces \(a\) to complete before \(b\) begins. The fork and the join create such edges, and so do two more constructs. The executions of all critical constructs of one name, by all threads, form a sequence \(R_1,R_2,\dots\) in an order that the run chooses; every event of \(R_j\) precedes every event of \(R_{j+1}\). The specification words this as "as if only a single thread at a time … executes the region" and gives all constructs without a name one shared name (OpenMP 5.2 §15.2, p. 300). A barrier orders every event that any thread executes before it ahead of every event that any thread executes after it (§15.3.1, p. 301). A pair of conflicting accesses ordered by such an edge is not a data race, and the edge makes the earlier writes visible to the later reads; Chapter 13 derives this from the flush operation.

Loop schedules. A worksharing loop has an iteration set \(\mathcal{J}=\{0,\dots,n-1\}\); the canonical form of the loop lets the runtime compute \(n\) before the first iteration (§4.4.2, p. 91). A loop schedule divides \(\mathcal{J}\) into chunks, contiguous non-empty sets, and assigns each chunk to a thread. The assignment is static if it is a function of \(n\), \(p\) and the chunk size alone, and dynamic if a thread that becomes idle takes the next unassigned chunk. Iteration \(i\) costs \(c(i)\) seconds, \(T_{\mathrm{work}}=\sum_ic(i)\), the total service time is measured on an identical reference processor; the load of thread \(t\) is \(w_t=\sum_{i\in\mathcal{J}_t}c(i)\), and \(E_{\text{dist}}=T_{\mathrm{work}}/(p\max_tw_t)\) is the efficiency of the assignment. Here \(T_{\mathrm{work}}\) is measured in seconds; the book-wide \(W\) remains an operation count.

Data environments. Inside a construct, a variable name \(x\) denotes a storage object \(\mathrm{obj}_t(x)\) for each thread \(t\). The variable is shared if the object is the same for every thread, private if the objects are pairwise different, and a reduction variable if they are pairwise different, start at the identity of an operator, and are combined into the original after the construct.

Cost symbols. Here \(p\) is the number of threads; \(T_1\) and \(T_p\) are wall-clock times on one and \(p\) threads; \(S_p=T_1/T_p\) is speedup; \(E_p=S_p/p\) is parallel efficiency; and \(f\) is the serial fraction of \(T_1\) in Amdahl’s model. Each experiment states which one-thread implementation supplies its baseline. New: \(k\) is the chunk size; \(\delta\) is the time that a thread spends taking one chunk from a shared queue; \(s\) is the time inside one execution of a critical region; \(t_{\text{crit}}(p)\) is the time between consecutive entries into a region that \(p\) threads keep busy; \(t_{\text{bar}}\) is the time of one barrier.

The running cases are the midpoint-rule computation of \(\pi\) of Chapter 11 and the book's Jacobi iteration for the Laplace equation on an \(N\times N\) grid. One sweep computes

\[ u^{\text{new}}_{i,j}=\tfrac14\bigl(u_{i-1,j}+u_{i+1,j}+u_{i,j-1}+u_{i,j+1}\bigr),\qquad r=\max_{1\le i,j\le N}\bigl|u^{\text{new}}_{i,j}-u_{i,j}\bigr|, \tag{12.1} \]

where \(r\) is the update norm, or fixed-point residual, that the driver compares with tol. It is not the differential-equation residual: for this Laplace stencil, the old grid’s discrete Laplacian has maximum norm \(4r/h_g^2\), with grid spacing \(h_g=1/(N+1)\). The update of cell \((i,j)\) writes one entry of unew and reads four entries of u, a different array, so the \(N^2\) updates are independent in the sense of Chapter 11. The residual is one value combined from all updates by the operator max: a reduction.

All measurements use the machine of Chapter 11: an Intel Core i5-12450H with 4 performance cores of 2 hardware threads and 4 efficient cores, \(m=12\) unequal logical processors; gcc 13.3 in WSL 2 Ubuntu 24.04; times from omp_get_wtime. Mutual exclusion and ordering: critical, atomic and barrier W4L2 4:38

critical. The lecture defines a critical region as mutual exclusion: only one thread at a time can enter it. Its slide has each thread compute a private value B and then execute res += consume(B); on a variable res declared before the region, which is shared. The whole statement, including the call of consume, lies inside the region, so the time \(s\) during which no other thread can enter includes the time of consume. All unnamed critical constructs of a program have one name (§15.2, p. 300), so two unrelated unnamed regions exclude each other; critical(name) limits the exclusion to regions of that name.

atomic. The lecture lists atomic as a later topic; it protects a supported individual memory operation and may cost less than a critical region, depending on the operation, implementation and contention. Only the read and the write of the location are atomic, not the evaluation of the right-hand side (§15.8.4, p. 311). Exclusion holds only among atomic constructs on the same location, and there is none against accesses outside them, "even if those accesses occur during a critical or ordered region" (p. 313): an update of x under atomic in one place and under critical in another is a data race. The listing compiles three constructs and prints the assembly lines that carry a lock prefix or a call of omp_get_…, with the function that holds them.

barrier. The lecture describes a barrier as a point that all threads must reach before any proceeds, and as a standalone statement. Its slide computes Arr[id] = big_ugly_calc(id, nthrds); on 8 threads, then a barrier, then Brr[id] = really_big_and_ugly(id, nthrds, Arr);. The barrier is needed because the second call reads all of Arr: thread \(t\) writes Arr[t], another thread reads it, and nothing else orders the two events. In general a barrier is needed between events of different threads that touch one memory unit, at least one writing it, when no other construct orders them. Every thread of the team must encounter each barrier, in the same sequence as the worksharing regions (§15.3.1, p. 302), so a barrier inside if (id == 0) is not conforming. The listing delays thread \(t\) by \(100\,\mathrm{ms}\times t\) and sums all of arr in the second step. The correct value is 36. Without the barrier the delays encourage thread \(t\) to observe only elements from threads \(0,\dots,t\), giving \((t+1)(t+2)/2\); that is a predicted sample pattern, not a guarantee for the racy program.

#include <stdio.h>
#include <unistd.h>
#include <omp.h>

#define P 8

static double arr[P], brr[P];

static double slow_calc(int id)              /* thread id needs 100 ms times id: thread 7 is the slowest */
{
    usleep(100000 * id);
    return id + 1.0;
}

static double sum_all(void)                  /* reads every element of arr */
{
    double s = 0.0;
    for (int k = 0; k < P; k++) s += arr[k];
    return s;
}

static void run(int with_barrier)
{
    for (int k = 0; k < P; k++) arr[k] = brr[k] = 0.0;
    #pragma omp parallel num_threads(P)
    {
        int id = omp_get_thread_num();
        arr[id] = slow_calc(id);
        if (with_barrier) {
            #pragma omp barrier
        }
        brr[id] = sum_all();
    }
    printf("%-16s", with_barrier ? "with barrier:" : "without barrier:");
    for (int k = 0; k < P; k++) printf(" %3.0f", brr[k]);
    printf("\n");
}

int main(void)
{
    printf("every thread should read the sum 1 + 2 + ... + 8 = 36\n");
    run(0);
    run(1);
    return 0;
}

The \(\pi\) program with a private scalar and one critical update W4L2 8:07

Each thread declares a scalar sum inside the region, accumulates its cyclic share of the terms, and then executes pi += sum * step; inside a critical region, where pi is shared. The slide's reasons: no array, so no false sharing; the protected update cannot conflict.

The serial part. The region is entered \(p\) times. The synchronization experiment gives 14–15 ns per entry at \(p=1\) and 0.115–0.147 µs at \(p=12\): roughly 1.8 µs for twelve entries. Against even a 0.05 s integration, this is only \(3.6\times10^{-5}\) of the time. This is a scale estimate from another kernel, not a bound on each individual acquisition.

#include <stdio.h>
#include <omp.h>

#define MAXT 16
#define PAD 8
#define REPS 3

static long num_steps = 200000000L;
static double sum_arr[MAXT * PAD] __attribute__((aligned(64)));

/* A: SPMD, cyclic distribution, partial sums in a padded array (the lecture's padded program). */
static double pi_array(int p)
{
    double step = 1.0 / (double)num_steps, pi = 0.0;
    int nthreads = 1;
    omp_set_num_threads(p);
    #pragma omp parallel
    {
        int id = omp_get_thread_num(), nt = omp_get_num_threads();
        double x;
        if (id == 0) nthreads = nt;
        sum_arr[id * PAD] = 0.0;
        for (long i = id; i < num_steps; i += nt) {
            x = (i + 0.5) * step;
            sum_arr[id * PAD] += 4.0 / (1.0 + x * x);
        }
    }
    for (int t = 0; t < nthreads; t++) pi += sum_arr[t * PAD] * step;
    return pi;
}

/* B: SPMD, cyclic distribution, private scalar, one critical update per thread. */
static double pi_critical(int p)
{
    double step = 1.0 / (double)num_steps, pi = 0.0;
    omp_set_num_threads(p);
    #pragma omp parallel
    {
        int id = omp_get_thread_num(), nt = omp_get_num_threads();
        double x, sum = 0.0;
        for (long i = id; i < num_steps; i += nt) {
            x = (i + 0.5) * step;
            sum += 4.0 / (1.0 + x * x);
        }
        #pragma omp critical
        pi += sum * step;
    }
    return pi;
}

/* C: parallel for with reduction. */
static double pi_reduction(int p)
{
    double step = 1.0 / (double)num_steps, sum = 0.0;
    omp_set_num_threads(p);
    #pragma omp parallel for reduction(+:sum)
    for (long i = 0; i < num_steps; i++) {
        double x = (i + 0.5) * step;
        sum += 4.0 / (1.0 + x * x);
    }
    return sum * step;
}

typedef double (*fn)(int);

static double best(fn f, int p, double *val)
{
    double b = 1e30;
    for (int r = 0; r < REPS; r++) {
        double t0 = omp_get_wtime();
        *val = f(p);
        double t = omp_get_wtime() - t0;
        if (t < b) b = t;
    }
    return b;
}

int main(void)
{
    fn f[3] = {pi_array, pi_critical, pi_reduction};
    const char *name[3] = {"array,padded", "critical", "reduction"};
    int ps[] = {1, 2, 4, 8, 12};
    printf("N = %ld; best of %d; seconds (speedup)\n%-14s", num_steps, REPS, "variant");

    }

}

A critical region inside the loop. The lecture asks what happens if the critical region is put inside the loop. Suppose each iteration does work of time \(w\) and then enters one critical region of service time \(s\). The \(N\) entries are serialized, so they need at least \(Ns\) in all, and the threads cannot finish faster than \(N(w+s)/p\) either:

\[ T_p\ \ge\ \max\Bigl(\frac{N(w+s)}{p},\ Ns\Bigr),\qquad S_p=\frac{T_1}{T_p}\ \le\ \min\Bigl(p,\ \frac{w+s}{s}\Bigr), \tag{12.2} \]

where \(T_1=N(w+s)\). Its limit \((w+s)/s\) is Amdahl's limit \(1/f\) with \(f=s/(w+s)\); for finite \(p\), (12.2) is weaker than Amdahl's formula \(T_p=fT_1+(1-f)T_1/p\), because the critical region of one thread can run while the other threads do their work. For the \(\pi\) loop \(w\) is about 1 ns and an uncontended region costs about 12 ns, so (12.2) bounds the speedup by \(13/12=1.08\) for every \(p\), and it assumes that the handoff of the region costs nothing. In practice the lock and the shared variable move between the caches of the cores, and \(t_{\text{crit}}(p)\) grows with \(p\); with \(w\) negligible, \(t_{\text{crit}}(p)\) is the time per iteration of the saturated loop. The listing measures it for critical, atomic and the reduction, with \(N=5\times10^{6}\).

{
    double step = 1.0 / (double)num_steps, sum = 0.0;
    #pragma omp parallel for num_threads(p)

Parallel loops: the worksharing construct W4L2 14:13

The lecture introduces #pragma omp for inside a parallel region. It splits the iterations of the loop that follows among the threads of the team, makes the loop index private, and ends with a barrier. For a[i] = a[i] + b[i] the SPMD version of Chapter 11 needs six or seven extra lines; the worksharing version needs one pragma. The lecture adds that parallel followed by for may be written parallel for.

What the construct guarantees. The iterations "are distributed across threads that already exist in the team", and the iterations of one chunk run in sequential order (§11.5, p. 247); nothing else about the order is guaranteed. The loop must have canonical form: for (init; test; incr) with a monotone variable, invariant bounds and no break that leaves the loop (§4.4.1, pp. 85–91), so that the runtime can compute the iteration count first (§4.4.2, p. 91). Only the outermost loop of a nest is divided unless collapse(n) adds inner loops. On the combined construct, default and shared go to the parallel part and private and firstprivate to the loop part (§17.2, pp. 339–340), so the lecture's equivalence holds for the clauses used here.

What the programmer guarantees. The construct does not check that the iterations are independent. A dependence between iterations is loop-carried: flow when iteration \(i\) writes what a later iteration reads, anti when it reads what a later iteration writes, output when both write. The lecture's recipe is: find the compute-intensive loops, make the iterations independent, place the directive, test. Its example removes a flow dependence: in j = 5; for (i...) { j += 2; A[i] = big(j); } each iteration reads the j that the previous one wrote. The repair substitutes the closed form \(j=5+2(i+1)\) and declares j inside the body, where it is private. Where no closed form exists, as in a[i] = a[i-1] + b[i], the loop needs another algorithm, a prefix scan (§5.6).

The definitions (§11.5.3, pp. 248, 252–253). {

        for (long i = 0; i < N; i++) s += term(i);

        for (long i = 0; i < N; i++) s += term(i);

}

#include <stdio.h>

{

    {
        for (int k = 0; k < K; k++) {
            #pragma omp barrier
        }

{
    long x = 0;
    double t0 = omp_get_wtime();

    {
        for (int k = 0; k < K; k++) {
            #pragma omp critical
            x++;
        }
    }

The second part, waiting, depends on the loads. Let \(w_{t,\ell}\) be the time of thread \(t\) in phase \(\ell\) of \(K\) phases. \[ T_{\text{barrier}}=\sum_{\ell=1}^{K}\max_t w_{t,\ell}+Kt_{\text{bar}},\qquad T_{\text{nowait}}=\max_t\sum_{\ell=1}^{K}w_{t,\ell}+t_{\text{bar}}. \tag{12.7} \]

For each thread, \(\sum_\ell w_{t,\ell}\le\sum_\ell\max_uw_{u,\ell}\), so \(T_{\text{nowait}}\le T_{\text{barrier}}\), the load terms are equal when one thread is the slowest in every phase, and the barrier version still pays \((K-1)t_{\text{bar}}\) more.

The running case: Jacobi with a parallel loop

The row loop of the Jacobi sweep (12.1) is divided with parallel for. The index \(i\) is private as the associated loop, \(j\) is declared in its own for statement and is private, and the arrays and \(N\) are shared. The residual is reduction(max:diff), and default(none) makes the compiler check the list. The serial driver exchanges the pointers u and unew and stops when the residual is below tol. The listing solves the Laplace problem (\(u=1\) on the top edge, 0 elsewhere, \(N=48\)) with the serial kernel and the parallel kernel on 1, 2, 4 and 12 threads, and compares the sweeps, the residual and the final grid.

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <math.h>
#include <omp.h>

#define IDX(i, j) ((i) * (N + 2) + (j))

/* Serial kernel: 5-point average into the interior of unew; returns max |unew - u| over the interior. */
static double jacobi_step(int N, const double *u, double *unew)
{
    double diff = 0.0;
    for (int i = 1; i <= N; i++)
        for (int j = 1; j <= N; j++) {
            unew[IDX(i, j)] = 0.25 * (u[IDX(i - 1, j)] + u[IDX(i + 1, j)] + u[IDX(i, j - 1)] + u[IDX(i, j + 1)]);
            double d = fabs(unew[IDX(i, j)] - u[IDX(i, j)]);
            if (d > diff) diff = d;
        }
    return diff;
}

/* Parallel kernel: the rows are shared out; the residual is a max reduction. default(none) makes the
   compiler check that every variable the loop uses has been given an attribute. */
static double jacobi_step_omp(int N, const double *u, double *unew)
{
    double diff = 0.0;
    #pragma omp parallel for default(none) shared(N, u, unew) reduction(max:diff)
    for (int i = 1; i <= N; i++)
        for (int j = 1; j <= N; j++) {                 /* j is declared in its for statement: private */
            unew[IDX(i, j)] = 0.25 * (u[IDX(i - 1, j)] + u[IDX(i + 1, j)] + u[IDX(i, j - 1)] + u[IDX(i, j + 1)]);
            double d = fabs(unew[IDX(i, j)] - u[IDX(i, j)]);
            if (d > diff) diff = d;
        }
    return diff;
}

/* Laplace problem: u = 1 on the top edge (i = 0), 0 on the other edges, 0 inside at the start.
   Returns the number of sweeps; the final grid is copied to out. */
static int solve(int N, int parallel, int p, double tol, int max_iter, double *final_diff, double *out)
{
    size_t n = (size_t)(N + 2) * (N + 2);
    double *u = calloc(n, sizeof *u), *unew = calloc(n, sizeof *unew);
    for (int j = 0; j < N + 2; j++) u[IDX(0, j)] = unew[IDX(0, j)] = 1.0;
    omp_set_num_threads(p);
    int it = 0;
    double diff = 1.0;
    while (diff > tol && it < max_iter) {
        diff = parallel ? jacobi_step_omp(N, u, unew) : jacobi_step(N, u, unew);
        double *tmp = u; u = unew; unew = tmp;
        it++;
    }
    memcpy(out, u, n * sizeof *u);
    *final_diff = diff;
    free(u); free(unew);
    return it;
}

int main(void)
{
    const int N = 48;
    const double tol = 1e-6;
    size_t n = (size_t)(N + 2) * (N + 2);
    double *ref = malloc(n * sizeof *ref), *g = malloc(n * sizeof *g), d0, d;
    int it0 = solve(N, 0, 1, tol, 100000, &d0, ref);
    printf("serial     : %4d sweeps, residual %.6e, u(N/2,N/2) = %.12f\n", it0, d0, ref[IDX(N / 2, N / 2)]);
    int ps[] = {1, 2, 4, 12};
    for (int k = 0; k < 4; k++) {
        int it = solve(N, 1, ps[k], tol, 100000, &d, g);
        printf("%2d threads : %4d sweeps, residual %.6e, grid bitwise equal to serial: %s\n", ps[k], it, d,
               (it == it0 && d == d0 && memcmp(ref, g, n * sizeof *g) == 0) ? "yes" : "no");
    }
    free(ref); free(g);
    return 0;
}

#include <stdio.h>
#include <stdlib.h>
#include <math.h>
#include <omp.h>

#define IDX(i, j) ((i) * (N + 2) + (j))
#define UPD(i, j) 0.25 * (u[IDX(i - 1, j)] + u[IDX(i + 1, j)] + u[IDX(i, j - 1)] + u[IDX(i, j + 1)])

static double step_reduction(int N, const double *restrict u, double *restrict unew)
{
    double diff = 0.0;
    #pragma omp parallel for reduction(max:diff)
    for (int i = 1; i <= N; i++)
        for (int j = 1; j <= N; j++) {
            double v = UPD(i, j), d = fabs(v - u[IDX(i, j)]);
            unew[IDX(i, j)] = v;
            if (d > diff) diff = d;
        }
    return diff;
}

static double step_local_critical(int N, const double *restrict u, double *restrict unew)
{
    double diff = 0.0;
    #pragma omp parallel
    {
        double mine = 0.0;
        #pragma omp for nowait
        for (int i = 1; i <= N; i++)
            for (int j = 1; j <= N; j++) {
                double v = UPD(i, j), d = fabs(v - u[IDX(i, j)]);
                unew[IDX(i, j)] = v;
                if (d > mine) mine = d;
            }
        #pragma omp critical
        if (mine > diff) diff = mine;
    }
    return diff;
}

static double step_critical_in_loop(int N, const double *restrict u, double *restrict unew)
{
    double diff = 0.0;
    #pragma omp parallel for
    for (int i = 1; i <= N; i++)
        for (int j = 1; j <= N; j++) {
            double v = UPD(i, j), d = fabs(v - u[IDX(i, j)]);
            unew[IDX(i, j)] = v;
            #pragma omp critical
            if (d > diff) diff = d;
        }
    return diff;
}

static double step_unprotected(int N, const double *restrict u, double *restrict unew)
{
    double diff = 0.0;                          /* shared, updated by all threads without synchronization */
    #pragma omp parallel for
    for (int i = 1; i <= N; i++)
        for (int j = 1; j <= N; j++) {
            double v = UPD(i, j), d = fabs(v - u[IDX(i, j)]);
            unew[IDX(i, j)] = v;
            if (d > diff) diff = d;
        }
    return diff;
}

static double step_serial(int N, const double *restrict u, double *restrict unew)
{
    double diff = 0.0;
    for (int i = 1; i <= N; i++)
        for (int j = 1; j <= N; j++) {
            double v = UPD(i, j), d = fabs(v - u[IDX(i, j)]);
            unew[IDX(i, j)] = v;
            if (d > diff) diff = d;
        }
    return diff;
}

/* Streaming copy b[i] = a[i] over 2 x 128 MB: 16 bytes per element moved (write-allocate traffic not counted). */
static double copy_gbps(int p)
{
    long n = 16000000L;
    double *a = malloc(n * sizeof *a), *b = malloc(n * sizeof *b), best = 1e30;
    #pragma omp parallel for num_threads(p)
    for (long i = 0; i < n; i++) { a[i] = (double)i; b[i] = 0.0; }
    for (int r = 0; r < 5; r++) {
        double t0 = omp_get_wtime();
        #pragma omp parallel for num_threads(p)
        for (long i = 0; i < n; i++) b[i] = a[i];
        double t = omp_get_wtime() - t0;
        if (t < best) best = t;
    }
    double check = b[n - 1];
    free(a); free(b);
    return check == (double)(n - 1) ? 16.0 * n / best / 1e9 : -1.0;
}

typedef double (*step_fn)(int, const double *restrict, double *restrict);

/* Residual returned by sweep number nsweep, starting from the initial grid. */
static double residual_after(step_fn f, int N, int p, int nsweep)
{
    size_t n = (size_t)(N + 2) * (N + 2);
    double *u = calloc(n, sizeof *u), *unew = calloc(n, sizeof *unew), diff = 0.0;
    for (int j = 0; j < N + 2; j++) u[IDX(0, j)] = unew[IDX(0, j)] = 1.0;
    omp_set_num_threads(p);
    for (int k = 0; k < nsweep; k++) { diff = f(N, u, unew); double *t = u; u = unew; unew = t; }
    free(u); free(unew);
    return diff;
}

static double sweeps(step_fn f, int N, int p, int nsweep, double *last)
{
    size_t n = (size_t)(N + 2) * (N + 2);
    double *u = calloc(n, sizeof *u), *unew = calloc(n, sizeof *unew);
    for (int j = 0; j < N + 2; j++) u[IDX(0, j)] = unew[IDX(0, j)] = 1.0;
    omp_set_num_threads(p);
    double best = 1e30;
    int reps = nsweep > 2 ? 9 : 3;
    for (int r = 0; r < reps; r++) {
        double t0 = omp_get_wtime();
        for (int k = 0; k < nsweep; k++) { *last = f(N, u, unew); double *t = u; u = unew; unew = t; }
        double t = (omp_get_wtime() - t0) / nsweep;
        if (t < best) best = t;
    }
    free(u); free(unew);
    return best;
}

A critical comparison requires \(N^2\) serialized entries. The unprotected version lacks the required ordering and has no correctness guarantee. A private maximum needs only \(p\) entries, roughly 1.8 µs in aggregate at \(p=12\) using the synchronization experiment’s largest per-entry average, small beside millisecond sweeps.

A streaming model estimates \(8+8+8=24\) bytes per update: one input loaded after row reuse, a destination write-allocate read and eventual writeback. It assumes ordinary cached stores and cache space for neighboring rows; it is not a universal lower bound. The fastest correct variant and team size in each capture takes 3.83–4.77 ms, or 20.1–25.1 GB/s under that model. Exercises

Exercise 1 (derive). A loop of \(N\) iterations has costs that rise to \(c_{\text{hi}}\) at the last iteration, handed out in order in chunks of \(k\). Using (12.5) with a take cost \(\delta\) added to each chunk, derive the \(k^*\) that minimizes the bound and show that at \(k^*\) the two terms that depend on \(k\) are equal. Compute \(k^*\) for \(N=10^{6}\), \(c_{\text{hi}}=2\ \mu\mathrm{s}\), \(\delta=25\) ns, \(p=8\), linear costs, so \(T_{\mathrm{work}}=Nc_{\text{hi}}/2\).

Solution

With \(\delta\) added to each of \(N/k\) chunks and \(C_{\max}\approx kc_{\text{hi}}\), the part of the bound that depends on \(k\) is \(g(k)=N\delta/(kp)+(1-1/p)kc_{\text{hi}}\). Its derivative is zero at \(k^{*2}=N\delta/((p-1)c_{\text{hi}})\), which is (12.6); multiplying that condition by \(k^*\) gives \(N\delta/(k^*p)=(1-1/p)k^*c_{\text{hi}}\), so the two terms are equal. Numbers: \(k^*=\sqrt{0.025\ \mathrm{s}/14\ \mu\mathrm{s}}=42.3\); \(g(k^*)=1.5\times10^{-4}\) s against \(T_{\mathrm{work}}/p=0.125\) s.

Exercise 2 (compute). A loop does \(w=2\) ns of work per iteration and then executes critical around an update of \(s=12\) ns when uncontended. (a) Compute the speedup bound (12.2). (b) Assume a saturated service interval \(t_{\text{crit}}(8)=120\) ns, representative of crit_loop.c, and estimate \(S_8\). (c) How large must \(w\) be for the service-interval model to permit \(E_8\ge0.5\), assuming \(t_{\text{crit}}(8)=120\) ns stays fixed?

Solution

(a) \(S_p\le(w+s)/s=14/12=1.17\). (b) \(S_8=14/120=0.12\). (c) As a necessary condition under the assumed fixed service interval, \(E_8\ge0.5\) means \(S_8=(w+s)/t_{\text{crit}}\ge4\), so \(w\ge4t_{\text{crit}}-s=4\times120-12=468\) ns; with a free handoff (\(t_{\text{crit}}=s\)) \(w\ge36\) ns would do.

Exercise 3 (counterexample). A student writes a[i] = f(i); with schedule(static) and nowait over \(i=0,\dots,8\), then c[i] = a[i] + a[i-1]; with schedule(static) over \(i=1,\dots,8\), and argues that both loops have the same static schedule, so no barrier is needed. Give \(p\) and a timing with a stale read, and name the sentence that the argument misreads.

Solution

Take \(p=2\). In gcc 13.3 the first loop gives iterations 0 to 4 to thread 0 and 5 to 8 to thread 1; the second gives 1 to 4 and 5 to 8. Iteration 5 of the second loop, on thread 1, reads a[4], which thread 0 writes; if thread 0 is descheduled, thread 1 reads the old value, and nothing orders the two events. The specification guarantees only that "the memory effects of a logical iteration in the first loop nest happen before the execution of the same logical iteration in the second loop nest" (§4.4.5, p. 95). Iteration 5 depends on iteration 4 of the first loop, and the iteration spaces differ.

Exercise 4 (diagnose an assumption). On the slide of W4L3 the critical program takes 0.53 s and the reduction program 0.68 s on 4 threads, and the lecture attributes the difference to the overhead of the reduction. Use the local synchronization measurements to estimate the scale of a four-partial merge, state what this can establish about the slide, and design an experiment to distinguish code generation from placement.

Solution

Using 0.15 µs as a representative contended per-entry cost gives a scale estimate \(4\times0.15=0.6\) µs, about \(2.5\times10^5\) below the slide’s 0.15 s difference. This is neither an upper bound on compare-and-swap retries nor a measurement of the slide machine. It shows why attributing the entire difference to an intrinsic merge penalty needs evidence; the one-thread rows already differ by 0.04 s. Compile both programs with the same compiler and flags, inspect their loop and merge assembly, then repeat paired measurements at \(N\) and \(10N\) under fixed and deliberately varied affinity. A constant-cost merge does not scale with \(N\); loop-code differences can. Holding placement fixed tests whether the ranking persists. Scaling alone cannot distinguish them because placement can also change per-iteration throughput.

Exercise 5 (design judgment). For \(N=10^{6}\), \(p=12\) and \(\delta=20\) ns, choose a schedule and chunk size, with reasons and numbers, for three loops. (a) Every iteration costs 5 ns. (b) The cost rises linearly from 1 µs to 10 µs. (c) 99 % of the iterations cost 1 µs and the other 1 %, at unknown positions, cost 1 ms.

Solution

(a) The queue does not saturate only for \(k\ge p\delta/c=48\), and dynamic scheduling never beats static here. Use static. (b) (12.6) gives \(k^*=\sqrt{10^{6}\times20\ \mathrm{ns}/(11\times10\ \mu\mathrm{s})}=13.5\). Use dynamic,16, a reversed loop with a larger chunk, or a static cyclic assignment with chunks of 8 or 16. (c) \(T_{\mathrm{work}}/p=0.92\) s. If heavy positions are uniformly random, a static share has about 833 heavy iterations with standard deviation 28, or about 28 ms of load variation; the slowest of 12 can be several standard deviations above the mean. This estimate does not cover adversarial clustering of unknown positions. For dynamic scheduling (12.5) bounds the loss by \((1-1/p)\,C_{\max}\) with \(C_{\max}\) up to \(k\) ms, so a loss of 9 ms (1 %) allows \(k\le9\). Use dynamic,8. Bound (12.5) still applies to the chunks actually produced by guided, but does not give the small bound based on \(k\): an early large chunk can cost about \(T_{\mathrm{work}}/p\).

Exercise 6 (implementation and measurement). Write a loop b[i] = 0.5 * i over a 64-byte aligned array of doubles, \(N=4\times10^{7}\), 8 threads. Predict from the cache-line arithmetic of Chapter 11 which of static, static,1, static,8, static,64 and dynamic,1 suffer from false sharing, then measure.

Solution

Element \(i\) lies in line \(\lfloor i/8\rfloor\). With static,1 the 8 elements of a line are written by 8 threads: false sharing is expected, and the same for dynamic,1 plus the take cost. With static,8 each chunk is one line with one writer, so no sharing is expected; the same holds for static,64 and static.

#include <stdio.h>
#include <omp.h>

#define N 40000000L
#define P 8

static double b[N] __attribute__((aligned(64)));      /* 64-byte aligned: 8 doubles per cache line */

int main(void)
{
    struct { const char *name; omp_sched_t kind; int chunk; } s[] = {
        {"static", omp_sched_static, 0},     {"static,1", omp_sched_static, 1},
        {"static,8", omp_sched_static, 8},   {"static,16", omp_sched_static, 16},
        {"static,64", omp_sched_static, 64}, {"dynamic,1", omp_sched_dynamic, 1},
        {"dynamic,64", omp_sched_dynamic, 64}};
    printf("b[i] = 0.5 i, N = %ld, p = %d, best of 5\n", N, P);
    for (int q = 0; q < 7; q++) {
        omp_set_schedule(s[q].kind, s[q].chunk);
        double best = 1e30;
        for (int r = 0; r < 5; r++) {
            double t0 = omp_get_wtime();
            #pragma omp parallel for num_threads(P) schedule(runtime)
            for (long i = 0; i < N; i++) b[i] = 0.5 * (double)i;
            double t = omp_get_wtime() - t0;
            if (t < best) best = t;
        }
        printf("%-11s %7.1f ms  %6.2f ns per iteration\n", s[q].name, best * 1e3, best / N * 1e9);
    }
    return b[N - 1] != 0.5 * (double)(N - 1);       /* 0 when the last element is right */
}

b[i] = 0.5 i, N = 40000000, p = 8, best of 5
static         32.9 ms    0.82 ns per iteration
static,1       90.4 ms    2.26 ns per iteration
static,8       47.2 ms    1.18 ns per iteration
static,16      50.5 ms    1.26 ns per iteration
static,64      35.0 ms    0.87 ns per iteration
dynamic,1     996.0 ms   24.90 ns per iteration
dynamic,64     55.0 ms    1.38 ns per iteration

The sample costs are 0.82 ns per iteration for static, 2.26 for static,1 and 24.90 for dynamic,1. Across captures static,1 takes approximately 2.2–3.1 times the static time, consistent with predicted false sharing. dynamic,1 takes 30–39 times as long; dispatch alone costs roughly 14–20 ns in dyn_cost.c, so this row cannot separate queue contention from false sharing. Line-aligned static chunks of 8, 16 and 64 take about 1.4–1.8, 1.5–1.9 and 1.1–1.7 times the static time despite one writer per line. Their excess needs a separate compiler/cache experiment; timings alone do not identify its cause.
